# 本人赠粮原点返回

## 实际缺口与范围

[十五日交接窗口审计](../reviews/food-handoff-window-replay.md)已经确认：合法接受项曾出现，另有交付与离开错时，以及旧活动占用决策时间。它没有证明菜单缺陷导致那条轨迹的饥饿。历史中收方也曾通过其他移动返回原点。

本次另查出一个较窄的行动表达缺口：本人赠粮记录记住精确交接点，并提醒“返回不保证对方仍在”，但接受后的收方只有撤回项，没有明确返回该点的编号行动。通用菜单不接受任意坐标，只提供四向六格探索、建筑及其他已知事务的目的地。它们可能偶然返回，却不是对本人既有交接点的可靠表达，尤其不能指定室内原格。

新增 `personalFoodGift.return`，只让合法收方自己选择沿真实路线回到本人已接受的原点。这是新增自主协调能力，不把历史错时重新命名为故障，不改变任何控制器、默认决策策略、资源量或生理参数。

## 行动边界

- 仅本人已知接受、未到原固定期限、凭据完整的收方可选；年龄与原赠粮身份继续复用原条款，v2 合法收方满六岁。送方、未接受、已知撤回及未知年龄均不能使用。
- 只带原 `giftId`，不接受坐标、数量、期限或代理人参数。室外到精确原点，不能用送方的相邻交付路由代替；室内走到原房间原格。
- 出发、行路和最后一段实际办理均检查本人状态、道路、房间权限和路径。新增操作不提供进入权、监护权或身体搬运能力。从别屋出发必须真实退出，再走到原屋。
- 走路后另花一游戏分钟核实本人到点，身体照常消耗。完成只记录本人返回，不增加食品、营养、健康或权限，不自动等待、进食或触发供者行动。接受、实际交付和进食仍是独立选择。
- 不延长原期限，不中断供者旧活动。收方仍可选择不返回、离开或立即撤回；忙碌时的 runtime 决策准入不变。
- 返回展示和固定地址只使用本人已知的接受记录及当前自身状态，不看远方供者的库存、死亡、位置或未传知撤回，也不因远方目的房屋毁坏或权限变化悄悄删掉地址。展示是尝试，实际执行仍按当前真实通路和权限拒绝失效目的地。返回本身不把世界真实赠粮状态刷新为本人知识。
- 已到原点不重复推荐。最终菜单最多另加一个返回项，按稳定 ID 和原有三十分钟窗口轮换，不拿进食、安全、照护、拒绝或其他原选项换空间。常规预算由84增至85，现有额外即时停止项规则不变。多份约定与短接触仍可能错过，数字编号和展示转动也可能改变，不能承诺模型选择不变。

## 实际验证

主测在默认正式种子5401中只显式布置父女接触位置，保留原九人、地图、财产、库存、食物批次、身体及日期。随后全部用最终编号选择和真实0.25分钟步进：提议 → 本人接受 → 自行走到住处门口 → 明确返回原点 → 送方另选交付 → 收方另选进食。原点距门口两格，该时刻的通用移动没有直接回到原点的选项。

修前新增三项主测为2失败、1通过，两个失败均是缺少返回编号项。实现后通过；保存中途真实活动，再从内存SQLite重载续走，可完成且不重复交付。该正式种子中的收方本来有食品，所以后续进食不声称一定吃到了刚收到的那个批次，更不声称救活了她。

另在项目内新建独占合成SQLite文件，保存真实返程中途活动，关闭数据库后重新打开，逐项核对活动、赠粮、批次及九人库存；继续返回、另行交付与进食，再次关闭/打开后不重复。该独立落盘脚本初次第二次提交漏传旧revision，被存储层以`stale_world_revision`拒绝；修正脚本提交参数后通过，失败记录未删除。脚本和完整合成存档只保留在本地`output/personal-food-gift-return/`，不随跟踪测试分发。

同一交接后检查点的十分钟对照保留同一供者交付选择，只显式改变收方选择：返回分支完成一份原食品的转移；留在别处分支交付失败。记录全部九人的食品、饥饿、体力、健康、危险饥饿分钟及实际进食收据；交付不等于吃饭。这只验证新行动能让这种自选协调成功，不是自主模型会这样选择的预测。

负面对照保留供者已经选择的120分钟等待：收方返回不能叫醒对方，最终原约仍到期，未增加或转移食品。另用同钟不选择返回的双世界比较，生成菜单不改变真实步进终态。过滤新增项后的旧语义选项集保持一致；不是字面编号不变的承诺。

[独立审查](../reviews/personal-food-gift-return.md)覆盖室内原格、别屋退出、年龄、撤回、远方事实、过期、最后0.25分钟、路径/权限变化、饱和菜单和本人记录边界。

## 复验与限制

```sh
env -i PATH=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/bin:/usr/bin:/bin \
  HOME="$PWD/output/personal-food-gift-return/home" TMPDIR="$PWD/output/personal-food-gift-return/tmp" \
  TSX_DISABLE_CACHE=1 node --import ./scripts/acceptance-offline-guard.mjs \
  --import ./node_modules/tsx/dist/loader.mjs --test --test-concurrency=1 \
  tests/personal-food-gift-return.test.ts tests/personal-food-gift-return-review.test.ts
```

Node路径按本机安装调整。主测5项与独立12项均通过，相关最终回归共127项通过。提交前第一版整套测试在不包含`.env`、`runtime`、旧`output`或`.git`的隔离副本中运行，源码/脚本/测试逐文件SHA-256与当时工作树一致，6385/6385通过，零失败、取消或跳过，用时约33.7分钟。依赖复用当前锁定安装，服务器先重新编译。首次整套运行因补齐目的地隐私反例而主动取消后重新冻结运行，首次部分结果不算通过。类型检查、服务器编译与显式关闭环境文件/项目配置加载的前端构建通过。首次把离线测试守卫直接用于Vite时，因为守卫替换了`realpathSync`而丢失其`.native`属性，构建失败；保留该失败，改用`configFile:false, envFile:false`的受控构建后通过。Vite仍提示主包大于500kB，未把它当作本功能性能验收。红测、对照JSON诊断、类型检查及回归结果保存在忽略提交的 `output/personal-food-gift-return/`。既往十五日原归档不在当前工作区，本轮没有冒充其重放，没有重新做十五日或多种子长期验收，没有调用真实模型或使用真实存档。不能由这些小范围合成结果推断真实AI的交接频率、长期供餐或存活改善。


## 提交复核后的共享出口修正

提交复核随后发现起步时出口已阻断会被共享逻辑当空路径而瞬出。原6385项没有覆盖该情况，不能当修后源码验收。已另作[共享出口修正](room-exit-boundaries.md)，保护当前室内位置、旧活动和搬运前副作用，并新增独立边界测试；最终验证应同时查看该报告及其后续复核。

修后最终完整套件为6411项中6409通过、2项隔离副本漏页面失败；补齐同hash页面后对应完整两文件17/17通过。该跨运行事实及守卫/复制重试均详列在共享出口报告，不能简称“6411全绿”。
