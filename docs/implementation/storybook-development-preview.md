# 开发专用可选绘本诊断预览

基线 `20b1971`。这一批把现有合成贴图和动画原型接到**明确选择后才开启的开发预览**，不把它接成正式默认画面。正式 `main.ts` 仅导出已存在的 `ValleyScene` 引用；正常生产构建不导入新入口、控制面板、合成图集或专用 Scene。原 2D 默认与原可选 2.5D 保留。

## 素材边界

仅使用仓库自制、MIT 许可的 `synthetic-animation-prototype` 诊断图集：48 个带 S 标记的四向箭头帧、地表、位置标记和共屋线框，不是人物、建筑或最终绘本美术。图集来源、PNG CRC/尺寸/哈希及帧契约见[原型接线](storybook-animation-wiring.md)。浏览器入口仍调用 `prepareStorybookAtlas` 的真实字节核验与默认 decoder，没有伪造浏览器解码。

**两张用户参考 PNG 尚未取得并核验像素，正式美术未制作。** 用户设计文字和完整提示词已在项目中，但本地素材目录只有提示词，没有对应 PNG；设计文本里关于图片已收的表述不能作为本批已取得图像的证据。本批没有改动那五项用户设计文本或五项赠食候选，也没有把概念图或诊断箭头冒充实际人物外观。

## 开启与退出

复用已有开发观察服务器，不新增启动器、后端或 HTTP API。以下是本地开发者可复现流程，本批验证没有启动真实服务或连接真实存档：

1. 从仓库根目录，在一个终端运行既有合成源：`node --import tsx scripts/dev-observer-server.ts`。
2. 另一终端运行既有开发前端：`node scripts/dev-observer-web.mjs`。
3. 打开 `http://127.0.0.1:5173/ai-town/?storybook=1`。只有单个精确值 `storybook=1` 才注入新入口；没有参数、其他值或重复参数都不会出现诊断面板。入口再检查 `import.meta.env.DEV` 和同一 URL 条件。
4. 页面仍先显示原视图。选择当前快照中一个**原居民 ID**，再点击“打开合成诊断预览”。下拉框默认空，不按数组顺序、姓名、性别或职业猜角色。绑定只为这一 ID 显示诊断动画；其他居民继续使用已说明的回退。绑定不自动改选择、跟随、外观或世界记录。
5. 原人物选择与跟随入口继续可用。点击“返回原视图”或按 Escape 退出；反复进入/退出不增加连接。改变窗口尺寸会返回原视图，再次显式打开以重新安装 viewport。

合成源本来就是静止停表的开局，诊断动画也应保持冻结。这里没有解除暂停、推进时间、注入行动、重置世界或模拟成果的按钮。已有服务器的 `--live` 功能不在本批扩展或实测范围；不需要也不应为这一预览启动正式服务、读取 key 或真实档。常规 `npm run dev:web` 和生产页面不注入诊断入口。

开发服务器继续只放行既有 GET `/ai-town/api/world` 与 GET `/ai-town/api/events`。新模块的加载属于静态开发资源，不是第二份观察 feed。原拒绝写请求、固定本机代理、禁止 `.env`/密钥/存档/output 访问的配置没有放宽；新入口不接受 URL、凭据、数据库或模型参数。

## 同源身份与生命周期

- `storybook-development-session.ts` 只消费传入的 `ObserverMap`。传给原动画控制器的是同一个 Snapshot 对象、连接状态和居民 ID，不复制成另一个世界，不启动引擎，不发送消息或写世界。
- 初始启用等待图集验证，等待期间原视图可使用。准备取消、房间改变、世界替换、ID 消失或重复会取消旧挂载；旧挂载不会自动恢复。世界替换后需重新选择 ID，其余情况需再次显式打开；迟到的解码或 Scene ready 不会重新开启。
- `storybook-development-preview.ts` 在**原 Phaser Game** 中创建一个专用 Scene，使用原 Game 循环，没有第二个 Game、RAF 或 interval。原 Scene 保持接受快照及原导航，地图指针输入临时关闭以避免一次点击同时命中两幅地图。退出恢复原输入状态以及进入前的 2D 或 2.5D 视图，不销毁原 Scene/Game。
- 点选沿用现有非透明像素拾取并传回原 ID。已有跟随状态决定窗口，采用动画记录核验的户外脚点，不按显示时钟推算位置。不能观察的跟随位置会恢复原视图而保留身份；没有把人补到门口或任意初始格。
- 室内仍未提供贴图。实际进入房间时返回原视图与原房间。全图、建筑/动物/项目定位、镜头手动操作等不受支持的路由先恢复原视图，再交给已有路由处理；这批不声称实现贴图地图自由平移/缩放。
- 世界暂停、断线、页面隐藏、系统减少动态继续使用原播放器冻结规则。环境通知直接采样并检查绘制结果，不等 Scene tick；恢复不补播成果，显示时间不改变世界脚点。
- 图集或 Scene 初始化失败、被吞下的绘制异常、相机变换、未知记录、原/专用 Scene 关闭均清理本批资源并回退。专用 Scene 先隐藏和停用，随后通过微任务从原 SceneManager 移除，避免在 shutdown/destroy/preupdate 中重入销毁。唯一 Scene key 避免旧回调移除新预览。
- HMR dispose、重复 close/dispose、取消后迟到的 ready 都释放本批订阅、输入/可见性监听、贴图、显示对象和 Scene。会话只改页面本地观察状态，未增加生产测试控制口或全局调试对象。

仍沿用原型最多 32×32 格、192 个显示对象、512 居民/8192 建筑记录限制。未覆盖室内、特殊身体状态、资源/动物/设施或库存内容不能被诊断画面解释为不存在。无生产级块缓存、大地图吞吐或帧率承诺；原 Scene 仍运行，不能用单独 Scene 的开销代表全页成本。

## 检查与未验收

新主测和[独立审查](../reviews/storybook-development-preview.md)使用合成内存世界与 Mock DOM/Phaser，覆盖严格开发开关、默认被动、精确 ID、同源对象、跟随、各冻结原因、室内/世界切换、异步取消、原 2D/2.5D 与输入恢复、绘制/注册/解码失败、相机/resize、旧回调和资源释放。1440×900、1280×720、390×844 仅验证接口参数和生命周期，不是实际屏幕版式或字体可读性检查。

新增主测23项、独立反例14项，共 **37/37 通过**。加入全部绘本原型、等距室内外、观察导航、人物跟随/状态与成果提示的选定回归共 **582/582 通过，0 跳过**。其中一项执行实际 `main.ts` 的调和与单一 GET/SSE mock，确认诊断视图收到原 accepted Snapshot 的同一对象和更新后的位置。最初该测试错误地额外加了半格脚点偏移；按现有动画坐标契约改正期待值后通过，没有改动人物位置实现。

全项目 `tsc --noEmit`、服务端编译、正常客户端构建和强制 `DEV=true` 的独立开发入口构建均通过。正常客户端四个产物与此前动画基线构建逐字节一致；另检查 Rollup 模块图确认生产产物没有新预览/合成图集，独立开发构建实际包含新增接线而非被 DEV 分支裁掉。两种客户端仍有已有的大分块警告，不代表性能已达标。全部命令清空环境，HOME/TMP 放仓库独占 output 路径；Vite API 明确 `configFile:false,envFile:false,envDir:false`，服务端/客户端输出不覆盖正式产物。验证日志在 `output/storybook-development-final/`，测试、类型、服务端与两种客户端构建分别留存。十项受保护设计/赠食文件与动工前 SHA256 完全一致。

没有运行全仓 `npm test`，没有真实浏览器、浏览器 IPC、GPU、美学、遮挡观感、手机设备、帧率/内存或长期自主生活验收。没有联网、读取 key/真实档或重试 bwrap；没有提交或推送。这些是选定合成套件的通过，不是全仓或生产验收。
