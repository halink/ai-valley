# 未知年龄不授予幼儿监护豁免

## 已复现的边界

离线合成七岁人物保留 `canDecide=true`、`canExpress=true` 与现有监护人，只将 `bornAt` 改为 `null`、`NaN` 或未来时点，原 `ageYears` 的兼容回退0就会被家庭规则当作真实幼儿年龄：志愿者可通过最终编号菜单提出 `fosterChild`，现监护人单独接受便能新增永久监护，孩子没有实际同意。

这不是正常出生日期的六岁生日计算问题，不撤回已有分数分钟生日校准，也不推断正常存档普遍损坏。本修复不修补出生资料、不推测真实年龄，不把未知年龄当成人。

## 有效年龄与家庭权限

- `world/time.ts` 新增纯函数 `knownAgeYears(bornAt, minute): number | null`。只接受有限数字，出生与当前时间、非负经过时间都须在既有安全数值域内。合法的0、负出生时间、分数分钟及真实生日边界继续使用原算法；缺失、非数字、非有限、未来与越界数据返回 `null`。
- `ageYears` 保持兼容的数字结果，未知仍回退0，避免已有成人 `<18` 拒绝门禁被 `NaN` 放开。但该0不再作为家庭幼儿或未成年代理的证据；授予这类权限须使用 `knownAgeYears` 并明确排除 `null`。
- 新监护提议、本人或监护人的肯定答复、实际永久登记均要求孩子当前年龄可核实且未成年。六岁以下仍可按现监护规则交接；六岁至十七岁继续要求本人实际签署及当前能力；十八岁及以上拒绝监护代理。
- 原 `guardianOffer`、本人签名、监护人签名、原一日期限和事件都不因坏资料、菜单读取或重载而重写。尚未完成的交接暂停；已经完成的合法监护不撤销。排队动作在完成时再次核验，末0.25分钟才出现坏资料也不能落永久权限。
- 未知年龄且有能力的本人和原监护人仍可通过最终编号菜单拒绝同一旧提议。拒绝不授予成人或幼儿权利，执行仍核对原提议绑定、原当事人、现有监护资格、能力和共处条件。拒绝后迟到接受不能恢复提议。收养及家庭迁居的原提议拒绝/撤回同样保留非授予入口，实际授权由各模块另验；这不开放未知年龄的迁居接受或到达。
- 同文件 `tendChild` 的幼儿喂养代理也须有有效的六岁以下年龄。未知不能靠已有监护列表代替本人授权。

## 生命周期不补造事实

未知年龄不触发 `lifeStage` 改写、年龄激活能力、成年转换或 `infantRest`。原阶段和决定/表达能力保持原值，既有能力也不是成人权限证明。到期提议和同住邀请照常清理；非年龄死亡和已记录孕育等独立事实不被停掉。

本切片不改变其他医疗、长期照护、救急或迁居规则；这些同源分支分别修复和验证后再统一回归。
