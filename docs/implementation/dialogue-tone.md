# 实际发言语气留存

## 复现与修复边界

正式 `createFrontierWorld(5401)` 只解除暂停并推进一分钟，在481分钟复制三份相同世界。苏庭分别从最终编号菜单选择向徐澜 neutral、friendly、hostile 说同一句“我知道了。”。三个动作均于484分钟完成；旧实现丢弃 `Action.tone`，事件、听者记忆、下一次完整模型输入和SQLite重载后的输入完全相同。

新增主回归先在旧实现运行：2/2失败，分别确认事件缺少语气，以及240字原话下的短记忆没有语气。现在完成动作才生成可选 `WorldEvent.speechTone`，并由原有事件投递入口复制到实际见证人的 `Memory.speechTone`。原 `event.text` 不改变，不把语气插入或改写为角色原话。

`friendly`、`neutral`、`hostile` 是本人选择并实际使用的表达方式，不是对听者的感受、意图、承诺或内容真伪的判定。系统不因语气改变任何好感、信任、矛盾或 `lastInterpretation`；原有交谈事件依据仍沿原路径登记，听者要另行明确选择理解才产生自己的看法。

## 传播、权限与旧档

- 仅实际完成 `talk` 写入。构造上下文、展示菜单、解析编号、提交未完成计划均不产生发言语气；迟到revision、失去决定/表达能力、目标死亡/离谷/远离/换室导致原执行失败时不产生发言事实。
- `emitEvent` 沿用既有 `canObserve`、同室和六格 `nearLocation`、显式 witnesses 交集。说话者、实际在范围内的受话者和旁听者都能保留同一事实；死亡、离谷、不能观察、异室或超距的人不获得这条记忆。本人和受话者原有 `source:'self'` 表示当事人，旁听者仍为 `witness`，不在此变更来源语义。
- 后到的人不补发，历史关系中的事件ID不能把全局事件反灌成本人的语气记忆。仍只保留原80条个人记忆、18条上下文，以及每模型3或6条短摘要；被遗忘的语气不会因仍有全局事件而重新出现。
- 语气为可选有限枚举；未知或损坏值不推断为neutral，不从原话中的“友善/hostile”等字样猜测。旧档、旧未完成动作以及无语气的讨论记录可继续加载。只增加JSON可选字段，无SQLite列迁移、旧档回填或真实存档扫描。
- 原有听觉规则不是物理声学模型：相同室内区域按房间坐标距离，异室不传播；室外同空间范围内不额外检查树木、cliff或视觉遮挡。此修复不改变可听范围，也不声称验证了穿墙声学。原有睡眠可观察判定同样保留。

## 原话与最终决策输入

与[完整原话依据修复](dialogue-content.md)共同增加可选 `speechText`，在正常1–240 UTF-16长度的实际talk完成时保存不含姓名前缀的原话。事件及本人记忆各自持有字符串；不从事件总账补造听者未收到的文字，也不解析旧文本重建所谓完整原话。

三种模型的短记忆把 `实际发言语气：neutral/friendly/hostile` 放在文字节录之外；长姓名或240字原话不会挤掉语气。最终 `social.interpret` 菜单使用对应本人记录展开完整发言、来源及语气，不替听者作理解。转义字符串里的角色标记、换行、编号、控制字符或HTML只属于引文资料，不作为新指令；渲染时无效语气不作为标签。

SQLite仍按原事件JSON和居民JSON持久化，内存数据库回归确认三种语气重载后都保持各自事件、记忆与三种模型完整输入，不改变指标和关系分值。
