# 分数分钟生日与年龄权限

## 问题与范围

居民真实出生会保存引擎当时的分数分钟。原先统一年龄为 `(minute-bornAt)/YEAR`，即使当前时间已经等于 `bornAt + 6*YEAR`，减法和除法仍可能得到 `5.999999999999999`；13、18和65岁同样存在。反方向也会发生：负出生时间的开局居民在生日之前一个可表示时间点，除法已经得到整岁。

这不只是显示问题。六岁生日最后工时仍可能沿用幼儿代理，新增监护、执行长期照护或开始医疗护送；十三岁的钓具权限、十八岁的成人权限与监护结束也会延迟。

## 统一语义

`src/world/time.ts` 的 `ageYears` 保留连续年龄，只在减法/除法和最近整岁生日的先后关系冲突时修正：

- 以已存出生时间加整岁年长得到生日时间。
- 当前时间达到该生日，而除法略低于整岁时，返回整岁。
- 当前时间仍在该生日之前，而除法已达到整岁时，返回低于该整岁的可表示值，最多比整岁低两个 ULP。
- 不向当前时间加容差，不四舍五入世界时间，不修改出生记录，不累加新的年龄状态。生日的前一个可表示时间仍未满岁。
- 普通分数年龄不变。绝对时钟较大、跨二进制指数边界时也依据同一生日比较，不使用随时钟增大的授权宽限窗口。

输入必须是有限数字，出生时间、当前时间的绝对值和非负经过时间均不超过 `Number.MAX_SAFE_INTEGER`。不满足时 `ageYears` 返回0，使已有 `>=18` 和 `<18` 成人许可/拒绝守卫一致关闭。这不是修复损坏日期，也不证明未知年龄具有幼儿监护代理权限。后续[未知年龄家庭权限修复](unknown-age-family.md)新增 `knownAgeYears`，将无效年龄明确表示为 `null`；家庭授予代理权限及生命周期只使用可核实年龄。接近数值极限时浮点本身不再能表达0.25分钟，不能据此声称模拟时钟仍具有该分辨率。

既有居民生命周期、行业、家庭、教育、医疗、长照、就业、财产、公共事务和决策菜单沿用 `ageYears`。另将三处直接减出生时间的居民判断接入同一函数：运行时幼儿照护优先级、开局监护关系、五分钟进食预测的老年风险快速路径。动物日龄/寿命与开局原始年龄配置不改写。

## 验证

先在原实现得到失败，再修改生产代码：

- `tests/fractional-age-boundaries.test.ts`：真实 pregnancy→`stepWorld` 出生，保留原分数出生时间；6/13/18生日之前和生日点，0.25及默认1.2分钟步进，内存 SQLite 重载，实际最终编号菜单、钓竿/斧头15分钟工作，能力、监护与成人事件不重复。
- `tests/fractional-birthday-consent.test.ts`：真实出生 `121440.001`，六岁生日最后0.25/1.2工时，监护必须另有本人同意，长照不扣料/供餐/付钱，医疗不开始幼儿代理护送；监护含完成前SQLite重载。1.2工时可能留下原有微小工作余数，测试也继续完成并重验，不修改动作计时器。
- `tests/fractional-age-review.test.ts`：独立负出生日期反例、生日相邻binary64值、6/13/18/65岁、1e9/1e12及2的30/40/52次方跨界、无效输入和连续年龄。
- 暂停、死亡时间、单份遗产和单条死亡记录保持不变；既有 generations/later-life 及各照护权限测试继续回归。

所有证据来自离线合成世界或内存SQLite。不调用模型、不读取密钥和正式存档，不代表真实模型多年验收。完整执行记录见[独立审查](../reviews/fractional-age-boundaries.md)。
