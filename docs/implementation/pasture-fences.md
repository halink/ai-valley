# 牧场围栏的实际磨损与本人修护

本项接通已完工牧场的围栏维护。它不改变土地议决、放牧所有权、动物护送或水槽的实际物资规则，不提供自动维修和公共劳动指派。

## 可执行的闭环

- 新围栏从 100% 开始，按已过去的模拟时间每天磨损 4 个百分点，雨天为 6 个百分点。同一分钟重复推进不重复磨损。到期但仍在原处的围栏继续磨损；已撤栏的不再磨损。
- 耐久降至 0 时，外围不再有阻挡作用，停止接纳新牲畜。草地仍被原牧场实物保留，原槽水和动物身份、位置不变。这里没有新增动物逃逸或自动迁群逻辑，原有在场动物仍按当前牧场活动规则照料。
- 责任人亲自接近已知牧场后，耐久不高于 70% 且本人持有 4 木材，可从正常决策菜单选择在原入口修护。每次选择 30 分钟，累计 60 分钟完成后恢复最多 40 个百分点，最高为 100%。所有工作仍须本人实际到达原门外，路阻和身份变化会停止执行。
- 4 木材在首次实际劳动时从本人库存扣除，保留在该围栏的修护批次。中断、重新决定和快照重载都保留已投入材料、实际工时、批次身份和最后工作时刻。未完工不增加耐久，继续原批次不再扣料；已结束批次不能重放。没有退款或新增回收物。
- 修复的是原围栏和原门，不扩张范围、不生成草水、不移动动物、不增加畜舍容量、不自动重新开放休牧场，也不延长用地期限。到期场可以保全原设施，但依然禁止新入场。合法继承的设施连同未完修护一起保留，继承人是否继续由本人重新选择，原主人不能继续操作。

## 观察与兼容

野外面板展示耐久、累计修护用木、已完成次数、当前批次工时和已投入材料。地图不再把无围栏旧牧场或已失效围栏画成仍有完整阻挡的围栏。损坏和本人实际开工、完工生成事实记录；远方居民不会收到当前耐久的行动选项。

旧档中没有围栏的牧场不会获得围栏、耐久、材料、水槽或水。已有实体围栏但尚无耐久字段的旧档从首次推进的当前时刻登记为 100%，不补算过去磨损，也不虚构维修历史。新修护状态作为可选字段随普通世界快照保存。

## 离线验证

主要测试：`tests/pasture-fences.test.ts`。覆盖晴雨磨损、同刻重入、跨快照继续磨损、旧档、屏障失效、普通决策菜单、实际材料和工时、中断重载、路阻、到期保全、设施继承、过期批次重放与只读观察面板。同时回归牧场扩建、有限地权、产业与基础设施测试。

使用仓库中已安装的工具，不访问包注册表：

```sh
node node_modules/typescript/bin/tsc --noEmit
node --import ./node_modules/tsx/dist/loader.mjs --test tests/pasture-fences.test.ts tests/pasture-expansion.test.ts tests/land-rights.test.ts tests/industry.test.ts tests/infrastructure.test.ts
node node_modules/typescript/bin/tsc -p tsconfig.server.json
node node_modules/vite/bin/vite.js build
```

边界：未完工建设阶段的围栏仍沿用原有保留/清理逻辑；本项不新增灾害损坏账目、迁栏协议、雇工修缮、自动补料或动物逃逸。未运行真实模型或读取真实存档；多年真实模型行为、维修成本平衡与浏览器视觉验收需另行验证。
