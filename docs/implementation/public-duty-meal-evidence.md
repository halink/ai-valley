# 公厨与公共照护实际供餐证据

## 实物来源和实际行为

新增默认关闭的 `publicDutyMeals` 独立切片，只记录成功完成的 `publicDuty.receive`。居民自己选择接受服务，原有班次、能力、到场、工位、时间窗、材料、拒绝和结束检查不变。提出公共预算、表决、采购交付、预留工资、认领、报到、值守、撤回和班次结束都不是供餐；没有新增自动喂养、物资锁定、替他人同意或读取远处库存的权限。

原引擎实际配方不是可自动互换的食物选择：

- 公厨 `kitchen` 从其指定来源扣 **2份芜菁和1份水**，受益者即时饥饿最多缓解42，健康不变。
- 公共照护 `care` 从指定来源扣 **1份餐食和1份水**，即时饥饿最多缓解20，健康最多增加8，分别受0和100边界限制。
- 没有拨款的班次使用服务者 `person:<providerId>` 个人实物，不支付工资。
- 已拨款班次使用原址 `public:<buildingId>` 对应 `civic.stores`，不是服务者个人库存、独立的 `public-reserve`、受益者库存或水桶。`treasuryStock` 是公共汇总，虽随真实扣减更新，但不另记一份消费。
- 公款从既有班次工资托管账户扣到实际服务者；记录预算ID、账户、每次工资、服务者钱款前后、托管余额前后和班次累计已付前后。工资、采购支出、营养和饥饿变化互不替代，采购或预留也不算服务工资。

每条记录保留实际事件与本人计划ID、动作定义、班次、建筑、角色、班次服务序号、服务者与实际受益者、来源容器、实际扣减数量和原批次可知事实，以及即时饥饿/健康前后与差值。公共照护原事件仍可叫 `care`，但本切片按真实 `publicDuty.receive` 独立记录，不并入普通 `careMeals`、长期照护、监护供餐、自主进食或加工。

## 原批次与未知

观测在实际扣减前读取本次来源容器的原批次，以原有最早到期顺序对应实际份数。原定义营养与本次固定缓解分开：两根旧芜菁可以有不同营养，低饥饿时实际缓解也可能少于42。水单列数量、零食品营养、空批次；不把水或健康增加换算成食品营养。原批次缺失、不足、损坏、过期、定义缺失、同次捕获中初始化补造或修补无法证明来源时，缺失营养/批次保持 `null`，不使用当前定义或饥饿差倒推。

未知来源标记只在当前捕获调用内保留，不新增持久来源标签。若原有引擎在更早一步已经初始化或修补批次，之后的观察只能读取当时已经存在的批次；本切片不恢复丢失的历史，也不能称为跨存档的完整来源证明。

## 隔离与持久提交

捕获沿用一次同步引擎调用的 WeakMap，只属于该 World 对象，`finally` 清理。不写入世界、居民、知识、最终菜单、存档或预测副本。启用与关闭观测须完整世界与保存结果一致。捕获不承担物理回滚，事务草稿及存储仍沿用既有机制。

运行时只在真实 `WorldStore.commit` 成功并安装已提交世界后发布 `food_step_committed`。提交失败不得发布草稿供餐；已提交库存、批次、工资和服务序号保持原状，重试成功才发布一次。重载不会重放既有回执。观察器或writer失败不倒退已提交模拟，但该段完整证据总量失效。

schema-1旧记录允许缺少 `publicDutyMeals`，缺字段表示未观测，明确 `[]` 才代表本段已观测零次。零步会话、漏步、缺边界、关闭失败或缺封存均不能生成完整新增总量，不因其他切片完整而补成零。

## 严格审核与逐日输出

严格边界只复制白名单数据属性，拒绝额外字段、访问器、符号字段、数组空洞、不安全身份、非有限数字和非法数量。审核核对来源身份、互异当事人、角色配方、原批次与数量/时点/营养、饥饿和健康限幅差值、工资三组实际差额、重复事件以及同一 `(shiftId,serviceNumber)` 重复。公款身份必须对应班次的托管账户，公共实物必须对应建筑容器。审核没有连接世界数据库重新取得议案，不是外部输入真实性的签名；实际预算、供货、工资、事件和批次的一致性另由真实引擎测试核对。

逐日输出保留原始回执、观测/未观测分钟、独立食物数量与营养、饥饿缓解、健康增益、次数、工资和个人/公共来源分项。总量只加一次实际物资，来源分项不再次叠加。缺测污染当日完整总量，后续明确零不能补齐。午夜完成归刚结束的一天 `(fromMinute,toMinute]`，不补造未观测日期。所有这些只覆盖指定成功动作，**不能称为全部喂养、完整食物账或完整健康账**。
