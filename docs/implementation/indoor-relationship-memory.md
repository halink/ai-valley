# 室内可见熟人的本人关系记忆

## 因果复现与规格调整

原关系摘要和社交可见性审查曾有意把室内回忆限制在 `canObserveBody` 的两格近察范围。这个条件适合身体迹象，却把“想起本人对她的看法”错误地绑定到“现在能近身观察她的身体”。本次明确调整该旧规格，不把旧测试描述成偶发实现错误。

`tests/indoor-relationship-memory.test.ts` 从正常 `createFrontierWorld(5401)` 开始，使用真实最终编号菜单、`parseChoice`、`submitPlan` 和每次 `.25` 分钟的世界步进：

1. 徐澜选择普通 `talk` 说出自己的话，苏庭的关系分数不自动改变。
2. 苏庭另选本人 `social.interpret`，形成好感 2、信任 4、矛盾 1 及自己的理解；时点为真实的第 `484.25` 游戏分钟。
3. 苏庭另选睡 5 分钟，实际走到床 `(2,5)` 并醒来；徐澜另选烹饪，实际到厨房 `(8,4)`。未改写人物位置来凑出主链。
4. 两人距离 7 格，真实可见、合法可走近，最终三种语气的 `talk` 均可选，身体近察和即时接触仍不成立。
5. 90 条合成本人日常事件挤出整个 80 条短记忆窗口后，三个模型的最终输入原先都不含已保存的本人看法。内存 SQLite 重载也无法解决。

主回归先在旧实现上执行，4 项全部失败：7 格摘要、实际小数时点、厨房/等待忙碌时摘要、SQLite 重载。修复后 4 项通过；旧关系与社交可见性专项合计 50/50 通过。

## 最小读取改动

生产代码仅改 `src/server/relationship-memory.ts`：

- 室内复用 `canSeeSocialTarget` 的十格保守视线、真实房间坐标、正确门口锚点、布局/家具遮挡、本人醒着可观察、人物在世且在地与非船上条件。
- 双方分别复用 `socialRoomAccess`，包括已有公共使用权、所有者/住户、有效公共床位或有限住宅租约。它不新增住房、厨房、经营或接触权限。
- 不把 `canExpress` 或目标是否忙碌当作回忆的先决条件；清醒而不能表达的本人仍可有自己的看法。本人睡眠或不能观察时不提供实时可见对象。
- 仅复制本人对 `knownPeople` 中对象的 `relations`，不读取对方的关系、记忆、身体数值、库存或意图。两格身体观察和实际动作完成规则完全不变。
- 理解时点改为有限数、非负且不晚于当前时刻，不再要求整数。`NaN`、无穷、负数、未来、字符串或缺失仍为未知。未修改排序和记忆轮转。

室外判断原样保留，包括十格、建筑/悬崖/树石/对角遮挡与未观察远处。旧档不补造理解或位置，不迁移、不写回。摘要仍是最多六人、24 字姓名、120 字理解的有界引用资料，并与短记忆和家庭记录分开。

## 行为与安全验证

主测试逐个比较三个最终模型路由：删去关系快照只影响输入，不改变任何菜单选项。只读查询前后世界完全一致，没有自动提交计划或模型请求。之后通过实际编号选择再次交谈，居民确实走到两格接触范围后才说话，双方分数仍不自动改变。

正常厨房工作与本人等待时可回忆，实际睡眠时不可见，醒来后恢复；内存 SQLite 保留位置、本人关系、未知信息和小数时点。独立反例另覆盖 3–10 格、11 格、家具与对角遮挡、异屋/门内外、坐标缺失/无效、双方权限和租约失效、未认识/远处、表达与观察能力、隐私、注入布局及旧档，详见[独立审查](../reviews/indoor-relationship-memory.md)。
