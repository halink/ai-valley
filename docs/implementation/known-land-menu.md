# 已知自有田地导航菜单

## 缺陷与本次范围

在 `1553a11` 的代码上重新复现并实现，不声称找回此前未保留的补丁。原 `buildChoices` 只选最近一块已知自有田；居民停留在同一位置时，其他田址可以一直不出现。该单一候选还会被 `focusedChoices` 的普通议程再次裁掉。

新增六项回归先在原代码运行：五项失败、一项通过。其中四田轮转只能见到一田，饱和最终菜单没有回田方向，能力不足仍产生田址方向。远程作物和路况不泄露的原边界保持通过。修复后六项通过，另加叠加菜单预算测试。

## 当前规则

- 一次最多一个已知自有田址导航。完整身份是田 ID 和坐标，重复身份合并，按身份稳定排序，每 30 游戏分钟轮换。先排除当前所在地址、非整数、越界等无效坐标，再计算轮换；固定候选集合在 N 个窗口内覆盖 N 个地址。同一窗口与输入顺序变化不改变结果。
- 地权提供地址，不提供远处作物、是否干田、成熟度、产量、存水或通路。候选生成不读取这些远程内容，也不找路或承诺可达。地权变化、离开当前田、候选增减在新 context 中重算；集合不断变化时不承诺固定的 N 窗口期限。
- 只有活着、在谷内且有决定与表达能力的本人获得可用于本菜单的自有田址。既有年龄、未知年龄自理、途中、乘船、被护送及仅可表达撤回的过滤先执行。六岁以上原有步行权限不扩大为种田权限。
- 最终议程只恢复 `buildChoices` 中实际存活的同一候选。它不再参加领域的第二次轮换；恢复阶段不从未过滤的世界数据重建动作。
- 优先用基础 56 项议程内的空位；已满则只替换最后一个多余的目标反思，至少保留原有唯一反思。没有多余反思时最多增加一行，不替换进食、休息、避险、拒绝、停止或任何其他非反思条目。其他类别仍按各自原有预算展示，不保证所有潜在行动同时可见。
- 选择编号只提交普通 `move`。引擎仍负责真实离室、路径、身体能力和途中失败，既有编号不能绕过这些检查。到场不是浇水；亲眼看见田况、有水且符合权限时，才另选实际浇水。无自动往返、取水、浇水、播种或模型调用。

## 菜单预算

普通在谷、非乘船/护送的最终菜单，按现有各组上界相加为 **84**：56 基础 + 2 水源 + 1 烹饪 + 1 播种 + 1 回田 + 9 社交语气 + 10 本人理解 + 2 浆果分享/听闻核实 + 2 日常约见。原文档的 82 尚未计入已经存在的播种保底；本次回田另增最多 1。

84 是各类别预算的理论合计，不是统一截断器，也不代表每次实际生成 84 项。独立恢复的 `care.stop.*`、`personalFoodGift.stop.*` 及通过能力/旅程过滤的 `health.cancelRescue` / `health.declineRescue` 可超过这个数字。日常约见的拒绝/撤回已经包含在其最多两项组内。镇外商人、访客途中、乘船及护送使用各自的菜单路径，不能拿 84 作为其统一上限。

## 验证边界

`tests/known-land-choices.test.ts` 覆盖完整轮转、全部关注领域下饱和展示、上下文只读、能力/年龄/旅程过滤、动态地权与位置、远程作物与阻路隐私、数字菜单解析、实际抵达后另选浇水，并用全组叠加合成 context 精确验证普通 84 行和另外的停止入口。另覆盖途中新增阻碍/丧失表达、旧导航在地权变化后不授予耕作权限，以及新建磁盘 SQLite 的新进程回读。

既有 `tests/water-source-choices.test.ts` 饱和测试仍断言原普通部分严格 56 项、田址严格 1 项、水源严格新增 2 项，并逐项确认原动作保留；没有删去原田地 fixture 或放宽原水源预算。

这里只证明隔离合成菜单与引擎边界，不证明真实模型会及时照料所有田地，更不代表正式九人十五日或跨季生存验收。未读取 `.env`、密钥或真实存档，未触碰临时助手接口，未运行模型或正式服务。
