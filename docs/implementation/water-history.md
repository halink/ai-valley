# 供水完成事实与历史观察

本项为[安全水供给第一阶段](safe-water-supply.md)和[有限协助饮水及赠桶](water-support.md)补充可核对的年表证据。它不改变居民决策、用水权限、库存规则或身体损耗，**不启用口渴、脱水或饮水健康加成**，也不表示四季持续供水已通过验收。

## 记录什么

每项供水动作只有在通过原有资格、地点、权限和库存校验并实际完成后，才在同一世界事件里附加版本化快照：

- 原完成回执、动作、行动者，以及实际饮用人或另一名当事人。赠桶接收人不计为饮用人。
- 涉及的原桶身份、完成前后的容量、水量、水质、持有人和实际存放场所。补入公共桶同时保留来源桶与目标桶，后来补水不被归功于原捐赠人。
- 实际影响的本人旧清水或木材库存前后值；泉水或有限原水登记的前后余量。
- 原协助授权或赠桶提议的身份，用于核对同一安排。授权、拒绝、撤回和赠桶提议本身不记作实物饮水。

制桶记录从无到有的空桶及真实木材消耗，不生成水。踏查记录从未登记到登记24份有限自然原水，不代表抽取或生产。煮沸记录同一桶的原水转为安全水及燃料消耗，不增加水量。装桶、倒回旧库存、捐赠、补水及实际接受赠桶记作转移，只有自饮、公共饮用、监护协助和有限成人协助记作实际饮用。

快照只包含本次操作所涉及的实体，不借今天的水量、归属、亲属关系或地点重建历史。它不追溯混合后每份水的最初来源，不是所有旧有采集、生产、灌溉、动物饮水、贸易和照护用水的统一账本。对于后来的权限停止，快照是观察者的当时事实，不表示远处居民知道相关库存或另一方已停止。

## 从年表查阅

年表和人物生平的历史筛选中可勾选“只看有实物快照的供水记录”，再按人物、年份、类别或原文组合查找。每条新供水事件可展开“这次供水的实物记录”，查看当次变化。原文搜索仍只搜索事件正文，不把内部身份或快照字段当成正文。

HTTP只读入口 `history/page?water=1` 采用现有稳定序列游标。供水筛选只匹配版本1结构化事实，不从“水”等文字猜测事件类型。供水筛选游标不能用于普通历史或另一组筛选；未开启新筛选的旧游标保持兼容。阅读较早页时新事件不会把读者移回最新，无关的新事件不会触发供水页更新提示。

## 旧档、保存和知识边界

- 新事件随既有不可改写事件账本一起保存。即使离开近期观察窗口、桶转手或重启，仍从已保存事件读取原快照。
- 旧档、旧回执及只有文字的旧事件原样保留，不补造历史快照。它们不会出现在“有实物快照”的筛选中，仍可取消筛选后按原文查找。
- 相同完成回执重试不再扣水，也不追加第二条事实；失败或尚在计划中的动作不产生完成快照。
- 新字段仅用于观察者历史呈现。没有增加居民记忆内容、远程通知、供给权限或模型请求。

## 离线验证

使用隔离合成世界与内存数据库，不读取密钥和真实存档，不调用模型、不运行 npm：

```sh
node --import tsx --test tests/water-history.test.ts tests/water-supply.test.ts tests/water-support.test.ts tests/history-pages.test.ts tests/history-reader.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.server.json
node node_modules/vite/bin/vite.js build
```

定向测试覆盖普通自主菜单至引擎完成、有限水源与燃料、两桶补水守恒、饮用人与赠桶接收人区别、授权与停止、失败和重放、旧记录、历史游标和分页、离开近期窗口后的存档、只读查询、HTML转义及新记录提醒。浏览器视觉验收和完整四季持续供水验收与这些规则测试分开，不据此开启新的生理风险。

2026-11-06最终离线验证：67条定向测试（其中11条新增）、1309条全仓测试、类型检查、服务端编译及Vite构建全部通过；构建仍有大于500kB的包体提示。独立复审见[审查记录](../reviews/water-history.md)。展开的供水详情可跨观察刷新保留，手动关闭后不会被重新展开。
