# 真实腐败损失的有限食物证据

## 范围与原有顺序

沿用默认关闭的 `directEatingEvidence` / `stepWorldWithFoodEvidence`，新增独立可选 `foodLosses` 和 `foodLossCoverage: "advance_food_spoilage_v1"`。来源新增、加工、进食、照护和损失各自列账，不相减推断净生产。

本批次只记录 `advanceFood` 过期处理处已真正扣除的实物食品。`cause: "spoilage"`、物品、数量、游戏时点、实际容器类别与匿名机器 ID 均来自该次扣减；没有伪造居民行动、事件、计划或当前过程定义。一次捕获内 `occurrence` 从 1 连续增加，同 tick 同容器同物品两次真实扣减也可分辨，不增加世界事件序号。

容器类别覆盖当前原有枚举的 18 类：个人（包括迁入前联系人、境外商人）、随身遗产、原址遗产包裹、商店、公共仓、公共储备、出售挂牌、援助、境外报价、运输货物、树上水果、动物待收食品、雇佣批次、加工批次、活动准备、活动贡献、家庭池份额和家庭赠与份额。遗产包裹 ID 可没有类别前缀，类别由原本那次枚举的真实来源确定，不从 ID 猜测。

`foodContainers` 具有遗产位置初始化、雇佣批次别名隔离等副作用。观察器没有额外调用它，也不新增盘点。原 `advanceFood` 已有枚举可选地同步保存类别；其它调用照旧。公共 `treasuryStock` 是汇总，第二次扣减不产生另一条损失。损失数量取同一实物扣减前后之差，而非累计 `spoiled` 差额；即使合成损坏世界让两个容器共享同一库存，新证据也不重复声称已经为零的实物又减少，且不会偷偷改写旧规则或旧累计数。

引擎依然先过期，再推进自然生成和居民动作。同 tick 腐败释放容量后生成的新食品属于新来源；过期食品不能继续完成 `eat`。批次不足后的加工取消、雇佣取消和原料退还只走原有逻辑，不另记损失。迁入、转移、赠送、采收、库存修补、汇总变化、活畜死亡、作物损害及其它损失均不由本切片推算。

这是有限的真实腐败切片，**不是完整损失账，也不是完整食物生产、消费或净收支账**。`foodProduction`、`foodConsumption` 继续未知。

## 原批次与未知

数量在实际物理扣减处取得。附加的批次信息只读 `advanceFood` 原初始化之前已有的 ledger，并验证过期子集与实际扣减一致。每个可确认批次仅投影数量、生产时点、过期时点、原定义与该数量的营养。不会带出原对象其它字段，也不拿当前商品或当前启用定义补营养。

旧食品缺失 ledger 时，原模拟可以自行初始化批次，观察器不改变此规则。但修补不是历史来源证据：捕获内在原初始化创建/裁剪处标记来源未证实，随后转移/合并保留同一元数据时仍未知。这也覆盖 `stepWorld` 在分钟循环之前先初始化、零寿命新规则让修补批次在首 tick 过期的情况。标记只在 WeakMap 中存在，异常清理，不进入世界或存档；元数据碰撞保守地保持未知。

原批次损坏、初始化改写、数量无法匹配时，真实扣减数量仍保留，`lots` 和 `nutrition` 为 `null`。原批次可确认但其定义没有可核实营养时，批次保留，营养为 `null`。没有捕获到的历史不能补造。存档既有合法批次只证明扣减时存在的原批次，不追溯证明其最早生产历史。

## 发布、writer 与逐日

采集器继续只附着一次同步调用的 World 对象；预测副本不串入、失败调用不返回成功证据。运行时仍先 durable commit，再安装新世界、复制并冻结后发布；数据库失败保持世界和存档原版本，不发布草稿损失。重试成功只发布一次，重载不重播。

writer 严格白名单检查每层对象/数组和数据属性，拒绝额外字段、访问器、非法标识、非有限数量、非食品、尚未过期批次、批次数量/营养不一致。匿名 ID 保持既有 identifier 字符集，遗产类别仅免除前缀要求，不开放任意叙事字符串。非法输入导致证据失败/未知，不能放宽边界或改变模拟。

`auditRuntimeFoodEvidence` 和持久 writer 报告单列 `foodLosses`，总量按物品记录份数，缺营养传播为 `null`。旧记录、旧会话、无新覆盖标记、缺步、重复/跳号、损坏或失效关闭不能证明零损失。没有已提交步骤的会话也保持未知。新的空数组与精确覆盖标记才能证明所列范围中本步没有损失。

隔离日报另有 `foodLosses` 明细、已观察/未观察分钟与独立总量。某日缺测时保留已知明细但总量未知，下一日重新累计。原 `spoiledUnits` 累计差额仍单列，不互相替代。日界使用 `(fromMinute,toMinute]`；恰在午夜发生的损失属于刚结束的一日，分数时点归实际所在区间。
