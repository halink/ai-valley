# 有轻中伤病幼儿的有限干地再撤险

本项修复[有限监护干地撤险](safe-ground-evacuation.md)在第二次灾害中的入口缺口，不开启新天气调度，也不扩大医疗、床位、财产、住所、监护转移或长期照护权限。

## 实际复现与原因

隔离世界没有接收建筑或床位。当前监护人从正常最终菜单选择干地撤险，完成15分钟接出和逐格护送，孩子真正送达干地。随后第二次洪水覆盖这个实际落脚点，正常世界步进24分钟造成损伤严重程度2.15、健康99。

此前菜单仅将“健康至少45且没有任何未结病例”的幼儿纳入灾害护送。常规救护菜单则要求健康低于45或病例严重程度至少20，并依赖接收床。执行端也直接拒绝一切带病例的幼儿。因此轻伤不是不宜搬运，却使新的有限撤险选择消失。

实现前新增24项回归中，16项因缺少入口失败；修复后全部通过。主链使用 `decisionContext → decisionChoices → parseChoice → submitPlan → stepWorld`，没有用底层完成函数代替正常选择或真实搬运。

## 本次有限变化

- 只有独立的 `safe-ground` 分支扩展到轻中伤病幼儿。原健康幼儿送床、室内已知地址尝试、常规医疗提议与稳定处理的资格保持不变；没有把所有幼儿放进常规救护列表。
- 幼儿健康须为有限数且至少45。每个未结病例必须有可核验的严重程度，低于 `min(默认严重阈值50, 病例绑定严重阈值, 病例绑定危重阈值)`，不能是危重阶段，且健康高于该病例的危重健康阈值。负值、非有限数据和不能确认的阈值保守拒绝。多个病例分别核验，康复中但仍严重的病例不能借阶段名放行。
- 旧病例缺少内联规则时读取其绑定定义；未绑定的旧病例仍使用原 `health/rules@1`。不会因当前新规则更宽松而忽略病例原有更严格的边界，也不把自定义较高阈值解释为可以默认搬运重症。
- 菜单、接出劳动、实际接出和每次继续护送都使用同一身体核验。接出前恶化不扣布水；接出后恶化在最后真实位置中断，不退还已经使用的材料、不自动治疗、不自动转去床位。
- 仍须本地存活、未满六岁、当前成年监护人、本人能够决定和表达、既有体力与物资、现场可接触和亲见危险。室内合法接触、真实门口、门外才选干地、八个实际步预算、逐边风险重验全部沿用。
- 新灾害使已送达地点不再安全时，监护人须从新的正常菜单重新作决定，重新绑定当前危险和临时干地点，并再次支付本人1布料、1清水。旧的已送达记录不变成长期许可，也不会自动续送。
- 现有拒绝与停止规则保持：`refusesCare` 阻止接出和续送；只具表达能力但没有一般决定能力的幼儿仍可立即停止自己的本次干地护送，或短等至多15分钟，不因此获得一般决定能力或同意治疗。

健康/严重程度是本模拟已有的保守资格指标，不是证明现实医疗搬运安全的诊断。未达到此资格的重症与危重儿童仍需要独立的救护判断，不能把“没有床”当成可随意搬运的理由。

## 兼容、财产与观察

没有新增保存字段、迁移历史记录或补造同意。新旧干地记录继续保存原危险、真实起点、累计步数和目标坐标；无床记录的 `buildingId`、`bed` 和 `offerId` 仍为 `null`。原病例、自然康复、药剂、现金、随身财物、原住所与监护关系不因撤险改变。

菜单说明继续明确只临时撤险，并新增途中重验伤情。实际事件分别记录两次送达，不宣称获得医疗、床位或后续照护。读取最终菜单仍不改变世界。
