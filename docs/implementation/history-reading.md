# 年表阅读保持与主动更新

## 修复范围

原先最新页发现匹配的新事件后，会在约两秒后自动读取新的60条记录。界面虽然恢复了相同的 `scrollTop`，正在阅读的事件仍可能下移或被移出页面。这与[观察设计](../design/observation.md)的阅读保持要求不一致。

现在年表、人物生平、动物年表、交谈列表和单场交谈共用以下只读规则：

- 已取得的当前记录集合保持不变。新匹配事件只把既有按钮改为“有新记录 · 回到最新”，不自动请求或替换正文。
- 点击“回到最新”才请求新的首页。请求期间和失败后继续保留原页面、游标及新记录提示；成功后整体换到新首页并回到顶部。失败重试仍请求最新首页，不误用原来的较早页游标。
- 较早页和缓存前后翻页保持同一阅读会话。翻页回复的较新观察版本不清除未读提示；第一页始终保留在最多五页的缓存中，避免返回第一页时因为没有有界游标而暗中取得新的首页。
- 提示按原人物、动物、类别、年份、交谈、原文、人口或供水筛选匹配。切换人物或筛选会立即清掉原集合和提示，并取消旧请求；晚到成功或失败不能覆盖新选择。
- 已观察到的匹配事件即使在请求期间或面板关闭期间离开近期窗口，仍保留其版本证据。关闭面板时不触发重绘，重新打开后再提示。世界替换会丢弃旧页、旧筛选、提示和未完成请求。
- 观察刷新重绘正文时，以当前可见事件身份及其相对位置恢复阅读点，避免提示换行等布局变化仅恢复旧像素。明确查阅、翻页和成功回最新会重置阅读位置。找不到原事件时退回像素位置；供水详情原有展开状态继续保留。

本项没有修改服务器、存档、居民知识、决策、世界时钟或模型。世界继续接收观察更新，不因为读者停留在旧页而暂停。

## 边界

- 后续[跨观察入口返回位置](panel-positions.md)已修复年表→人物生平→返回年表的滚动归零，按视图与内容版本分别恢复。仍没有浏览器历史栈或页面刷新后的永久书签。
- 提示仅基于客户端实际收到的近期事件及响应版本。断线期间被近期窗口完全裁掉、从未观察到的匹配事件不补造提示，也不计算未知的新记录数；“回到最新”始终可手动使用。
- 旧响应缺少 `observedRevision` 时不能推断新记录。仍可手动回到最新。
- 事件锚点只能覆盖实际渲染的记录。人物生平上方实时摘要或交谈概览本身不是历史快照，未扩展成所有面板的滚动书签系统。
