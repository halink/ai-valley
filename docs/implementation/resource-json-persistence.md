# 资源差量按完整 JSON 保存

状态：小范围存储修正，独立审查与持续规则验证另记。对应世界升级实施规格的“旧字段不变，仅实例/权限/季相变化，重载不丢”。不实际注册新气候、资源类型或权利规则，不迁移或补充库存，不调用模型。

## 问题与最小修正

formal 保存把资源拆为首次不可变 base 与当前索引差量。旧比较只列 id/kind/位置/amount/max/regrowthDays/lastHarvest/部分 floodDamage；任何其他 JSON 字段独自变化都可能被漏掉，包括已经存在的 `foodItem`，不只是未来字段。

现在 encode 先对完整 resources 数组做一次 JSON 归一化快照，再把每个完整资源对象与持久 base 比较。不同就写入完整对象差量，无字段白名单。新增、修改、删除及嵌套数组顺序均参与；undefined 等遵循既有 JSON 持久语义，不承诺保存函数、Symbol、循环图或 BigInt。

对象字段次序不同可能产生冗余差量，允许多存，不把这种假阳性称为数据损失。未引入额外规范排序、摘要哈希或并行 schema；数组顺序仍有意义。恢复格式继续为已有 `ledgerVersion:1`、resourceCount 与 `[index,resource]`，旧档无需改写版本。

MVP validation 原本直接保存完整世界，行为保持不变；同一组用例分别验证两条路径。资源列表新增、重排与截短仍按原位置差量/数量恢复。

## base、别名和事务

`resourceBases` 缓存只由数据库解压读取；readWorld 对 base 深克隆，调用方不获得缓存引用。首次提交的新 base 现在使用本次 JSON 快照，不借用调用方 resources 对象，也不把尚未提交的 base 放入缓存。

base 插入、资源差量、世界 revision、事件与收据仍在原世界事务内。首次提交失败后 base 行回滚，重试重新创建；已有 base 的更新失败不会改变 base。没有额外执行路径或新外部副作用。此更改不替代已有所有权锁及未知版本闸门。

## 合成覆盖与边界

临时验证输出位于忽略的 `output/resource-persistence-verification/`，不新增测试套件、不提交数据库或日志。

- formal/MVP：原字段不变时 foodItem 新增/删除，未知嵌套字段新增/改/删、整字段删除、null 与缺失、undefined 省略、数组顺序。
- 对象字段重排仍正确往返；不要求冗余差量数量为零。
- 从 base 加载的嵌套对象独立；调用方在提交后修改对象不改变已保存结果；独立关闭重开正确。
- SQLite 触发器注入首次提交失败、已有世界更新失败；事务回滚后同一 Store 重试，仅最终成功值被持久化。BigInt 与循环图序列化失败同样保持已提交状态，移除非法值后可重试；并非新增对这些值的支持。
- formal 资源列表新增/重排/截短及再次扩展/重开，旧 base BLOB 保持不变。

当前成本是对资源内容完整 JSON 编码/解析及逐资源比较，约 O(资源 JSON 大小)，并有同量级临时快照分配。1595资源 formal 合成样本30次 commit 平均约7.65ms；33资源 MVP约1.91ms，包含原提交成本。不同机器/复杂嵌套/大型资源集不可由该样本推定；对象重排可能增加差量和压缩成本。没有针对大型用户存档作性能保证。

尚未验证：真实线上档、大型长期资源集、生产发布。此修正保证现有 JSON 保存语义覆盖完整字段，不等于新字段的游戏合法性、权限、迁移或季节玩法已实现。
