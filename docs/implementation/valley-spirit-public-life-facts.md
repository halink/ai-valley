# 谷灵 G0：公共生活事实投影基础

谷灵只有在持久存档记录了实际行为的专用收据、且当前有该来源的明确公开许可时，才能读取白名单字段。新增独立版本化读适配层，不接原始事件、居民 ID、发言内容、计划或关系；观察者可见、同处现场、目击或被列为参与人都不是公开许可。每次只解析最多 24 个确定来源；其中一个缺失、失效或版本不对时拒绝整个包。

到场、真正发言且收到、本人实际吃掉食物是分开的事实类型，互不推断。提议、同意、排期均不构成这些事实，不进入这一投影。来源引用基于持久随机收据身份，同一事实的更正版本保持来源锚点但改变对应授权绑定。已发送字段的公开版本变化也会使旧包失效；并不承诺撤回供应商已收数据。

**仍未接入运行时。** 后续须把实际行为终态、独立收据和显式许可流程接入持久事实权威，保证每份授权按最新版本从同一个一致性读取提供；不得从旧存档回推许可，也不得从已有事件正文生成此包。接入年鉴后发送前、发布前和所有读取面都须重验。本切片未发送真实模型请求，不构成提测。

## 私有 SQLite 权威

独立可选表在世界写入锁下使用。物理只读连接进行预检与公开读取；未知格式、异常状态和运行中回退会隔离该模块，不改世界基础表。只有已核对的同世界、非未来终态收据可以追加；新来源默认不公开。逐来源审批锚定收据版本和前一授权版本。撤回和重新授权递增授权版本，更正立即使原公开授权失效。读取时再次确认当前已提交收据，单个来源失效则整包不出。有限日志满时拒绝增长，但给每个活跃授权保留撤回空间；不覆盖历史。

实际引擎终态到收据的适配器、显式审批管理入口及年鉴调用仍未接入。不得直接用先前存档、公开观察面板或角色名单替代该权威；完整数据库备份恢复仍需单独设计版本屏障。

## 实际个体进食接线

持久 MVP 会话新增内部、默认关闭的提交后观察钩子。显式接入时，仅用引擎刚完成的 `eat(meal)` 实际扣减证据，并要求恰好匹配本次新写入的类型化进食事件。拒绝未提交草稿、历史事件、做饭、安排、变更量猜测和事件文本。私有保管表以真实事件及准确行动计划固定同一随机收据身份；读取重验已提交的世界版本及类型化事件。原始居民、事件和计划身份不出投影。

该钩子未在运行入口预设启用。私有保管、发布权限及世界写入各自有事务；若世界已成功而进食保管未成功，资料保持缺失，不从历史事项补录或伪造。真实世界未授权公开，不接模型，不构成交接。

## 约见到场与交谈来源审查

本检查点**没有**启用这两类来源。已核实的上游能力与缺口：

| 上游 | 已有真实证据 | 缺少的持久绑定 |
| --- | --- | --- |
| 正式世界 `src/world/social-appointments.ts` 的 `completeSocialAppointment` 与 `advanceSocialAppointments` | 本人实际完成赴约工作的访问时间 `visits[].arrivedAt`；独立的 `metAt` 仅为双方在原窗口内共同到场。MVP 验证世界不能执行 `socialAppointment`。 | 实际成功的 `attend` 现在在终态事件内写入私有结构化收据，锚定世界、约见、原提议和接受事件、本人计划、实际开始/到场时点及事件 ID，并随正式世界同一 SQLite 提交。普通快照及历史接口剥离该字段；还未接谷灵的持久授权读取。旧访问不回填；共同到场仍需独立事实，不能由个人到场推断。 |
| MVP 普通 `talk`（`src/world/engine.ts`）和通用 `emitEvent`（`src/world/events.ts`） | 完成时确有目标，对话位置及发言条件通过，引擎产生对话事件。当前通用事件可写附近可见居民记忆。 | 实际完成发言/传达时写入独立、持久且同一执行绑定的发送及收听证明，区分预定目标和实际接收者，并记录交付时刻、完成的行动与事件身份。当前 `actors`、`witnesses`、`conversationId`、语气/正文皆不能证明指定对象实际接收；通用记忆会裁剪，且给事件参与人标为 `self`，不是独立接收收据。不得解析正文、把同房等同听见或把双方在场当成已交谈。 |
| 正式世界特定 `shareFoodSource` | 已有发送端一次性收据和实际收听者的 `heard` 记录，仅覆盖特定地址的真实面交。 | 不是 MVP 普通交谈或普遍公开授权；私人地址和人物内容不会借这个能力进入谷灵。将来若单列此类事实，仍须独立公开审批、专用白名单和实际已提交的发送/接收核验。 |

上游收据应由引擎完成相应动作时写入耐久权威，并与世界提交共同存活；裁剪 UI 或居民工作区记录不能挪走确证。接入后仍然默认私有，单来源、精确版本另行授权。在这些依赖存在之前，归档和年鉴对该类型只报缺失，不从旧存档、排期、观察者全景、叙述文本或接近猜测去补。

正式约见的赴约凭证仅记个人实际完成动作；隔离计划预检仍能检查动作，但不写真实凭证。原规则已允许的赴约缺少新增披露证据时仍可照常完成，但不附加凭证。不从会面文字、旧访问数组或其他人的到场推断。未启用谷灵的正式世界发布，也未给普通观察者增加私有计划标识。

### 正式约见私有托管

正式/开拓世界的新鲜、已证实赴约终态走专用可选存档点：只接收本次世界提交新追加且由引擎标记的原始事件，在同一 SQLite 事务中核对归档的精确终态、同一条款的提议和接受，以及原计划与提议的持久回执，再分配私有随机编号。复制事件、已有档案的导入、普通会面记录及失败动作都不产生编号。可选格式未知或证据不全时不登记，不阻止正常世界提交。

私有查询按精确已知事件取编号，或按编号核验承诺的时点及版本。每次核验重查原世界和精确证据；窗口裁剪或重开不影响有效档案，缺失或变更即拒绝。取出的形状仅有世界、类型、时点、版本和不透明编号，无居民、位置、计划或约见条款。此编号**不是公开授权**；正式世界仍未接入当前仅限 MVP 的生活事实发布器、模型或 Web 入口。

### 正式约见单来源离线发布

独立的显式开发附件只认同一正式世界已保存的一个私有到场编号，不改写为 MVP 世界 ID，也不放宽 MVP 解析。默认不开启，没有玩家路由或自动调度；打开后仍需独立审批明确绑定受众、世界、来源、收据摘要和当前授权版本。接受约见只产生原玩法结果，不能代替实际赴约或披露批准。仅在同一 SQLite 事务内重查已提交正式时钟、私有证据与授权版本后，发布一行固定到场事实；不输出人物、约见内容或私有编号，也不调用模型。

只读查看按同一来源、正式世界和当前授权重验，撤回后旧节、旧批准和旧引用都不能恢复。关闭后重开遵循新撤回；再次批准也须生成新版本才可发布。打开只读附件必须传入宿主独立掌握的目前版本下限，早于它或缺失的档案拒绝读取；同一连接同时防止已见日志倒拨。该边界依赖宿主提供真实未倒拨下限，不声称能独立检测完整数据库回滚。尚无正式世界 UI、网络发布、官方授权流程或通用多来源正式年鉴；本切片只在临时本地库验证，不提测。

### 正式世界开发回环读取

显式隔离夹具可在随机本机回环端口运行一个只读 GET，普通正式、自托管、Godot 和旧观察器启动均不安装它。独立的可信夹具宿主需提供同一正式世界、当前 SQLite 世界版本、规范时钟及授权版本下限，不能从请求或被检查的发布日志生成这些预期。读取时在同一 SQLite 读取事务内重验精确原凭证、世界头、授权状态及宿主下限，再一起返回匹配标记和匿名到场行。无缓存、事件流、凭据、模型调用或外部网络；无人物、计划、原事件、来源摘要或私有收据编号。未授权、撤回、旧世界头或错误输入均为通用不可用响应。普通应用协议和玩家界面未改变。

内部年鉴接缝默认关闭：对已授权的生活事实按确切游戏时段准备白名单包，接受的选择仅有编号及固定句式，不接自由文案。输出区分实际到场、传达交谈及进餐；保存完整证据包和已定稿的来源行。发送、定稿及所有读取仍须各自重验；任何所用包中的来源撤权或更正都隐藏整段，旧版本不可读。本接缝未接调度、持久发布或对外请求。

开发夹具可显式安装独立生活年鉴发布器和只读查看器，不变更既有天气年鉴格式。发布器先保存单一时段的尝试及最小编号菜单，只运行内置离线合成选择；叫号前、定稿前和每次最新条目读取均重新核验完整来源，失败或重启后的未决尝试不自动重发。夹具 GET 接口与已绑定世界一致才可读，撤权、损坏或未启用均只返回不可用，且禁止缓存。普通入口未注入查看器，也没有外部供应商、公共写入或真实模型署名。

同一时段的更正必须由开发夹具明确给出该时段上一版的标识，并用一组已变更、现仍获准的确证重新定稿。只有排列顺序改变不构成更正。每一前版只允许一次更正尝试，重启或撤权后不自动重发；密封记录保留替代关系，读取不会回退到已经失去许可的版本。


Godot 的「生活年鉴（离线）」仅在夹具世界快照重新验证出当前可读条目时出现。快照标记绑定同一世界、版本、游戏时刻和条目身份，不带正文；客户端随后读取同一条目并核对来源和离线合成署名。后续快照若无标记或标记变化（包括门口动画期间收到），会取消当前请求、清空旧文；迟到响应不能恢复，正常推进但条目未变时继续显示已核验内容。天气档案和天气年鉴授权仍独立。

### 正式约见：独立提议与接受的私有凭证

正式世界完成本人的当面提议或另一位当事人的独立当面接受时，原生引擎为该草稿的新事件生成不序列化的类型化证明。正常玩法、事件和观察者输出不变。独立内部选项默认关闭，仅接受非夹具的正式世界；天气溯源许可不启用它。仅显式开启时，私有 SQLite 表与正式世界共用写入事务，核对精确事件字节、两人角色、实际动作计划回执和不可变约见条款；接受还必须能核验同一约见的原生提议凭证，提议与接受各有自己的实际计划。复制、历史导入、预检、状态或文本不生成凭证；证据缺失只影响私有档案，错证回滚私有批次，不撤销正常玩法动作。

私有读取在同一快照重验现存世界、原事件、计划和确切的先前提议。此凭证不是赴约、交谈或进食，也不是披露同意。现有三类对外生活投影、正式离线到场披露、模型和 HTTP 入口均未扩展。
