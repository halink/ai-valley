# 室内幼儿按已知地址尝试撤离

这是[有限监护灾害护送](guardian-evacuation.md)的一个窄扩展：同处灾屋的当前监护人，可以选择把健康、未满6岁的幼儿接出，按本人已经知道的公共或本人所有诊所/会馆地址尝试护送。**地址不代表实时安全或空床；床位只在实际到达门口后核验和保留。**

## 为什么需要另一条入口

原健康幼儿入口只枚举监护人当下能检查的接收建筑。在一栋房间里无法观察另一栋房的床位，所以室内受灾幼儿没有实际菜单入口。单纯删去可观察筛选也不正确：原医疗护送在接出前查询并预占目的地床位，而且完整洪水寻路会通过“远处现在能否走到”泄露未观察的危险。

本改动保留原有户外已核验床位路径，另加明确的“已知地址尝试”。最终菜单继续沿用最多两项轮换监护选项和56项总限额，保留等待及其他决定；不会自动替人选择、搬动或登记。

## 权限、知情与实际行动

1. 监护人须成年、有决定和表达能力、健康和体力满足原护送条件；孩子仍是其当前受监护的未满6岁幼儿，未拒绝，双方在合法可接触的同一房间。真实室内坐标、接近路线和出口必须存在。门外坐标相同、没有房间坐标或没有房间使用权都不算接触。
2. 现场已观察的活动灾害或可见预警须真实覆盖孩子，原房屋不能已经提供足够保护。接出前每次核验原威胁；威胁消退、监护变更或孩子拒绝，旧选择失效且不花物资。
3. 目的地只能来自本人已有地址，且公共或本人所有的诊所/会馆使用权仍有效。新菜单不读取别栋建筑的实时空床、屋况或危险，不称它“已确认安全”。不能以灾情获得他人私屋进入权，也不新增住房、产权或监护登记。
4. 监护人实际走近幼儿并完成原有15分钟接出劳动，才使用本人1布料、1清水。新运输记录保存原灾害编号和 `evacuationDestination: 'known-address'`，初始 `bed: null` 表示尚无预留。它不占用医疗床或避难容量。
5. 幼儿随监护人实际走到室内出口，再沿地图步行。初始计划只使用当场可观察的灾害格子，避免远方活动洪水成为接出成功/失败的查询器。原地图地形、建筑和设施寻路继续适用；每个真实步子仍按完整物理通行和已见危险规则核验。途中出现危险或阻挡会停止，不能保证所有地址都可达，也不会自动改道或改送。
6. 屋况和目的地风险在接近到可观察位置时重新核验；床位在抵达准确门口时才核验并串行保留。已有登记床权、借住/租约、医疗运输预留、预约及实际占床仍优先，离家住户的床不能占用。多组人可以各自选择尝试，但一张床不能重复保留。核验后还须实际进屋、走到床位并完成交付劳动。
7. 接出后原危险结束不把孩子丢在路上。监护失效、孩子拒绝/自行停止、权限、床位或风险变化则终止；室内新障碍也逐格重验。失败保留最后真实室内坐标或室外位置，不回传原家、不传送到目的地，不退款已实际使用的布水，也不重复扣除。

## 保存与兼容

新模式是可选字段，旧医疗运输保留原有整数床号，不补造历史或改成未核验。SQLite内存重载覆盖接出前、尚未验床的室内同行、已到门口保留床位三个阶段；位置、室内进度、危险绑定、模式和用品支出均保留。重载后仍须重验，没有再次接出、重复扣物资或重复交付。

`actionRoom` 在床号为空时不生成目的地室内工位。只有门口实际核验后才建立床位路径，避免先进入房间再发现无权/无床。护送标识和模式须与实际运输一致，模型只能选菜单项，不能自行填写或切换这些字段。

## 仍未覆盖

本页已知地址模式不是无床干地抱送；后续[干地撤险切片](safe-ground-evacuation.md)另行提供室内先实际出门、门外现场选点的独立选择。就本页模式而言：即使接收建筑最后没有床，动作仍是对指定已知接收地址的有限尝试，没有另建任意安全地点落脚机制。非危重失能成人、没有当前监护人的健康幼儿、未知地址、完整灾后照护交接和补给仍未实现。停止后也不会自动安排下一次护送。

没有开启新天气调度，没有真实模型15日或九人四季验收，没有浏览器验证、npm、访问密钥/真实存档、提交或推送。
