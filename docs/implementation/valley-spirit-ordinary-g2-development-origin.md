# 普通规则 G2 开发原档

默认只建立开发原档，不默认执行落果。显式调用 `createOrdinaryG2DevelopmentOrigin()` 可建立全新的本机普通规则开发原档。调用者不能传入、转换或领用已有存档；新文件由内部创建，物理身份和秘密固定在原所有者进程。首次原生世界写入和原档标记在同一 SQLite 事务；失败全部回滚。

这一入口没有 HTTP、自动时钟、公开界面、模型、调度或真实生产操作。世界只能显式逐次推进普通原生分钟，并可读取简单世界头；同一原始文件与所有者闭包可以关闭、重开。普通、正式、季节、旧开发档、复制件均不能使用此能力；普通存档加载和写入在识别该标记或保留 V3 账本名时拒绝。保留的非空账本名只有持新原档和正确 V3 独立审阅权限才可读取；同名视图或不认识的记录一律拒绝。旧单果源与普通档模式不转写。整个进程退出后无法解封原档；它不是面对特权 SQLite 写入者的外部信任根。

原档首次建立后，可关闭并重新打开同一所有者闭包，同时显式配置 `privateOrdinaryMultiFruit`、`privateOrdinaryMultiCandidate`、`privateOrdinaryMultiSelection` 和 `privateOrdinarySelectedRehearsal`。新入口仍不接受路径、外来存档或原生会话访问，也不启端口。每项真实果批按普通原生提交生成；至少两处有效果批且当前闭雨、对应已授权天气、地理适宜时，才有只读候选。只有本机内存替身可以选择，并须经第二把独立密钥签审才会在副本中演练。原档保留凭证，关闭不保留选择、演练资格。验证中的真雨和前置环境在同一新建临时开发档内准备，真正整点捕获、编号和原生演练均经过原闭包。没有把准备好的地图库存视作天然果批。

## 开发态单次真实转移

显式加上 `privateOrdinaryDevelopmentV3`（`ordinary-g2-development-v3-one-unit/v1`、第三把独立 Ed25519 开发审核公钥）后，正向独立签审的原生分离演练才可生成一份待签报价。第三份签章与原档和确切持久世界内容、同头闭雨和授权、被选果批的原龄和原归属、目标及稳定机会一一绑定。签署前后不授予正式模式批准。事务重新验证当下来源、天气许可、真实候选，再以真正世界重跑分离演练。成功只扣除被选果源一份；同一 SQLite 事务消费该果批凭证、写一份同龄地面物和唯一机会回执。其它果源的旧头凭证不伪造重绑定，在这个暂停档头不可读。未给居民库存记入任何物品。

只有同一原所有权与原开发公钥可重开读取地面物、回执及实际扣量。重放不能再扣量，撤权在首次提交前阻断。来源撤回不会改写已经安全提交的私人保管历史。异常或提交失败全部回滚；替换地面物、单项缺失或两表删除却保留锚时拒绝重新打开。已落地档暂不允许继续走原生时钟，直至实现真实观察、拾取、死亡与原龄到期处理。仍没有 HTTP、公开展示接口、自动调度、真实模型、普通／生产运行准入或生产执行批准。

### Original V3 manual discovery and expiry

After an actual V3 placement, only the same in-process original owner with the
same third review key can ask the no-port closure to advance one ground minute
at a time. Generic `advanceOne` and all selection/transfer work remain stopped,
including after expiry. The dedicated method has no supplied resident, plan,
geometry, time or world. It runs the real native chooser/observation phase on
the committed head, retaining one personal first observation per actual resident.
The private read is keyed to one resident; no observation is made a world event,
mail, broadcast, ordinary/public read, or authorization to pick up.

The stored birth and expiry never change. The native observation phase excludes
the exact expiry minute, and the same transaction removes the one physical row
at the first expired minute. World head, normal bounded event suffix, private
continuation receipt and origin latch update atomically under exact archive and
writer guards; expiry retains the stable opportunity and original signed
placement permanently. The pre-existing weather grant cannot authorize later
releases and withdrawal after a completed transfer does not erase physical age,
discovery, or custody. Current personal evidence may be reread on exact original
reopen; copies, wrong keys, damaged seams, and generic/player opens do not
acquire the scope. There is no V3 eating or scheduler here. Other native
changes to stock do not rebind candidate custody or reenable ordinary writing.
A native minute that would also settle a meal or addressed speech, exceeds the
bounded event/discovery archive, or sees an unknown writer is rejected before
commit. No partial discovery, expiry, or ordinary event settlement is emitted.


### Native at-site pickup and original held custody

The original, same-key no-port owner can attempt one pickup minute separately
from observation/expiry advancement. This does not accept a resident or a plan
and does not reserve the lot. Without a prior committed personal discovery,
a resident already standing at the exact accessible site, and the native
idle-fallback chooser's actual completed one-minute action, the request does
not change time or state. Ordinary health, food, water, rest and commitments
retain their priority. The exact inherited expiry wins over any attempted
pickup at that minute; use the ordinary ground-minute continuation to settle
expiry.

The same V3 transaction debits the single ground row, credits one privately
held unit with the same lot, owner, birth and expiry, and attests the native
resident/action/observation receipt under the original latch and archive.
No scalar inventory, nutrition, movement intent, public event or public
view is credited. The original private host can read a held fact only by
the exact resident key. The ordinary controls stay paused after
pickup. The original no-port host has a separate manual held minute that
runs the native engine with only one original holder’s restricted outdoor eating capability.
It preserves the inherited timestamp, keeps the first pickup receipt
as history and, at the first elapsed expiry boundary, debits the one
held unit and advances the head and receipt/latch atomically. Closed or
reopened terminal scopes cannot advance or replay. If the holder leaves
the supported in-world living custody or the native minute requires an
unsupported event settlement, the entire minute refuses unchanged.
The normal held minute never grants a hall route; see the separate original hall scope below. Opportunity replay and generic advance remain
blocked. Weather withdrawal after actual placement does not erase custody.


### Native outdoor eating in the original held scope

A hungry holder may choose the actual ordinary outdoor self-care action
only when the native chooser gives it priority. Existing table preference
and higher-priority needs/actions still apply; the V3 hold never grants a
hall seat, room route, or substitute outdoor choice. No host input chooses
the resident, food amount, action, or minute boundaries.

The first through fourth real native minutes retain the exact one resident,
outdoor place, plan, original age, work count, and committed head. Interim
minutes do not relieve hunger or change scalar inventory. Only the fifth
minute on the same plan commits the actual native nutrition, one held debit,
and the normal generic eating event and event index with the new archive
seal. A finish at the original expiry is not eligible; the held expiry
path remains authoritative. The original owner may reopen mid-work and
retrieve evidence by the one resident key. Without that V3 original archive
and key, persisted work is unsupported and does not grant save access.
There is no public detail, model, automatic scheduler, or alternative
route on failure.

### Native approach to personally discovered ground fruit

On the original no-port owner, a separate attempt may let the normal idle
fallback choose at most one bounded route of one or two legal cardinal
steps. No host input selects the walker or path. The authenticated record
contains the actual native move plan, verified position/pending path and
only the edges the normal movement engine completed. Movement itself never
debits the fruit, grants possession, or reserves the target. Resumed movement
requires the same exact route on original reopen; expiry stops it before a
tied step. After native arrival the resident still must independently choose
pickup in a later minute.

Another actual resident already at the site, with their own committed
discovery and ordinary pickup priority, may take the fruit during movement.
The normal native actor order governs whether a step has already happened;
only the actual remaining path is cancelled. The ground debit, real pickup
receipt, resulting held unit and route closure settle in one transaction.
The route is available only under the original owner with the exact resident
key, never in the normal player run or public view.


### Native shared-hall eating in the original held scope

The original owner can separately advance a hall minute. The native chooser
uses the holder’s known real shared hall, existing ordinary food priority,
route and exact seat; there is no actor, destination or seat argument.
An occupied seat cannot be taken over. Ordinary eligible food (including a
carried berry or preserve) still receives its ordinary table/meal choice.

Authenticated hall progress distinguishes outdoor travel, indoor travel,
seated arrival and actual claimed work. Only the holder’s unique current seat
claim can count; travel and arrival provide no nutrition. The first work
minute requires enough time for all five native minutes strictly before
original expiry. A persisted action can only be removed early by the exact
same-run native typed refusal for that actor, plan and minute, or the exact
expiry path with that cancellation. The refusal pays no nutrition and
does not mint inventory. A successful fifth work minute sums native hunger
and nutrition and writes the actual room-located observer-only event and resident
index with the one held debit and original latch in the same transaction.

The original scoped archive authenticates reopens during travel or work.
This does not enable a player save, public broadcast, arbitrary room or
table movement, other eating authority, model, or automatic scheduler.

### 单机会私有公平与果源流量审计

原 V3 无端口所有者可用 `readDevelopmentFairness` 核对已认证的一个机会。已链接签审的候选、真正落地、本人实际发现、真正拾取分别计数；这里既不统计所有候选，也不返回居民身份。进食和过期仍分开记账。落果只从源转移到地面，不凭空增加供应或证明因果增产。

从落地提交后的真实果源数量开始，通过同一次原生分钟运行的采摘事件与自然恢复见证，分别累计该源的普通采摘和自然恢复，即使二者抵消也是两条实际流。流量必须连续、精确匹配原源坐标、起止世界版本和库存；与原始存档同事务签封。凡旧轮次没有记录、原生捕获失败或不连续，累计流量保持不可用，不从后续库存补算；不会为流量统计额外推进世界，也不会因此阻止原本合法的物理过期、拾取或进食。覆盖只到现有 V3 私有生命周期终点，不代表全世界公平性、其他果源或反事实收益。

### One independently signed committed-time due review

The same original no-port host can record one exact pending due review, not
an effect or permission to spend. The third reviewer signs a distinct
purpose containing the current native positive rehearsal, exact world bytes,
original lot and stock owner, site, rain opportunity and exact archived rain
packet. The due minute is accept minute +1, strictly before that original
eligibility and lot deadline. Pending and terminal facts use a paired
sealed body and separate immutable origin-bound sentinel, not any existing
ground or effect receipt. Missing, corrupted or copied authority is rejected.

Only the explicit due-minute operation can advance after acceptance. It
runs one real ordinary native minute and atomically rechecks the new
persisted head and current lot lease, same legal site, latest closed rain and
unchanged permission/archive. It then reruns the real detached rehearsal
at the new head. It does not reuse an hourly menu at minute +1. Terminal
outcomes are eligible-detached, expired (including insufficient time
remaining for the detached rehearsal), or invalid. There is no transfer,
override, dispatch, account, provider, public report or automatic ticking;
real ordinary native background changes are distinct from this advisory
review. The one-shot review lane stops after settlement; only a separate
opt-in fourth-key consent can start the original paired transfer below.


### Separate fresh-head consent for an eligible due review

A fourth independent key may be pinned only on the original no-port
development host. Its separately domain-bound approval binds the immutable
accepted and eligible due records, exact fresh compressed head, source lot
cohort and original age, site, commons ownership, closed rain, unchanged
permission and the single opportunity. The older due or immediate approval
cannot execute this transfer. A fresh clone and current native source,
weather grant, exact archived rain and site checks still run on the due head
inside the final transaction.

The transfer consumes the exact native lot slot, debits one physical source
unit and creates one actual original-aged ground unit. The placement receipt
contains the fourth signature; the consumed due receipt authenticates that
signature and exact immutable placement receipt. Both halves and the won
opportunity are required on reopen or lifecycle read; they are written and
verified in the same transaction as the world and slot. No review history is
reset, and no old approval or partial/copy can grant another debit.

The resulting original-only ground lot uses the established private V3
discovery, pickup and expiry paths. This is not a player save admission,
production enablement, automatic scheduling, model dispatch or public reveal.

### Reusable native source conservation (no execution seam)

The source-balance calculation is a pure function of two actual world
heads, the authenticated placement baseline provided by the owning archive,
and a captured native minute. The original V3 store still owns all
authentication, database reads, one-minute preparation, and writes.
This function tracks same-minute natural renewal and ordinary gathering
separately, rejects missing or discontinuous evidence, and cannot infer
unobserved gross activity from net stock. It does not admit, authorize,
produce, settle, or expose an effect for any ordinary or production save.


### 原档只读落果标记

原所有者闭包的 `readDevelopmentGroundMarker()` 仅在显式启用开发 V3 的原档可用。每次在同一只读事务核验真实存档头、原签审、落果保管账及当前实际地图；原龄仍未到期且一份果实仍在地面时返回 `{status:"active", x, y}`（整数格）。已确认拾取或地面到期仅返回 `{status:"empty"}`；尚无认证落地记录、闭包关闭或证据异常则返回 `{status:"unavailable"}`。观察时不推进世界，也不返回人物、来源、时钟、对象编号、果龄、签章、历史或原世界内容。

这是原档闭包的瞬时最小事实，不是居民知识、可执行资格或可复制的存档凭证。`empty` 和 `unavailable` 都不保留之前的标记，没有接入 Godot、普通世界数据、Web／HTTP、存档导出或游戏写入。

### 同机私有落果观察窗

由原档信任引导预先提供 `{trustedGodotExecutable: ...}` 可选配置，固定可信的 Godot 本机程序（绝对路径，以 `godot` 开头），与原档所有者使用同一受信 OS 用户。未预配置时闭包不提供入口；预配置后，同一原档闭包可显式调用无参的 `openDevelopmentGroundObserver()`。实际启动前重验固定真实路径、文件身份与文件状态；请求不能换程序。该措施不替代对 OS 用户和所安装二进制的信任。窗口只读取当前标记，不加载主场景、存档、天气、人物或游戏端口；在有图形显示的客户端直接显示「一枚落果在地面」及整数格坐标。没有标记时区分确证空地和观察不可用。

原档所有者通过子进程继承的匿名 stdin 管道单向发送三种短记录，不传凭据、路径、对象标识或世界头，不写观察文件、不开放端口；进程 stdout / stderr 不转发。创建／推动原档仍由已有显式拥有者操作；观察不会自动推进。真实转移、拾取、到期操作结束时重新发送，此外每 125 毫秒重新验证原档；窗口在停收超过 375 毫秒、损坏数据、结束或关闭时清除标记，不把旧帧当作现在的状态。进程与画面的调度时间并非原子提交，机器阻塞时可能在该短显示时限内才清除。这里没有面向其他 OS 用户的发布、普通游戏 G2、远程观察或写权限。
