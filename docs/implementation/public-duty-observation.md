# 公共服务的现场核实与实际室内路径

本批只收紧公厨与公共基础照护的观察、接近和完成边界，不改变物资所有权、工资、公共预算、服务量或个人同意规则。全部证据来自离线合成世界与内存 SQLite，不读取真实存档或调用模型。

## 已知地址、公开班表与当前事实

- 本人认领的班次仍可查看。公共班表只在实际能看见入口公告板时提供；历史记忆和地址不证明当前有人在岗或尚有材料。
- `receive` 只在实际可观察服务桌台或床位、具有完整合法路线、并能在班次内完成时提供。沿用共屋的保守视线走廊，绕行可达不等于隔家具看见；室内必须使用真实 `roomAt`，门口别名、缺坐标、船上位置都不能补作视野。
- 被遮挡的合法已知地点保留 `publicDuty.inspect`。它仅按建筑地址与几何生成，不绑定任何班次，也不读取提供者库存、公共物资或工资余额。本人显式走到桌下或床右的旁站位核实，之后另选服务。旁站位不夺取桌台/床位或 `clientId`。原可自主接受服务的6–17岁居民也可查看，不因此获得认领或值班权限；未满6岁的既有行动限制不变。
- 本入口的不可达 `receive`、`inspect` 与公告板访问不提供。通用历史地址的 `move` 提议保持原有语义与执行端路径检查；本批不是全局移动菜单改写。

## 重验和互斥

1. 提交第一项 `receive`/`inspect` 时重验目标、观察和路线，开始时再次检查。排队后状态变化不会绕过检查。
2. 接近中每次重新核对房间起点、目标、使用权、提供者与物资。保存的室内路径每个格子都按当前障碍检查。新增障碍即原位中止，不穿越、不自动改道或重新服务；本人可重新选择现存合法绕路。
3. 到桌台/床位才预占唯一 `clientId`。公厨同时保留既有厨房组与真实桌台 claim，照护保留原床位 claim。查看使用独立旁站位，不占服务席。
4. 已经开始服务后，丢失坐标、移离实位或丢失席位均中止，不走回来接着累计。每个工作单位和原子完成前继续验证实际位置、障碍、合法席位、提供者及真实库存。
5. 仅既有成功完成事务消耗个人/授权公共实物及支付工资。检查和失败不扣料、不付薪、不算完成。SQLite 重载后延续同样规则。

- 主回归：`tests/public-duty-observation.test.ts`，最初20条中16条红，最终扩展到30条，覆盖两类真实最终菜单→编号解析→提交→实际行走→服务、隐藏状态不干扰菜单/prompt、静态绕行、动态安全停止后本人重选、缺坐标、变化与到场、占用下查看、SQLite以及公共/个人守恒。
- 独立审查：`tests/public-duty-observation-review.test.ts`（25条）与 [审查记录](../reviews/public-duty-observation.md)，额外发现并修复真实桌台未互斥、查看占服务席问题，并覆盖公共工资、失位与原子完成拒绝。
- 原共屋观察、公共供餐证据、房间与公共预算回归继续运行。原遗产可达测试更新为更早从 `dutyTarget` 拒绝；精确关班测试在构建菜单前已真实就座，不再让测试助手隐藏进屋时间。
