# 记录洪区内的近处撤离菜单

## 修复范围

居民站在已察觉、尚未消退的实际洪区内时，普通决定菜单现在按洪区的真实格子集合寻找可步行的附近出口。旧策略只试12个固定远点，并把整个半径加两格都排除；因此真实河岸只有两步就能离开洪区时，引擎可以执行，菜单却没有撤离选项。本修复不把半径内所有干地都视为洪水，也不把出口称为高地。

- 从居民的实际位置做一次四邻接搜索，以实际步数限制到24步。最多访问1,201个格子，只提供一个最近可达的撤离选项，不逐格反复运行整张地图寻路。24步限制的是菜单候选搜索；引擎仍按原有道路时间权重重新选路，不机械复用菜单搜索轨迹，但采用相同的通行与风险约束。
- 终点须在所有尚未消退灾害的实际范围外。已察觉野兽、旧半径灾害的终点仍保留原来的两格余量。旧灾害没有 footprint 时保留原有策略，不补造几何或历史。
- 菜单、引擎起步寻路、每批移动中的逐格检查共用同一撤离边约束：可以从已占据的危险区域走出，但不能进入或重新进入已察觉危险。洪水预警也按记录格子判定，不为绕路扫描远方野兽。
- 地形、树石、围栏门和损坏桥码头仍按实际通行边核验。特别是从坏桥上撤离，可以在桥面内走到出口，不能先离桥再抄近路重新踏上坏桥。
- 途中道路或已察觉风险发生变化时停止，交还居民重新决定。抵达时仍重验终点与灾害记录，失败不会留下完成撤离的事件。

这是菜单可用性与实际执行路径的一致性修复。没有自动提交计划、传送、强迫居民选择、授予床位或物资。居民仍可选择等待或其他事情。洪区外、纯野兽或旧半径灾害不启用这次近处搜索；其他行动仍使用原导航。**新天气调度仍默认关闭，本改动没有启用它。**

## 先红后绿证据

[洪区撤离回归](../../tests/flood-retreat.test.ts)使用代码新建的隔离世界，没有真实存档或外部模型。

1. 13×13地图在 x=6 建立实际连续水道，由 `floodFootprint` 生成洪区。居民在(5,6)，安全处(3,6)为两步实际可达，仍处在旧半径范围内。修改前首批6项回归2通过、4失败；真实普通菜单的撤离选项为0，而直接提交同一两步动作通过引擎完成。
2. 独立复核发现另一个危险：只验证干燥终点时，路径可能穿过居民原本未进入的风暴。在狭窄河岸走廊复现后，新增回归先失败，再通过共用逐边约束修正。没有仅修改测试预期来接受穿越危险。
3. 覆盖正常菜单选项与实际提交、实际时间移动、完成记录、读取不动人/不提交计划、居民拒绝撤离、途中树木/新增预警阻断、终点新预警重验、重叠洪区、无出口、围栏门、破桥入口、U形坏桥实际五步走出、24/25步边界及最多1,201格的搜索成本。

本轮独立复核见[审查记录](../reviews/flood-retreat.md)。最终代码的验证结果：

- 新增14项，以及原洪灾/天气/居民起点导航回归，合计38/38通过。
- 全量 `tests/*.test.ts` 1425/1425通过，零失败、零取消、零跳过，最终运行100.6秒；此前一轮同样1425/1425通过。
- 全项目TypeScript检查、服务端编译、Vite生产构建通过；只保留已有的大于500kB分块提示。
- 独立复核另跑35项危害专项与70项周边回归，全部通过；最终静态复核无阻塞项。

没有读取密钥或真实存档，没有调用模型、浏览器、npm，没有提交或推送。

## 离线重现

使用已有本地依赖，不安装软件或调用 npm：

```sh
node --import tsx --test tests/flood-retreat.test.ts tests/frontier-hazards.test.ts tests/weather-hazards.test.ts tests/food-source-navigation.test.ts
node node_modules/typescript/bin/tsc --noEmit
node --import tsx --test tests/*.test.ts
node node_modules/typescript/bin/tsc -p tsconfig.server.json
node node_modules/vite/bin/vite.js build
```

这不构成真实模型、浏览器、正式世界或完整四季灾害验收。未知的未来风险、完整受照料者与牲畜撤离补给、高程/流域模拟及长期恢复仍属于原有未完成范围，不能因本次菜单回归通过而启用新天气调度。
