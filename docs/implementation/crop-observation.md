# 本人可见田况进入决策输入

## 复现与修复

原先 `decisionContext.plots` 含近处作物，但最终 `prompt` 不写田况。本人清水为0时，今日未浇与已浇的未成熟田没有浇水菜单，最终模型输入完全相同。`tests/crop-observation.test.ts` 先在原实现中以两份真实 context → `prepareModelDecision` 复现同文失败，再验证修复后的差异。

现在每份决策按实际世界生成独立的田况快照，最终输入使用明确白名单的粗粒度观察，而不是序列化原始 Plot。本人没水也可看见尚未具备用水条件；没有实际清水时仍无浇水动作。观察、候选菜单、准备输入均不提交计划，不代替本人取水、浇水或收获。

## 可见边界与内容

- 只含本人拥有的田。产权可提供已知地址，但不提供远处实时田况。他人的田和私有库存不进入新观察。
- 本人须活着、在谷内、可理解观察、室外且无残留室内坐标、位于合法可站立地面，不能正在原地睡眠或船上。正常地面行走、搬家或地面护送本身不抹除真实在场。
- 使用8格曼哈顿范围，与生产菜单统一。保守直线视野不能穿过建筑、已占地施工、悬崖或仍存在的树石；对角角落两侧也须无遮挡。这不是完整光照/视觉模拟，不假设夜间完全失明。
- 每条观察与当前 `minute` 相符才进入输入，显示明确观察分钟。内容为未种田间作物、未成熟、成熟或阶段未知；已种作物的今日浇水状态；未成熟作物的当前季节和眼前雨水条件。
- 成熟和季节按已种作物固定的 `crop.definition`，不随 `activeDefinitions` 变更。已成熟但过季仍可自主选择收获。
- “今日已浇”与“正在下雨”不同。雨水可满足当前用水条件，不改写浇水记录，也不保证日界时仍下雨。绝对日使用 `floor(minute / 1440)`，不使用季内日期。
- 不输出精确生长计数、播种时间、历史浇水日、下一次生长时间、世界随机种子或未来天气。不增加天气预测或保存新知识字段。

`DecisionContext.plots` 内部继续携带复制后的有限 Plot 字段供现有菜单使用；最终模型输入仅由 `observed` 投影。今后不得直接把整个 context 当作模型消息。世界推进不会修改已经准备好的快照。

## 有界摘要与菜单

田况独立于会截断的 `familyNotes`、库存与本人关注领域。单次至多8块，先保留当前菜单指向的田和最近田，其余每30分钟轮转；距离和ID稳定排序，世界数组重排不改变输入。超过上限明确说摘要未列完，不代表其余田不存在。

基础菜单、生产菜单和空田种树候选共用在场/可见过滤。原默认作物菜单还修复了先遇到其他作物就挡住合法默认浇水候选的问题；真实快照的默认成熟判据也采用固定定义观察。没有观察字段的既有手工上下文仍保留默认芜菁版本1的有限旧接口。

浇水/收获的路径、产权和实际库存仍由原引擎重新核查。未修改日界生长、耗水、产量或自动行为规则。菜单中的既有生产方法/收成说明未改造成未来天气或远处田况来源。

普通浇水成功事件及其见证记忆另见[真实作物名称修复](crop-watering-memory.md)：按完成时田地绑定定义取名称，名称不明保守写“作物”，不改上述观察投影、行动规则或历史记录。

## 离线证据

- 真实 context → 最终输入 → 编号解析 → `submitPlan` → `stepWorld`，覆盖选择停留不照料、另选取水、再另选浇水。
- 日界前后、前日晴/雨、未浇/已浇、成熟与过季、冬根6日固定版本、其他作物不挡默认菜单。
- `WorldStore(':memory:')` 中途保存/重载、重复计划不重复扣水；途中产权/库存/作物改变仍由引擎失败关闭。
- 大段家庭记录和拥挤56项菜单下仍有观察；对三个受支持模型的完整准备消息执行字节上限检查，新增田况段至多8条。
- 独立反例与审查见 [crop-observation review](../reviews/crop-observation.md)。
