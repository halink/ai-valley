# 居民活动与决策保护观察

批次 1 的只读观察部分已经接入居民名册、地图人物选框、人物档案和历史年表。该界面只读取已有快照，不提交居民行动，不改变保护期限、床位分配、资源或世界时间。它不代表批次 1 的可达粮食余量、旧档救急和真实模型长跑已经完成。

## 活动状态的依据

| 显示 | 已有记录依据 |
| --- | --- |
| 等待自主决定 | 在镇且能够决定、表达，没有活动和待执行计划，已经到下次决定时刻。详情区分正在等待回复与等待调度或重试。 |
| 准备行动 | 已有自主计划，下一项活动尚未开始。 |
| 赶路 | 尚有室外或室内路线、正在离开房间，或尚未到达行动对应的真实工位。前往床位不会提前记为睡眠。 |
| 实际睡眠 | 已到可确认的睡眠位置。缺失或不可用的床位另显示待核验。 |
| 自选停留 | 正在执行本人选定的等待；显示本段剩余游戏分钟，不等同模型等候。 |
| 等待履约 | 诊疗或教学行动已经到场，但对应参与者尚未实际执行配对行动；或者已到岗位、预约或课堂位置而约定时刻未到。教学结算已有 `pauseReason` 时显示“等待教学条件恢复”及原原因，不因师生同时在场而误报授课。不会仅凭一份未来约定推断本人正在等候。 |
| 等待复工 | 工程结算已经将项目设为 `paused`，但旧施工活动尚待下一轮核验；显示工程暂停原因，不继续声称施工推进。在途者仍显示赶路。 |
| 正在行动 | 到达实际位置并执行所选行动。共同工时及资源结算仍以对应业务记录为准。 |
| 渡运或护送途中 | 实际在船或正在医疗护送；停航、等开航和靠泊未下船分别显示。 |
| 当前无法自主决定 | 决定或表达能力受限，不误标为等待模型回复。 |
| 尚未到下次决定时刻 | 无当前活动，但下次决定时刻尚未来临；不推断为自选停留。 |

已经死亡或迁出的人物保持独立标签。全镇停表是另一层状态，顶栏和档案分别显示范围与原因，不覆盖个人的原有活动。网络断开仍使用原有连接中断提示，不把观察端断线冒充世界停表。

当前可显示活动的 `startedAt`，标题为“本段安排开始”，其中可能包含赶路时间。并非所有业务都存有单独的到场或等待开始时间，界面不从当前状态倒推这些时间，也不凭空补写完整等待时间线。

## 保护期限与损耗记录

人物档案读取现有 `decisionProtection`：

- 原开始时刻、原定截止、实际结束及原因。剩余时间按世界分钟计算，不使用浏览器或现实时间。
- 开始前身体状态、当前身体状态；近期事件中仍有匹配的结束记录时，另列真正的结束时状态。较早事件不在快照中时，引导查阅完整生平，不拿当前状态替代。
- 暂缓的饥饿与耗竭健康损失，以及保护期间记录的饥饿、耗竭、伤病、野兽与灾害损失。
- 已有危机解除时刻。无效回复、重新连接和页面重开不会重新计算期限。

保护的历史起止事件也显示其自身保存的身体快照和损失来源，后来的身体变化不会覆盖历史。面板明确说明这些数值只是本次保护期间的记录，并非完整健康账目或死因判断。无保护记录的旧档保持“没有记录”，不推断过往是否受过损失。

## 验证

无需密钥、模型调用或真实存档：

```sh
npm run check
npm run build
node --import tsx --test tests/resident-status.test.ts tests/history-reader.test.ts tests/formal-observer.test.ts tests/decision-protection.test.ts tests/education.test.ts
```

定向回归覆盖 13 个观察测试：个人状态与全镇停表分离、室内外床位和工位、没有可用床位、诊疗与教学缺席、实际教学结算的材料不足与恢复、工程授权到期停工、提前到岗、渡运与护送、原保护期限与损失来源、历史和当前身体快照分离、无记录提示、文本转义、只读不改状态，以及增量快照与重新连接的一致性。结合已有历史、观察协议、生存保护与教学回归核对。

本轮已完成类型检查和构建。浏览器视觉验收仍待补：自建九人内存场景已准备，但本执行环境启动 Chromium 时因 `socket() failed: Operation not permitted` 退出；批准提权后仍有相同限制。另试提供的云浏览器，无法连接本地隔离预览端口，返回 `net::ERR_CONNECTION_REFUSED`。因此不把桌面/手机截图、实际布局、关闭重开及页面交互冒充为已通过。下一轮应以同类隔离场景核对 1440×1000 和 390×844 视口、长文本换行、名册与档案重开、停表后的余时保持，以及保护结束后的年表记录。
