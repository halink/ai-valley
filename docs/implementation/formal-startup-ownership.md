# 正式存档启动所有权

正式入口现在先实际绑定 `127.0.0.1:PORT`，保留同一个监听 socket，再取得存档所有权，最后才构造 `WorldStore`、执行迁移和初始化 runtime。端口不可用或所有权冲突时，不打开或迁移世界数据库。

## 锁的生命周期

每个存档旁有一个永久保留的零字节 `<数据库名>.runtime-lock` 文件。进程在独立 SQLite 连接中使用内存 journal 并保持 `BEGIN EXCLUSIVE`，只用其操作系统文件锁，不写入世界数据或锁页。进程正常关闭时，先撤销 runtime、关闭 HTTP 和世界数据库，再释放所有权；`SIGKILL` 或崩溃后由内核释放，不需要检查或删除“旧锁”。

- 不记录、信任、探测或终止任何 PID，不使用时间过期判断，避免 PID 复用和错误抢占。
- 不删除、替换或修复未知锁；非零文件、未知锁 journal、硬链接、符号链接和不安全目录均拒绝。
- 拒绝路径祖先的符号链接，使用目录/文件描述符锚定路径；不同 cwd 和端口不能绕过同一存档的锁。
- 拒绝把锁文件自身作为世界数据库。
- 同进程重复取得也被拒绝，并避免关闭额外文件描述符导致既有 POSIX 锁失效。

锁文件不是可自动清理的临时文件。不要在服务运行时删除、替换、恢复或复制覆盖存档目录中的文件。此协议用于协作的正式入口，不是对有权任意修改这些文件的同一用户进程的操作系统沙箱。

## 平台和升级边界

本批只实现并实测 Linux 上已知本地文件系统（ext、XFS、Btrfs、tmpfs、overlayfs）。未知文件系统、NFS/SMB/FUSE，以及 macOS/Windows 均明确拒绝启动；尚未恢复这些平台的正式启动兼容性，属于发布阻断，不应宣称跨平台可用。隔离开发预览不使用这一正式入口。

升级前必须停止旧版正式进程。相同端口的旧进程会被新入口的绑定顺序保护，但旧版或直接使用 `WorldStore` 的其他代码不遵守新所有权协议，不能凭新锁保证它们在不同端口下互斥。此修改不会查找或终止旧进程，也不会修改已有存档以伪造所有权。

模型是否可执行由独立生产安全策略决定。取得存档所有权不等于获得外部模型、费用或数据传输授权。

## 离线验证

`tests/runtime-lock.test.ts` 和 `tests/formal-startup.test.ts` 使用仓库内新建合成 SQLite、清空环境的真实 Node 子进程和本机 HTTP，不读取 `.env`、真实存档或密钥，不调用外部模型。

覆盖端口冲突前零写入、不同端口/cwd 的同档互斥、四子进程同时启动、原实例 revision 与文件指纹不变、正常关闭与 `SIGKILL` 后恢复、独立存档并行、初始化失败释放、EACCES/非法配置、未知锁、符号链接和硬链接。相关 HTTP、store、runtime、历史和隔离预览回归另行运行；不替代父任务协调的最终全量测试。
