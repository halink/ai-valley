# 谷灵：四层公平审计只读投影

这是开发进度，尚未运行真实发现或拾取，不提测。内部审计从四份明确记录分别计算：

1. **候选指向**按被提议的格子统计。候选没有点名受益人；失败、过期、不获批准不变成落果。
2. **实际效果**按权威落果收据的格子统计。独立于候选统计，不从效果补造候选，也不因落果推断有人发现。
3. **实际发现**按本人先前提交的现场证据统计。同一居民第一次发现同一份落果使用同一稳定标识；旁观者事件、视图、记忆或传话都不能冒充发现。
4. **实际拾取**按本人权威结算记录统计，必须关联同一居民、同一份落果、此前已提交的发现。一次扣除一份公共地面果实、一次增加一份本人鲜果。只看见、计划或发起动作不计为受益。

重放顺序不影响结果；完全相同的重复记录不加计。身份冲突、缺少实际来源、同一份果实由不同人重复领取、以旧库存回填回忆或同一修订中伪造“先前发现”均使审计不可用。允许发现与拾取处于同一模拟刻，但拾取修订必须晚于已持久化的发现。系统不会修复缺失事实，不为均衡主动通知人、调配落点或送果。投影只给内部审计使用，不出现在居民认知或公共年鉴中。

当前模块接受未来权威存储接口传入的明确记录，验证结构、跨记录依存和一次性语义，不验证外部调用方是否真的持有事务权限。独立保存实际发现并在一个权威事务中结算库存和拾取仍须完成；如果只能提供分截时间窗、缺少实际父记录，不应调用该投影。局部日志没有候选方向时不从别的层补计。没有运行时接入、模型、日志扫描、通知或生产开关。

封存 MVP 的开发读取从一个已验证 SQLite 快照分别核对实际落地、独立本人发现与实际拾取。提议仅取同一存档锁下可读且字节稳定的私有队列；无文件、破损或对不上当前时钟／记录时，该层不可用，不将真实落地补写成提议。该队列不是跨文件事务或完整历史证明。没有安装的账与已安装但没有事件的零值分开。每次落地和拾取只记相应库存转移，绝不从余量归因自然再生。此结果仅供封存档内部核对，不进入世界决定、居民通知或公开视图。
