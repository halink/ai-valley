# Godot MVP 最小自主饮水子集

依据 `docs/design/world.md` 的独立口渴与常温轻劳每日约两份水设计，只在 32×24、`godot-mvp-*`、validation 小世界启用。正式模式仍使用原安全水供给体系，本次没有将其口渴规则启用，也没有搬入制桶、公共饮水、照护或净水系统。

- 新世界从口渴 0 开始；每 720 个实际模拟分钟增加 50，最高 100。不按离线墙钟补算。
- 满 50 时本人可选择 `mvpDrink`，实际工作 5 分钟后，从自己 `inventory.water` 扣 1，口渴减 50，并递增持久消费数与完成事件。完成前重新检查本人能力、需求和库存。
- 没有水则须另选已有 `gather`，真实寻路、到泉边工作并扣泉水库存。取水不是饮水；水不会自动灌给居民，等待或拒绝喝水均不消费。饮水不改变饥饿、健康或体力。
- 源的**当前存量有限**，保留既有日界慢再生：距最近采集满一天时至多补 1 份、不得超过 max。跨日账应为 `原存量 + 实际再生 = 源余量 + 随身余量 + 已饮用`，不能宣称闭源无补给守恒。未改原 10000 份泉水初始值，未因测试增发资源。
- 本版没有高温/劳动修正、脱水伤害、疾病风险、幼儿或失能者饮水、容器运输约束；满口渴暂不损害身体，是明确未实现的边界，不代表现实缺水安全。

## 保存与自主选择

`world.mvpDrinking` 保存版本、采纳时间、每位居民口渴与累计消费。旧 MVP 首次加载时原子保存一次采纳（原 revision 校验后递增），从当时口渴 0 开始，不伪造先前消费或缺水历史。其他库存、活动和泉水再生不变。已有不支持版本、异常数值或缺少居民值的状态拒绝加载，不静默清零。

模型上下文只提供本人口渴，菜单在有需求及实际随身水时提供饮水；取水仍是已有可见资源选择。模型可选择其他动作。规则演示按口渴决定取水/喝水，仍明确标注为合成规则，不是模型自治。Godot 只读详情显示当前口渴、携带水及实际动作，无控制入口。

## 验证范围

`tests/mvp-drinking.test.ts` 运行真实 submitPlan/stepWorld 的短时合成取水、饮水、存档中途重启、资源扣减、停表/等待、无水/能力失效、旧档迁移和损坏档拒绝，以及真实模型菜单/提示的离线检查。所有数据库均为测试临时文件，无真实模型请求；这些不是长期稳定运行或真实 AI 验收。

本批验证记录：9 项饮水专测及 MVP/观察/旧正式供水定向回归共 62 项通过；`npm run check` 通过；Godot 4.6.3 `test_observation.gd` 在项目内可写 XDG 目录通过。独立审查发现旧档 CAS 提交错误、缺少异常状态校验和只读需求显示，均已修复；复核无新增 P1。首次默认 XDG 路径不可写导致 Godot 初始化崩溃，切换测试专用可写目录后复测通过。未跑全仓库回归、原生桌面视觉或真实模型长测。
