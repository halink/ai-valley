# 截止前后本地开始与实际请求的精确对账

## CI 依据

`bob 7aab62d` 的 GitHub CI run `43032664311`，3/4 在 `production-model-continuity-review.test.ts:58` 出现 `14 !== 13`。14 是世界 `metrics.requests` 的增量，不是 `localDecisions`。同次合成演练的 model/session 各有13次 attempt、13次完成，无 pending，worker正常退出；并未执行真实模型。

`ValleyRuntime` 先持久记录本地请求开始，再于发送前重复核验准入。若持久提交刚好跨过固定准入截止，后置核验会正确停止发送，随后正常排空。这留下一个本地开始，却没有对应的 transport、model/session intent 或成功决定。旧测试把两个计数当作相等；旧观察验证器的 `>=` 又不能排除没有解释的额外开始。CI 没有记录具体被哪一次后置 gate 截住，因此不宣称已还原该次事件的精确毫秒。

## 最小运行时变更

- 不移动或减少原 `requests++`，不移动发送，不删除任何原准入、价格或截止核验。
- 仅显式启用同步取消观察器的受控 runtime，在持久开始之后、尚未调用注入模型、准入明确关闭且仍存活并排空时，提交一个取消回执。普通 runtime 不创建该字段。抛错、失效代次、一般停止、费用失败或模型错误不能冒充取消。
- 世界只保存一个最新回执及累计计数。回执记录人物、模型、本地请求序号、修订号、wall/monotonic时点、runtime构造时的请求/取消基线，以及上一回执的哈希。它不创造居民决定、物资、退款、请求额度或供应商账单。
- 回执持久提交成功后才调用观察器。写入失败、观察器异步或抛错仍失败关闭，不把不完整证据标为可恢复完成。
- 合成价格桥独立读回世界，检查回执完全相同、唯一在途人物、两账无pending且attempt/completed相符、真实内存transport次数相符，再保存有界观察。观察记录绑定该回执所在世界指纹与两条审计链的准确历史末端。

## 严格等式与持久核对

固定单槽 `sustained` 片段至多一个终末取消。以下等式同时成立：

- 本地请求开始增量 = 实际观察请求数 + 显式取消数。
- 世界取消计数增量 = 显式取消数。
- model attempts = session attempts = 各自 completed；本段增量 = 实际观察请求数。
- successes增量 = localDecisions增量 = 实际观察请求数，failures不增长。

取消事件还必须逐字段等于独立重开数据库中的世界回执，基线等于报告的before计数；时间不早于原准入截止或最后一次tick/ack，也不晚于报告完成，修订必须在最后进展之后、停止提交之前。实际请求原有的截止前观察、响应/ack、身份、费用和硬截止约束全部保留。

worker将观察写入原哈希绑定报告。guardian在新预留之前及本段完成之后独立重开世界，检查已绑定报告中的历史回执链。最后真实回执反向绑定所有较早回执，重复编号必须相同，缺少历史证据则拒绝，不补造记录；最多720项，世界本身仍只留最新一项。独立测试对账器另外回放两账，并单独检查历史链，不把报告自己填写的哈希当作充分证明。

旧的平衡报告可以没有取消数组。缺少取消证据不能解释不平衡计数，旧坏报告不会被自动修补。修改源码也不会重写旧合成run的source契约。
