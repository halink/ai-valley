# 谷灵落果存档兼容边界

本说明补充[普通带龄地面容量](valley-spirit-ground-fruit.md)与[谷灵交付门槛](valley-spirit-delivery.md)。它不新增存档格式、迁移路径或执行许可。

- 普通空容量保留原有兼容约定：V1 的有效空槽可由未启用该能力的普通入口忽略；V2 原生空槽需要显式匹配的配置和存档头。空槽不是一次实际落果，一次性开发档的原生过账也不是普通或旧实验存档的容量记录。
- 原生过账的专用表或归档锚存在时，普通、正式、旧实验入口及未显式启用该能力的开发入口均在迁移和写入前拒绝。名称大小写变化、同名视图等不视为无表，也不会读取其载荷。
- 原开发档只能由持有原文件能力的同进程所有者、以合法的显式原生落果模式重开。原外层标记、专用表及归档锚、已有双签收据和存档头必须一致；未知、不完整、错配或有篡改痕迹的存档不补写、不回滚扣减，也不推定不存在落果。
- 这是合作式所有权及可辨认的归档证据围栏，不是防原始文件篡改的恢复协议。若原始文件写入者抹去所有可辨认的格式标记和证据，普通入口不能反推已经发生的扣果。

仍须按交付门槛分别确认实际普通游戏接线、正式单类型批准及相应运行和公平验收。此处的拒绝、原档重开和字节不变验证不等于提测或生产启用。
