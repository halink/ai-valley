# 谷灵：隔离存档中的居民发现和拾取

只在显式获得隔离开发夹具权限的 SQLite 中启用，不属于正式规则、模型或 Web 入口。普通存档不接受这一状态。由于谷灵设计尚未全部接通，不单独提测。

夹具显式采用 `mvpClimate.spiritFruitSettlement` v1；它与原落果及收据处在同一个权威世界版本。采用、现场发现和拾取分别使用专用写入口；普通提交、未知结构或省略旧状态都不能新增、更改或删除该账。后续关闭落果生成并不删除真实发现或已结算记录。

每次专用调用在 SQLite 写事务下读取最新世界，从真实居民局部视线和当前位置重验发现。拾取必须通过真实本地规则选择器的最后空闲分支，不将正常工作、饮水、休息、等候交易或躲雨替换。只有已先行提交的本人发现、同一份仍可拾取的地面公共果实、精确的时间/位置/居民版本才可结算。

事务同时写一份拾取收据和本人鲜果库存加一。实时地面视图从既有出生落果减去匹配的拾取；同一份已拾取的果实消失，但旧落果收据、真实雨和出生行不得用来再生成、也不被抹掉。重复只重读之前的收据，另一个居民竞争同一份失败，不发通知、不补偿库存、不自动食用。失败则全部回滚。

落果夹具的占用上限按当前可拾取地面存量分别限制同格和全世界；只有权威拾取结算后才释放该份的占用。累计出生行、历史收据、雨源去重及独立累计效果上限保持不变，新雨的新落果仍需独立批准并真实扣除果源。拾取从不归还果源、不增加可采数量或记作第二次产出。居民发现和拾取均记录为私有有类型事实，不新增广播事件。实际生产入口、审批、正式挂接和长期测试另行完成。

开发用原生居民私有回合只接受无参数的回合操作，且仅能在受拥有者锁与本机临时档封印保护的 MVP SQLite 运行。它从已提交、已落地的真实效果开始，按原居民顺序读取本人的当前视野；第一次只追加本人发现。在以后独立回合，已发现的同格食物只有在原生规则选择真正的最后闲候时才能原子拾取一份。回合不自行推进时钟、不启动路线、不生成常规规则计划，也不把闲候条件替换成供给。原拍照、普通运行和观察页无此入口。历史效果能由具名批准及原生落地凭据辨认，但旧 MVP 账不承诺回溯保存原签名信封。

封存 MVP 另有一格真实步进的离线探针。只有本人在权威存档中已有实际发现、还看得见、相邻地块仍可通行且原生选择确为闲候，才在独立副本调用原生移动计划和引擎。它只回报完成的真实格边，整份引擎副本和其中所有副作用都不写回，不宣称动作完成、时钟已推进或已有领取权。较早落果的天气披露权限被撤销不会抹去实物；当前位置、地权与危险仍单独复核。普通档和公开接口不可调用，未加入鲜度或拾取。

封存 MVP 可由独立内部操作提交一格相邻移动，不接受居民或坐标。原生单分钟函数照常为所有其他居民决策；目标本人仍须在排序到本人时选中最后闲候，才以真实一步行走替代。原生事件、计划状态和粮食账按共用事务一起提交；未接入的用餐凭据、无法确证的交谈或独立必要凭据失败，都使此次专用操作回滚。到达后仍保存原生未完成移动活动，不领水果；须后续规则执行完成才可能由独立发现／拾取回合处理。未接公开接口或普通存档，也未加入鲜度。
