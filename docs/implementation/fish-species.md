# 有限分种鱼群与渔获

这是第 5 批的独立生态交付，不代表狼狐繁衍、完整灾害或四季供给已完成。实现只操作已登记的水域和已有实物，不增加开局鱼群总量，不启用新的居民损耗或灾害。

## 实际流程

- 湖鲈、河鲤、夜鲶、雨鲂、海鲷、寒水鳕、冬鲫分别保留野生数量和鲜鱼商品。普通菜单逐种提供当前附近可钓选项，每个附近已登记片区保留至多八个岸边候选，不让耗尽的近岸截掉另一片水域，居民仍须有自己的可用鱼竿、实际走到岸边并完成劳动。
- 一个行动绑定所选品种。天气、季节、时间、库存或可达条件在完成前失效时停止，不能改钓另一种来兑现旧选择。居民和野鸭从同一水域的同种数量扣减；钓具只在成功时磨损。鱼群间的水路不能穿越正在发生的洪水。
- 每种渔获可食用、入店、挂单、售出和取回。新增鱼种的储备提案菜单只提供本人当前实际持有的品种，避免七种空想采购挤掉既有公共事务；实际采购授权仍走原独立表决。库存键就是品种，原有食品批次在转移时保留原保质期。湖鲈、河鲤、夜鲶、雨鲂、海鲷保质两天，寒水鳕和冬鲫三天。
- 每种鲜鱼有独立鱼餐配方；任意两份分种鲜鱼可以按明确的同种或混种配方，在既有罐藏工位用一份水、一份木材和 60 分钟制成两份罐藏食品。没有工位或原料不能开工，未完批次保留真实品种、地点与工时，变质沿原食品规则取消。产物使用现有餐食/罐藏类别，配方和加工批次保留原品种，不声称成品仍能逐条分鱼。

## 容量、繁殖和迁移

每个已登记的 32×32 水域片区共用原容量，默认 12 份。品种分别积累繁殖进度：湖鲈在春季，河鲤和雨鲂在春夏，夜鲶在夏季，海鲷在夏秋，寒水鳕在冬季，冬鲫在春冬。只有仍有存量、有实际水面且不在当前洪流中的品种可以繁殖；所有品种合计不得超过共同容量。完全耗尽的孤立水域不能自行补满。鱼群单位是可捕获的种群份量，不是逐条有性别的鱼，当前没有鱼卵、配偶或幼鱼个体模型。

每天至多从每个水域迁出一份，单个目的水域至多接收一份。两端必须是相邻的已登记片区，有不超过 64 格的实际连通水路、相容栖地和目的地空余容量。只从至少两份的较多种群向同种数量明显较少的一侧转移，不凭空创建鱼。长时间跳步只在当前时刻检查一次迁移，不追补跳过的每一天，也不假定过去水路仍与当前相同。鱼群移动和迁移不扩展未登记水域；枯水、河道改变与灾害导致的长期分布变化仍待后续交付。

品种按登记时实际水格所属栖地分配；一个片区跨越湖河海分类时保留相应多种。片区内仍采用一个可观察鱼群位置，不把彼此隔开的水坑视为多个独立种群。当前模型也不保证所有季节都能持续捕捞。

## 旧档和防重

- 首次分种只把水域原有数量确定性分配给适用鱼种；耗尽水域仍是零。原总量、原时间和已有来源登记不重置，不从历史时间倒算新增繁殖。
- 现有通用 `fish` 库存、原食品批次、挂单和在制鱼餐继续作为“未分种鲜鱼”流转。不会改名、复制、延长保质期或补写其历史品种。
- 新增食品规则采用独立兼容定义，旧食品定义和旧批次不改写。新配方不替换旧鱼餐配方或旧在制批次。
- 新增分种开局数、繁殖、钓获、捕食、迁入与迁出累计数随存档保留；满足“现量＝登记量＋繁殖＋迁入－钓获－捕食－迁出”。同一时刻重复推进、读档和已经完成的行动重放不重复生产或迁鱼。

## 观察与验收

鱼群详情列出逐种数量及累计变化，生态面板区分分种渔获与旧通用鲜鱼。实际钓获、野鸭捕食和跨水域迁移事件带水域身份与地点。登记之前未记录的鱼种保持未知；此处只提供有限累计账与事件，不代替完整生态长期档案和因果图。

[产业水域观察修正](fishing-observation.md)另核对每种独立繁殖进度和水域绑定容量，明确局部灭绝不能自行恢复；不会将分种进度相加成补鱼倒计时，也不改变原模拟规则。新旧验证范围和浏览器阻断分别记录，不覆盖下述历史整批验收数字。
