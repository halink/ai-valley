# macOS 持久 MVP：支持边界与实施设计

状态：**设计调查，不是 macOS 支持实现，也不是 macOS 实测通过。** 本次没有修改锁策略、安装软件、访问用户电脑、读取真实存档或调用模型。

## 当前阻断在哪里

`src/server/runtime-lock.ts` 在取得所有权前明确拒绝非 Linux 平台。这不仅是一个平台白名单：逐层目录打开、数据库及 SQLite 锁文件的打开依赖 `/proc/self/fd` 锚定同一目录/文件描述符，拒绝符号链接、硬链接、未知 sidecar 和未知文件系统。`node:fs` 的公开接口没有相应的 `openat` 操作；不能把 `/proc/self/fd` 字符串替换成未经验证的 `/dev/fd` 就宣称等价。

`godot-mvp-persistent.ts` 取得锁后还通过该锚定路径检查、创建和同步 `.self-hosted-session`，然后才打开 WorldStore。会话标记、数据库和 journal 必须属于同一受保护目录。只更换锁算法而把其余文件操作退回普通路径，会丢失现有路径保护。

因此本批保留失败关闭。不能用删平台判断、PID 文件、超时抢锁、启动时删旧锁、固定端口或只在启动前检查一次路径作为替代。锁释放也不等于未决模型请求被确认完成：崩溃后允许重新取得 OS 锁，但持久会话标记仍必须阻止不确定请求被重新发送。

## 可实施的原生路线（尚未实现）

1. 建立 macOS 原生存储桥接层，使用 `openat` / `fstatat` 的 no-follow 语义逐层打开目录，保留描述符至整个 WorldStore 关闭。使用本机文件系统类型检查，只开放经过验证的本地 APFS；其他卷先拒绝。
2. 不能仅提供一个原生“锁”函数。SQLite 数据库、journal/WAL/SHM、锁文件和会话标记的打开/删除/同步都必须经过同一描述符锚定层。可选实现是独立受审查 SQLite VFS 与 Node 原生绑定，桥接现有 WorldStore 使用的同步数据库 API。现有 `node:sqlite` 没有仓库已实现的 VFS 注册桥，因此需要明确替换/适配该边界，而非假装新增一个 JS 分支即可完成。
3. 同一数据库目录项映射永久锁文件；持有独立 SQLite EXCLUSIVE 锁直到存储关闭，禁止删除锁文件。保留同进程 inode 注册，避免关闭第二个相同 inode 的描述符意外释放 POSIX 锁。所有失败路径都需覆盖。
4. 会话标记先持久化，随后才能发送模型请求；未知请求、异常停机或标记同步失败保持 fail-closed。审查 macOS `fsync` / `F_FULLFSYNC` 与目录同步的实际保证，显式区分进程崩溃与断电保证，不能默认照搬 Linux 成功结果。

依赖：受信任的 macOS 原生编译工具链、审核过的 SQLite/VFS 源码及版本锁定、Node ABI/架构构建策略、真实 macOS APFS runner。至少分别验证目标 arm64 / x86_64 构建，未验证架构不列为支持。当前未安装或引入任何依赖，也没有这些平台的执行证据。

## 最小准入验收

- 两个不同 cwd/端口及四个并发进程竞争同一合成数据库：仅一写入者；拒绝方不迁移、不改 revision，不影响持有方。
- 同进程重复获取、正常释放、SIGKILL/崩溃后 OS 锁释放；失败的 store.close 必须继续持有锁。
- 路径祖先/数据库/锁/sidecar 的符号链接、硬链接、目录换名或替换竞争、未知锁内容、不安全目录及非本地卷均拒绝或保持原 inode，不触碰目标文件。
- 合成模型请求执行中杀进程：重启取得锁后仍被会话标记挡住，不重复请求；干净关闭、未决错误、标记删除/同步失败分别验证。
- 合成 SQLite 重开与 Godot HTTP 观察；模型禁用、429、备用配置等用合成模型，不把它们写成真实模型验收。

Linux 回归只能说明既有 Linux 路线未退化，不能替代以上 macOS 测试。

## 不改锁的桌面观察替代方案

现有 Godot 客户端允许编辑 HTTP 地址；Linux 持久服务只绑定 `127.0.0.1`，所以 Mac 不能直接填写远端 Linux 的该地址。若用户**已经拥有**可连接的 Linux 主机和 SSH 通道，可由用户建立仅本地监听的 SSH 转发，例如 `ssh -N -L 127.0.0.1:13415:127.0.0.1:3415 <已授权的Linux主机>`，Godot 填 `http://127.0.0.1:13415`。保持服务只读、仅回环监听；不新增公网监听或自动配置凭据。本次没有连接该主机或测试 Mac 窗口，此处只是部署方案。

已有 Docker Desktop 也**不能直接当作已支持方案**：Mac bind mount 可能是共享/FUSE 文件系统，不能放宽锁白名单来允许；持久数据须位于满足现有校验的 Linux 卷。且当前容器服务只绑定容器回环地址，普通 `-p` 发布不等于可达，仍需受审查的网络通路/本地转发设计和实测。本仓库没有交付经过验证的 Docker 持久入口；不要求用户安装 Docker，不提供声称开箱即用的容器命令。
