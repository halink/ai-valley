# 未知年龄不取得儿童限时照护豁免

## 修复范围

`ageYears` 为旧的连续年龄调用方保留未知日期返回零的兼容行为，但这个零不是“已经确认小于六岁”。儿童专用 `emergencyCare` 改用 `knownAgeYears`：

- 新提议、独立复核、本人接受、原约喂养和儿童当次救急均须能够确认受助者未满十八岁。缺失、`null`、字符串、非有限值、超安全数值域或未来出生时间均不能建立儿童资格。
- 只有已经确认未满六岁的孩子可在独立复核后免本人接受。六岁及以上仍需本人有决定和表达能力并独立接受；不能由复核人代答。
- 提供者和复核人也必须有能够确认的成年年龄。未知年龄不成为成年资质，也不能替代独立复核。
- 旧约遇到年龄失效会停止，原标识、期限、已发生的接受/复核时间、餐数和回执仍保留。不补生日、签名、餐食、钱款或财产权；后来恢复生日不会复活已停止的约定。
- 本人有表达能力时仍可单独拒绝或停止原约，年龄未知或决定能力不足都不能屏蔽此选择。通过共用的即时停止入口，在下一次喂养完成前生效。只允许当前受益人自己的原协议，不开放代签、接受新约、扩额、其他工作或替别人停止。提供者、复核人等其他参与者仍按原来的完整能力条件撤回。

本切片不改通用基础 `care` 的危重失能救急条件。不能证明儿童身份的未知年龄者不能使用儿童专用入口；真实危重与能力条件仍由通用照护自己的实时规则判断，不能因日期坏掉就推定失能。

## 正常行为与知识边界

合法幼儿的独立复核后照护、六岁及以上本人接受、每次自愿到场喂养、四餐上限、提出时起二十四小时固定期限不变。完成仍重新核验本人拒绝、当事人能力、合法位置、监护关系与自有餐水。

未知日期导致的内部失效不把远处决定自动写入个人记忆。原址核对与参与者撤回继续保留；本人停止只记自己的决定，不冒充已经获知远处原因。喂餐失败不产生成功餐食回执。

## 验证

新增 `tests/emergency-care-unknown-age.test.ts` 通过真实 `decisionContext → decisionChoices → parseChoice → submitPlan → stepWorld` 链路，覆盖：

- 八种未知/损坏日期，新提议和一次儿童救急均无幼儿豁免。
- 已排队的独立复核最后四分之一分钟日期失效，不变成 `active`、不写接受或复核完成。
- 幼儿和已独立同意孩子的喂养最后四分之一分钟发生日期、提供者/复核人资格、拒绝或能力变化，不扣餐水、不记成功回执。
- 内存 SQLite 将非有限日期写回 `null`，或保存缺失日期后继续执行，仍保留原期限且保守停止；日期恢复不复活旧约。
- 未知年龄且只具有表达能力的本人经真实菜单立即停止；伪造协议、替别人停止、夹带工作和伪装为同意均不能借此得到权限。
- 正常三岁、六岁、十岁的复核与独立同意行为，以及人数、钱款、库存、住处、亲属、监护和地权守恒。
