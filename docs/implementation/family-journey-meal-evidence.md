# 家庭迁居逐成员实际供餐证据

## 真实物理路径与范围

本切片只观测 `family-relocation.consumeRation` 已完成的实际扣减，沿用默认关闭的运行时食物证据入口，新增独立 `familyJourneyMeals`。不改模拟规则、居民决定、菜单、知识、存档字段或原旅程时钟。它不是完整消费账本。

原路径在一次 `foodTransaction` 中按已签约的 `c.members` 顺序逐人执行：从该成员约定的 `providerId` 本人库存扣一份 `meal` 和一份 `water`，只缓解该成员的饥饿。成年人通常各自供给，儿童由已签署的供给者承担；提供者不一定等于受益人。所有成员的现物和资格先按原规则核验；不足时整组不供餐，不把仍有库存的成员先记为已吃，也不消耗到达后的保留供给。

实际触发点只有：

- 已接受安排的出发 `depart`。
- 距上次供餐至少120游戏分钟、又实际选择并完成的 `resume`。
- 实际同行中原有每120分钟检查通过的 `travel`。

提议、签署、预留床位或口粮、接送、搬运、暂停、未到间隔的复行、撤回以及个人到达登记均不产生供餐收据。到达登记只是核实原有保留粮水，并不再次扣减。腐败记入既有损失切片，不能记作摄入；死亡、脱队、路线或资格变化仍按原规则暂停或拒绝。若同一步先实际供餐再遇路线障碍暂停，已发生的供餐仍保留收据。

## 每份原批次与水的含义

同一提供者可能为多个不相邻成员供给。原模拟按该提供者先前已扣的份数计算 `foodValue(n+1)-foodValue(n)`，批次最终在同一食品事务结束时一次扣除。因此收据在扣减前读取原批次，并按该提供者自己的 `providerPortion` 截取区间，而不是按全组序号截取，也不是把整组库存差复制给每位成员。

例如提供者先有0.25份营养10的旧批次、再有营养30的批次，则其第一份包含0.25+0.75，营养25；第二份为后一个批次的一整份，营养30。另一位成年人使用自己的库存、独立从份序0开始。低饥饿截断可令实际缓解小于原批次营养，之后的代谢变化不混入即时供餐效果。

每条 `inputs` 明确只有真实扣减的 `meal:1`、`water:1`。水沿用既有个人库存物资语义，`nutrition:0, lots:[]`，不是食品营养、额外进食动作、饮水生理收益或容器水的证明。此路径不扣其他材料，不从当前配方推算未发生的投入。

原批次缺失、数量与物理库存不一致、同一捕获内初始化/修补产生的批次，以及原定义营养缺失，均不能由当前定义或饥饿下降补造营养。能确认的原批次可保留、未知营养为 `null`；无法确认原批次时批次和营养均为 `null`。原 `foodValue` 回退照常运行，证据不改其效果。食品事务可能外层先初始化再调用迁居完成点，已有不可证原批次标记也适用于这条嵌套路径。

## 身份、严格校验和去重

每个成员收据包含 `action:familyRelocation, operation:ration`、真实 `trigger`、时刻、原 `relocationId` 与 `definition`、原已用餐次加一的 `rationNumber`、`memberIndex/memberCount`、`providerPortion`、提供者、受益人、本人来源容器、实际投入及饥饿前后和缓解。

行路供餐没有独立的既有世界事件或本人计划，因此不虚构 `eventId`、`planId`，也不新增存档计数。逻辑事务身份为 `(relocationId,rationNumber)`，份身份为上述身份加 `memberIndex`；恢复继续原存档餐次，不重放旧份。

严格 schema 拒绝额外字段、访问器、符号、数组空洞、异常原型、非法身份、非有限数、越界成员/份序、不符触发的餐次、错误容器、食品或水数量、过期/未来批次、批次数量及营养矛盾、不可能的饥饿差；已知原营养还须符合原饥饿截断公式。

审计检查会话边界、世界与会话身份、序号、连续分钟及递增修订；同一餐次必须完整处于一个已提交步，成员按原顺序0至n−1出现，受益人唯一，各提供者份序从0连续。缺成员、重复份、跨步重放、组内元数据冲突或重复受益人均让总量未知。`completedActions` 为兼容既有汇总形状而保留，明确统计实际受益份数，并非居民所选动作数；一次三人供餐只加三份 meal 和三份 water，不加三次全组库存。

审计不会连接世界数据库追溯任意历史收据的真实性，也不能替受信任引擎/持久提交来源作签名担保。逐日明细 helper 只分桶已经观测的收据，不独立证明完整性。

## 可选捕获、持久提交与旧覆盖

捕获仍属于单次同步引擎调用的原 World 对象，存在 WeakMap 中并在 `finally` 清理。预测副本不继承捕获。只在真实食品事务返回后准备的成员事实进入这次可选观测；运行时继续仅在 `WorldStore.commit` durable commit 成功且安装提交世界后发布。SQLite写入失败或竞争修订拒绝时，不发布草稿成员收据，不改变持久世界和运行时世界；恢复成功后一次发布全组。观察器抛错或异步拒绝不回滚已提交的模拟，但会停止声称证据完整。

`familyJourneyMeals` 与原 `journeyMeals` 分开；旧 schema-1 记录即使有访客旅途 `journeyMeals:[]`，也不能证明家庭迁居被观测。新字段缺失为未知，显式 `[]` 只表示该步本切片观测零份。缺步、零步会话、封存缺失、源指纹变化或证据损坏保持总量未知；writer回读同时抑制顶层与嵌套总量。日报保留已知明细、观测分钟与未观测分钟，后续零次不能修补此前缺测；午夜按 `(fromMinute,toMinute]` 计入刚结束的一天。
