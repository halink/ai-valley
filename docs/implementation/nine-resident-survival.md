# 九人长期生存的独立合成判定

这项交付把“九人终点仍活着”和“本次长期健康与供食达到门槛”分开。原 `scriptedSurvivalPassed`、默认 v4、所有策略顺序、决定预算、世界规则及资源均不变。新入口运行同一 seed 5401、默认 v4 的十五日编号菜单压力测试，只增加观察，另写 `syntheticLongTermSurvivalPassed`。新字段不能当作真实模型自主能力或完整 1.0 发布验收。

动机来自已有[压力测试](nine-resident-menu-stress.md)及[因果审计](../reviews/resident-survival-causal-audit.md)：历史 v4 九人终点存活，但苏葵健康 40.497、饥饿大于 95 累计 1387 分钟；只看终点饥饿也会漏掉此前撞到 100 上限的损害。本实现不把历史稀疏快照补成逐分钟数据，也不重新解释旧结果为改善。

## 事前固定 v1 门槛

规则由 `tests/helpers/nine-resident-survival.ts` 的冻结常量 `SURVIVAL_CONTRACT` 独立版本化，首次新长跑前固定，不接受运行参数覆盖。以下门槛必须**每一名初始居民分别满足**，不能用全村平均、公共库存或其他人吃下的食物抵扣。

| 类别 | 固定条件 | 含义及局限 |
| --- | --- | --- |
| 范围 | seed 5401、初始九人身份集合全程不变、完整 21600 游戏分钟、精确终点、无运行异常 | 不接受短跑或替补人口冒充十五日 |
| 存活 | 初始至终点没有任何已观测死亡 | 死后恢复仍失败；不能只看最终 alive |
| 健康 | 所有已观测健康值至少 80，较此前健康峰值的最大跌幅不超过 20 | 是工程准入线；不是病因归因，最终恢复也不抹掉中途最低值 |
| 持续饥饿 | 饥饿至少 80 的最长连续观察段不超过 120 分钟 | 80 对应现有睡眠健康恢复的阻断边界；两小时是保守工程容忍上限，不是新增生理规则 |
| 危险饥饿 | 饥饿严格大于 95 的观察时间为 0 | 95 是现有饥饿健康损耗边界；恰好 95 不计危险暴露，但仍计入持续饥饿 |
| 实际供食间隔 | 相邻正营养实际进食、开始至首餐、最后一餐至终点，均不超过 1440 分钟 | 不把背包库存、获得赠食、制作/收获或许诺计作吃下；开头尾部没有免费豁免 |
| 全期营养 | 每人已覆盖实际摄入至少 820.8 | 固定 `.038 × 21600` 基础需求；不使用初始饥饿缓冲或饥饿上限截断来降低需求 |
| 终段营养 | 最后 4320 分钟，即 72 游戏小时，摄入至少 164.16 | 窗口是 `(终点−4320, 终点]`；防止前期富余掩盖尾段断供，不证明未来产能 |
| 观察覆盖 | 每个真实引擎调用后采样，单段大于 0 且不超过 1 分钟，所有区间连续 | 分享时的 `.25/.75` 两段分别记录；不存在跨缺口插值 |
| 供餐覆盖 | 自主进食、普通照护、幼儿照护、长期照护、个人旅途、家庭旅途、公共服务、紧急照护八类数组全部全期存在 | `[]` 是已观察无事件，字段缺失是未知；营养未知不以饥饿缓解补值 |
| 动作及持久化覆盖 | 原动作覆盖所有项、原 v4 支持覆盖所有项及实际重开覆盖都为真 | 原两套覆盖公式不修改；新总门槛把二者明确纳入，缺共屋领取等仍失败 |

这些是预先冻结的、偏保守的 **v1 工程检查标准**，不是生理定理或“默认世界不可能生存”的判断。它们是本批版本化的工程判定约定，不代表用户已经批准的唯一 1.0 发布标准。总营养及末窗条件可能拒绝依靠初始身体缓冲或进食节奏波动的轨迹；应保留其失败，而不能按结果调低门槛。需要改变标准时应建立新版本、解释理由、保留旧结果，不能追溯修改 v1。真实模型、四季供应、灾害、照护和世代接续仍有另外的验收要求。

## 数据和失败语义

采样器只读真实世界字段和引擎返回的既有进食回执，不调用可能补初始化资料的 physiology 访问器，不写居民、库存或世界，不参与菜单选择。观察对象包括所有居民；采样身份集合改变即关闭通过。没有已知 `.038` 生理增长率的资料也不会自行填默认值。

每位居民保留初态/末态、最低健康及发生时刻、最大健康回撤、最高饥饿、全部持续饥饿段、累计及最长饥饿时间、每类供餐覆盖分钟、每餐受益者归属和营养/缓解量、全期及末窗摄入、首尾含在内的最大进食间隔，以及逐条带机器代码的失败原因。供餐按真正受益人而不是扣货人计数；零营养服务材料不算一餐，水不当食品营养。重复事件及重复家庭成员回执被拒绝，数值溢出关闭通过。

缺采样、漏渠道、未知营养、截断 journal、变更身份、未知标准或缺封口都不等于零。已观测的局部数值保留为 `observed…`；缺完整覆盖时，完整危险饥饿时间、营养和最大进食间隔为 `null`。`failures` 分为 coverage、survival、health、hunger、food。身体证据不完整会阻断存活、健康、饥饿分项；供餐证据不完整会阻断供食分项。单纯未覆盖共屋领取等动作只令 coverage 失败，不把已完整观察的健康、存活或供食也误标失败；总判定仍要求所有分项通过。修正后的判定器标记 `evaluatorRevision:2`，门槛常量不变。

“观察饥饿分钟”是每次调用结束状态代表该次调用长度的离散统计，不是连续物理轨迹的精确积分；健康最低值也是采样最低值。`.25/.75` 不再被一整分钟末态覆盖，但引擎调用内部未采样的瞬时变化仍不宣称已知。净健康变化不等于毛损害，`grossHealthDamage` 与 `modelAutonomyAcceptancePassed` 始终为 `null`，`completeFoodLedger` 始终为 `false`。

## 独立重复执行

要求 Linux、Node.js 至少 22.13.0及已安装的锁定依赖。命令清空继承环境，使用项目内工具临时目录并预加载已有离线守卫；不加载 `.env`、真实档或密钥，不调用模型、网络或生产服务。

```sh
set -eu
NODE="$(command -v node)"
mkdir -p output/test-tmp
TOOLS="$(mktemp -d "$PWD/output/test-tmp/survival-tools-XXXXXX")"
LOGS="${TOOLS}-logs"
mkdir "$LOGS"
trap 'rm -rf -- "$TOOLS"' EXIT
offline_node() {
  env -i HOME="$TOOLS" TMPDIR="$TOOLS" TMP="$TOOLS" TEMP="$TOOLS" \
    TSX_DISABLE_CACHE=1 "$NODE" \
    --import ./scripts/acceptance-offline-guard.mjs \
    --import ./node_modules/tsx/dist/loader.mjs "$@"
}
offline_node --test tests/nine-resident-survival.test.ts \
  tests/nine-resident-survival-review.test.ts >"$LOGS/tests.tap" 2>&1
set +e
offline_node scripts/acceptance-nine-survival.mjs --offline >"$LOGS/fifteen-day.json" 2>&1
STATUS=$?
printf '%s\n' "$STATUS" >"$LOGS/fifteen-day.exit"
cat "$LOGS/fifteen-day.json"
printf 'Retained logs: %s\n' "$LOGS"
exit "$STATUS"
```

新入口固定跑十五日 v4，自动在新建 `output/test-tmp/nine-menu-stress-XXXXXX/` 留下原始压力测试产物及四份新增资料：

- `survival-evidence.jsonl.gz`：开头标准、来源指纹与初态，连续逐调用状态和八渠道原始回执，最后原动作/支持覆盖及封口。标准 gzip 支持串接成员。
- `survival-verdict.json`：完整逐人判定与失败，不只通过布尔值。
- `survival-evaluator-source.ts`：本次判定器逐字副本；原 `controller-source.ts` 同样保留。
- `survival-artifact.json`：上述证据、判定器和控制器的 SHA-256。哈希用于意外篡改/版本不匹配检测，不是来源签名，不能认证伪造轨迹。

首次运行本身就会重新读 journal，重算并核对落盘 verdict 完全一致。之后使用相同 `offline_node` 定义执行：

```sh
offline_node scripts/acceptance-nine-survival.mjs --offline \
  --recheck output/test-tmp/nine-menu-stress-XXXXXX
```

`--recheck` 不推进世界、不读 SQLite、不调用控制器；只允许上述固定形状的隔离目录，拒绝链接、非普通或多硬链接文件、超大文件、哈希不符或判定器版本不符。旧档没有该 journal，不能从稀疏 report 推断通过。入口参数没有策略、天数、门槛、真实档或模型选项。

退出码：**0** 表示这项合成标准所有门槛通过；**1** 表示完整重复判定成功但标准失败（仍保留全部证据）；**2** 表示参数、守卫、IO、哈希或重复核对等执行错误。不因合成门槛失败把单元测试标红，也不把单元测试通过冒充长期生存通过。
