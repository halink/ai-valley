# 供应商来源材料：离线托管证明校验

`createProviderSourceCustodyDryCheck` 是独立且未接线的组件。已有部署签审和 held 进程继续按原接口运行；它们验的是启动申请与其声明摘要，本组件额外要求提供五份**精确原字节的审阅记录**，不是复读摘要、接收任意文件或声明供应商收费已经查证。未配置受信引导时默认拒绝，不读文件、环境或网络。

受信引导固定现有 gated 合同、原准入 JSON、实际账户身份摘要及七个不同的 Ed25519 公钥（已有启动的两个公钥仅用于排除复用；另外五把按材料固定），同时提供相应时钟。在真正部署前必须独立分配/分发这些公钥，不能向申请者询问公钥或从存档装载。输入只接收五个有界、ASCII 紧凑 JSON、可逐字复核的证据封套；每份字节必须吻合原准入里预先声明的精确 SHA-256，且各自的签名必须由所属审阅人验证。每份材料范围都绑定同一账户、世界、运行、模型、指定端点和合同；合同基础摘要暂不含最终准入摘要以避免哈希循环，现有准入校验仍验证了最终材料集合完整哈希。

协议：D = `ai-valley-provider-source-custody/v1`，B = `sha256(JSON.stringify([D,"basis",accountIdentityDigest,modelEvidenceHash(productionCandidateContract(contract))]))`。签名直接覆盖规范 UTF-8 记录（每份最多 1024 字节），外层封套是 `{utf8, signature}`，签名无填充 Base64URL。每份记录为 `[D,role,B,payload]`；角色与 payload：

- `authorization`：`[有效起始UTC毫秒,有效终止UTC毫秒,原准入数据范围,0微元预算]`；同时覆盖当下及合同窗口。
- `prior-request`：`[上一请求身份摘要,提交时间UTC毫秒]`；只能指新运行前的请求，不含请求正文或个人数据。
- `outcome`：`[同一请求摘要,原准入处置,观察时间UTC毫秒,输入token量,输出token量]`；观察必须落在该请求至对账期间；未执行不能带用量，完成必须提供至少一个已量化 token。
- `billing`：`[同一请求摘要,确切处置记录SHA-256,原准入对账时间UTC毫秒,同一输入token量,同一输出token量,0微元,"CNY"]`；不接受空账单或把另一次请求当成这次。
- `pricing`：`[原准入官方价格地址,同一检查时间UTC毫秒,同一失效时间UTC毫秒,0输入档位价格,0输出档位价格,0其它适用价格,"CNY"]`；必须仍符合原准入的时效；在验证全部材料后重新读取受信时钟并执行原准入，逾期或时钟回拨都不通过。

验证的是独立审阅人签署的**本地证据记录**及其一致性，非供应商原生发票、签名或托管证明格式。测试用临时公钥和闭合样本；未知真实材料不得塞入一个新写的哈希或布尔值。运行时保留 `liveAuthorized:false`、`providerIdentityVerified:false`、`actualProviderCostCny:null`；成功不证明外部资料真实、用量实测或账单结清。仍需要由有权人士核验真正供应商材料、凭据账户与账单身份；有真实原生证据格式时须独立接入，不使用这里的样本协议去冒充。
