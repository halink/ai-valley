# 本人尚未理解记忆的有界轮转

## 已复现的问题

正式 seed5401 在第481分钟使用真实编号菜单让听者等待30分钟。另一人期间通过真实 talk 菜单连续说6句，每句保留完整原话与实际语气。等待结束时首句仍在听者记忆中，但旧 socialOpportunities 永远只扫描最后5条。再等12次30分钟也不能出现首句 interpret 入口。

仅扩大候选不足以修复：decisionContext 旧快照只复制最后18条，而议程与聚焦会再次裁掉解释候选。旧多人事件固定取前两名对象，重复 actors/memories 也会浪费名额。

## 规则与上限

- 本人最后80个实际保留的记忆条目是唯一入口，与现有 emitEvent 的80条自然遗忘上限一致。不查全局原话替本人补记，也不把长期关系 evidence 当作仍记得的原话。
- 对最后80个条目按 eventId 去重，保留最后一次有效送达的整份记录；不拼接另一条的原话、语气或来源。旧档超80部分只在本次读取中排除，不修改旧档或回填记忆。未来 receivedAt/event.at 不授权现在的理解。
- 只考虑对应事件仍存在、目标本人认识且居民记录仍存在、该 `(本人,event,target)` 没有既有解释收据的候选。来源、原话或语气缺失不会从全局记录补写。现有 source 未核实消息继续标为消息，不因此变成事实。
- 每30游戏分钟轮转最多5个候选事件，每事件最多2个目标，总计最多10条解释菜单。对事件actors再次去重；已解释一个对象不阻止同事件其他对象。
- 设候选事件数为N、tick=floor(游戏分钟/30)。事件偏移为 tick % N。对象偏移为 floor(tick/N) % 该事件尚可理解对象数。同一完整N轮内对象偏移固定，避免两层直接使用同一模数导致永久跳过部分 `(event,target)`。
- 对资格不变、持续保留且每30分钟观察菜单的集合，N个采样轮覆盖所有事件；有T个目标的事件在至多N×T个连续采样轮内覆盖所有目标。这里是可选择性的保守上界，不是自动执行时间表。新的记忆、遗忘、收据、权限变化或错过采样时段会改变集合，因此不承诺动态输入下无条件最终执行。
- 不设额外日龄TTL。记忆保留再久也可以回顾，但已经被80条上限自然挤出的记忆不能再解释。旧理解也不证明对象现在的意图、身体或库存。

## 最终菜单与依据

decisionContext 复制同一有界本人记忆集合；一般短记忆段仍只显示末尾3条或6条，不扩大日常摘要。解释专用证据只展开本次最终编号菜单选择的最多5条记录，继续安全JSON引用完整speechText与实际speechTone；旧档缺字段保持未知，旧经历摘要仍受1024字符上限保护。

最终恢复从 buildChoices 的已受年龄、能力及交通限制的输出取候选，因此乘员、船上、撤回专用或家庭旅途菜单不能因此获得新权限。恢复不再次轮转：利用空位、仅替换多余目标反思，或增加最多10行；现有非反思、紧急、吃饭、拒绝和停止不删。原68条饱和普通菜单最多变为78条，实时停止入口仍按旧规则额外恢复。菜单生成不提交计划、不解释、不改变关系或记忆。

本人明确选择编号后，仍由既有 socialReason 在实际执行时重新检查能力、记忆、对象与收据。菜单生成之后遗忘或别人先完成重复动作不能绕过校验。输入完整依据优先于综合家庭摘要；若整体仍超过模型原有输入上限，既有 guard 拒绝请求，不丢原话或自动改选。

## 保存与旧档

不增加持久化字段、游标、数据库表或版本迁移。轮转只依赖当前游戏时间、仍保留的本人记忆与既有收据，同一快照重载得到同一菜单与prompt。WorldStore 已为本人记忆保留相应事件，SQLite已存收据在运行时瘦身加载后仍防止同一理解反复刷分。遗忘不会删除持久关系看法，但不因此恢复旧发言入口。
