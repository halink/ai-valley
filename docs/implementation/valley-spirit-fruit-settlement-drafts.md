# 谷灵：现场发现与拾取事务草案

这是开发内核，不是已接入的拾取动作，也不是提测。当前模块不写存档、不改运行器和普通规则。调用者必须拿到可信的已提交小山谷状态和独立居民规则本轮真正的最终空闲选择，不能从公开请求传入。

- 发现草案重新检查本人在现场实际看得到且地块可达。观察者记录、雨、旧地址、假 ID 都不算发现。记录稳定的本人×落果 ID 并提出独立世界修订，不改知识、库存和可见性。相同发现重放不会写两次。
- 拾取要求同一居民、同一份果实此前已有提交的本人发现。当前必须是本人实际站在该格、仍走得到、没有更急的既有需求或活动；最新选择必须完全匹配一份、公共产权、地格、原放置时间、本人和时间版本。草案只增加本人一份鲜果，提交草案中的扣一加一公平记录；不会自动进食或改变其他人。
- 原落果收据和出生库存保持不可变，以唯一拾取收据从记录的地面存量中扣除一份。重放已结算意图不再加库存；另一居民抢同一份直接失败；移走后不再为新人补发现。版本未知、遗漏来源、时间反转、旧收据不匹配均不继续。
- 未来必须将发现/拾取记录作为权威版本字段或同一数据库事务的数据，而不是异步下载/镜像。实际提交必须在获得最新权威世界后重算草案，与原修订比较，并将居民库存、可用地面存量及公平证据全部提交或全部回滚。草案不自行授予执行资格；隔离验证和正式权限仍需各自检查。

本地单元测试覆盖物理发现、重复、领取守恒、竞争、行动优先级、伪造或过期证据与未知状态；无模型调用、无长测、未提测。
