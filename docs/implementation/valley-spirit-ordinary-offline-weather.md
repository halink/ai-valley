# 谷灵：普通规则入口的离线天气小刊

开发切片，默认关闭，不等同于整套谷灵提测、生产运行开关或真实模型接入。正常的持久规则入口已有只读天气年鉴阅读器；本切片增加独立的程序化发布接缝，不新增 HTTP 路由、自动发布或调度。普通启动既不调用发布接缝，也不自动批准内容。

由受信任的本机操作者在关闭普通规则进程后，取得同一存档运行锁，只对已经存在、已经启动并留有公共气象点的普通验证世界操作。封印开发夹具不得进入此接缝；不要在真实玩家存档上运行开发验证。单次发布明确指定已结束的游戏时段及所选来源，使用固定离线选择、既有事实核验和 v1 渲染；不调用供应商、账户或网络，不声称模型创作。首次发布只接收尚无刊物的时段；已建议更正时，必须另外走下列签审更正流程。

操作者预先固定独立审核人的 Ed25519 公钥，不从请求、存档、环境变量或 HTTP 取审核人身份。审核人先看预览的实际内容，再在服务之外签署 encodeOrdinaryOfflineWeatherReview(terms) 的准确字节。签名绑定同一存档身份、世界提交版本、当前公开权限、前一刊物表摘要、所选天气证据与准确渲染版本。操作期间保留原运行锁，写之前再次核验；未知存档/权限/来源/表格式、错误或过时签名、内容/范围伪造、重复发布都不接受。现有刊物表与独立私有签名收据通过同一次 SQLite compare-and-replace 事务保存，一处写入失败则两者都不成功。收据含准确签署条款、签名及审核公钥，不保存私钥，不进入 HTTP、刊物正文或公开 DTO。提交事务再次核对当前世界提交版本、权限版本及前一刊物表摘要。已有独立收据的刊物不可通过一般发布、纠正或覆盖绕过其约束。

普通只读入口保持原 URL、公开刊物模式、投影和渲染版本；内部分别标记新审签刊物和旧版离线刊物，公开来源标签仍为 offline-synthetic。已审签刊物每次读取必须有完整有效的准确签名收据、同一存档文件身份、当前来源的完整公共字段摘要及当前天气授权。即使改的是未出现在文案中的来源字段，旧刊也隐藏。缺失、篡改、未知结构、外来收据一律不给出旧文案。历史版本中已存在但没有该内部标记的刊物继续沿用旧的事实和权限校验，明确不等同于有独立耐久审签；不为旧刊伪造审签，不自动更正旧路径。

## 独立签审更正与撤回

已有审签刊物可以由原独立审核人另签撤回。只有以 `source-correction` 撤回的审签首版能成为同一时段更正二版的前任；永久编辑撤回、仍公开的首版、未审签的旧刊、已替换的首版及二版均不能进入该更正接缝。撤回与更正是两项独立批准，不会自动刊登二版。

本机程序用 `previewCorrection(oldEntryId, range)` 取得实际二版文案、私有前任关系及条款；用 `encodeOrdinaryOfflineWeatherCorrection(terms)` 生成准确签署字节，再用 `correct(oldEntryId, range, approval)` 验签和提交。更正作用域与首版签审相同，签名用途不同；同时绑定同档、原审核人、当前世界修订、当前天气权限、完整获准天气证据、刊物目录、前任刊物/发布收据/撤回收据摘要及二版的确切内容。天气来源独立于 SQLite，以同一协作锁在写入前再次读取；刊物和更正收据在同一 SQLite 事务写入。只读预览 owner 不能提交。没有命令行提交、公开写端点、自动模型或 Seasonal 私有草稿转公开的接线。

公开读取不返回已撤回的原刊和其精确链接地址；二版的公开 `supersedes` 为 `null`。再撤回二版不会复活旧刊，也不支持第三版。前任签章、撤回记录、二版签章或当前天气来源有异常时，受影响的刊物保持不可读；在没有其他合格刊物但仍有天气权限时显示客观手记。

关闭并重启同一原始存档文件可继续核验。备份恢复到不同文件身份时，普通世界与客观天气仍可读取，但新审签刊物不保留已审签阅读状态。这个机制没有常规用户授权 UI、外部公钥登记或不可回滚服务；信任前提仍为可信程序化调用时固定的独立审核公钥与受保护的本机存档，不能防全存档恶意重写或整体回滚。

仅通过普通持久规则入口的 GET /ai-town/api/valley-spirit/almanac/latest 与已有精确 entryId 路由读取。天气证据仍须当前有效；天气本身撤权时整页不可用，重新开天气只回客观手记、不复活旧刊物。刊物缺失或其私有数据未知但公共天气仍有效，回 objective-only。任何新刊物不改变世界、居民知识、权限或 G2。

读取保留完整收据一致性门：普通请求最多先全量核验 256 条已审签收据，单条不超过 4 KiB；候选精确来源复核仅重新验证该刊物的索引收据，最新页的候选上限仍为 24。超量、缺失或错误收据保持客观回退，满额不覆盖旧刊。

## 本机开发：导出待签预览

`dev:weather-editorial:preview` 只读取已停止的**普通本机开发存档**，不会发布或写入 SQLite/权限/世界；普通启动不会运行它。不要用共享、生产或真实玩家存档。

1. 使用普通持久规则开发入口运行临时档，在 Godot 的「天气档案」确认有已结束游戏小时；也可在客户端已连接时读取 `GET /ai-town/api/valley-spirit/archive?fromHour=N&toHour=M&limit=24`。记下返回的 `worldId`、所选 `observed` 记录的 `sourceRef`，以及时段（游戏分钟，包含首尾）。
2. 正常关闭该运行进程。确认由独立审核人提供的 Ed25519 **公钥**文件已在本地，脚本不接受私钥。
3. 在项目根目录执行（把示例值换成上一步的实际值）：

   ```sh
   npm --silent run dev:weather-editorial:preview -- \
     --save /tmp/local-weather-dev/rules.sqlite \
     --world godot-mvp-your-world \
     --from 480 --through 539 \
     --source godot-mvp-your-world/weather-1-8 \
     --reviewer-public-key /tmp/local-weather-dev/reviewer-public.pem
   ```

可重复传 `--source`，最多 24 条，范围小于 24 个游戏小时；重复、窗口外、跨世界、无权限、缺证据与已有同范围刊物都会被拒绝。退出码：0 成功，1 预览不可用，2 参数无效。成功时 stdout 只有一个 JSON，`edition` 用来核对文字、`terms` 用来记录准确审核条款、`signingBytesBase64` 要按 Base64 解码后逐字节签署，不能签 JSON 输出、Base64 字符串或格式化文本。预览含审核指纹和存档范围摘要，只在本机审批链流转；它不是刊物或公开 DTO。

预览只取得普通本机运行时已有的协作锁，并拒绝有 SQLite 日志副文件的档案；它不保护直接绕过锁、并行修改原始存档文件或天气记录的程序。

此命令刻意没有 `apply-reviewed`：接受命令行传入的公钥再接受同一操作者的审核包，会让审核包提交人变相选择信任根。已单独固定可信独立审核人的本机程序仍可通过文中的 `openOrdinaryOfflineWeatherRelease(...).release(range, approval)` 既有接口复核并写入；签章在外部完成，随后同一原始存档重启才能在常规「查看年鉴」看到已审离线内容。开发命令不改变现有信任边界。

### 独立签审一个既有观测字段

停止普通存档后，受信本机工具可用 `previewSelection({sourceRef, field})` 取回一项待签审事实，再使用 `releaseSelection(selection, approval)` 提交。字段只允许天气、气温或相对湿度；选择不接收数值或文案。数值必须同时来自本世界当前获准天气档案的已结束小时，并与固定气候规则复算一致。独立审核签章绑定原始 SQLite 存档头、权限版本、来源、该字段和现有渲染器输出；普通批量签名不能代用。一次只发布一个事实，仍用既有年鉴读取和撤回流程，权限撤销时回退，不新增接口或模型调用。
