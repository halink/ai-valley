# 医疗接收场所的灾害重验

本修复针对照护审计中已复现的错误：普通医疗 `rescue` 可以把幼儿送入活动洪区的会馆，登记为 `delivered`，随后幼儿继续受伤；同一建筑在避难规则中已被判定不安全。

## 统一的实际规则

`building-safety.ts` 将建筑对灾害的真实防护规则抽成共同函数。灾害伤害、临时避难、医疗接收不再各自判断房顶是否有用。

- 有 `footprint` 的洪水，以实际记录格子判定，不能用大半径猜测干地，也不能认为屋顶会保护被洪水覆盖的门口。
- 旧档没有 `footprint` 的洪水保留原核心半径规则，不补造几何或历史。
- 风暴中屋况至少35才提供保护。医疗无灾害时仍沿用原来屋况大于0的接诊门槛；这不是把所有普通诊所改成临时避难所。
- 预警和活动灾害都会使已确认不安全的接收场所失效；退水后可重新作出安排。其他重叠灾害仍逐一检查，不能只核对最初那一场。
- 已知地点、公共或施救者/医生自己的使用权、真实床位、预约与原有实际通路条件继续适用。护送床位还核对在本地存活、住宅登记一致的住户实际分配，住户暂时出门不意味着其床位可以被占用；途中新增登记也会使原预留失效。患者接受医生自己诊所的邀请，不等于取得产权或其他人的诊疗使用权。

## 知情与物理执行分开

普通菜单不查询远处目的地的实时屋况、空床和完整通路来保证其可用性。已有地址仍能提出尝试，但不会因居民未观察到的远方洪水而消失，也不因看见一场大洪灾的中心就获知远处新增加的洪水格子。只有本人可以实际观察该建筑，才用该处的实际灾害判断医疗菜单。

出发、接出和途中继续重验原有权利及约束。到可实际观察目的地的位置后，新出现的危险使安排中止；不是自动改送别的建筑。进入室内、到床位和实际治疗阶段再按真实世界核验，不能用未知状态获得安全交付记录。

原导航仍按真实地形、洪水与基础设施通行边拒绝不可能走通的路径。这次没有建立“过去知道的道路地图”，也没有把所有既有行动改成局部导航系统。

## 覆盖的医疗生命周期

- 护送提议、接受、正常接出、途中移动和床位交付。
- 预约提议、患者接受、医生/患者赴诊、实际共同治疗与结算。危险取消没有发生的治疗，不给报酬；未用材料与预存费用依原规则退回，不能重复退款。
- 已经不安全的安排仍可拒绝、撤回，不需要先恢复场所。
- 每次室内移动前和每个室外步子前重验。一个时间片可能跨过多段道路，第一步看见危险后不会再走第二步。
- 陆上接出和交付必须完成实际路线及工时，不能仅靠活动对象或已经到床边提前完成。原有靠泊船只的接触、席位释放、退款和实际岸上路线继续保留。
- 动态失效时患者留在施救者的真实位置，不回家、不传送、不重新发物资。保存到隔离内存SQLite后重载，仍保留进行中的路线、床位占用、用品支出与中止结果。

健康幼儿的有限新入口见[监护人灾害护送](guardian-evacuation.md)。其灾害标识绑定原先亲见的威胁，接出前消退即失效；已接出后可以继续送达安全床位，但当前监护权限、拒绝与目的地安全仍逐步核验。仅这类绑定的幼儿撤离进一步复用已有避险逐边规则：可以走出已处于的危险，不能进入另一项已见洪水预警、活动洪水或风暴；菜单、起步、接出路径和途中每个步子保持一致。普通医疗护送没有该字段的旧记录无需迁移，也不改写它们既有通路策略。

## 明确边界

没有读取密钥或真实存档，没有调用模型、浏览器或 npm，没有提交推送。测试只使用代码新建世界和内存SQLite，不代表真实模型、九人四季或完整失能居民撤离验收。新天气调度仍默认关闭。

本次覆盖 `health` 的护送与接诊预约，不擅自扩宽 `publicDuty` 公共照护或 `longCare` 私宅照护的独立授权。它们的目的地安全与知情规则需另行审计。已完成交付之后新发生的危险，也不会自动替居民作出下一次撤离决定。
