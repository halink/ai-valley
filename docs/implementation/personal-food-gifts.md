# 自主居民的有限个人赠粮

## 切片与权限边界

[居民自主行动](../design/people.md)与[实际履行](../design/simulation.md)要求提出、接受和交付分别发生。已有双向交换不能表示单方赠粮，照护同意、监护、公粮自助也不是普通成年人之间转移个人食品的授权。本切片新增独立的 `personalFoodGifts`，不改用医疗、失能代理、照护或公共预算规则。

- 双方必须在谷内、在世且都有完整决定和表达能力。送出者满13岁，接收者满6岁且可自主进食；已入谷访客也按同样年龄与能力核验。任何一方未成年时每份提议限1份，成年人之间仍为1–3份。睡眠、船上、被护送或家庭同行不能形成当面赠粮。旧成年证据不自动扩权，详见[青少年有限切片](teen-personal-food-gifts.md)。
- 只能指定送出者本人实际随身携带的可直接进食物品，每份提议按冻结年龄条款限1份或1–3份，不能指定清水、木料、公粮、商铺、家庭库存、受保护财产或他人的物品。本人最多保留三份未结束的送出提议。
- 赠粮是食物所有权转移，不是给别人喂食。提议、接受和交付均不降低接收者饥饿、不增加健康、体力或营养，也不生成照护、监护、床位、医疗或后续代理权。收到后是否进食，仍由接收者另选原有 `eat`。
- 天气自动调度仍默认关闭。

## 三次独立选择与真实路径

1. **提出。** 送出者在合法近身现场，从真实最终菜单选择接收者、食物种类和原年龄条款允许的数量，完成1游戏分钟办理。提议固定有效120分钟，不扣货、不预留、不把接收者的沉默视为接受。
2. **接受。** 指定接收者另外选择接受；双方仍须合法近身、清醒、有能力。原数量和绝对截止不变。接受也不扣货，不检查远处或他人的私有库存。接受时记录双方实际见证的接收者位置，作为本次固定交付地点。
3. **交付。** 送出者须再次自主选择亲自送交。引擎沿正常户外与室内路径花费真实时间，走到原位置并完成1游戏分钟合法近身交付。地点不是接收者实时追踪器，接收者离开后不会自动追赶、改变路线、传送物品或改送旁人。原屋使用权丧失、路径阻塞、对方不在、失能、睡眠、死亡、离谷等会使本次尝试失败。

室内必须有实际房间坐标、合法使用权、真实门口和不受阻的短近身通路。赠粮不会授予进入私宅的权利，也不会把缺失室内位置回填成门口。室外近身同样检查短实际通路，不穿墙、围栏或水面交付。途中检查本人能力、所持数量、绝对期限和合法连续路径；到场后重新检查对方的当前能力、位置、意愿和原完整条款。

## 本人反悔、竞争和未知信息

送出者可撤回自己未交付的提议；接收者可拒绝或撤回接受。停止必须是属于本人的单独行动，提交后立即生效，包括送出者正在赶路或最后四分之一分钟。本人另有活动、乘船或同行时仍保留撤回入口，不依赖对方同意。该入口对具有原约本人权限及完整自主能力的当事人开放：送出者满13岁、接收者满6岁；旧版本仍保留成年人门槛，不引入失能表达或代理例外。

赠粮不预留食品。本人仍可吃掉或使用它，也可能因竞争、变质而不足；最终交付数量不足时失败，不补货、不改用其他物品、不动用公粮、不部分交付。完成交付用既有 `foodTransaction` 与明确个人容器路线转移届时实际持有的同类食品，按原批次先到期顺序取用，保留生产时间、失效时间、定义版本和数量；提议本身不是锁定某个批次的托管。

两份提议可竞争同一库存，先实际交付的一份消耗真实物品，后者不能复制库存。已经完成的交付不可撤回成未交付记录；任何进一步回赠都须另行提出和独立接受。

远处的内部状态不是居民所知。撤回事件只给实际合法近身的当事人留下记忆。未收到变化的人仍看到原条款、原期限、尝试交付与本人停止入口，而看不到远处状态、坐标或失效原因。原路线不因为对方的远处变化而追踪或改道，到场失败只说明在这里没有完成。绝对截止是本人已知条件，到期不会续约。无人愿意提出、接受或送达时，不生成自动救济。

## 版本、原始证据与保存

新菜单使用带版本的回执及 `@2` 年龄条款证据，冻结选择时出生时间、选择时间和数量上限；旧 `@1` 回执与事件保持原成年人语义，不补造或升级。跨18岁后原约仍只交付原数量，新增成人额度须重新提出。详见[版本与兼容验证](teen-personal-food-gifts.md)。

每份提议保存原提出回执、双方、物品、数量、期限、接受地点、独立接受时间、状态和事件。执行检查精确字段、主体与完整条款，不能添加代理人、公共库存、替代接收者或额外动作。提交提议绑定当次本人版本，原提议回执和最终交付回执进入持久账本；换计划编号、重复完成或SQLite重载不会再扣货或复制食物。

提出和接受分别以不可变事件核对当事人顺序、真实见证、权限范围、资源数量及原始绑定。办理时间另记录连续实际工时，单改剩余时间或直接调用完成函数不能伪造交付。存储的工作事件窗口保留这些原始证据；旧档没有赠粮记录时仅初始化空集合，不从旧照护、聊天或交换补造同意。

观察者可以通过事件、居民当前行动标签和baseline/delta/reconnect看到实际状态。这些完整世界事实不注入居民的远处知识。读取菜单不会改变世界。

## 隔离验证与复现

主测试 personal-food-gifts.test.ts（历史路径：`../../tests/personal-food-gifts.test.ts`，已移除） 从真实最终菜单、`parseChoice`、`submitPlan`、世界步进与内存SQLite验证行为。初始未实现时3项真实菜单测试全部失败；完成实现后21项通过。独立反例与修复详见[独立审查](../reviews/personal-food-gifts.md)。

```sh
node --import tsx --test tests/personal-food-gifts.test.ts tests/personal-food-gifts-review.test.ts
node --import tsx --test tests/*.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.server.json
node --input-type=module -e "import {build} from 'vite'; await build({envFile:false});"
node scripts/acceptance-long-run.mjs 3
git diff --check
```

使用合成世界、内存SQLite与隔离控制器。没有读取环境密钥、真实存档或私人日志，没有调用真实模型、浏览器或npm，没有提交、推送或部署。Vite明确禁用环境文件读取。离线通过不证明真实模型会自主选择赠粮，也不等同正式世界或浏览器视觉验收。
