# 本人理解时的完整发言依据

## 原问题与红测

正常编号 `talk` 接受最多 240 个 UTF-16 单元的文字，但最终普通记忆只取前 120、`interpret` 选项只取前 140，二者都没有省略标记。正式 seed 5401 第 481 分钟从真实编号发言后，末尾分别为“我愿意答应。”和“我拒绝答应。”的 240 字记录会丢失决定性尾句。

`tests/dialogue-content.test.ts` 先对最终 GLM 输入断言完整原话，未修复时失败。修复后同一测试覆盖 GLM、Qwen、DeepSeek 的最终准备输入，并继续通过真实 `parseChoice → submitPlan → stepWorld` 完成本人选择的 `interpret`。仅验证传入信息及执行边界，不推断真实模型会怎样理解。

## 交付与展示边界

- 普通 `talk` 实际完成时，单独保存可选 `speechText`，不混入姓名；它等于实际说出的合法 1–240 UTF-16 单元原话。与 [实际发言语气](dialogue-tone.md) 一起，仅复制给既有 `emitEvent` 判定的真实 witnesses。未完成、未听到或仅全局可见的记录不授予本人知识。
- `decisionContext.memories` 复制对象，防止已准备菜单的记忆被后续发言、对象改写或并发请求替换。
- 新增最终“本次理解依据”段，仅依据本次最终编号菜单中已有的 `interpret.eventId`，从该 context 的本人记忆取值，不从世界事件、他人记忆或关系证据回填原话。
- 同一事件针对不同人物的编号共用一条依据，最多五条，保持现有最后五条候选扫描不变。每条新发言原话完整呈现；无需让模型先在缺少尾句时作解释。
- 普通记忆仍按 120、菜单仍按 140 UTF-16 单元节录，截断时明确写“已省略；仅节录”；不切断 surrogate pair。菜单提示完整依据位置，正文绑定本次实际编号。
- 所有新引用用 JSON 字符串转义。换行、控制字符、方向字符、HTML/角色分隔符和反引号不能形成新行、新角色或伪菜单项；转义可还原原文。原话、语气和本人解释明确区分，不从语气计算感受或关系变化。

## 旧档与预算

旧档缺少或含无效 `speechText` 时标“原话完整记录未知”，仅展示本人已保存的 `memory.text`，最多 1024 UTF-16 单元；超长部分明确省略。未知语气不改作 neutral，也不根据文本猜测。本人记忆缺失时整体保持未知，即使全局事件还保存原话。读取不修改存档。

单个新发言最多 240、旧记录最多 1024，最多五条。GLM/Qwen/DeepSeek 原有输入硬限保持不变。若完整依据使最终序列化 JSON 超过模型字节限，仅缩短原本已节录的家庭等综合记录：用实际 UTF-8 JSON 字节计算二分保留最长前缀，并明确说明“家庭等综合记录已省略部分；本次理解依据未再裁剪”。不删除编号、原话、语气、即时状态或其它专门观察段。其它内容本身仍超限时原 `model_context_limit` 继续阻止请求。

这不是扩大历史队列：忙碌时较早未理解记录被最后五条窗口挤出，仍是后续专项。也不改变原听觉模型，包括室外 cliff 的现行边界；测试按既有实际 witness 集判断交付，覆盖远距、隔室和 observer-only 未交付。

## 离线证据

主测覆盖真实 seed 相反尾句、1/119/120/139/140/141/239/240 长度、241 拒绝、emoji 边界、多条发言与编号对应、无自动关系变更、SQLite 内存数据库重载、并发快照、旧档缺失/超限、不从全局补造、未听者、提示注入及三个模型预算。

独立反例与结论见 [独立审查](../reviews/dialogue-content.md) 和 `tests/dialogue-content-review.test.ts`。测试及构建均使用离线合成世界；不读取密钥或真实存档，不调用模型，不代表真实模型长时验收。
