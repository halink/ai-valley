# 室内外连续跟随观察

本项实现[连续跟随设计](../design/observation.md#跨室内外跟随)的客户端闭环。观察者改变自己的镜头，不发出居民行动，不改变位置、计划、知情范围、门禁、房间占用、游戏时钟或存档。

## 已接通

- 人物选框和档案的跟随入口固定同一个人物身份。镜头根据快照中实际 `inside` 切换室外和房间，不把家、计划、房间目的地或未来路径当成已经到达。
- 房间内跟随实际位置及已记录的行走进度。离开后回到人物的室外位置，并恢复进入前的室外缩放。渡船沿用现有乘客真实位置和座位偏移。切换坐标空间时清掉旧动画，不在室内坐标和谷内坐标之间飞跃。
- 拖动地图（室内外均可）、停止跟随、手动进出房间、关闭选择、返回村落、地图定位或改看其他人物/对象交还镜头控制。同一对象的档案仍可查看；重新跟随必须主动点击。
- 目标离世、离开谷内、当前记录缺失、房间消失或谷内坐标失效时立即停止，镜头保留原处并显示原因。目标重新出现或连接恢复不会擅自恢复。新世界清除旧跟随状态。
- 当前对象选框显示跟随地点、停止原因和停止按钮。人物已不在当前快照时仍保留姓名与说明，可转到年表；没有补造已被移除人物的档案。

## 旧档与边界

跟随状态只在当前观察页面内存中，没有新存档字段、迁移或后台写入。旧档只记录所在房间而没有 `rooms` / 有效 `roomAt` 时，镜头展示房间全景；同房间重新跟随或坐标精度丢失也恢复全景。既有室内样章中的人物位置保留作示意，横幅和悬停文字说明其性质，不画表示精确位置的选择圈。

室内点必须为布局范围内的有限数；插值只接受同一实际房间的有效路径点和有限进度。不因此改变原始记录或模拟路线。镇外区域旅程不在本项地图跟随范围内；历史轨迹回放、跨刷新记住镜头及截图像素验收也不包含在本项中。

## 离线验证

用已安装工具与隔离合成世界，不读取真实存档和密钥，不运行 npm，不调用模型：

```sh
node --import tsx --test tests/resident-follow.test.ts
node --import tsx --test tests/*.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.server.json
node node_modules/vite/bin/vite.js build
```

定向测试覆盖往返房间、重复操作、另一房间、真实路径进度与失效路径、室内外手动拖动、主动退出后不被拉回、改看对象、停止与重启、死亡/镇外/缺失/房间消失、观察增量与同世界重连、新世界、渡船座位、冻结世界只读、旧档全景、精度降级，以及桌面/手机/短横屏的正缩放。

场景回归转译并执行真实 `ValleyScene` 源码，以轻量绘制替身检查控制流和镜头坐标，不替代 Phaser、DOM 或真实浏览器验收。此前 Chromium 启动遇到 `socket() failed: Operation not permitted`；本轮遵守限制，没有重试或换路线绕过，未生成桌面/手机截图。独立审查见[审查记录](../reviews/resident-follow.md)。

2026-11-07 最终验证：25 项定向回归、1342 项全仓测试全部通过；类型检查、服务端编译、Vite 构建和差异空白检查通过。独立复核再次执行 25 项定向回归和类型检查，无待修复发现。Vite 仍提示单包大于 500 kB，不把构建通过视为已完成包体优化或浏览器视觉验收。
