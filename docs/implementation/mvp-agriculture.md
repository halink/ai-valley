# 三品种规则农业 v1

本批为规则驱动纵向农业闭环；不启用真实模型、谷灵、居民气候压力或资源减产。旧野食恢复底线不变。最终状态以本批冻结验证报告为准。

## 品种与精确生长

春秋芜菁：春秋可播，极限0/30℃、适温8–22℃，4有效日。夏根：夏可播，极限8/38℃、适温18–30℃，4有效日。冬根：冬可播，极限−8/20℃、适温0–10℃，6有效日。跨季已有作物继续按实际温水增长，不按许可播种季停长或死亡。每茬真实产3根、每根20营养，三套独立种子/根菜不与旧seed/turnip通兑。

温度因子Tf分母400，极限至适温线性上升、平台400、适温至极限线性下降。水因子为clamp(W−10D,0,20D)/(20D)。进度整数分子分母8000D，代表有效微分钟；目标为4或6×1440×10^6×8000D。D沿用PAW精确分母。

未成熟新作物耗水候选4 PAW/日×Tf，对应每微分钟10000×TfNum分子；旧作物耗水0。微步顺序明确为雪入→融雪→雨入→蒸发优先→作物取剩余水→排水→用该微步结尾PAW增长。成熟当微步仍取水，之后停止增长和作物耗水。这是明确的游戏参数，不宣称已证明真实农业平衡。

solver在固定天气cell内分解雪耗尽的整步/部分微步/尾段；土壤为饱和等差序列，截限水分因子之和采用整数等差求和。成熟通过单调前缀二分定位最早微分钟，之后切为无作物耗水。调用末尾、JSON存读不是新数值边界。不使用caller dt欧拉法。初始/最终水账都保存cropUse，守恒式增加减去实际cropUse。

成熟时保存原规范段maturityProof，后续段仍可核验最早成熟时刻。证明核验真实气候cell/sample/rates、品种温度因子、原起点守恒、实例/目标及前缀最早成熟offset，不能凭任意自带rates制造自洽证明。

## 版本与迁移

气候schema3/capability agriculture-v1；current.schema3/agriculture=true。土壤schema2/integrator2；新增农业schema1。三者双向依赖，缺任一或未知版本拒绝；Store防已有农业提交时删除字段降级。默认模型/生产Store拒绝任一新能力字段。

迁移保留旧气候锚点、PAW/雪/累计水账和原动作时间，增加cropUse=0，实际迁移端点结清旧前缀再开新版本段，不追算过去。全部田登记稳定需求epoch，已有旧作物登记legacy实例，不猜actionIndex或改变在途工时。旧seed/mvpSeeds/crop/turnip@1及旧物品永久保留。

旧plant完成同事务登记legacy实例；旧harvest完成同事务退役实例。新旧播种都不刷新公共需求epoch；clear也保留，只有真实harvest打开下一需求epoch。crop实例ID与需求epoch独立。外壳/registry必须双向一致，校验不会补造丢失身份或清理孤儿。

## 有限公共种源

每品种grantId为world/content-batch/kind稳定身份，不含schema。首次冻结P=真实产权且可达田数、N=拥有这些田的存活常住居民数及首次合法播种窗口，数量min(P,2N)。当前4人8田每品种8份，不硬编码8。三种库存一次发放，非播季不能领取。不会因重开、季变、扩田、人口变化再发。

grant库存/发放收据同事务；stock+实际claim数=initial。claim与collect执行receipt双向唯一，缺半边或坏数据拒绝，不补发。

领取行动冻结目标manifest，每田必须本人有权且路线可达，空田或明确确认替换原实例。按plotId排序逐份分配本人当前已持同种种子；只有未被覆盖且未领取的目标可领1份。完成时重新核验。公共无+1备用种。

claim记录保存actor/plot/epoch/cultivar，唯一锁是plot+epoch。取消、重提、换品种、播种后清田均不能刷新资格。manifest中的既领目标不因既领而被从已有种子分配中排除。claim epoch也绑定执行receipt及原typed事件，不能只改claim键重新开放。

## 自主动作、真实成本与入口

新作物通用模块处理plant15分钟、harvest10分钟、clear30分钟、collectSeed10分钟、saveSeed30分钟、cook20分钟；真实室内路线与种台/厨房竞争照旧。新Action及持久恢复严格核验操作和字段，不能依赖TS union。

清田必须本人到场、重验原实例，移除不返种、不产粮。先收成熟/先备替代种只是规则偏好，不是引擎硬门。私人留种1根→2同种种子，没有策略数量上限。烹饪2同种根+1清水→1份42营养meal。每次执行有持久ID，成功库存、实例/段、收据、原typed事件同事务；失败回滚，不在重试时另造执行身份。

浇水复用原water动作、8分钟、持久water执行ID、扣1水/+30 PAW路径。新作物要求expectedInstanceId；不受今日已浇、播季、成熟或PAW满的硬限制，重复付费可灌，超量立即排水不退款。旧在途无期望ID保留旧作物行为，但不能误浇后来替换的新作物。旧harvest明确拒绝新crop；旧日界增长跳过新crop。旧wateredDay可保留兼容记录，新生长不读取。

## 规则与观察

规则需求优先，野食/饮水/休息仍在农业前。新农业优先收成熟、用本人收成留当前轮种、合适时烹饪、仅按真实公种缺口领取、用本人种子播种、PAW低时取水灌溉。私人“每田下一轮+1备种”只是演示策略，不限制引擎。

snapshot.mvp.agriculture提供逐田新/旧/空、实例、需求epoch、品种、生长比例和温水限制原因，以及公共有限余量。全部显示数值有界；温度permille四舍五入仅为显示，不参与solver。soil schema2显示实际cropUse；Godot不从天气自行推测进度。旧雨日说明按每田是否legacy分支，不全局套给新作物。

## 验证口径

纯solver自验25,000微步对照+2,000长跨度组合；独立24,600例（含6,517成熟）对照全账、成长、最早成熟及拆分一致通过。独立动作检查使用真引擎，但其成熟前置有合成fixture，不代替自然成长。

本批自然回放另用三份明确季节初态fixture：仅设初始季节时钟并对齐资源时钟，不注入新种子、食品、生长进度或后续补给；createMvpSession实际规则推进，分别要求同一田两次真实收获及真实留种/烹饪。结果与最终源码指纹另记；不将其称为连续跨季自然冬储证明。30分钟统一冻结验收和实际浏览器画面由父批次执行。
