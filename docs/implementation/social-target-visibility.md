# 精确面对面社交对象的观察与接近

## 原问题与有限范围

合成世界中 A 与已认识的 C 位于 cliff 两侧，`canSeeOutdoorPoint` 返回 false，关系摘要正确不把 C 当作眼前人物，但 `decisionContext.people` 只用 `coLocated` 的同室与距离检查。最终编号菜单仍为 C 提供完整说话语气，并可提供当面交换。这把“过去认识 / 在附近 / 可能听见”误当成当前可见的精确对象。

本项统一通用 `talk / offer / accept` 的观察、接近和实际完工边界，并让基础 `formalOpportunities` 的 `care / propose / respond` 使用真实可见且可接近的在世对象。保留所有既有语气，不选择友好或敌对，不自动解释、移动、说话或更改关系分值。

这是有限修复，不是全部共址机制改造。临时讨论与活动的听众、`culture.invite`、借款、收养/家庭及专门照护流程仍有各自的规则，未在本项统一审计或改变。尸体证明与寻找、单方撤回或结束关系、本人历史理解、远方商行信件等独立路径不受通用面对面对象过滤。

## 三种事实分别检查

- **看见**：未离谷、在世、有效的真实位置、同一室内外空间，无船岸混用。室外仍是原十格保守 sight，实体建筑、施工、悬崖、树石及对角角点遮挡均不能穿过。室内保留原十格范围，但必须有真实 `rooms`、正确门口坐标与非缺失的合法 `roomAt`，并按真实布局使用同一保守视线走廊。不能用 `roomAt ?? entry` 补造看到的位置，也不能把两步拐弯绕家具当成穿过对角障碍的视线。
- **可接近**：说话或当面交易还要求本人认识对象、有表达能力，以及可用路线。室内沿用原产权人、登记居住者、公共空间、有效借住/租住的双方权限，并检查真实房间路径。室外检查实际路径终点与接触边；仅看见水带另一侧但无法到达，不提供精确面对面选择。
- **已接触**：`talk / offer / accept` 完成时重查当前真实 sight、近身两格物理路径及室内权限。能从远处看见不等于立刻可说话或交换；菜单形成后增墙、封路或离开，不授予完成权限。

视线透明的水或围栏不会被定义成不透明。能看见但不能接近的人仍可保留本人可见关系摘要，不能获得直接社交选项。室内关系摘要现复用十格实际 sight 和双方原有房间使用权限，只呈现本人对已认识对象的看法；身体观察和实际完成接触仍分别保留两格限制。旧版曾把关系摘要也限在两格，正常睡床与厨房链证明这会丢失同屋可见熟人的个人看法，因此在[室内关系记忆修订](indoor-relationship-memory.md)中有意调整。

## 围栏与迟到选择

`findPath(..., adjacent=true)` 在相邻时可直接返回空路径，不能据此证明隔栏接触合法。`socialApproachPath` 先验证实际终点与目标之间的边；若边不通，则沿真实门口走到观察位置的完整路径，在最后一步之前停下。没有合法路径才排除。菜单与引擎使用同一接近规则，既不隔栏交谈，也不错误删掉可绕门接近的选择。

迟到选项仍绑定菜单当时的 `observedTarget`。引擎只按保存位置找路；房间内也必须重新真实看见且可接近，才刷新 `talk / offer / accept` 的目标位置。不会因为仍在同室十格内就自动追踪已被挡住的人。完成前的真实接触复验继续阻止旧选项越权。

`interactionEligible` 与已有 `talkEligible` 只是当前决策快照字段，不写入存档，不迁移权限。手工构造的旧 context 可继续缺省这些字段；真实世界入口始终提供明确值。

## 听觉、记忆与自主性

没有修改 `emitEvent`、witness 范围或既有身份发现规则。隔 cliff 的居民仍可能按现有规则听到并记住发言；这份已收到的本人记忆仍可进入 `social.interpret`，但不因此提供说话者当前精确位置或面对面选择。未定义新的声学模型，也未把 witness 来源改称为新视觉证明。

菜单、prompt 与关系摘要只读，不改世界、计划、库存或关系。真实选择三种语气均只说本人填入的原话，关系分值保持原值；如何解释仍需另行选择。远方商行信件继续通过既有 `foreignTrade.propose` 正常编号、实际预留与寄出路径执行，不要求商人在 `people` 列表中。
