# 绘本地表：实际观察入口纵切片

## 已接入，而非独立概念页

`isometric-ground.ts` 由真实 `IsometricViewport.render` 调用，使用已经接受的观察快照、可见格范围和季节。默认页面中的 **2.5D（试用）** 入口显示这层地表；默认 2D Phaser 入口不变，室内仍使用原有真实布局绘制。此阶段是**程序化过渡美术**，不是完整绘本画稿，也不是全世界资产重构完成。

采用成熟的分层绘制方式：

1. 纯函数从真实地图生成有界地表命令，最多 40×40 格；保留 32×16、2:1 原投影。
2. 地面、岸线、局部笔触分别按色合批绘制矢量路径。相邻同色格共用填充路径，不为每个格子描边；地面留白，低细节。
3. 在实际显示相机变换下绘制地表，不把地表先降采样为 1× 像素再放大。原像素人物/建筑仍按原 nearest-neighbor 路径合成，过渡期不强行模糊它们。
4. 已排序的原对象层置于地表之上。选中身份、位置、脚底、遮挡、拖动/缩放/跟随、进入/离开房间均不改变。
5. 动画更新复用地表计划，不重新读取地图。新快照、视口或季节变化时重新生成有界计划，昼夜与对象层使用同一 darkness。

## 不伪造世界

- 河岸只来自真实的水格与非水、非桥格邻接，装饰严格落在水格内。
- 地图外或视口边缘不被解释为河岸；桥接水面不封岸。
- 微小水面笔触是静态材质，不声称流速、水深、鱼群或资源。
- 不添加花草资源、山体、通路、碰撞或对象。点选仍使用原投影和原对象命中逻辑。
- 季节色板为过渡表达；水格不因冬季自动变成可走冰面。

## 兼容与成本

旧像素 terrain 数据暂时保留，供已有浏览器外栅格测试、预算统计与兼容工具使用；户外浏览器实际绘制跳过旧静态地表画布。新计划额外成本上限为每格 1 个底面、4 条岸、4 个岸边笔触和 1 个水面笔触，或 3 条桥板线。当前尚未取得真实浏览器帧时/GPU数据，不能以单元测试代替性能验收。

## 验证边界

自动化覆盖邻接、桥、地图/裁剪边缘、季节、昼夜、合批、无世界修改、真实 viewport 接线、动画复用与原观察交互回归。独立 review 新增专门测试。Canvas 测试适配器记录路径调用并注入真实 painter，而不是让生产代码为测试绕过地表。

本轮验证：322/322 项 isometric 与 storybook-ui 回归通过（含 8 项独立 review 测试）；`tsc --noEmit` 通过；Vite 生产构建通过，显式 `envFile:false`，仍有现存的大包体提示；`git diff --check` 通过。

本轮不调用真实模型、不读 `.env` 或真实存档、不做长期运行验收。真实浏览器、移动端触控、GPU、抗锯齿外观和整体美术一致性尚未验收。人物、建筑、树木仍是原像素素材；后续应在相同世界入口逐批替换经验证的高清资产，不能把本地表纵切片称为完全重构。
