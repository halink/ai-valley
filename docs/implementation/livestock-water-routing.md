# 家畜有限饮水驱动与实际绕行

本项先核对既有家畜驱动，再修复一处会让渴畜无法接近已有水槽的实际寻路缺陷。没有增加水、饲料或动物，没有降低饥渴、调整产物/繁育参数，也没有用界面动画代替引擎行为。

## 已有驱动与边界

- `advancePastures` 由真实引擎推进。牧场内动物按实际昼夜和体力休息，白天从本场有限草量取食，寻找已送入槽内的水，遇到附近野兽时在场内选择远离的位置。草、水和身体状态都实际改变，不是只画“觅食”或“饮水”。移动仍沿用每15分钟最多一步。
- `advanceIndustry` 独立增加饥渴，检查健康、遮蔽和寿命，处理死亡；成年且条件满足的个体才积累产品，既有妊娠到期才产生带亲代与独立身份的幼畜。牛奶还受既有泌乳期限约束。
- 居民通过真实菜单选择喂食、送水、护送、繁育和收取。动物会喝已经送达的水，但不会替居民选择填水槽、买料、修栏或搬迁。畜舍内的身体需求仍推进，不等于有独立的室内走动或完整群体行为。
- 既有动物档案读取真实 `activity`、原因、目标、身体状态和妊娠；持久年表只涵盖已登记事件，没有完整连续轨迹。本项不改显示。

这些已有规则不等于生态已经完整。本次审查还发现，`breedAnimal` 的伴侣校验以相同 `barnId` 为同舍依据，未证明公母实际在同一位置；仅有身份归属不能证明实际接触。隔离反例中，将原公鸡记录在另一合成牧场、距母鸡7格，直接行业完成仍可建立妊娠。该繁育接触问题未在本次修复，后续需独立处理菜单、护送、执行时复验及旧妊娠边界，不能据本次饮水回归宣称繁育已完整。

后续[繁育实际同处修复](livestock-breeding-location.md)区分既有同牧场照护抽象与跨地点漏洞，补上同畜舍/同一连通牧场核验和无效首伴侣遮蔽。没有新增公母逐格接触，本文饮水阶段的历史验证范围不变。

## 可复现的饮水缺陷

原代码先求不限制牧场、也不考虑家畜占位的通用最短路，然后才检查整条路线是否留在牧场，以及下一格是否空闲。

1. 一只低体力休息的山羊占住直线路径，另一只渴羊有合法场内绕路。旧实现连续120分钟仍重复选择被占用的一格，不能喝已有水。
2. 合成弯曲牧场内存在合法路线，但全图最短路穿过场外。旧实现先得到这条短路，再将整路否决，没有寻找场内的可行替代。
3. 开始行路后出现新占位，和中途SQLite重载的反例同样失败。

修复前首批9项测试为5通过、4失败，原输出保留在忽略的 `output/livestock-water-routing/before.log`。首批反例没有模型调用、真实存档或浏览器参与。

## 修复方式

水槽搜索从一开始就把本场范围、活家畜占位和既有护送目的地预留作为可走条件，复用既有寻路的地形、围栏门、洪流和损坏设施规则。搜索目标是实际可到达的接触位置，不要求穿进被另一只动物占着的水槽格。

只有水槽本身仍在本场且可通行，实际位置距水槽不超过一格时，才按原速率扣槽水、减少口渴并登记照料时间。途中没有提前供水。水槽空、场内断路或水槽格被静态地形阻塞时不供水。下一次推进重新计算路线，没有新增路径缓存或存档字段。

草量恢复、放牧、体力、天黑休息、居民交互和躲避野兽的优先顺序不变。没有把损坏围栏修好、将动物自动送回畜舍或提高牧场容量。

## 离线验证

`tests/livestock-water-routing.test.ts` 的15项覆盖：

- 休息动物占路的实际绕行、场内弯路、完全断路、占用水槽仍可从邻格饮水、途中新增占位。
- 每分钟最多一格、每步可通行、不出本场、不重叠，接触之前不减少口渴。
- 槽水 `delivered = consumed + water`，同一分钟重入不重复扣水，SQLite内存存储重载与不中断结果一致。
- 空槽、槽在场外、静态阻断不供水；鸡、鸭、羊、山羊和牛分别消耗最后0.01份水，后续不复制。
- 复用真实地权/施工链，从最终编号菜单分别护送两只已明确为合成的成年动物、用居民本人库存填入1份水，然后观察家畜自己绕行到这份水。初始位置、低体力阻挡和高口渴属于明示合成前置，不是模型自发安排；居民库存只因本人选定送水而扣减，没有追加喂料。
