# 家庭迁居的已知年龄与本人签署

本次修改限定于 `src/world/family-relocation.ts` 的家庭迁居权限，不把出生资料异常当作幼儿，也不据此推定成年。沿用 `knownAgeYears` 的有效时间域与生日边界；不修改日期、能力、亲缘、住处或库存来“修复”存档。

## 权限与原约

- 新提议须能核实所有同行者的年龄。成年人须具有当前决定与表达能力；满六岁的孩子同样须能自主答复。未知年龄既不能建立幼儿免签，也不能授予成年监护或房主权限。
- 每步启程、复行、同行移动、供餐及逐人入住重新检查当前年龄与能力。出生资料失效后，已在同行的家庭原地暂停；尚未开始的动作拒绝完成。暂停不消耗新口粮、不搬家、不释放旧床、不自动折返。
- 幼儿接出、接送同步与取消后的返回，仅允许明确未满六岁、且原约没有要求本人独立答复、也没有本人实际签署的孩子。满六岁后暂时失能不恢复幼儿代理权限。
- 本人仍有决定与表达能力时，年龄未知不剥夺其对既有安排的拒绝或撤回。该负向行动仍核验是否为原约当事人，不授予签署、入住或监护权。
- 原约中的出生年龄豁免不是本人同意。跨六岁时，动态要求本人另外接受；若已有真实本人签署则保留，不重复要求签署。原幼儿条款下新增的真实补签同样保留本人独立参与要求；即使出生记录后来回退成可解析的三岁，也不能重新授予监护代理，失去决定或表达能力时仍暂停。本人接受入口可用于原提议、已接受安排、途中暂停或到达后尚未入住的原约，不能在仍行路时同时签署。
- 新签署只追加真实选择及事件，不修改原 `requiredSignerIds`、成员责任、协议 ID、创建时间、出发窗口或总期限。原提议必须同时满足原签署名单和当前本人要求才能变成已接受。途中暂停接受后仍维持暂停，必须由负责者再次选择按原约复行。
- 一旦满十八岁，原孩子照护角色不再成立，仍按已有规则要求重新商量。远方房主与目的地事实继续在实际接触目的地时核验，不新增远程消息或自动传送。
- 未同行但仍有当前监护关联的未知年龄人员，不会仅凭未知年龄被当作可独立留下的成人；缺少留在原处的合格监护人时阻止新迁居。

## 验证

`tests/family-relocation-unknown-age.test.ts` 只使用合成世界和内存 SQLite，涵盖：

- `null`、字段缺失、NaN、正负无穷、字符串、对象、未来或不可解析时间；最终编号菜单及直接执行均不得创建幼儿豁免。
- 原幼儿协议受损后无代理接送、出发或入住；本人负向选择仍经真实菜单、解析、提交与引擎完成。到期不延期、不重签。
- 最后一位原签署者签署前的六岁变化、已接受原约的本人补签、本人能力丧失、实际已有签署保留。
- 出发已开工、途中下一步及到期餐次前、接出孩子后、入住最后 0.25 分钟的异常重验，核对库存、位置、旧床及原约不被改写。
- 两次 SQLite runtime 重载不把 NaN→null、字段缺失或未来出生日期变成幼儿授权，不生成同意。有效 `bornAt=0` 与负小数出生时间继续允许正常幼儿流程。

部分测试以合成家庭关注目标使相关执行动作出现在正常有界编号菜单，不直接注入许可菜单，也不改变菜单轮转。原 24 项家庭迁居、小数时间与同行回归另行保留。

本说明不把全仓测试、浏览器、模型或真实长期运行视为已完成；这些检查须按最终冻结版本另行记录。既有小数时钟审查仅覆盖当时的时间窗口修复，不自动覆盖本次权限修改。
