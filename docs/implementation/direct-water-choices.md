# 饱和菜单中的有限本人饮水

本项只修复已经合法的本人饮水选项被普通菜单挤掉的问题，不开启口渴、脱水、自动饮水或健康恢复，不新增水、桶、照护权限或居民知识。

## 原问题与有限预算

原有 `waterSupply` 非控制选项统一每30游戏分钟轮换两项，并且只能占空位或替换多余目标反思。在56项普通菜单已满、没有多余反思项时，本人已有安全桶水，或附近共屋已有依法捐赠的安全水，也可能完全看不到实际饮用。

现在从已经经过原年龄、能力、交通与供水资格过滤的 `drink` / `drinkPublic` 候选中，按稳定选项身份排序，每30游戏分钟选取一项展示候选。原议程先完成，再依次使用空位、多余目标反思或最后一项可让出的一般工作位置，在原56项普通预算内保留这项饮水。候选稳定且每次仍有可用位置时，N个可饮用容器在N个连续轮换时段均可展示；不承诺在资格持续变化、所有位置均受安全保护或决定时刻跳过时段时仍有该界限。

原已选进食、休息、饥饿取粮、撤离、动物照护、有限成人在场、儿童紧急照护、遗产代管以及成对救援/照护交接回复原样保留。已经入选的停止、拒绝、撤回、通用确认与投票，以及其他供餐/救生类别也不能让位。仍由本人选择是否饮用。普通目标、一般工作等有限轮换可能少获得一个位置；本项不声称保留原菜单的每一项非紧急内容。

**安全预算例外。** 若56项均为受保护的安全/控制项，没有空位、多余反思或可让出的一般位置，本轮不强插饮水。原供水两项如果均为本人协助授权、协助饮用或监护幼儿供水，也保留这两项，不挤掉照护、不加第三项供水。不会为保证自饮而隐藏已经出现的撤回或扩大菜单上限。这是明确保留的安全边界，不宣称任意饱和条件下都有自饮选项。

本人饮水与其他非控制供水合计仍最多两项。原两项供水轮换先按原顺序完成，使用原空位/多余反思规则；之后自饮可替换已入选的非照护供水，或在尚未占满两项供水时使用非安全一般位置。已经入选的本人协助授权、协助饮用和监护幼儿供水不让位。没有扩大56项普通菜单、既有独立水源补充预算或最终菜单的其他补充预算。原即时停止和护送拒绝的独立恢复机制不变。若没有合法本人饮水候选，原供水轮换保持不变。

## 执行与保存边界

- 只提取已经存在的候选，不因知道泉水地址或携带旧生产清水就创造直接饮水动作，不读取远方水量。
- 空桶、原水、他人桶、未捐赠公共桶、缺少一整份安全水、滚动24小时额度用尽仍不提供本人饮水。
- 幼儿、失去相应自主能力、运输/同行或只能表达撤回的菜单不通过本项恢复饮水。
- 菜单不是工位或物资预留。共屋桌台被占、未完成的本人安排、后来水量/归属/场所权限改变，仍由原引擎拒绝，不抢占劳动、不扣水、不产生完成回执。
- 没有新持久字段或数据迁移。原回执防重、滚动额度和现有JSON/SQLite语义不变。

## 离线回归

`tests/direct-water-choices.test.ts` 使用合成世界和内存SQLite。先在原实现运行新增六组测试，五组因合法自饮未进入饱和菜单失败，非法来源/额度组通过；修复后补足十一组测试，覆盖全部关注方向和多个轮换时段、56项预算、本人/公共饮水、关键照护与停止、多桶稳定轮换、无合法水、年龄/能力/交通限制、额度、本人安排锁、公共桌台竞争、变化后的执行拒绝与重载防重，以及全安全项饱和时不强插饮水。

独立审查发现初版提前占位会把原本可见的 `revokeAssist` 挤掉，实际编号菜单也能复现；该版本不交付。修正后改为原议程先完成，再只替换非安全位置。独立红灯反例保留在 `tests/direct-water-choices-review.test.ts`，不放宽撤回必须保留的断言。

全仓检查随后发现，将其余供水改成单项轮换会使既有灾害联合链的 `assistDrink` 无法及时展示。未改旧灾害测试；最终修正保留原两项供水轮换，再补本人自饮，保护原已选供水照护。独立补充两项照护预算红灯也保留原预期转绿，原灾害联合四项回归全部通过。

这些是菜单与既有执行规则验证，不代表居民会自主选择饮水、九人长期供水或完整四季验收。口渴与脱水仍按[安全水供给阶段](safe-water-supply.md)保持关闭。
