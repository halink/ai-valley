# 普通浇水事件与记忆的真实作物名称

## 问题与最小修复

普通 `water` 完成分支原来始终记录“为田里的芜菁浇了水”，即使田地实际种的是 `crop/flax@1`。`emitEvent` 又把同一文案复制给本人及实际见证者，因此最终决策记忆也会重复错误品种。

现在只在成功完成浇水时，读取该田地当前 `crop.definition` 对应定义的 `data.name`。有效非空字符串去除两端空白后用于中文事件，亚麻当前登记的显示名称为“纤维作物”。不使用行动的默认芜菁依赖、最新活动定义、产出物品或 ID 猜测品种，也不把整份定义、精确生长值、季节、产量等资料写入事件或记忆。

定义缺失、名称缺失、空白或非字符串时统一写“作物”。旧版 `crop/turnip@1` 没有显示名称，同样保守回退；不补写定义或迁移历史。旧事件与旧记忆保持原样，新事件沿用原 `emitEvent` 见证范围。

## 不变边界

- 使用权、到场位置、实际有作物和本人清水仍由原执行逻辑核查。
- 实际成功仍只耗一份水，设置当前绝对日；工时、生长、产量、种子、技能和其他资源规则不变。
- 不自动选择、浇水或供应水；不新加同日去重。同日再次明确选择仍按原规则再次耗水。
- 名称在完成时读取，不缓存开始时的品种。已有计划及合成旧档不需要新字段。
- 本次不调整播种、烹饪或其他生产文字，也不修复未知定义在其他模拟阶段的既有行为。
