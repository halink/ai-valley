# 永久收养：未知年龄不构成幼儿豁免

## 问题与范围

`ageYears` 为兼容已有连续年龄显示及成年拒绝门槛，在出生资料为 null、NaN、未来时间等情形返回 0。旧收养流程同时用这个 0 判断「未成年」和「不满六岁」，因此可以在仅有监护人签署时登记永久收养。

本修复只收紧收养流程的资格与证据判断，不修补出生时间，不生成同意，不撤销已经登记的亲缘关系。复用 `time.ts` 的 `knownAgeYears`；该函数在日期不合法、不可解析或仍属未来时返回 null。

## 执行规则

- 新提议必须能核实孩子未成年、收养人成年及现有监护人成年，其余相识、实际在场、亲缘和死亡证据规则不变。
- 待签提议中的孩子或收养人年龄未知时，不新增肯定签署或登记。监护人本人的新肯定签署也必须能核实其成年资格。
- 只有能核实孩子不满六岁，才适用原来的幼儿本人签署豁免。六岁至成年前仍需孩子目前可决定、可表达且有实际本人签署；十八岁及以上仍不能被当作孩子收养。
- 读取本人同意时检查有限的签署时点、原提议起止范围、当前时点及同一孩子的匹配签署条目，还须核实签署时已满六岁、未满十八岁。引用事件的时点必须与签署时点一致，且是孩子本人发起、涉及该收养人的关系事件。缺失、NaN、未来、六岁前、事件缺失或错指其他当事人的旧字段不算同意；不会在读取时改写、补造或清理原记录。合法原签名保留，年龄恢复后无需重签。
- 原当事人有能力时仍可拒绝或撤回。年龄未知不增加代理权，也不封锁负向选择；本人、监护人和收养人仍须符合各自原有身份、能力和在场条件。共同年龄菜单在幼儿早退之前保留这些不授予权利的入口。
- 原提议因年龄未知而停用时保留其 ID、签署、理由、状态和期限。`advanceAdoption` 不把「无法核实未成年」混同为「已经成年」。原期限届满、实际死亡、离开或恢复资料证明已成年时仍按原规则失效。

## 工时与中途变化

原提议和答复仍需 5 游戏分钟，登记仍需本人走到已知公共会馆门外并处理 15 游戏分钟。`engine.processActivity` 每步重验 `adoptionReason`；出生资料在途中或最后 0.25 分钟失效时，当前活动失败，不再移动、签署或登记。

年龄恢复不会自动重启已失败的活动。居民须重新作出选择；未过期原提议与合法历史签署继续使用。拒绝或撤回已经结束的提议，不会被旧编号动作、恢复年龄或后台推进复活。

签署字段和事件时点交叉核验，也防止一个被改成未来的签署时间仅凭时钟推进就自动成为有效同意。原有 `store.referencedFacts` 已将收养签署事件列为持久引用，工作历史裁剪及 SQLite `loadForRuntime` 都保留它们；短记忆被挤出不影响真实签署。缺失的历史事实不会自动补造，本人仍可在原提议内重新选择同意或拒绝。

## 离线验证

`tests/unknown-age-adoption.test.ts` 通过真实 `decisionContext → decisionChoices → parseChoice → submitPlan → stepWorld` 验证提议、签署、拒绝、撤回和登记，另以直接调用交叉检查执行守卫。

覆盖范围：

- null、NaN、未来出生时间，以及缺失、字符串、无穷和不安全数字的新提议拒绝。
- 原幼儿提议保留、真实六岁能力恢复、本人另行签署后登记；合法历史本人签名恢复后继续有效。
- 提议、监护人答复、孩子本人答复、登记末 0.25 分钟资料失效；登记途中立即中断，恢复不自动继续。
- 本人、监护人、收养人的拒绝或退出；未知年龄时登记与拒绝同时完成的两种居民处理顺序。
- 仅合成 `WorldStore(':memory:')` 保存与重载，明确 NaN 经 JSON 编码为 null，未来时间原值保留。重载后不变幼儿豁免、不伪造本人签署。
- 2、6、9、17、18 岁原规则，原期限到期，已登记历史保留，无重复永久亲缘与登记事件。

局部命令：

```sh
node --import tsx --test tests/unknown-age-adoption.test.ts tests/adoption.test.ts
node --import tsx --test tests/unknown-age-adoption.test.ts tests/unknown-age-adoption-review.test.ts tests/adoption.test.ts
```
