# 监护交接：跨六岁生日的本人选择

## 原因与边界

原 `fosterChild` 把未满六岁的 `guardianOffer.childApproved` 初始化为 `true`。孩子在一日有效期内过六岁生日后，这个年龄豁免仍会隐藏本人同意菜单，并让现监护人单独接受即可增加永久监护人。

现在年龄豁免与本人实际选择分开。新提议使用 `childApproved=false`、`childApprovedAt=null`，未满六岁时仍可依原监护交接规则完成；一旦当前年龄达到六岁，须本人有决定和表达能力，并另行完成该提议的独立同意。生日、沉默、他人签署和能力恢复都不代填本人选择。十八岁以后直接拒绝旧监护代理，无需等待生命周期清空历史列表。

本修复只影响尚未完成的 `fosterChild` 交接，不撤销生日以前已合法完成的监护，不扩展救急照护权限，也不改变收养的各方签署和实际登记流程。原身份、出生亲缘、住处、财物及 `refusesCare` 保持各自含义；监护交接不是搬家、收养或一次喂养。

## 实现

- `world/guardian-consent.ts` 提供纯读取门禁。菜单和实际完成都按当前年龄检查，不依赖 `advanceLife` 是否先执行，也不因读取菜单而写入签名或修改期限。
- 新提议记录原 `createdAt`、一日 `expiresAt` 和提议事件 `id`。仅孩子本人实际完成同意后才写入 `childApprovedAt`；现监护人的选择只设置 `guardianApproved`。
- 时间证据须有限，不能早于原提议或六岁生日，不能在未来或原到期时点之后；明确 `false`、`null`、缺失或不一致的新证据都不能授权交接。
- 完成时复查现监护人仍有资格，现监护人及志愿者均为有能力、在场的成年人，志愿者尚未成为监护人。孩子满六岁但当前缺决定或表达能力时，交接保守暂停，不替其表态，也不落新的监护人接受。已有孩子签署不被删除，恢复后仍须另一当事人实际选择。
- 孩子先签与监护人先签均可。当前有能力的孩子保留原提议的同意与拒绝入口；现监护人也可拒绝。拒绝按原规则删除该待交接提议，迟到动作不能恢复它。原一日期限保持，不能因生日、暂停、恢复、读取或重载而续期。
- 最终编号菜单的 `familyConsent.offerId` 绑定具体提议；模型不能另填该字段。拒绝后同一分钟重新提议也使用不同事件 ID，旧选择不能签署新提议。旧存档中无绑定的排队动作保守失败，需要重新选择；已有本人同意与原期限不因此失效。

## 旧档连续性

旧写入路径固定 `expiresAt = 创建时刻 + DAY`，因此仅对 `id`、`createdAt`、`childApprovedAt` 均不存在的旧格式，用 `expiresAt - DAY` 判断提议当时的年龄：

- 原提议时不足六岁：旧 `childApproved=true` 是默认豁免，不算本人同意。原字段保持原样，满六岁后本人同意菜单重新可用。
- 原提议时已经六岁：旧 `childApproved=true` 只能由本人完成接受形成，因此保留这项可证明的旧选择。确切签署时间仍未知，不把提议时间伪写为签署时间。
- 部分新字段缺失不能触发上述旧格式规则；新本人接受会在原提议上写入真实完成时间。
- 不修改已有事件、不生成迁移同意事件、不重建已拒绝提议，也不凭历史监护列表取得成年人的代理权。这不是任意手工篡改存档的密码学真实性保证。
