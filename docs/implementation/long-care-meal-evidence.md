# 长期照护实际供餐证据

## 实际行为与覆盖范围

本切片只记录成功完成的 `longCare.visit`，沿用默认关闭的食物证据入口，独立字段为 `longCareMeals`。提出、接受、孩子同意、开启分支、观察、通知、交接、撤回以及失败到访均不是供餐。普通 `care`、监护人 `tendChild`、`emergencyCare`、运输、腐败和其他消费不并入此切片，不能据此宣称完整食物或健康账本。

既有引擎实际从照护者 `person:<providerId>` 的个人库存扣除已签约 `agreement.rules.materials`，不是公共库、家庭库、受助者库存或安全水桶。到访完成前仍检查当前约定、签署/同意、表达与行动能力、窗口、真实到场和物资。成功后才登记该约定窗口、实际支付，并产生原有照护事件。新增观测不改这些规则，也不增加动作、锁定库存或自动安排照护。

每条证据包含实际提供者和受助者、个人来源容器、实际事件与计划ID、已签约定义、agreementId、slotKey、实际扣减数量和可知原批次，以及受助者的即时饥饿前后/缓解和健康前后/增益。完成时使用已签约规则，即使当前版本已换配方也不改约。营养读取完成前原食品批次；缺失定义或批次数量不足保持 `null`，不由饥饿变化反算。

长期照护并不是普通 care 的固定22缓解或 tendChild 的固定48缓解。它使用既有 `foodValue` 对签约物资计算效果，饥饿下限0；健康增加已签约 `healthGain`，上限100。原定义缺失时模拟本来就有食品值回退，但证据仍保留营养未知。例：两段原批次共25营养，低饥饿时实际缓解可能只有4；99健康按3点增益规则实际只增加1。健康增益不是食物营养，也不代表毛伤害、治疗总量或全天净变化。同一步代谢不属于该次供餐即时效果。

## 隔离、提交与未知

捕获只关联同一 World 对象的一次同步引擎调用，使用 WeakMap，`finally` 清理。它不进入世界、知识、决策上下文或存档；预测副本不被原世界捕获。启用与关闭观测的世界完整深比较相同。捕获不是回滚器，抛错不会返回成功观察，但物理回滚仍由现有草稿与存储事务负责。

运行时继续只在 `WorldStore.commit` 成功且安装已提交世界后发布 `food_step_committed`。草稿已完成供餐但 durable commit 失败时，不发布记录，已提交库存/访问/支付不变；恢复后只发布一次真实完成。观察输出经过白名单验证、独立复制和递归冻结。观察器或 writer 失败不撤销已提交模拟，但证据完整总量不再成立。

schema-1 旧记录可以没有 `longCareMeals`，缺字段表示未知，显式 `[]` 才表示已观测零次。零步会话、缺边界、漏步、失败关闭、丢失封存或损坏均不能产生完整新增总量；原有其他切片保持独立。隔离逐日输出保留原始 receipt、已观测/未观测分钟和可用总量，当日出现缺测后，后续观测零不能修复完整性。时点归属采用 `(fromMinute,toMinute]`，午夜完成归刚结束的一天；不补造未观测日期。

严格 writer 不接受额外文本、访问器、符号字段、数组空洞、非有限数或不合白名单的身份/定义。审核核对实际来源身份、互异当事人、正数且不重复的物资、原批次数量/时间/营养、饥饿和健康边界与差值、事件时点和跨切片重复事件。相同 `(agreementId,slotKey)` 在整个会话只能完成一次，即使事件ID不同也不能重复计量。签约配方可变，所以不会强加固定1餐食1清水或固定健康增益。独立审核器不连接世界数据库重建合同，也不是对任意输入真实性的签名；原约定与实际支付/事件的一致性由真实引擎完成测试核对。
