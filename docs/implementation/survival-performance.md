# 生存预测性能验收

本项优化对应[限时生存保护](../design/recovery.md#当前实现边界)，只减少只读预测的复制成本，不改变保护资格、持续时间、居民自主选择或世界推进规则。它不是第一批设计的整体验收，也不替代正式模型下的长期观察。

## 实现

CPU 采样发现，九人同时饥饿和耗竭时，主要成本是反复序列化完整地图。正式地图包含 307,200 格，地形值都是原始字符串。

[预测副本](../../src/world/simulation-copy.ts)对地形数组使用 `slice()`，其余对象图仍一次 `structuredClone()`。每个副本拥有独立、可变的地形数组，不与真实世界共用数组。地图坐标与活动目标等共享坐标引用仍一起深复制；外置已提交收据保留只读查询，预测产生的新收据只写入副本。

引擎的自救预测和首动作校验使用该副本。没有跨 tick 缓存，没有放宽权限、库存、保质期、路径或工位检查，也没有冻结其他居民已承诺的活动。完整预测依旧按一游戏分钟推进世界。

## 复现命令

在仓库根目录安装现有依赖后运行：

```sh
node --import tsx scripts/benchmark-survival.mjs
node --import tsx --test tests/survival-performance.test.ts tests/decision-protection.test.ts
```

基准默认预热 2 次，记录 7 次连续 tick；可传入样本数（3–20）和预热次数（1–10），例如 `node --import tsx scripts/benchmark-survival.mjs 10 3`。请串行运行，不要与构建、测试或其他基准并行。JSON 输出包括环境、每种场景的完整 tick、菜单生成、普通复制和优化复制耗时，以及保护人数。每次 tick 推进 1.2 游戏分钟，并通过真实 `decisionContext` / `decisionChoices` 生成正常菜单。

所有世界都由固定种子 5401 在内存新建，保留正式地图、九位居民和实际房间规则。不读取 `.env`、现有存档或模型凭据，不联网，不调用真实模型，也不产生持久存档。

## 受控场景

- **随身餐食**：九人饥饿 98、健康 2.7、体力 80，每人持有 3 份真实餐食。
- **饥饿和耗竭**：九人饥饿 98、健康 3.6、体力 1，每人持有 3 份餐食，必须实际进食并获得休息才消除两类损失。
- **无可用食源**：九人背包为空，并显式清空可收集动物产品、果实、温室作物与鱼群存量。只清空背包不够，创始居民原本拥有可以收取鸡蛋的动物。
- **服务者留岗／离岗**：一位濒危居民在真实公共厨房餐桌旁，另一位具备真实材料且已到岗；后者分别已有留岗或一分钟后离开的计划。预测必须推进该计划，不能假定服务者原地不动。

所有场景移除无关田地、野外资源和灾害，以隔离预测成本；服务场景也移除上述独立食源。基准首先断言菜单救援资格，随后断言保护人数分别为 9、9、0、1、0。无保护基线使用同一初始世界，但不启用保护回调，其健康轨迹会不同，不能当成等价的优化方案。

## 本地对照结果

2026-11-06，Linux x64、Node 24.22.1、AMD EPYC 9V74，环境报告可用并行度 9。两种实现串行运行同一脚本，预热 2 次、采样 7 次。旧实现放在独立临时源码副本中，仅将 `copyForSimulation` 恢复为原先的完整 `structuredClone(world)` 和收据继承；没有改动共享工作区中的实现来计时。

单位：毫秒。样本少，P95 即该组最大值，不能视为延迟保证。

| 场景 | 旧复制，中位数 | 优化后，中位数 | 旧复制，P95 | 优化后，P95 |
| --- | ---: | ---: | ---: | ---: |
| 随身餐食 | 180.08 | 50.05 | 240.42 | 65.95 |
| 饥饿和耗竭 | 964.03 | 196.46 | 1054.18 | 211.67 |
| 无可用食源 | 65.35 | 56.10 | 95.54 | 106.42 |
| 服务者留岗 | 229.23 | 62.26 | 239.24 | 70.37 |
| 服务者离岗 | 137.12 | 45.71 | 145.71 | 108.10 |

复合危急场景的 tick 中位数减少约 80%；单次副本复制中位数从 38.43 毫秒降到 2.05 毫秒。无可用食源本来主要走保守的快速否定路径，少量耗时波动不表示优化收益。此前审计中的“无粮”场景没有清除鸡蛋等独立食源，与这里的严格无食源场景不同，不能直接比较数值。

同日独立审核复验同一九人饥饿和耗竭场景，中位约 196 毫秒、最高约 203 毫秒。该复验是另一轮测量，不替换上表原对照样本，也不将小样本最大值视作服务延迟上限。

## 正确性与剩余边界

新增回归（历史路径：`../../tests/survival-performance.test.ts`，已移除）覆盖副本数据相等、双向隔离所需的独立地形与嵌套状态、跨地图坐标引用、已提交与待提交收据、五种真实菜单场景，以及普通深复制和优化副本执行进食休息、食物变质、服务者留岗和离岗后的完整世界状态一致。测试还确定地检查大型地形没有进入 `structuredClone`，不使用容易受机器负载影响的毫秒阈值。

原有保护回归（历史路径：`../../tests/decision-protection.test.ts`，已移除）仍验证购买取回、变质、断路、其他人离岗、过期回复、工位占用、实际伤害、到期、重启和全镇停表恢复。新增 13 项加原有 25 项，共 38 项通过。

这里测量的是同步 `stepWorld` 加正常菜单生成，不包括网络模型延迟、数据库提交、快照传输、浏览器绘制或整个运行服务的端到端延迟。完整预测仍随候选数量、世界状态大小和预测步数增加；大人口、复杂竞争、灾害与长期存档的最坏耗时还未验收。不得把这组九人受控测量描述为所有情况下都低于一秒。
