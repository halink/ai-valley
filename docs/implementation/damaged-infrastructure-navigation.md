# 损坏桥码头离开后的禁止重入寻路

## 证据与范围

本项修复一个独立的生产代码缺陷，不调整饥饿、健康、资源再生、菜单策略或赠食规则。

原 `walkable` 允许已经站在损坏桥或码头上的人沿设施离开，但禁止从外部重新进入。`findPath` 与 `reachableTilesFrom` 为了允许离开，会把起点所在的整座损坏设施排除出静态障碍索引；此前只对洪水逐边核验，不对损坏设施逐边核验。因此寻路可能先离开坏桥走较快的道路，再从另一端重上坏桥，实际执行却在重入时失败。

隔离反例使用 `infrastructureFootprint` 真正支持的 18 格直桥，不依赖不受支持的 U 形设施。居民起点在桥上，桥侧有较快的道路岔路，另一岸有本人记得的浆果地点：

- 原路径从 `(3,4)` 下桥，沿道路到 `(19,5)`，再试图进入坏桥 `(19,4)`。没有中途地形变化，执行仍报“原路线出现阻挡，需要重新决定”。
- 原桥上一直存在合法的 18 步离桥路线。修复后走这条路线到 `(21,4)`，不自动采集或进食。
- 在坏桥中段另有活动洪水时，道路绕行也不能授予重新上桥的权利；无合法通路就应返回不可达，而不是先给出必败路径。

原始反例与红绿回归保存在被忽略的 `output/resident-survival-water-review/`。初次新增测试里还有一个测试夹具错误：准备在上桥前破坏设施，却已让居民走上桥；随后把起点后移一格、明确验证仍在岸上，保留初次失败，再取得修复前 **3 项失败、2 项通过**的有效红灯记录。没有删除或改写失败日志。

这不是历史默认九人饥饿的已证实原因。另行精确回放旧 v5 前 1,300 分钟，匹配 299 次选择、290 次完成及完整检查点，前两次野猪撤退失败确实来自野猪移动后的危险边界改变。旧十五日赠食可见性候选仍有苏葵健康 43.872、饥饿 88.334 的终点风险；本项不把旧失败改写为成功，不采用实验 v5 为默认。

还用只读 SQLite 核对该旧合成运行的第 22,080 分钟终点：登记的基础设施资产为 **0**，完整选择轨迹的施工选择也是 **0**。因此不能把本次坏桥修复说成改善了这次历史九人结果；它补齐的是今后存在损坏桥/码头时，实际离开与食源访问可能被错误寻路阻断的缺口。

## 实现

[`src/world/navigation.ts`](../../src/world/navigation.ts) 将活动洪水与未退役、耐久已归零的桥/码头分别编成禁止外部进入的格集合。A* 与起点连通性扫描都用当前边的起点和终点核验：终点在某一受限区域内时，起点必须也在同一个区域内。

保持以下边界：

- 不合并重叠区域，不把处于一座设施内解释成可以进入另一座设施。
- 健康设施、已退役设施、道路和墓园不因本规则新增阻断；道路的原速度权重和有步数上限的搜索保持原义。
- 不改变现场执行的 `walkable`，也不自动改写旧存档中的在途路径。行动期间再次损坏或出现新危险，仍应在真实位置停止，等待本人重新决定。
- 查询只读，不补物资、不移动居民、不新增记忆、计划、权限、暂停或保护时间。

## 副作用与未验收项

无效的“快捷路”会变成较长的合法路线，或变成明确不可达。修复前到失败点的耗时不能与修复后到终点的耗时当作同一成功任务比较；新路线仍真实消耗时间、体力和饥饿，并不保证危急居民一定撑到食品处。

每次搜索增加损坏设施格集合的编制与逐边检查，未做大量损坏设施下的最坏性能验收。没有重跑十五日、完整四季、真实模型或浏览器视觉验收；不能据此宣称默认村落长期生存问题已经解决。
