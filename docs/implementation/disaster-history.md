# 同一灾害的持久事件链

观察者现在可以从野外天气面板的预警/发生灾害、最近十二场已消退灾害、带原灾害编号的泉水，以及山谷年表的任一结构化灾害记录，打开这次灾害的留存事件链。近期列表只是入口，不是完整历史；没有进入这些短列表的旧事件仍可从持久年表查阅。

## 身份与证据边界

- 仅使用原事件的 `hazardFact.disasterId` 精确关联，不依赖相邻日期、相同地点、文字提及或当前受损设施。没有编号的旧记录不会回填归因。
- 可展示原来已经留存的预警、发生、消退、实际损害、伤害、撤离、进入遮蔽与修护。事件种类不限 `hazard`，例如 `care` 类实际抱送撤险也可进入同一档案。
- 每条保留原日期、原文、阶段、原对象编号，以及实际记录的前后值。只记录一侧的数值明确显示另一侧未知，零值不会当作缺失。单位与数值含义以原文为准，不把不同指标相加成总损失。
- 缺失阶段不等于未发生，也不代表零损害、全员安全或全部修复。当前灾害快照与历史原文分开，快照缺失时显示当前状态未知；读取不会重建灾害、修改居民记忆或开启天气调度。

## 只读接口与存储

沿用 `/ai-town/api/history/page?disaster=<编码后的原编号>`，服务器只查询当前运行世界。该参数映射为 `HistoryQuery.disasterId`，必须是非空字符串、最多180字符，不允许重复参数；没有灾害筛选时行为不变。既有 GET/HEAD、拒绝写入方法及 no-store 响应策略不变，没有新增模拟控制权限。

查询要求 JSON 字段是字符串并精确相等，仍可与人物、动物、类别、原文和日期范围相交。`event_disaster` 表达式索引覆盖世界及原灾害编号，依托 SQLite 的行序进行有界分页；不将完整年表加载到客户端。索引建立只读取既有 JSON，不改事件原文，也不将无编号旧事件当成某次灾害。普通提交事务失败时，新事件与其索引一并回滚。

分页沿用入账行序倒序，不按 `at` 排序。因此同分钟的记录不会跳漏，回补的较早日期仍按真实入账顺序出现。默认每页60条，最多100条，额外读取一条判断后页。游标绑定世界与全部筛选，包括精确灾害编号；更换灾害、世界或筛选不能复用。未使用灾害参数的旧普通、供水及动物游标保持兼容。

历史不依赖工作快照最近180条或当前灾害对象是否仍存在。合成重启测试在137条同灾害事件后追加210条无关记录，裁掉工作窗口并移除当前灾害状态，依然能逐页读取原来的完整137条。

## 阅读行为

复用 `HistoryReader` 和 `PanelPositions`，每次灾害选择拥有独立视图身份。同一选择重复点击不重复查询，离开后返回仍保留当前页和阅读位置。更换灾害后不接收旧请求的晚响应。

新 observer 记录只有精确匹配当前灾害及筛选时才提示“有新记录”，不会自动插入、换页、发请求或滚到顶部。手动“回到最新”成功后才换页并重置位置；失败保留原页和位置，明确重试。翻页、筛选、关闭再开以及晚响应均走既有保护机制。灾害筛选不会隐式锁成 `hazard` 类，也不显示不相关的“只看供水快照”复选框。
