# MVP PAW 水账 v1

## 范围与升级

本片将规则小世界的气候能力升级为 `mvpClimate.schemaVersion=2 / capability=soil-water-v1`。天气算法仍是 v1，current 改为 schemaVersion=2、soilWater=true，不再带 observationOnly。新增 `mvpSoil` schemaVersion=1、integratorVersion=1。旧 observation-only v1 可读，规则启动会一次迁移至 v2；旧二进制不应降级解释新档。

只做土壤水/雪水与观察，不让旧作物读取 PAW，不新增作物耗水、居民压力、资源倍率、模型调用或雨事件账。日照仍不参与耗水。气候影响水账，因此本片不再宣称气候“仅观察”；旧田农业仍双轨旧机制。

所有已有田（含空田、旧在途灌溉的田）一次初始化 PAW=50、雪水=0，从实际 adoptedMinute/adoptedUs 开始积分，**不从该格左端补算迁移前天气**。气候原采用锚点不重写，土壤采用不得早于气候。重复采用不重置水量，播种/收获不重置。当前地图新增/删除田须另有明确迁移，不能通过缺字段默认补50。

## 冻结候选参数与精确单位

这些是游戏数值候选，不是真实毫米，也未经农产/生存平衡验证。PAW 0–100，雪以同种游戏水单位保存。

令 U=1,000,000 微分钟/分钟，D=1440×U×1,000,000=1,440,000,000,000,000。所有水量保存非负规范十进制整数分子 N，真实游戏量为 N/D；JSON 不编码 BigInt。中间无浮点舍入。

气候采样的整数 P=降水 permille、RH=相对湿度 permille、W=风强度 permille、T=0.1℃。每微分钟的整数分子速率：

- L=clamp(50T,0,1000)
- rain=120×P×L
- snow=120×P×(1000−L)
- meltPotential=120000×clamp(T,0,300)
- evaporationPotential=6×(1000−RH)×(1000+W)

对应峰值降水120 PAW/日；融雪在10℃为12/日、上限36/日；蒸发6×(1−RH)×(1+W)/日。融雪和蒸发均受实际库存限制。一次完成灌溉+30，不再次扣水。作物耗水固定0。参数精确字符串与 SHA-256 在 mvp-soil.ts 冻结，改变需新版本。

## 规范段与数值法

绝对格为50,000微分钟（0.05分钟），与绝对0对齐。网格及确定性热分量切点组成天气 cell：降水区间起止、20分钟斜坡、60分钟槽和日/季边界均格对齐；季温/昼夜/槽扰动的温度量化变化可能落格内，通过各个单调分量的首变化点二分找到，不能假定三者之和单调。每个cell左端用 climateAtUs 直接采样精确微分钟，不转回 Number。

气候连续变动在cell内以左端冻结率求积，是明确的游戏数值近似，不是连续天气解析积分。格内真实灌溉事件重开土壤状态段，但保持该cell的sampleUs和速率；调用末尾/存档不是采样点。阈值也不重新采样天气。

每田保存 segment.startUs、endUs、gridUs、sampleUs、cellEndUs、起点完整水账及冻结率；current是从同一段起点求到endUs的前缀。再次推进从原起点算，不从显示值累计。段结束才用完整结果开下一段。所有小数余量都在整数分子中，不丢余数。

语义参考是每一微分钟：降雪入雪 → 受库存限制融雪 → 雨与融水入土 → 受库存限制实际蒸发 → 超100排水。solver并非逐微分钟循环，而是其精确闭式分阶段实现：

1. 雪输入≥融雪潜力时持续满额融雪；否则分完整融雪前缀、至多一个部分融雪微步、输入受限尾段。
2. 每阶段实际融雪恒定，土壤净率恒定。正净率在最早容量微步后进入溢流；负净率在最早耗尽微步后仅蒸发实际输入。
3. 精确累计每阶段雨入、雪入、融雪、实际蒸发、排水，再拼接。不能把雪耗尽前后的不同入水平均后粗步clip。

容量/耗尽是内部解析切段，不因外部调用截断改变；边界持续向外使用受限稳定模式，不生成零长循环。该实现须以小范围逐微分钟参考逐项差分验证。未来新作物水分阈值/耗水尚未实现，不能由本片推定其数值器已经成立。

## 灌溉事件与事务

旧引擎真实动作完成时刻仍为 world.minute，不擅自移到理论 remaining 归零分数时刻。每个旧子步先结算 [previous,t)，再按原 residents/processActivity 顺序执行 t 的动作。水作用于 t 之后。同刻多次灌溉各自扣自己的1份水，超容量立即排水，不让未来蒸发抹掉溢流。

Activity 原无 actionIndex，且 plan.actions 会shift。不能用剩余数组下标或新展示事件编号推断执行身份。本片在新 water Activity 创建时从持久 nextWaterExecutionSeq 分配 mvpWaterExecutionId；首次迁移为真实旧在途 water 一次登记身份，不改动作/剩余时间。计数器上限10^18，规范字符串，耗尽拒绝。已经采用的活动缺身份、重复身份、仍active却已有收据都拒绝；完成时不补身份。

成功前验证身份/plot/actor/未结收据，之后既有扣水、wateredDay、PAW+30/排水、原action事件的typed soilWater事实、receipt、清除Activity在同一live draft/Store事务。事件ID只作证据链接，不能作重试主键。收据与原事件双向校验（身份、人物、田、时刻、30单位），不解析中文、不新增第二条私人知识事件。失败回滚计数器、扣料、水账、事件；试算只改副本，不写外部世界。

守恒逐田检查：

- snow = snowIn − melt
- water = initial + rainIn + melt + irrigation − evaporation − drainage
- irrigation = 30D × 该田真实执行收据数

## 兼容、关闭与显示

soil存在必须有climate v2 soil-water；climate声明该能力也必须有合法soil。未知版本、坏段/余数、错误缓存、缺田/新增田无迁移、气候缺失均拒绝。Store对已有soil拒绝新提交同时删soil+climate或降回v1。默认Store/模型入口仍拒绝气候世界，仅专用规则入口显式允许。没有提供独立关闭气候的开关；缺依赖使规则会话故障暂停且拒写，最后完整数据库保持。无法据此识别外部工具离线重写整段历史成旧档，不宣称防恶意文件篡改。

snapshot.mvp.soil 是已发布水账的只读投影：paw、snowWater、累计雨入/雪入/融雪/灌溉/蒸发/排水，显示四舍五入3位；exact保留精确分子，显示值不参与结算。Godot无需解析BigInt。前台标签是PAW可用水而非空气湿度%；旧田明确不受PAW生长约束。
