# 本人随身食品时效提示

## 缺口与范围

审计合成对照在 `createFrontierWorld(5401)` 上把本人库存设为5浆果、3根菜，二者分别提供60营养，交换其到期时间。原 `foodCoverage` 有批次信息，但最终 prompt 只保留同一个口粮总量摘要，无法据此判断本人哪种食物先到期。这里是显式改造库存的提示测试，不是原九人开局或模型自主行为证据。

本次将本人随身食品的只读时效摘要送入真实 `decisionContext → prepareModelDecision → prompt`。不替居民排序行动或选择食品，不自动进食、补充库存、改变营养规则、腐败时间或行动执行。

## 数据与知情边界

`personalFoodFreshness` 只读取当前居民的 `person:<id>` 批次和本人实际库存。实际库存是数量上限；没有持有物的残留账目不展示，零库存、非直接可食用材料不当作食品。不存在的食品账不会初始化，数量差额、非法期限、未来生产时间及前后矛盾的登记保持“时效未知”，不会按目录保质天数推算为新鲜。

原 `foodCoverage.lots` 不能直接作为新摘要来源：它可能含一处有权领取的公粮或家产，且会剔除五分钟内到期、非完整可食份数等条目。新视图完全不读这些来源，也不新增他人、公共库、商店或尚未领取赠与的时效信息。原口粮总量估算保持原有范围。

每种本人食品只保留固定大小的聚合：

- 本人实际持有份数；小数不取整冒充完整可吃的一份。
- 最早有效且尚未到期的部分：份数、绝对游戏分钟期限、合计营养。
- 其余更晚到期部分：份数与合计营养，明确后续时点未展开。
- 已到期份数及未知时效份数，分别说明，不计为新鲜。

同一时刻到期的多个批次可合并，按各自历史 `definition` 的营养累加，而不是套用当前目录值或假称每份营养相同。缺营养定义时采用现有 `foodValue` 的目录回退；负值、非有限值或溢出标记“营养未能确认”。最早部分和后续部分可能组成一次完整进食，因此展示部分的合计营养，不把它们混称为固定每份营养。营养也不等同实际饥饿下降值。

未知日期可能导致旧批次排序比较器非传递。库存上限分配沿用原顺序，摘要另行比较有效期限，确保不会把后来遇到的更早期限错列为“更晚”。没有修改引擎的批次消费顺序。

## 有界最终提示

每次最多展开8种食品，先保留当前正常菜单列出的直接 eat 食品，再按已知最早期限补入其余食品。同期限用固定物品表顺序。遗漏种数明确说明，没有声称摘要列完全部库存。每种只有一个最早到期段与一个后续聚合段；再多原始批次也不会扩大每种输出。

新段落在家庭笔记之外，三个现有模型输入配置都能收到。登记带本人ID和观察游戏分钟，身份或时点不匹配时不把旧视图当成当前事实。绝对游戏分钟与剩余游戏分钟同时给出，能区分同一天内的不同到期时刻，不用真实墙钟或容易混淆的季节日号。

提示不证明能赶上一次进食，也不替行动执行承诺成功。即使食品只余1分钟、5分钟，仍如实展示实际期限，实际腐败和执行失败由原引擎裁定。

## 阻止观察时补造批次

主回归发现原有行业菜单在附近畜舍枚举 `placeAnimal` 时会调用 `industryTarget → initializeFood`，顺带修补本人未登记的食品。这样第一次提示未知，第二次就会变成刚登记的新鲜食品，并破坏未知数据重载一致性。

因此行业菜单调用新增的只读校验标志，跳过这个观察阶段的食品/活畜初始化。实际行动校验、完成、正常世界初始化和推进仍使用原默认行为。完整初始化世界的菜单与行动不变；尚无登记身份的旧运输笼须等待原正常初始化，菜单观察不再创造身份或食品批次。这不是迁移或腐败规则变更。
