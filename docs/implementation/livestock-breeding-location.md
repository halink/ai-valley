# 家畜繁育的实际同处校验

本项修复家畜仍挂在同一 `barnId` 名下、却已经分处不同牧场、舍内外或护送途中的情况下，仍能建立新妊娠的问题。不新增动物、不补配偶、不修改年龄、饥渴、健康、孕期、容量或产品参数，也不重写已经成立的妊娠。

## 先区分已有抽象与真正缺陷

[世界设计](../design/world.md)要求健康成年、同舍、同种雌雄，由主人实际发起且预留空位；`CONTEXT.md` 同时区分牧场、畜舍和运输中的位置。原 `tests/frontier-livelihood.test.ts` 明确验证默认开局两只牧场鸡可以繁育并产生户外幼鸡。原动作只有主人绑定工时（默认30分钟），没有公畜逐格接近、配对运输或交配阶段。

因此，**“同一牧场内两只动物距离大于一格”本身不是本次判定的漏洞**。保留既有同处照护抽象，不在修bug时悄悄改成严格接触繁殖，也不宣称已经实现真实求偶、精确接触或完整生态。

确定的问题是：入口只比较 `barnId`，没有核验双方当前是否真的处于同一场所。另一个相关入口缺陷是正常菜单先截取第一只公畜，再验证资格；首只不合格时，后面实际同处且符合条件的公畜不会被提供。

## 当前规则

新妊娠仍须通过原有产权、存活、性别、年龄、健康、母体需求和容量检查，另加实际同处核验：

- 双方均在原同一可用畜舍。正常安置后的旧式记录没有 `at`，以原栏位表示在舍；这只适用于没有 `pastureId`、且 `inside` 为空或为该舍的记录。保留精确位置的室内个体须 `inside` 为原舍且外部锚点是原舍门口。
- 或双方都有实际户外坐标，位于同一个仍保留的牧场，牧场绑定原舍，两个坐标都在该场的真实范围内，两个端点本身均可通行，且场内地形、围栏门与通行限制允许一条连通路线。不能借道场外绕过把本场隔开的障碍。退役场不能作为新繁育场所；到期但仍保留在场动物的实际牧场没有被自动清空。
- 有 `carrierId` 或在途 `destinationId` 的任何一方不能建立新妊娠。登记的家舍和目的地不等于已经到场。
- 有牧场登记却丢失坐标的旧记录保持位置未知，不能凭没有 `at` 推断已经回舍。独立审查先复现了这一反例后收紧兼容条件。

这是场所及地形连通性校验，不会让公畜自动走过那条路线，也不把暂时共用场所变成逐格接触证明。既有动作开始与完成都经 `industryTarget` 重新核验当前选定的 `partnerId`；期间的世界仍在推进，最后条件不满足则失败，不自动换另一只公畜。

## 正常选择与恢复路径

每只无妊娠母畜仍最多得到一个繁育选项，按原个体顺序找到第一只真正可执行的公畜。死亡、异处或其他资格不符的首只不能遮蔽后面的合法对象。菜单标签明确“实际同在畜舍或同一连通牧场”；不额外给居民新的动物知识，也不替居民选择行动。

分处两牧场的动物可以继续通过原普通编号 `moveAnimal` 动作逐只实际接出、走路、进入同一畜舍，之后才重新获得繁育选项。没有自动搬运、瞬移、扩容或费用补贴。

## 旧档与已经成立的妊娠

不新增存档字段或迁移。原无牧场登记的隐式畜栏仍合法，不要求为它补造精确室内坐标。已有妊娠的生父和到期时间保留，之后搬场或生父死亡不撤销已经发生的孕育；原出生规则不改。本项不倒查或取消旧档里可能早于本修复成立的妊娠。

`tests/wildlife-population.test.ts` 中唯一的室内容量夹具从室外模板复制后，只清除了 `at` 却留下 `pastureId`。本次显式清除该夹具的牧场登记，使它真正表达原测试声称的在舍个体，原入场/胎儿预留容量断言完全不变。不能用保留矛盾测试前置为由，把位置未知解释为已回舍。

## 验证范围

首批14项主测试在旧实现下10失败、4通过，记录于本地忽略目录 `output/livestock-breeding-location/before.log`。最终主测试15项包含：

- 跨牧场、舍内外、场外坐标、缺失场所、护送、错误室内及被地形分割的牧场均不能建立妊娠。
- 原同牧场繁育、旧隐式栏位与明确室内表示均保留；无效首只不会藏住后续合法伴侣。
- 真实最终编号菜单选择、绑定工时、两次实际护送后恢复繁育；已选伴侣变动不自动替换。
- 最后0.25分钟之前将合成SQLite落盘、关闭重开，改动原公畜位置后由真实引擎完成复验并失败，不产生新妊娠事件。
- 已有妊娠迁场、生父死亡、重载后保留原到期时间和亲代，出生一次不重放。

主测试、独立反例和受影响产业/开拓生计/生态、野生种群、机会覆盖与牧场食品链共 **120/120通过**，包含最终13项独立测试。独立补项核对同一分钟地形、动物移动、运输、退休或畜舍失效后新菜单与已选动作都重新判断，并在80种小场地形上将本地连通扫描与有界导航逐一对照。原默认牧场鸡繁育测试未被改成“必须逐格贴近”，其户外幼畜位置与容量断言继续通过。独立审查见[审查报告](../reviews/livestock-breeding-location.md)。这不是全仓通过或长期真实模型验收。

最终TypeScript检查、服务端编译及隔离Vite内存构建通过，Vite的配置/环境文件加载显式关闭，不写入dist。仍保留既有大包提示。首次隔离构建因离线守卫包装后缺失 `realpathSync.native` 而失败；仅在本地构建包装中将该属性指回受保护的 `realpathSync`，未恢复无检查的原生入口。专门自检确认不存在的合成敏感路径及网络入口仍被拒绝，原失败日志保留，未改动生产守卫。

## 有限性能采样与成本

性能审查发现，若每个候选公畜都重新做整条场内路径搜索，同一个被隔开的母畜可能对50个候选重复搜索50次。因此一次同步、只读菜单的前筛选matcher对每只母畜复用一次场内连通集合，逐边调用原 `walkable`，不分配全图路径，也不把集合存入世界或动作。通过前筛选后的正式 `industryTarget` 资格验证仍独立重验，成功候选以及后续因其他条件失败的尝试可能增加扫描次数，不能称整个菜单每母总共只扫描一次。普通动作校验及下一次菜单即使在同一分钟，也不沿用上次结果。

基线为 `5a422b2` 的原行业菜单与目标检查，旧源码副本仅重定位导入路径，独立审查已还原比对。只测 `industryOpportunities`，每场景预热10次，再做100对交替顺序取样；断言每个合成户外个体坐标唯一、取样前后世界JSON不变，保留三份候选源码散列。单位均为每次局部调用的毫秒：
