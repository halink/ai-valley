# 前端首屏与观察面板加载

## 测量与范围

2026-11-07，在同一工作树、Node.js 与本地锁定 Vite 7.3.7 依赖下测量生产构建。比较对象是此次改动前的工作树，不是 Git HEAD。JS 行以 Vite 最小化（minify）后的文件字节数计；gzip 行使用 Node 默认参数，对各文件独立压缩后求和。不包含 CSS、地图快照、HTTP 头或浏览器缓存。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首屏静态依赖闭包 JS | 1,509,520 B | 1,421,155 B |
| 首屏 gzip | 440,956 B | 412,215 B |
| 首次打开辅助面板额外 JS | 0 B | 91,575 B |
| 辅助面板 gzip | 0 B | 31,765 B |
| 所有 JS 合计 | 1,509,520 B | 1,512,730 B |
| 所有 JS gzip 合计 | 440,956 B | 443,980 B |

首屏减少 88,365 B（5.85%），gzip 减少 28,741 B（6.52%）。这是延后非首屏代码的下载/解析，不是减少全部代码：加载完全部面板后，分块和加载状态处理使 JS 总量增加 3,210 B，独立 gzip 合计增加 3,024 B。没有浏览器计时，不声称实际首屏秒数或帧率提升。

原构建只有一个入口、没有动态入口。最大的依赖是 `phaser/dist/phaser.js`：Rollup 的压缩前 `renderedLength` 为 8,275,910 B；其次是入口代码、地图绘图、建筑、房间和场景。这是压缩前模块归因，不能与上表最小化后的文件体积直接相加或比较占比。Phaser 在首屏创建地图，不能仅为消除警告而延迟或移除。当前仍会出现默认 500 kB 分块建议警告，没有提高阈值，也没有把首屏依赖机械拆成多个静态块。

## 加载边界

- 地图、连接状态、居民名册、关系图、地点、文化、年表和历史读取错误处理仍立即可用。
- `panel-renderers.ts` 汇集粮食、经营、家庭、借贷、公共账本、雇佣、基础设施、墓园、长期照护、保障、医疗、产业、生态、图纸、教育、贸易、野外，以及人物档案的补充渲染函数。首次打开其中任一入口才下载一次。
- `main.ts` 不静态导入此模块。Vite 产物中入口只有一条指向它的动态边，HTML 不预载它。该块引用入口已有的时间、物品、公共组件等，不复制 Phaser。
- 原有渲染函数及模拟规则不改写。地图对象的简短选择卡仍同步可用；完整人物档案首次打开可能短暂显示加载提示。

`LazyModule` 合并同时发生的请求、缓存成功结果。加载失败保持错误状态，不会因每次快照更新、再次打开面板或切换居民而反复重试。用户可显式重试；若旧页面对应的哈希文件已在部署中删除，提示刷新页面获取新版本。发布时应原子切换 HTML，并保留旧哈希资源一段时间，避免仍在线的旧页面失去动态块。

加载完成只重绘当前仍打开的辅助面板，使用最新快照和人物选择。关闭面板、按 Escape、切回基础面板或人物消失都不会由旧请求重新打开旧内容。加载失败不影响地图操作、事件流接收或现有历史读取错误提示。

## 离线复现与验证

已有依赖时，不需安装包或执行 npm：

```sh
node scripts/measure-client-bundle.mjs
node node_modules/typescript/bin/tsc --noEmit
node node_modules/typescript/bin/tsc -p tsconfig.server.json
node --import tsx --test tests/lazy-module.test.ts tests/client-loading.test.ts tests/client-loading-review.test.ts tests/client-bundle.test.ts
node --import tsx --test tests/*.test.ts
```

测量脚本明确设置 `envFile:false`、`configFile:false`、`write:false`，镜像当前生产配置的 `/ai-town/` base，不读取环境文件、不写入 dist，也不启动服务或模型。脚本静默 Vite 普通日志只为输出可解析的 JSON；常规构建警告设置不变。未来若修改生产配置中的插件、分块或编译选项，应同步测量脚本与构建图测试。

本次最终验收：129 个测试文件、1411/1411 测试通过（包括新增及独立审查的 12 项），全仓类型检查、服务端编译、生产 Vite 构建及 `git diff --check` 均通过。全量测试使用空环境与仅允许本机连接的临时网络守卫，未执行多年验收脚本。生产构建仍如实报告首屏块超过 500 kB。

测试分三层：加载器状态机；真实 `main.ts` 配合 DOM、Phaser 和传输替身运行的事件/HTML状态回归；真实 Vite 生产构建图确认延迟模块不进入任何首屏静态依赖闭包或 HTML 预载。独立复核见[前端加载审查](../reviews/frontend-loading.md)。它们不替代浏览器对视觉布局、GPU 绘制、慢网和真实部署缓存的验收；此次未运行浏览器或真实存档，也没有运行模型与额外多年模拟。

后续若继续优化，应先在获准的浏览器环境测首帧、下载和解析时间，再评估 Phaser 官方构建是否有可安全裁剪的功能。没有视觉回归证据前，不替换渲染引擎或引入未经验证的定制 Phaser 构建。
