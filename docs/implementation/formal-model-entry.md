# 正式模型入口：保持关闭的发布边界与接线方案

## 本批结论

当前不能安全实现“显式配置后即可使用、且可证明不会意外收费”的真实正式入口。`main.ts` 继续只运行无模型观察服务，`siliconflow-free-only` 继续报告 `blocked`。没有增加解锁环境变量、凭据读取、真实请求、代理或替代入口，也没有复活已退休的短测入口。

这不是重复申请已有授权。授权范围、目前的官方价格、上一笔请求结果/账单、提供商是否强制拒绝收费请求、正式运行接线是否完整，是五个不同问题。既有适用授权应复用，但不能用其中一个代替另一个。历史文档与合成记录都不能核实当前账户状态。

本批只修复一个具体的正式接线缺口：`startFormalServer` 原先接受调用方任意 `providers`，随后直接交给 `ValleyRuntime` 的默认模型函数。`main.ts` 的 `providers:[]` 只是单个调用点约定，不是这个启动函数的执行约束。

现在正式启动函数在监听端口、获得存档所有权、打开 SQLite 或构造 runtime **之前**：

- 拒绝非数组或非空 providers，且不枚举条目、不读 key。
- 只接受本进程 `readProductionModelPolicy` 创建的不可变关闭状态；遗漏时补上默认 `no-model`。拷贝、JSON、伪造字段或 accessor 对象不能作为启动策略。
- 经过异步监听边界后只传入内部新建的空数组，不再读取调用方数组，避免检查后被修改。
- health 始终分开报告观察服务 `ok:true` 与模型 `ready:false`，不会因未传策略而省略模型阻断信息。

这只是防止可信代码误接线，不是防御恶意本机代码的沙箱。仍可直接构造其他低层候选；其接口不是正式启动许可。本批没有改变任何低层真实候选的权限或价格检查。

## 现有组件能证明什么

- `production-model-policy.ts`：精确单模型、默认关闭。型号名称不证明价格。
- `production-model-admission.ts`：核对授权/旧请求/价格记录的形状、摘要、范围和期限，不鉴定证据来源。任意人计算的64位摘要不是已审核的证据。
- `production-model-http.ts`：已有固定端点、无重定向/重试/回退、有界响应和派发前重验；明确 `providerBudgetEnforced:false`、实际费用未知。构造 gated candidate 并不表示生产条件满足。
- `production-model-journal.ts`：FULL intent→响应→世界提交确认、累计次数、绝对时限、未决恢复锁停。它依赖可信调用方与独占句柄，不提供跨运行目录的账户级预算所有权。
- `model-budget.ts`：一分钟请求/token 限流与保守预留，不是货币预算或提供商账单。只有能证明尚未调用的精确预留才可取消。
- `production-model-runtime.ts` / `production-model-price-runtime.ts`：真实 runtime 与 durable 世界事务、双账、排空和未发取消的**合成桥**。其中合成价格评估不能移入 live 路径；journal 的普通 checkpoint 也不接受 gated live 契约。
- price evidence/session 与 process ledger/guardian：已有合成价格期、累计片段预算、真实子进程监督、清理与只读重开检查。但价格来源标明 synthetic，存储 marker、worker 与恢复协议仍固定 synthetic；不能简单替换 transport 就声称生产接通。

此前未决真实请求的结果/账单在本批没有核实。本批没有读取真实产物，因此既不认定已经核对，也不把未知改为“没有执行”或零费用。

## 为什么零价格还不够

`spendingLimitCny:0` 是本地限制意图，不会改变提供商的计费规则。请求/token 上限能限制调用量，不能保证收费为零；15分钟内的官方免费说明也不能消除检查与实际计费之间的改价/账户适用性窗口。200、usage、赠额、余额为零、abort、SIGKILL或“客户端已经退出”均不能证明零账单。

现有代码与已查阅的仓库资料没有可验证的提供商侧零费用强制保障。因此在当前“不能意外收费”的要求下，即使补完剩余机械接线，正式入口仍必须关闭。不能改成“看上去免费就请求”，不能以一次收费后再停止来满足零支出要求。

未来可接受的保障需要先确认提供商确实支持，例如：由提供商逐请求原子执行的最高金额为零约束，或可核验、对本账户/精确端点/精确模型生效并在任何收费条件下拒绝执行的硬性免费范围。只是事后告警、延迟生效的额度限制、文档中的预算建议或本地布尔字段均不满足。这里只定义所需性质，**没有宣称 SiliconFlow 已有这些能力**。若供应商不能提供，不能在原要求下启用该正式实时方案。

## 可执行的分批方案

### 1. 先完成证据与零支出能力核实，不读 key 做探针

由可信审核方核验已有授权适用范围、旧请求原始记录与执行/账单结果、当前官方精确型号及账户适用价格，以及上述供应商硬性免费保障。原始来源与检查时点绑定到同一账户的非秘密标识、端点、型号、源代码版本和全局运行契约；敏感原件不能进普通 health、日志或仓库。

缺任一项时报告具体原因，保持 blocked。`production-model-admission` 的结构校验只是之后的一步，不是核验器；不能把“sourceAuthenticityVerified:true”字段、环境变量或调用方传入的 hash 当成核验结果。若将来实现能力令牌，发行方与审核来源必须独立于可编辑配置，并明确有效期/撤销方式和信任边界；类型品牌本身不证明外部事实。

验收：篡改摘要、错误账户/模型、未知或非零金额、过期/撤销证据、旧请求未决和仅有合成证据均在凭据提供函数执行前拒绝。缺少供应商保障时没有 live permit，不能进入下一步的真实运行。

### 2. 独立增加正式生命周期，不能把 synthetic 类型改名复用

复用既有有界 HTTP 请求编码/解析和日志顺序，保留独立的 live 契约。实现正式 runtime 的世界提交桥、价格期与守护进程协议，使合成输入与真实执行许可在每个边界都不可互换。不能调用合成的零价格 `assessPrice` 为真实请求放行。

守护进程先拥有安全目录/日志/世界的独占能力，再启动单个 worker；总墙钟从 spawn 前开始。正式 worker 的可信入口获得经过核验的唯一 permit，只在 durable intent、剩余额度、有效价格/硬免费保障与所有权都复验后读取内存凭据，并在读取后、固定端点 fetch 前再次检查。不得从环境或任意 HTTP 参数直接构造 live transport。

费用验证失败、失权、请求失败、价格到期、截止到达或响应不符均停止；没有自动重试、换模型、换端点或付费升级。到期前排空，不把排空误作撤销已发送请求的远端执行事实。

验收：先仅使用品牌内存 transport，冻结源码后测试正常决定→持久世界→双账确认，以及 credential 回调耗时、intent慢写、价格边界和停机竞态。正式 source tree 不得存在旁路 CLI。任何新增真实测试另需满足当前授权与全部门禁，本批不执行。

### 3. 把恢复与预算绑定到原运行，而不是新目录

建立唯一正式活动运行登记，使同账户/已授权范围的新目录不能领取另一份请求、时长或费用许可。登记、世界、模型日志与价格会话必须绑定 source/run/world/account 的非秘密身份及各自审计末端。旧未决不能通过新 run ID、复制目录、删除 marker 或换入口规避。

沿用原始绝对截止与累计次数；intent/response pending、未封片段、停止未完成、账本分歧和世界指纹不符继续失败关闭。多库提交仍非原子，不宣称 exactly-once；断点处保留未知，只允许有独立核对证据的恢复流程，不提供通用清锁按钮。

验收：逐个落盘间隙强杀、父进程死亡、TERM/KILL清理未知、跨进程抢占、复制旧状态、双目录启动、旧源码/证据重放、无关 pending 与晚到回复。实际进程退出、本机资源清理、远端取消和费用核对分别报告。

### 4. 最后才把统一许可接到正式 main

未配置仍为 no-model；显式配置但条件不足为 blocked。只有完整、不可伪造的正式启动能力才能构造受监督的模型服务，不能重新开放裸 providers 参数。健康接口分别给出观察可用、模型准入、运行阶段、停止原因及费用是否核实，不泄露凭据/提示/证据原文。

真实长期验收与这里的安全机械验收分开：九人十五日自主生存、逐人健康/供餐与资源变化必须有单独可重复门槛。软件版本、证据和检查结果保存在可备份的发布包中。任何一项仍未知，都不能把 `readyForProduction` 或长期 `acceptancePassed` 改为 true。
