# 正式模型入口：官方免费模型的接线与发布边界

## 当前结论与旧结论纠正（2026-11-12）

目标是把用户已授权的硅基流动免费模型接入正式模拟，而不是建立永远无法解锁的抽象门禁。`main.ts` 目前仍是无模型观察服务，`siliconflow-free-only` 仍报告 `blocked`；本文不是启用命令，也不表示真实模型已运行或通过长期验收。

**纠正旧结论：** 本文上一版把“供应商逐请求原子执行的最高金额为零保障”设为必要条件，并据此断言即使机械接线完成也必须关闭。该条件不是用户对官方免费模型授权的必要含义，也不是已经证实存在的 SiliconFlow 功能，不能继续以它无限期阻止实现。应落实的是精确官方免费型号、当前适用价格与账户资格核验、有限调用、未知结果不盲重试、无收费回退及风险披露。它们不能承诺绝对零账单。

当前批次的实施范围是默认不由 `main` 导入的 **gated HTTP → journal → runtime → durable world 生命周期候选桥**，先以合成 transport 验证。候选桥的实现和测试结果须以对应源码及审查报告为准；本文分批方案本身不证明某一步已经实现。它不替代可信证据核验、账户级唯一运行登记、正式进程监督或正式启动接线。

## 官方依据与费用语义

以下是本次方案使用的公开依据，不是对当前账户或某笔请求的核验：

- [免费模型与限流 FAQ](https://docs.siliconflow.cn/docs/userguide/faqs/rate-limit-and-upgradation)：免费模型需要实名条件，FAQ 说明免费模型账单金额为 0；限额按账户和型号适用，增加 key 不是扩容办法。
- [其他 FAQ](https://docs.siliconflow.cn/docs/userguide/faqs/misc)：Pro 版本收费。反命题不成立，**非 Pro 名称不自动证明免费**。
- [官方价格页](https://www.siliconflow.cn/pricing) 与 [官方模型目录](https://siliconflow.cn/models)：启用时需要核对精确型号的当前输入、输出及其他适用费用。搜索索引、历史截图或当前页面仅出现型号，均不能单独替代价格核验。
- [服务条款](https://docs.siliconflow.cn/docs/legals/terms-of-service) 第 6.2、6.3 节：存在先使用后计费及欠费风险，价格也可能调整。

唯一候选是 CN 端点 `https://api.siliconflow.cn/v1/chat/completions` 的 `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`。不允许 Pro、近似名称、其他供应商、端点重定向或收费 fallback。以后即使换成另一款官方免费模型，也需要单独验证行为能力与适用价格，不可运行时自动替换。

`spendingLimitCny:0` 是本地使用意图；请求/token 上限是调用量上限，都不是提供商货币硬限制。当前没有在已查资料中发现可用的逐请求 `max_cost=0`，这既不是“不可能存在”的证明，也不再是阻止开发的前置条件。当前官方免费说明无法消除价格检查与计费间的变更窗口；200、usage、余额为零、赠额、abort 或进程退出也不能证明零账单。状态必须保留 `providerBudgetEnforced:false`、`actualProviderCostCny:null`，直到有真实账单证据；不得以合成费用断言替换它们。

## 既有边界与可复用组件

- `startFormalServer` 在监听、打开存档和 runtime 之前拒绝非空裸 `providers`；只接受本进程生成的关闭策略，异步边界后仍使用内部空数组。这是误接线防护，不是恶意本机代码沙箱。新增候选桥不能绕过或悄悄删除这层正式入口限制。
- `production-model-policy.ts` 固定单模型、默认关闭；名称不证明价格。
- `production-model-admission.ts` 校验授权、历史请求和价格记录的结构、摘要、范围及有效期，**不鉴定来源真实性**。手填 `free:true`、`sourceAuthenticityVerified:true`、环境变量或可自行计算的 hash 都不是可信价格证明。
- `production-model-http.ts` 固定端点，无重定向、重试或回退，有界响应、派发前再验；构造候选不等于具备正式运行能力。
- `production-model-journal.ts` 在派发前 FULL 提交 intent，随后记录响应和世界确认；保留累计次数、绝对截止、未知请求和恢复锁停。独占 SQLite 句柄不是跨目录账户级锁。
- `model-budget.ts` 提供一分钟请求/token 限流及保守预留，不提供账户账单保证。只有能证明尚未派发的精确预留可取消。
- 既有 synthetic runtime、price session、process worker/guardian 是可复用的机械验证，不是 live 价格证明或正式进程协议。不能只改 marker 名称或替换 transport 就宣布生产接通。

历史真实请求的执行及账单结果，本批没有读取或核实。未知仍是未知，不能因重启、换目录或没有收到响应就记为“未执行”。既有适用用户授权应复用，不为同一免费范围重复申请泛化授权。

## 可执行的最小纵向链与验收

### 阶段 1：把当前官方价格核验接到有限运行契约

可信集成方核验精确官方型号价格、账户实名/免费资格、适用限额、已有授权范围，以及历史未决请求的执行和账单结果。保存非秘密的账户标识、官方来源 URL、检查时点、有效截止、来源内容摘要与审查记录，并绑定 endpoint/model/run/source 版本。原文、账户敏感资料和 key 不进入普通 health、仓库或世界日志。

来源真实性必须来自可复核的官方原始材料和审核过程，不能由一个调用方布尔字段自证。结构校验只负责防止材料错绑或过期。网页或接口没有精确价格时停止，不从型号名称或模型列表推断免费。当前实现采用的短价格有效期是本地复核频率，不是官方价格锁定承诺。

验收包括来源缺失、错误型号/端点/账户、非零或未知价格、过期、撤销、摘要错绑、未决历史请求和仅有 synthetic 材料；这些情况必须在读取 credential 前拒绝。**不要求提供商原子零费用保障才允许完成本阶段。**

### 阶段 2：受信 runtime 候选桥，不开放 main

复用有界 HTTP 与日志顺序，连接实际 runtime 决定、持久世界提交及 journal 确认。候选桥只接受匹配的 gated 契约和已审核 admission；每次派发前重新核验有效期和运行范围。live 路径不能使用 synthetic `assessPrice` 的固定零价。

次序是 intent 持久化 → 最后价格/额度/所有权检查 → credential 获取 → 再检查 → 固定端点请求 → 有界响应校验 → 世界事务提交 → journal 确认。世界提交和日志确认之间不是跨库原子事务；该间隙崩溃必须锁停，不声称 exactly-once。

先以合成 transport 覆盖正常决定、世界持久化、确认和重开；同时覆盖 401/402/429、超时、截断或错误 JSON、型号不符、晚到回复、价格过期、credential 回调耗时、慢 intent 落盘、并发请求和停机竞态。429 暂停模型及世界推进，不能升级套餐、换模型或自动重试。未知结果保留 pending 与原因。合成 credential 访问不是读取真实 key，模拟 HTTP 也不是供应商验收。

### 阶段 3：监督、唯一运行与恢复

正式父进程先获得账户范围活动运行登记以及世界/日志独占能力，再启动一个 worker；总墙钟从 spawn 前计。检查 source/run/world/account 标识、累计预算和原绝对截止；不能通过新目录、新 run ID、复制记录或删除 marker 领取新预算或清除未知请求。

价格到期或停止前排空；响应失败、失权、价格未知或不再免费立即停止，不触发任何回退。intent/response pending、未封片段、停止未完成、账本分歧和世界指纹不符都保留锁停。恢复必须有原请求核对证据，不能提供通用“忽略未知并继续”开关。重新核验价格不是重新执行旧请求。

逐落盘间隙强杀、父进程死亡、TERM/KILL 清理、双进程竞争、双目录、旧证据重放、晚到回复应有独立测试。分别报告本机退出、资源清理、远端取消与账单核对；前两项不能推导后两项。

### 阶段 4：正式启动与有限真实验收

默认 `no-model`，显式选择但缺条件为 `blocked`。完成以上受监督生命周期后，正式启动使用专用、受信的集成接口，不重新开放任意裸 provider。健康接口分别报告观察服务、模型准入、运行阶段、暂停原因、未决请求和费用核验状态，不公开 key、提示或证据原文。

先执行有限真实验证并核对请求型号、trace、usage、决定、持久世界和账单，再扩大范围。真实执行遵循既有免费授权和适用操作规则；**本批不做真实模型调用、不读 key 或真实档、不查询实际账户账单。** 真实长期验收另行验证九人十五日生存、逐人健康/供餐与资源变化，不能由合成 transport、模拟天数或类型检查替代。只有完成实际所需验证才可标记 `readyForProduction` 或长期 `acceptancePassed`。
