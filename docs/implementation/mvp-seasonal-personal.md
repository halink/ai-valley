# 居民季节感知与行动接口（候选，模型入口仍关闭）

## 接入而非自动启用

本片接入既有 `decisionContext → decisionChoices/buildChoices → prepareModelDecision/parseModelCompletion → submitPlan`，没有单独规则代决，也没有发真实模型请求。旧的气候 MVP 模型启动拒绝门保持原样。合成模型回复只验证输出解析与真实引擎执行，不代表模型判断、记忆、性格或连续生活表现。

## 个人所知

- 户外清醒且具备实际观察位置时，从同源新气候给定性天气/冷暖/干湿感。温度低于10℃为偏冷、达到24℃为偏热；RH低于35%为偏干、达到80%为潮湿。这是版本1游戏感知分档，不是仪器读数、体温、医疗判断或新增需求/伤害。室内不补给户外当前事实；提示开头不再把旧日晴雨冒充新天气。
- 当前自己可见的田才可提供作物实例、成熟状态及游戏土壤干湿分档（PAW<30为偏干，其余有可用水）。不展示未来温度/产量、他人田或远方当前生长。
- 真实 `stepWorld` 的原观察阶段保存本人亲见田地收据，包含世界、观察者、模拟时间、观察者位置、田址、实例和需求epoch及当时允许字段。收据追加且SQLite提交禁止改旧记录；latest只指向该田最新收据。相同事实不每tick重复记录，不提升actorRevision取消计划。菜单/提示/查询不会创建收据，旧档不会补造历史。
- 离开后只能读明确标记时间的本人旧收据，不从World刷新。领取种子可引用这些旧目标；原引擎按实际产权、实例、路线、种源与本轮领取记录重验。失败不增加种子，也不透露远处的新实例或别人意图。
- 已知灶堂只提供恒定地址与查看选项。实际站在种台/厨房工位才给种源/安装事实，远方余量或占用不影响新菜单；本人罐藏仅自己的已知批次/旧鲜度未知量。

## 必要的现场查看动作

`mvpInspect` 仅有 `seed`、`kitchen` 两个公开工位目标。动作通过现有路径、房间占用和位置核验，实际进入灶堂后观察1游戏分钟，不领取、不安装、不加工、不增加库存。只允许已知公共灶堂，不扩展私宅访问。查看成功只提供观察位置，后续领取、安装等必须由另一真实决定发起。

## 可选择的工作

当前可见本人田提供三品种播种、成熟收获、实际浇水、清除原作物。清田不要求替代种或未成熟，保留本人自主放弃的权限。种台可用本人根菜留种，或按本人旧田记录选择一次公共领取（有原作物的领取选项明确说明本人计划替换，不自动清田）。单田领取只授权该田；已有一份种子且只计划一田时，不出现额外领取。另有明确列出两块田及各自替换意图的双田方案，仅按该方案缺额领取；未选择的记忆田不扩大配额。厨房提供同种根菜烹饪、真实有成本罐藏安装/加工。现有引擎仍负责物资、工时、并发、实例与失败回滚。

新工作按作业类别进入既有32项基础菜单预算，类内按已有30游戏分钟窗口轮换，不挤成一次无限大提示；**尚未实现同快照可查询分页与持久round的完整公平契约**。这仍是关闭真实模型入口的必要后续关卡，不宣称所有候选始终可见。

## 持久与范围

个人收据独立v1字段保存在居民状态中。预检拒绝未来版本、错世界/观察者、未来时间、无效实例/epoch、缺号或错误latest；存储拒绝删除已有知识或篡改已保存收据。该片不修改全局知识框架、不扩展formal世界、不从谷灵全局观察倒灌居民。

本片的成对世界无泄漏检查只覆盖新季节投影及新菜单；不是对所有历史DecisionContext字段、社交/报价/既有错误文案的整体认证。

## 下一启用关

需要完成同观察快照分页/预算、持久请求与过期回答恢复、现有全部上下文审查及居民/谷灵共享账户准入后，才能评估解除气候模型入口门。真实模型测试继续禁止，不能用“试运行”改名绕过。G0客观记录与真正模型叙事也须分别标注。

局部检查放在忽略的output，不作为长期测试套件推送。整批30分钟及真实画面验收由协调线程另行记录。


## 当前定向证据

构建检查与四个忽略的合成脚本已覆盖：纯查询不补历史/不变世界；亲见田→真实进入种台→使用旧记录领取；准备模型提示与合成回复解析后真实种、水、清、留种、做饭、安装及罐藏；远方种量/安装/占用/他人字段成对变化不影响新投影和菜单；过时田实例拒绝且不发种；观察途中SQLite恢复；已存收据篡改/删除拒绝并保持原DB。另验证饱和食物/社交菜单仍在32项内提供烹饪和罐藏代表，以及单田不借其他记忆田领取、双田明确列明并只领缺额。人工库存仅用于动作契约验证，不证明正常生产积累。Godot无界面解析仍不是实际画面或浏览器验收。
