# 合法播种菜单保底

## 问题与范围

逐居民合成试验中，陶笛在春季已有种子、亲自在本人空田时，生产机会生成器已校验并列出芜菁、谷物、亚麻，最终编号菜单却可能三个都没有。原因是 `focusedChoices` 的 56 项普通预算及每 30 分钟的领域轮转，采集、查看食物地点与留种等条目可把整个播种组挤到预算之外。这不是季节、地权、距离、水量或土壤限制。

修复只调整已生成合法选项的可发现性，不改变生产机会、年龄、旅途、观察、土地、种子、季节、执行校验或资源规则。上游仍只为当前选定的可见空地生成候选，不借此查询远处土地或额外制造候选。

## 选择与预算

1. 从经过 `buildChoices` 年龄、旅途及表达能力过滤的完整候选中，按 `plotId + cropId` 去重并稳定排序。旧机会 ID 不含作物品种，不能单凭 ID 查重。
2. 每 30 分钟轮换一个完整身份，保证在候选集合不变时，一个完整周期能看到全部候选。没有候选时完全不改菜单。
3. 原普通菜单计算保持不变，不先移走播种候选，避免改变领域轮转长度及其他入口的分配。旧菜单已经展示的其他播种也保留。
4. 在 `focusedChoices` 的最后恢复选定候选：若该完整身份已经可见则不动；否则用空位，或替换最后一个多余的目标反思项。保留至少一个已有反思入口，不替换任何非反思选项。
5. 如果菜单已满且没有可替换的反思，只额外增加一项。原来为 56 普通项、至多 2 取水项及 1 烹饪项，此处显式上界为再加 1 播种项，即 60。之后既有对话、理解、食物线索、约见和立即停止等恢复组仍按原各自边界处理；60 不是整个最终菜单的统一上限。

即使已有另一种作物可见，也要保证本次轮到的完整候选可见，不能以“任意播种已出现”跳过恢复，否则品种仍可能被另一次轮转长期排除。增加一项会改变最终展示编号，但不会替居民选择、提交计划或消耗种子。
