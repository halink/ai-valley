# 默认九人编号菜单离线压力验收

新的[独立长期健康与供食判定](nine-resident-survival.md)在显式观察模式中另计逐人健康、持续饥饿、实际供食和覆盖门槛。原 `scriptedSurvivalPassed` 公式、v4默认与全部策略均保留；终点9/9不等于新门槛通过，更不是真实AI验收。

这项测试从未经改造的 `createFrontierWorld(5401)` 开始，用固定脚本选择居民当前合法的编号菜单，保留动作、食物流和失败诊断。当前默认保持v4：赠食提议、受赠者自主接受、交付尝试、本人失败探索退避和共屋核实。v5仅作为显式选择的实验候选，在v4基础上增加基于本人亲见位置的有限会合尝试；它未通过会合覆盖，不能据此自动成为默认。v5十五日9/9存活，但成功会合后的赠食闭环仍未覆盖，苏葵终点饥饿98.93且无食品；不能称持续供食成功。历史v3十五日葛川饥饿96.392、健康15.476；v2为6/9存活、生存验收失败。任何脚本结果都不表示真实模型验收通过。

实现仅在 测试控制器（历史路径：`../../tests/helpers/nine-resident-menu-stress.ts`，已移除） 和 专项测试（历史路径：`../../tests/nine-resident-menu-stress.test.ts`，已移除） 中，不增加生产路由、CLI参数或测试控制口。它不读取密钥、环境配置或真实存档，不调用真实模型。

## 固定条件与决策链

当前默认策略名为 `visible-needs-gifts-and-feedback-v4`。省略 `policy` 与显式 `policy:'v4'` 等价；只有显式 `policy:'v5'` 才运行 `visible-gift-meeting-v5` 实验候选。另保留 `policy:'v2'` 的 `visible-needs-and-farming-v2` 和 `policy:'v3'` 的 `visible-needs-farming-and-retreat-v3` 对照模式。开局保留默认九人的身份、年龄、家庭、产权、地图、物资和规则；只按既有离线夹具的方式解除初始暂停。后续位置、健康、饥饿、作物、天气和库存均由真实引擎推进，不补粮、补水、改出生资料、瞬移或强制完成动作。决定预算仍为每轮30000次，时间范围和既有动作时长也不延长。

每次选择经过：

`decisionContext → prepareModelDecision → 当前编号回复 → parseModelCompletion → submitPlan → stepWorldWithFoodEvidence`

脚本只能读取本人的 `DecisionContext`、最终菜单和本人的脚本记忆。诊断可以观察世界，但不会把远方库存、其他人的私有状态或检查器结论反馈给策略。编号每次重新解析，不缓存旧编号，也不直接构造菜单之外的动作。

v3至v5先从最终菜单中寻找 `frontierHazard/retreat`，且动作、危险ID、目的地必须与本人 `context.formal.opportunities` 中的一项完全相同；选择第一项匹配编号，优先于吃饭、睡眠和生产。危险说明文本、别人的状态、观察者世界数据，或仅有一侧的撤退行都不能触发。没有匹配行就继续原策略，不猜目的地、不伪造行动，也不中断已经开始的计划。这里只改变空闲且仍有决定/表达能力时的下一次选择，不增加自动避险能力或安全保证。

之后的原策略依次考虑随身食品、恢复体力等事项；食物按本人可知的最早到期时间排序。它会另行核实听来的浆果地址、分享本人亲见地址、收获和浇水，为每名有土地的居民选择一个已知自有田址种植 `crop/turnip@2`，并保留此前亲见干田产生的取水意图。缺粮时再选择采果、合法领取、查看旧址或探索；兜底是本人选择等待30分钟。wait-only负例仍直接等待，不启用撤退。

v4增加以下固定规则，参数在长跑之前确定，不随结果调整：

- 本人撤退和饥饿时吃随身食品仍优先。随后尝试最终菜单中的已接受赠食交付；本人饥饿至少30或无可食菜单时，才能自行选择接受赠食。供者与受者有各自的context、菜单、记忆和计划，提议不等于接受，接受不等于交付。
- 只有本人当前 `people.bodyObservation.atMinute` 等于当前分钟，且显示对方饥饿或虚弱，才考虑菜单中的赠食提议。供者饥饿小于50、体力大于45，送出后同类随身物品至少留1份；同一供者对同一受者120分钟内不再提议。不会读取对方真实饥饿值或私有库存。
- 选提议或接受后，脚本自愿在原位短候，截止为选择时刻后15分钟，每次最多5分钟，剩余不足1分钟不生成非法小数等待。撤退、已有食物进食和已接受交付可以优先；不中断已有行动。新的独立接受可以重设这个人的截止，因此15分钟是每次提议/接受的等待窗口，不是全局总等待上限。
- 下一次本人context显示上次探索失败，且没有该次之后成功移动回执时，才把那次起点/终点组合退避240分钟。不检查私有世界地图、不假装知道全建筑范围或水域；若所有显示的探索方向均在退避，选择合法等待30分钟。记录失败本身不保证以后路径安全。
- 缺粮且没有更高优先行动时，先使用实际可见采果，再看实际可领取菜单；仍无份额时，按本人已知共屋地址选择核实，单建筑240分钟冷却。核实不是补粮，也不假定有库存或领取权；只有本人机会与最终编号菜单都出现 `takeFood` 才领取。

v5只在测试脚本中增加有限会合，不扩大赠食权限。它读取完整本人context中的记忆，依赖当前中文消息格式；格式变化会使匹配关闭。这不证明实际模型提示呈现了相同数量的记忆，更不证明真实模型会作出同样选择：

- 将当前合法decline行的数量、品名、截止，与本人 `source=self` 的提议记忆精确匹配，要求收方姓名一致、`receivedAt=截止−120` 且只有一个匹配。再用本人亲见记录中的唯一姓名对应ID；同名、同期限多提议、记忆缺失或无法唯一对应均不追逐。
- 供者位置来自本人当前context或最多120分钟前的亲见记录，保留观察时间、室内ID和房间坐标，旧址不是活定位。本人已知供者死亡、空间未知或非法坐标时停用。原始context已有accept而最终菜单缺行时，不把它错当“不近身”；本人一旦选过该gift的accept，也不再尝试会合，即使那次接受后来失败。
- 每份提议最多3次会合选择，不重复同一gift/起点/动作。只选最终菜单中使世界坐标曼哈顿距离严格缩短的move，单次直线格距最多12、直线必要耗时小于剩余期限，并回避本人已知失败探索方向。绕行、室内步行和目标移动仍可能使实际耗时更长或过期。
- 若供者已知在公共建筑内，只可另选该建筑当前真正提供的共屋核实动作作为室内会合尝试。没有合法室内机会就保留缺口；不虚构房间移动，不把到门外或核实完成当作相遇。
- 撤退和本人随身进食优先。v5将体力≤45时的合法睡眠提到赠食交接等待之前；有会合候选且饥饿≥70时，现有采果、收获或领粮动作也优先于交接等待和会合。v4原顺序保留。其余接受、交付和进食仍各自独立选择，不自动执行。

该策略是有意收窄的可复验控制器，**尚未实现治疗、交易、家庭供餐和跨季作物切换**；v2还忽略危险撤离。即使菜单有这些选项，它也可能不选。脚本导致的死亡不能据此归因为引擎没有相应能力，或默认世界必然无法供养九人。撤退优先还可能增加行走、消耗体力或推迟进食与生产，需要记录副作用而不能预设更好。

## 可复现命令

要求 Linux、Node.js 22.13.0或更新版本，以及已经安装的锁定依赖。以下命令从仓库根目录执行：先运行类型检查与当前定义的十四项专项（其中正向五日使用默认v4），再单独生成v4的15日证据。它使用现有离线守卫，清空继承环境，并把工具的 HOME/TMP 指向本次仓库内临时目录；没有依赖安装或联网步骤。

```sh
(
  set -eu
  NODE="$(command -v node)"
  TOOLS="$(env -i "$NODE" --input-type=module -e '
    import {mkdtempSync} from "node:fs";
    import {join} from "node:path";
    import {testTmpdir} from "./scripts/repository-temporary.mjs";
    console.log(mkdtempSync(join(testTmpdir(), "menu-stress-tools-")));

  trap 'rm -rf -- "$TOOLS"' EXIT
  LOGS="${TOOLS}-logs"
  mkdir -- "$LOGS"
  printf 'Retained logs: %s\n' "$LOGS"

  offline_node() {
    env -i HOME="$TOOLS" TMPDIR="$TOOLS" TMP="$TOOLS" TEMP="$TOOLS" \
      TSX_DISABLE_CACHE=1 "$NODE" \
      --import ./scripts/acceptance-offline-guard.mjs \
      --import ./node_modules/tsx/dist/loader.mjs "$@"
  }

  env -i HOME="$TOOLS" TMPDIR="$TOOLS" TMP="$TOOLS" TEMP="$TOOLS" \
    "$NODE" --import ./scripts/acceptance-offline-guard.mjs ./node_modules/typescript/bin/tsc --noEmit

  offline_node --test --test-reporter=tap tests/nine-resident-menu-stress.test.ts >"$LOGS/tests.tap" 2>&1
  STATUS=$?
  printf '%s\n' "$STATUS" >"$LOGS/tests.exit"
  cat "$LOGS/tests.tap"
  [ "$STATUS" -eq 0 ] || exit "$STATUS"

  # 单独的v4十五日压力运行；v5实验须明确改为policy:'v5'。
  offline_node --input-type=module >"$LOGS/fifteen-day.log" 2>&1 <<'JS'

const r = runNineResidentMenuStress({days:15,policy:'v4'});
console.log(JSON.stringify({
  directory:r.directory,

  STATUS=$?
  printf '%s\n' "$STATUS" >"$LOGS/fifteen-day.exit"
  cat "$LOGS/fifteen-day.log"
  exit "$STATUS"
```

最后一段把**生存结果**映射为退出码：通过为0，失败为1，证据都会保留。helper本身返回报告，不因生存失败自动抛错，不能只依据调用它的 Node 进程退出码判断通过。历史v2的6/9结果对应退出码1。只需专项时，可省略最后的15日段。将 `policy` 改为 `'v2'` 或 `'v3'` 可重跑旧策略，显式改为 `'v5'` 才运行会合实验；`days` 可分别指定5或15。历史v5对照使用此前封存的v2/v3/v4证据，没有重新执行它们的长模拟；后续恢复默认v4也没有重跑5/15日。守卫或平台检查失败应如实报告，不应移除保护后称为同一次验收。

每次 helper 调用都在 `output/test-tmp/nine-menu-stress-*` 新建独立目录，不接受真实存档路径。工具临时目录的退出清理不会删除这些证据目录，也不会删除相邻的原始TAP/长跑日志目录。它们包含：

- `manifest.json`：种子、策略、运行选项、初态指纹、源码/配置指纹、helper SHA-256和Node版本。
- `controller-source.ts`：本次控制器源码副本，用于核对helper哈希。
- `decisions.jsonl.gz`：逐条选择时的本人context、完整最终菜单、原始编号回复及完成记录；是串接的gzip成员，可用标准gzip解压。
- `trace.json`、`report.json`：动作索引、结果、逐人统计、日界快照和已覆盖食物流。
- `first-<居民ID>-<问题>.json`：首次失败、健康下降、临界需求、失能或死亡的前后状态、最近决定和相关事件记录。
- `synthetic.sqlite`：仅属于本次新建世界的持久化检查点。

v3起manifest另记有效决定预算，v4的schema 3保存固定支持规则参数，v5的schema 4还保存会合参数。v5 trace另记本人提议记忆匹配、供者亲见位置、不能行动的原因以及实际选中的会合编号。每条trace保存本人撤退机会与最终编号的交集，实际完成的撤退附同刻引擎事件；报告分开统计选中、完成、失败、在途及未选机会。资源诊断保存初态、日界和终点的有限浆果/泉水量、九人及公有库存、自有作物和危险累计数；这些观察者数据不进入策略。死亡分类保留引擎死因、死亡事件、失能情况、最后决定年龄与此前撤退记录，不自动推断“当时本可逃生”。

`output/` 已被忽略。原始测试输出、数据库、工具临时文件和任何真实档都不随这项源码交付收录。

## 通过条件分开计算

- `actionCoveragePassed` 要求没有运行异常、到达精确终点、保持原九人身份集合，并实际覆盖九人进食/睡眠、分享、听闻地址核实、播种、浇水、收获、留种和同田再次播种。它不要求所有人最终活着，也不表示所有选择都成功。
- `scriptedSurvivalPassed` 要求没有异常、`actionCoveragePassed` 为真，且固定九人全部存活。历史v2的5日和15日均为 `false`；各轮实际结果另列。
- `supportCoveragePassed` 单列v4赠食提议、独立接受、实际交付、零库存后的下一次进食关联、共屋核实、共屋领取和失败探索退避是否全部实际覆盖。它不混入原动作覆盖或生存公式；任何一项未发生都会是失败，不以策略有此分支冒充完成。
- `meetingCoveragePassed` 单列本人提议识别、会合选择、会合动作实际完成，以及其后接受/交付/下一选择进食的顺序链。它既不替代 `supportCoveragePassed`，也不混入原动作或生存公式。完成移动不等于相遇，顺序关联不等于会合是唯一原因。
- `gates.reloaded` 单列持久化覆盖，不混入动作覆盖公式。当前专项要求终点重开；分享途中、生长中和收获后的实际检查点另行报告，不强行制造事件来满足断言。
- `realModelExecuted` 始终为 `false`，`modelAutonomyAcceptancePassed` 和长测的 `technicalWaitMinutes` 保持 `null`。

当前十四项专项定义检验实现、输入边界、默认策略路由、回执一致性及报告公式，不要求正向长跑必定覆盖或存活。原覆盖门槛未删改；如果动作未发生、食物未领取或人物死亡，报告仍须如实失败。

提交成功、动作完成、库存取得和实际进食是不同事实。完成记录须有引擎完成依据；死亡或中断后动作消失不会自动记成成功。食物回执按实际actor、plan、物品和时刻关联，不把失败采集当生产，不把分享地址当交付食物。

## SQLite与证据限制

SQLite检查位于真实分享中途、生长中、收获后且下一次决定前，以及终点。历史v2前三个时点为510.25、2880、5815；v3的收获时间可随真实行动变化，不强行对齐。每次比较完整持久化世界指纹。分享采用真实0.25分钟推进、重开、再推进0.75分钟，将两段原始回执合并为既有采集器要求的一分钟观察，不修改剩余工时。

这是**同进程SQLite关闭重开**，脚本记忆仍在该进程内；不证明进程崩溃、未决模型请求恢复或重复派发安全。独立runtime专项只验证短段排队/假回复接线，15日主体直接推进引擎，不覆盖真实请求延迟、限流、网络、费用或长期模型调度。

`sampledPreStepStateMinutes` 按每次推进前状态采样，`queuedPlan` 单列尚未采到活动开始的计划，不能当精确活动时长账。`startedAt=null` 表示没有采到开始时点，包括一步内完成的动作，不表示未执行。撤退elapsed为选择至结束的总经过时间；净健康、能量和饥饿变化可能含同期自然消耗、恢复或袭击，不能当撤退专属毛成本。有限源量和库存端点也不构成完整守恒或可持续性证明。

赠食另存实际完成步的供者/受者库存前后值、引擎交付receipt和合约状态，并关联三个独立动作。`zeroStockNextEatLink` 仅在受者同类库存0→1、供者减1、受者下一次决定正是吃该物品、存在真实进食回执，且期间没有另一同类个人赠食交付或已观测腐坏时成立。它不是批次身份追踪或完整转移账；一般的食物转移观察器未覆盖个人赠食，不能把空数组说成没有赠食。

字段 `recentWitnessedEvents` 实际纳入居民为actor或witness的相关事件记录，不保证其中所有元数据都曾被本人有意识地感知。该诊断字段不进入策略。食物流仍是有明确覆盖范围的分项证据，`completeFoodLedger` 为 `false`。

独立复核的方法、修正项和冻结源码哈希见 [审查摘要](../reviews/nine-resident-menu-stress.md)。
