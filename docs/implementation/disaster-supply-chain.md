# 天气灾害、撤离与供水的隔离联合验收

本项将已有有限天气链、正常决定菜单、实际引擎行动和供水权限放在同一个合成世界中验证。**不启用正式世界天气，不启用口渴或脱水，不代表批次4/5整体验收完成。** 没有调用模型、读取真实存档或使用浏览器。

## 场景与方法

联合回归（历史路径：`../../tests/disaster-supply-chain.test.ts`，已移除）新建种子73的三人正式规则世界，使用40×32合成地图、一格真实淡水、两处明确有限的泉水、一处干燥共屋和一处岸边建筑。人物、材料、空桶或预置桶水均在场景开始时明确设定；灾害不会赠送补给。该小地图不模拟真实海拔、完整流域或全村人口。

在合成世界中明确启用天气采样，通过逐分钟 `stepWorld` 积累实际模拟降雨，直到引擎生成洪水预警。检查90分钟预警窗、径流证据和记录洪区后，立即停用后续天气调度。已记录灾害仍经同一引擎自然发生、伤人、损坏和消退，未修改其强度、阶段或期限。

所有居民行动均从 `decisionChoices(decisionContext(...))` 的最终普通菜单选择，经过 `parseChoice`、`submitPlan` 和实际时钟执行，没有直接调用行动完成函数，也没有在灾害发生后传送人物。测试脚本选择具体分支，不把这些选择描述为真实模型的判断。

紧凑菜单会轮换普通动作，每30游戏分钟最多轮换展示两项非撤回供水选项。若所需合法选项尚未展示，测试从同一普通菜单明确选择等待1分钟再查阅，最多240次；不改变菜单容量或强塞动作。通过说明路径可完成，不保证任意时刻所有合法供水动作都会同时展示，更不保证真实居民一定选择它。

## 已完成的联合分支

1. **预警、主动撤离与实际伤病。** 预警不移动居民、不提交计划、不加库存。第一人选择步行撤离而没有受伤；第二人从菜单选择停留，洪水实际发生并累计暴露后损失健康、产生真实外伤病例，随后另行选择撤离。记录以同一灾害编号区分预警、发生、伤害和撤离。
2. **满员与第二人的选择。** 两人先各自读取同一个只有一人容量的共屋选项。首人实际到达后进入，第二人提交旧选项被执行前容量复核拒绝。新菜单不再提供该满员避难处，第二人仍可自行选步行撤离。未产生住所、床位、财物转移或强制搬运；灾后首人也不会被自动驱逐。
3. **淤塞、替代泉和有限协助饮水。** 原泉实际留下洪灾淤塞，水量仍为7；灾前读取的装桶选项在灾后执行失败，活动期不提供清泉选项。照护者另选可达且未受损的替代泉，扣其3份水装入原空桶。伤者在安全位置本人授权后，照护者再独立选择5分钟协助，实际消耗1份安全水，只计一次饮用和授权次数，没有健康加成。
4. **退水、材料修护与再取水。** 灾害自然消退后，清泉消耗1木2石和至少60分钟，只解淤不补水；岸边建筑另用2木1石及实际修护时间恢复。泉水与建筑的完成记录仍关联原灾害。
5. **保存重载与回执。** 正向链写入新建临时SQLite文件，关闭后重新打开；灾害、泉水损害、健康病例、供水授权与回执均保持一致。重放已完成供水计划不重复耗水。重载后仍从正常菜单到已清理原泉取水，不重置调度开关。
6. **中途重载与撤回。** 另一分支使用3份明确预置安全桶水，在真实洪伤后开始协助饮水，尚未完成时经 `WorldStore` 保存重载。受助者从普通菜单即时撤回；恢复中的行动失败，不扣水、不记饮用、不增加授权使用次数。灾害消退本身也不会自动清泉。
7. **重症边界。** 第二次真实洪水暴露把外伤推进到既有重症阈值，人物仍可决定并步行撤离；虽然此前已授权且现场有安全桶水，普通菜单不提供有限协助饮水，诊断核验明确为重症不适用。未把原授权扩大成医疗或紧急强行供水权。

## 本场景可核对的实物账

正向链的泉水初始合计为16份（7＋9），桶中0份、居民旧清水0份。替代泉装桶后仍合计16；协助饮用1份后剩15。清泉和修建筑不改变水量；关闭并重开数据库后，从原泉再装3份，原泉4、替代泉6、桶5，仍合计15，加已实际饮用1份等于初始16。没有设置泉水再生，也没有其他用水动作。

照护者初始8木8石，两次修护后为5木5石。满员拒绝、无效旧取水选项、供水撤回和已完成计划重放都没有额外材料或水损失。这是上述受控行动的实物核对，不是跨季总产量、食物消费或毛伤害的完整账本。

本轮不改变生产规则，仅添加联合验收与更正过时文档。现有公共桥梁洪灾受损后的表决、材料投入与分阶段修护由同批执行的 `infrastructure.test.ts` 独立覆盖，不冒称它与本三人场景共用同一灾害。
