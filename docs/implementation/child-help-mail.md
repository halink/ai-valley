# 儿童求助的有限镇外捎信

这是批次 2 的一个独立子批次，连接[已有儿童求助](child-help-notices.md)与[既有分段来访](visitor-journey.md)。只扩展消息和独立来访的可达路径，不新增信使、人口、粮食、住房、进入权或监护权限。

## 正常菜单与实地链路

1. 仍由有资格的亲见者记录原地址和固定 24 小时期限，再本人实际到谷口张贴。张贴本身不授权出信。
2. 原报告人另选 `sendHelp`，实际到原公示处花 5 分钟交托。尚未张贴、已知撤回、已经交托或到期不能重复交托。六岁以上孩子自助和青少年代幼儿记录仍沿用原边界。
3. 只有之后实际经过该谷口的既有外运货单信使才能捎信。原货运须独立达成、准备和出发，不为了求助创建货单或信使；已经经过的货运不能追溯取信。历史地址、孩子姓名与原观察日期随同一份原信移动。
4. 货运实际到达其原居地后，才向同源、已有可核实来访路线、实际处于居地且有自主接信能力的一位既有人物交信。不会初始化迁居系统、临时创造人物、跨来源转送，或把正在旅行的人当作在家。没有合格接收人时，记录信留在到站居地，不能凭空生成读信人或自动重送。
5. 收信人获得本人的持久回执，另选 `declineHelp` 或 `travelHelp`。拒绝和静默均不来人，也不远程通知报告人。选择来访只开启原有同身份分段旅程，每段之后仍须本人决定继续、吃随身食品、休息或折返；不自动续程，不补给，不预订床位。
6. 实际入谷后仍为访客。本人另选 `visitHelp` 按原址探访，合法见到孩子后才走原有救急或 `offer`、独立 `review`、必要的孩子 `accept`、每餐另选 `feed`。信中的监护缺口不是读者的死亡证明，求助不开放私宅，也不允许强行搬运或永久监护。

## 消息、失败与历史边界

- 一份原信只完成一次镇外送达。未到镇外便实际退回谷口的，保留原货单与退回日期，只能等另一趟既有外运，不能重放同一货单。已到站但无人接信不自动变成已退回。
- 出信前已撤回的原信不再交付信使；出信后的撤回不传送到远方。收信人的菜单仅使用实际收到的原文、本人回执与本人当前能力，不从世界状态读取孩子的新位置、死亡、拒绝或监护恢复。
- 过期原信仍可被实际送到并记入历史，但不能据此启程。途中到期不会传送旅人回家或强制改变其方向，旅人仍掌握真实旅程；到谷后不能再执行已过期的旧址探访。新求助必须重新现场核实，不能延长旧信。
- 谷口或镇内通路受阻不会假定已到场；分段旅途可反悔、休息、断粮或中断。报告人死亡不为已交托或已上路的纸信撤销独立运输，也不会自动张贴或交托其未完成草稿。
- 求助原观察、交托、货运接取、到站/退回、收信、独立答复及原址探访分别保存。人物档案只读显示这些阶段，不能向居民注入知识。已收信被短记忆挤出后仍可从个人回执看到原始线索；工作事件裁剪和 SQLite 重载保留这些证据。
- 旧档缺少 `outbound` 或镇外回执时不补造过去的出信或来访，既有求助仍保持原期限。货运、出信、答复、入谷和喂养不因重复提交或重载重复执行。

## 验证与明确缺口

新增正常编号菜单和反例位于 `tests/child-help-mail.test.ts`、`tests/child-help-mail-review.test.ts`；[独立复核](../reviews/child-help-mail.md)记录问题与最终离线结果。沿用 `tests/child-help.test.ts` 的室内进入权、独立复核与固定历史地址测试，以及原分段来访的食品、身体时间、受阻、死亡和重载测试。

本批不扩展访客本人捎儿童信、更多公示点、商行本人离店探访、任意跨来源路线、无人接信后的二次转送、远方撤回回信、幼儿接出、跨地护送、住宿交接或永久监护。原信没有实际货运、合格在家接收人，或对方不愿来访、已过期、道路不通、现场无合法接触及食品/独立复核不足时，照护缺口仍存在。

只使用合成隔离世界与内存数据库，不读取 `.env`、密钥或真实存档，不调用真实模型或浏览器，不提交推送。未进行真实模型十五日或四季长跑，静态界面回归不等于浏览器视觉验收。
