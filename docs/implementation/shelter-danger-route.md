# 临时进屋避险的已知危险路线

## 问题与最小修复

`frontierHazard.shelter` 原先只确认屋子可用，再用普通最短路走到门口。与 `retreat` 不同，菜单筛选、实际开始寻路、活动逐边通行均未使用现有的已知危险边界。因此即使有合法绕路，居民也可能为躲避已看见的野兽而主动穿过它的危险圈。

当前只在三处把进屋避险接入原 `frontierRetreatStepAllowed`：

- 菜单仍从本人已知、附近可核实且具有使用权的屋子中选择，并按原48步上限核对避险路线。最近屋子无此路线时，可列出另一处本已合法的屋子；这发生在本人选择前。
- 开始实际行动时，对原选定屋门重新寻路，不追踪或替换目的地。
- 执行已经保存的路线时，按当前实际可见危险与物理边界逐边核对。新阻断使原行动失败，留在实际位置，等待本人重新决定；不自动重规划或传送。

复用规则允许离开已经身处的危险圈，不允许从圈外进入或重新进入已知危险。没有增加未见野兽的路径过滤或远程危险知识；这也不是安全到达保证。动态危险、饥饿、伤病和实际耗时仍有后果。

未修改建筑权限、容量、屋况、洪灾遮蔽判断、原到场完成重验、床位或住宿权；未改变 `retreat`、普通移动和医疗护送语义，也未启用新天气调度。既有旧存档的 shelter 路线直接接受同样的逐边核验，不需要存档迁移。

## 可复现的合成案例

由正式seed5401生成九人，再显式设置测试地图与警戒状态：居民在(9,9)，已看见的野猪在(13,9)，可用共屋门在(17,9)，其余人不行动。野猪固定位置，已有两分钟后执行的攻击警戒。普通直线路线8步，原避险规则存在16步绕路。

修复前独立内存探针通过最终编号菜单选择“暂避野猪，沿路到河谷共屋内遮蔽”，普通提交成功；第1分钟进入半径3的危险圈，第2分钟距离2时遭袭，健康100降至74。初始健康25时，同一动作在第2分钟死亡，死因“野猪袭击”。同条件原地等待4分钟不受伤。这个探针证明固定已知危险下的路线因果，不代表正式存档发生率。

主测试固定同一警戒与几何，经真实 `decisionContext → prepareModelDecision → parseModelCompletion → submitPlan → stepWorld` 验证安全绕行。0.25分钟和默认1.2分钟步进分别覆盖初始健康100与25；每步均不进入危险圈，实际到达同一屋门，健康不减。三种模型格式只解析本地编号回复，不调用模型。

其他主测试覆盖：无安全路线时菜单消失与旧回复失败、另一合法屋子的菜单选择、已在圈内撤出后不重新进入、途中新增树或风暴预警、未见野兽不影响个人选择、内存SQLite重载正常分数路线与旧不安全路线，以及最后0.25分钟的屋况、容量和权限失效。

独立反例与复核结论见[独立审查](../reviews/shelter-danger-route.md)。
