# 未知年龄的运行时排队与等待保护

## 已复现的范围

`ValleyRuntime.observedChildPressure` 原来通过 `ageYears` 判断未满六岁。
该兼容函数把不能核实的出生时间返回为0，因此登记在监护人名下、处于原有
近身范围、饥饿或低健康的未知年龄人物，会被误计为幼儿照护压力。
同一结果进入普通排队加权、快钟的危急优先级，以及慢钟立即保护性停表。

用正式 seed5401 的合成世界、真实 `ValleyRuntime`、内存 SQLite 和注入假决定
复现：8种异常出生资料让健康监护人抢在真实饥饿者前面获得唯一请求槽；
慢钟在没有真实幼儿依据时立即停表。初始11项回归中这9项失败，真实0岁
优先/停表和监护人自身饥饿保护两项对照通过，修复后全部通过。
未读取真实存档，因此没有关于坏档发生率或真实居民年龄的结论。

## 限定修复

- 只在 `observedChildPressure` 使用 `knownAgeYears`，先排除 `null`，再按原 `<6`
  门槛计算压力。有效0岁仍然是真实幼儿，不被真假值判断误排除。
- 保留原存活、非镇外、同一 `inside`、曼哈顿距离不超过12和登记监护关系
  条件。普通饥饿/健康与危急健康阈值、权重、排序、请求槽、重试时限均不改。
  这是原运行时可见范围规则，不宣称已重写为更严格的室内遮挡/照护权限核验。
- 每次排序和慢钟判断均读取当前时点的出生依据，不缓存旧的幼儿压力。
  排队期间资料变为未知或孩子满六岁，不继续沿用旧优先；恢复可信出生资料后
  可按当前事实重新判断。真实生日的原有独立决定能力激活仍正常执行。
- 不改 `bornAt`、`lifeStage`、能力、签署、监护登记、普通菜单、执行授权或存档
  格式。历史幼儿身份不能替代当前可核实年龄。本批没有出生日期修复或迁移。

## 三种保护不能混为一谈

1. 幼儿需求影响的是监护人排队，以及慢钟的立即停表。未知年龄不再提供这项依据。
2. 本人真正饥饿、耗竭或健康不足仍按原规则排队；正式慢钟保留普通急需30秒
   宽限后的停表，严重健康、首次决定、约定期限和全镇模型失联等保护也未修改。
   未知年龄本身不取消这些年龄无关的普通等待条件。
3. 引擎的180游戏分钟个人保护必须已有本人决定/表达能力、实际健康危险，且当前
   正常菜单确实存在可及时完成的自救路径。它只暂缓新增饥饿/耗竭损伤，不凭
   他人需求创造个人保护，不补物资、不返还伤害，也不自动采取行动。

本批完成时，正式模式未知年龄者的既有年龄菜单不提供普通吃饭/睡觉选项；
后续[本人最小自理修复](unknown-age-selfcare.md)已补足此缺口，并相应更新旧回归。
仅有 `canDecide/canExpress` 和低健康仍不足以证明可自救：必须核实本人食物、
已有真实床位和及时可执行路径，不授予成人或幼儿权限。未知年龄者自己的普通
急需停表，以及照看未知年龄对象的已知合格居民凭真实食物/床位取得个人保护仍保留。
保护的原180分钟期限、重载不续期和全镇无决定时的独立停表边界均保持。

`tests/unknown-age-runtime.test.ts` 使用真实运行时队列，不直接调用私有优先函数。

快慢钟、真实饥饿与危急竞争、双请求槽、等待中的资料变化、真实跨六岁、无效回复、
停止后的迟到回复、SQLite重载及原个人保护期限。定时器和网络均由测试隔离，
