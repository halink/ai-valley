# 季节储备纯计算器（不接行为）

`src/server/mvp-seasonal-reserve.ts` 只接受显式输入并返回公式结果，不读World、不访问资源、不调用模型、不修改默认名义两日缓冲，不新增存档字段。未实施四日政策，也不把旧轨迹的401–404当居民目标。

## 输入责任与计算

调用者必须给出本人身份、窗口、恒定基础日需求及证据、覆盖声明、窗口起点本人实有可食库存及证据（onhand.asOfMinute必须等于startMinute）、按真实顺序排列的原子净供给事件。该小片仅支持窗口恒定需求，不自动平均变动需求。0需求合法。

供给事件 `semantics:'atomic-net-supply'` 明确不是裸库存delta或进食扣量。烹饪同一事件先把-40/+42合并为+2；实际留种为-20。吃饭由需求端覆盖，不再从A重复扣。每项携带来源证据：P只乘一次0.8，实际可得A乘1；实际负成本必须用A，禁止把负P折减以缩小真实成本。无量纲标志自动推断、已有恢复预算再打折、全谷平均分配均不在本函数内发生。

按事件前后分别计算累计 `1.2 × D × elapsedDays − A` 峰值，再加 `2D`。库存只在最后计算新增缺口时扣除，不作为供给事件再加入。首批拒绝起点同刻供给，明确起点库存是边界全部已结算后的快照，避免同一批食物在起点库存和事件中重复计量。事件必须唯一、严格晚于起点且不晚于终点、按分钟升序且同刻order严格递增；同刻顺序由调用者提供，本函数不排序或臆造。坏值、重复、乱序、非法语义和溢出均拒绝。

## 输出边界

- `unknown`：供给覆盖未知；空数组但没有显式零供给覆盖；声称完整却不足34日或缺少已观察到的窗内春首收证据。没有可供默认规则使用的数值目标。
- `observed-prefix`：只给 `conditionalLowerBound` 和 `conditionalAdditionalLowerBound`，不出现完整required字段。条件包括调用者供给归因、种根保留处理及覆盖声明成立。
- `complete`：至少34日、明确完整覆盖、实际春首收不晚于窗口终点且绑定同分钟、A来源、正净营养的真实事件ID，才输出 `requiredObserved/additionalObserved`；第32日首收而观察至第34日有效，第36日迟收不能将窗口截在第34日。这是已提供完整窗口的计算，不是对未来天气/行为/路线的保证。

所有输出均 `guaranteesFuture:false`。函数能验证数值和契约形状，不能凭字符串证据自行认证真实可达性、本人知识、是否确为首次春收或供给记录完整；这些是后续经独立审查的调用适配器的责任。目前没有该在线适配器，也不向居民暴露开发回放的未来事实。

`npm run check`；临时 `output/seasonal-reserve/verify.mjs` 覆盖：空供给未知/显式零、原子烹饪及留种、P与A一次性系数、0需求、34日与首收门（含32日首收/34日终点、迟收越窗、假零供给首收、库存错时点及起点事件拒绝）、11项坏值/重复/乱序/越窗/错误语义、输入不变。

复核 `output/agriculture-solver/observed-reserve-prefix.json` 全部8个本人/窗口组合，误差小于1e-7：28日窗口359.1528、367.576、364.0528、362.3376；31.422日可得前缀400.7488、404.4952、403.0624、400.7032。它们仍是历史乐观净流条件下界：原证据在实际留种完成才扣根，没有逐时扣除早先计划预留，且没有闭合至少34日及次春首收。因此全部输出observed-prefix，绝非完整冬储目标或未来保证。
