# 长期照护：跨六岁生日的本人选择

## 原因与权限边界

原 `offer` 把未满六岁的 `childAssent` 初始化为 `true`，混淆了监护签约和孩子实际选择。原服务只复查这个布尔值，孩子跨六岁生日后仍可被喂养、扣除照护者物资并向照护者付款，且没有本人同意入口。

现在幼儿的监护安排可以在未满六岁时按原规则履行，但不会记录虚构的本人同意。满六岁后，原约先暂停实际服务和收费，须本人有决定及表达能力、没有现存拒绝，并在照护者身边选择原约的同意后才可继续。监护签署、公共资助、危急需求、沉默和恢复能力都不能代填该选择。本人已有的拒绝不被清除；仍能表达但不能完整决定者只保留原有即时停止，不取得新的签约权。

## 实现与状态

- `world/long-care-consent.ts` 提供纯年龄与同意证据门禁。服务开始、每步工时及实际完成沿用 `longCareReason`，即使生日发生在最后0.25分钟、尚未运行生命周期归一化，也不能先扣料或付钱。
- 新约的 `childAssent=false`、`childAssentedAt=null`。成人本人接受或六岁以上本人 `assent` 的实际完成时才记下精确 `childAssentedAt`。监护人接受不设置它。
- 生日暂停复用 `awaitingChild`，加 `assentPausedAt` 区别“原已成立约定暂停”和“首次尚未完成同意”。原合约ID、接受时间、物资定义、访问记录、账户、预付款和起止日期均保留。暂停不退款、不再次预存、不延长，也不自动取消本人的原约。
- 初次待本人同意的合约仍在首个窗口结束时过期。已成立后的生日暂停保留到原有限期限，届时按原来源结算未用余额。本人可先拒绝/即时停止并退款；恢复能力、重载和重放旧计划都不能重新开启已拒绝的约定。
- 本人同意前，菜单保留拒绝及取消；有独立能力时提供原 `assent`。本人同意不产生餐食、不结算服务、不重新扣费；此后仍须完成一次完整实际服务，且每个原窗口最多结算一次。同意完成时也重验提供者的当前排程，排程检查排除同一份原约，不能把自己当冲突。
- 照护者原来明确开启的有限安排在暂停期间不能执行，但仍可自行关闭。本人同意后只沿用原授权，不重新开启照护者已关闭的分支。中断的服务不保留成可直接结算的半成品；在途原地址核实跨生日也不会把暂停误记为终止或清除原执行选择。
- 远方原 `promise.withdraw` 对尚待本人同意的已签约项也执行真实取消和退款，不只标记知情、留下冻结钱款。原远方“是否已内部结束须核实”的知识边界不变。

## 旧档

- 旧记录没有 `childAssentedAt`，且提议时不足六岁：旧 `true` 是历史默认值，不能证明实际选择，归一化为无本人同意。仍未满六岁时保留原监护照护；已满六岁时安全暂停。
- 旧记录提议时已经六岁，且保有合法接受时间及 `active/childAssent=true`：原代码只有真实本人同意（或成人本人接受）才会形成这一状态。用 `legacyPersonalAssent=true` 保留这个可证明事实，而 `childAssentedAt=null` 保持准确时间未知，绝不把监护签署时间假充本人的同意时间。
- 明确的新证据须为有限、在接受之后、当前之前且已满六岁的时间。缺失、未来或不满足条件的证据不能授权实际服务。已取消、已过期和已结束项不会被迁移复活。归一化可重复执行，不产生扣款、物资或新同意事件。

## 离线验证

主测试 `tests/long-care-age-consent.test.ts` 使用真实最终编号菜单建立照护提议、监护人签约，推进到六岁生日，再经编号菜单独立同意或拒绝。涵盖：

- 两种居民处理顺序、最后0.25分钟无供餐回执/扣料/收费，独立同意后完整服务只结算一次。
- 初次待签与生日暂停的不同期限、旧提议跨生日才接受、原拒绝和他人代填被挡、仅表达或完全失能的安全暂停。
- 照护者原有限分支、暂停期间独立关闭、远方原承诺拒绝、暂停时钟下即时停止。
- 旧档幂等迁移、有效旧本人同意的保留、工作集SQLite重载、原ID与预付款保留、回执重放、陈旧提交不能覆盖生日暂停或已拒绝状态。
