# 谷灵：落果与自然再生的供给审查

依据[谷灵规格](../world-upgrade/GUARDIAN.md)的落果守恒与间接增产要求。在同一初始小山谷的两个独立内存 SQLite 中，比较不落果与一次批准落果、无人拾取两种情况。果源 `mvp-supply-fruit-0` 有 12 份上限，实际自然再生率为每天 1.6 份，起点进度为零。测试用真实已结束的雨、实际隔离落果审批与提交、现有生产资源更新函数；未运行居民行为、长期循环或真实模型。

| 同一起点后 | 无落果：源／地面／居民 | 一次落果：源／地面／居民 |
|---|---:|---:|
| 刚落果 | 12／0／0 | 11／1／0 |
| +899 游戏分钟 | 12／0／0 | 11／1／0 |
| +900 游戏分钟 | 12／0／0 | 12／1／0 |

落果事务立即扣源一份、加地面一份，两组总量均为 12。到第 900 分钟，落果造成的空位让原本会被满源丢弃的自然再生积累出一份，随后两组源库存均回到 12；落果组地面仍有原来那份，实物供给总量因此是 13 对 12。仍只有一张落果收据，居民均未拾取或获益。这个差额应归为自然再生的间接产出，而不是第二次落果，也不是居民受益。固定政策下的一次验证不能估计连续放行后的供给总量。

该行为符合规格已指出的间接增产路径，但不支持“只搬运、在任何时间都不影响总供给”的说法。生产启用前建议明确审批每个可再生果源的额度与冷却，并分开统计实际源扣除／地面增加、自然再生、可获得存量、实际拾取。当前不改动成熟规则、不自动放行或补偿，也不把这一次隔离样本作为提测或上线依据。若游戏设计要求相对于未落果的对照严格零增量，需另定未拾取地面库存是否占用原果源的再生容量，不能仅靠落果事务的瞬时守恒保证。
