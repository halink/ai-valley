# 谷灵：私有临时文件的重启恢复

独立开发夹具能在两次进程之间验证落果事务恢复；这不是生产存档接入。内存夹具仍可独立使用。普通世界入口、浏览器快照、真实模型、用户存档和 G1 队列不引用私有文件入口。普通存档打开逻辑即使只看到空夹具的数据库标记也拒绝；不能用配置选项传入任意数据库路径获得夹具写权限。

创建必须显式指定演示承载上限，随后只在 Linux 本地文件系统的随机 0700 临时目录中创建独占空 SQLite 文件。打开或重开必须持有隔离的续开凭证，校验目录、数据库 inode 和私有清单，取得描述符锚定的 SQLite 运行锁，再在私有只读副本上核对清单对应的数据库认证标记、版本、唯一世界及实际效果档案。凭证只在本地测试进程之间传递，不发布、不输出到进展或 HTTP。复制、替换、改配额、陌生格式或档案不一致都拒绝先写，不自动修复。它以遵守运行锁的本地工具为边界，不是同一用户任意进程的沙盒。

实际世界、落果原始批次、收据和观察者事实沿用原有原子提交。文件重开只认可同一事务中的权威收据；补写测试镜像不执行世界效果，也不第二次扣果。未创建居民拾取路径或证明真实线上档案恢复。完整生产权限、配额、候选调度和跨进程服务仍关闭。

开发验证使用新建的私有临时文件，无用户存档。四项局部检查覆盖无凭证/错误凭证、重复申请所有权、换文件或移植目录、篡改封印/容量。第一个短进程在已提交但未显式关闭 SQLite 的状态退出，让第二个从 WAL 核对同一果源扣一份、同一地面一份、同一收据且重放不再扣果；另验证缺少对应事实档案时拒绝重开，普通世界入口也在写之前拒绝使用。局部测试文件不提交、不推送；不运行长测，谷灵未提测。
