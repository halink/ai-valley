# 谷灵全量开发交接门槛

设计以 [谷灵](../world-upgrade/GUARDIAN.md) 和相关决策记录为准。**只有 G0、G1、G2 的设计功能全部实现，且开发侧完成本地单元测试与快速功能验证后，才可交给测试组。** 允许独立提交和备份，但中间批次只记为开发进度。详细、长时间及跨浏览器测试由测试组或项目所有者安排；测试源码和执行产物不提交。

| 阶段 | 交接前需有的实施证据 |
| --- | --- |
| G0 客观观测与模型年鉴 | 持久来源、明确缺失、时间和来源可复查；模型只接当前允许的版本化字段（发送字段快照与权限版本可追溯）；发送前、发布前及各读取面重验；无模型时显示客观记录，不冒充模型；更正、撤回、异常中断和恢复有明确状态。 |
| G1 选题及沙盒 | 只读选题、依据和配额；结构化候选、证据、版本、截止、成本与冷却；隔离预检不会改写真实存档、通知、知识或预算，候选不具执行权。 |
| G2 雨后落果 | 权威已发生且持久的雨事件，成熟果源和目标现场合法；源扣除与地面增加守恒，归属不变；居民仅现场发现、自主拾取；版本无关的机会标识、同事务的收据和结果、防重及中断恢复；提议、效果、发现、拾取分别记账，另审查累计自然恢复和实际供给。 |
| 横切保障 | 共享账户限额与居民优先、具体类型的批准和默认关闭、版本未知时按影响隔离或暂停、关闭后仍能解释既有效果。以合成输入及注入替身验证，不调用真实供应商。 |

可以实现并验证默认关闭的能力，不能把“具备实现”当作“已启用”。真实模型调度受现行账户授权、共享准入与失败恢复约束；G2 生产执行另需单类型批准。交接时须列出确切版本、启动方式、可重现步骤、预期结果、未验证范围和哪些能力保持关闭。

观察页「谷灵」下可读取最近 24 个已结束小时的档案，也可查看最新已发布年鉴。没有获准发布条目时，客户端明确回退到客观档案；这个界面不会触发模型生成。换世界、重新连接或失去发布许可时清空已有页面数据。

## 当前开发检查点（尚不可提测）

- G0：客观天气档案已接入游戏，年鉴查询可显示已发布条目或诚实回退。模型选材、权限复核、事实校验、发布和共享准入在隔离环境走通。已新增私有进食收据和明确发布授权的存储；仍需把到场、收听等生活事实接到引擎与年鉴，并接通受同一账户约束的运行时。
- G1：公开事实选题、私有候选队列和只读预检已有实现；候选验证不等于授权。实际候选的受控驱动和完整队列调度仍在接入。
- G2：已用真实规则步触发已结束的降雨，再在隔离 SQLite 内守恒落果；权威收据可以补写失败的镜像。在专用开发存档中，居民已经可以现场发现并真正拾取，一份地面果实原子转入本人库存。真实跨进程恢复确认已有收据不会重复扣果，普通运行入口仍不启用落果。四层公平投影已有独立模块；生产调度、配置和批准仍不能当作完成。

### 最新开发检查点（仍不可提测）

- G0：开发夹具的生活年鉴已接隔离发布、原版约束更正和 Godot 读取。每次权威快照分别复核生活条目，撤回只清除生活版，不影响仍获准的天气档案。正式到场凭证已接独立、默认关闭的单来源离线发布和撤回；保留原世界身份，需独立披露批准。普通交谈的收听证明仍只在显式开发入口私有保存。上述正式到场离线发布不等于正式年鉴 UI 或正式公开授权流程。天气年鉴与居民共用配额已在离线季节运行时验证，合成 HTTP 调度现也能在模拟交接前绑定共享配额；结果未知时不重发，已有确证时可补结算而不重开原运行。正式入口和模型供应商仍未接入。
- G1：封存开发存档已接权威雨、合法地块、公开天气依据、编号候选及有界影子评估。正式世界有默认关闭的原生降雨记录及同存档地理核查，可核对已闭合降雨、原生可采浆果和可达公共地块；结果仅证明地理与当前库存条件，不是已批准或可执行的落果。正式地面果实能力、选题权限和调度器尚未接通。
- G2：封存 MVP 开发存档可持久排期，签批及时限由事务内复核；中断后先查权威收据，排期镜像不能证明执行。封存正式开发存档也能对单笔独立签批的原生浆果执行原子转移，写入公共地面浆果和收据，保留原世界身份；重开不会再次扣果。封存正式档的离线居民决策可从本人现场发现的私有菜单选择步行拾取；复走原生行动和路径，结算才把原批次浆果转入本人库存，不延长鲜度、不自动进食。地面已拾取标记、原生食品账和绑定原行动的私有收据同事务提交。正式普通运行、真实居民模型接线及正式批准仍未启用。满载果源的落果对照见[间接供给审计](valley-spirit-renewal-audit.md)：腾出的空位可让规则自然再生，不能计为额外落果。

封存正式档 G1 可选接线使用独立于落果签批准的封存审阅公钥。审阅许可版本只授权本档某次已闭合原生雨及精确候选地址的影子投影，支持拒绝、撤回和期限；不发布天气，也不能批准 G2。离线步骤只选合法菜单中的编号 1，私有候选保留正式机会身份、原雨起止、世界修订、权限/菜单版本、期效、冷却和零模型用量。独立账坏时隔离，不改写它、不阻断正常世界；公平核对仅统计实际持久候选。此开发接线不证明正式调度、发布或 G2 授权；整份开发档回退不是受保护的操作。

双密钥封存正式档的新 G2 落果另需独立效果签批，精确绑定本档现行 G1 审阅与候选的摘要及许可版本。只可在同一已核对世界修订和分钟内执行；撤回、过期、世界前进或候选账不可读时拒绝新扣减。已经入账的效果仍由世界锚和原签批只读重放，不能因撤权重复，也不能靠旧候选产生新效果。原单密钥封存档的既有验证与重放保持不变。

封存正式档可为仍有效的原提议写入一条有界排期意向，无库存预占、扣减或执行权。到期以实际世界时钟和同档 SQLite 状态重查原许可、同次闭合雨、源和地块、容量及食品规则，只写不可执行的新鲜检查点。过期、撤权和尚未判定都不解释为已执行；历史检查点不能让 v3 签批跨修订生效。到期执行仍需独立新版签批，本阶段没有执行器。

双密钥封存档的延期签批另用 v4-due。它必须匹配持久排期、原审阅、到期证据摘要和真实同一世界修订／分钟。写入前在同一事务重算雨、位置、库存、容量和原食品规则；不接受只看历史检查点或排期镜像，仍不预占、不换地点。执行结果只按权威效果收据认定，重开可读重放，不重复扣果；普通运行和自动调度未接入。

Godot SQLite 本地规则运行器可在内部显式启用 G1 地理探针；缺省关闭。它只在世界提交后按游戏时间有界抽查，并用当前天气许可中确实落在同一已闭合原生雨窗的存档记录；旧许可被撤回后不能由重开或恢复许可复活。返回仅表示当前公共果源和落点的地理条件，未安装地面承载或拾取，不能验证或执行。没有候选持久化、模型请求、HTTP ／ Godot UI 接线或默认无存档演示变更。

Godot SQLite 私有地理观测还可在权限仅限本机当前所有者的开发档中，通过独立选项留存。每个原雨和果源机会只留首见，落点、雨窗、实际雨点及当时许可绑定在同一私有记录；重开或恢复新的许可都不会替换早前记录。没有真实雨点就不创建记录或表。该有界附属账独立于世界事务，不是候选队列、执行审批、生产配置或公开输出。

### 当前隔离验证补充

- **年鉴**：Godot 持久规则入口可单独接上已获准的交谈章节，只读、默认关闭。天气和生活合编已在封存开发库中使用同一 SQLite 快照核对两个当前许可及原生事实，按独立签名保存确切版次；重开仍要复核。现有公开路径和正式模型年鉴未切换。
- **原生拾取**：封存 MVP 档已快速走通独立签批落果、本人发现、真实走一格、重开与完成移动、原优先级允许才在另一事务拾取；更紧急的原生行动仍优先。普通运行未接入该循环。
- **供给和果龄**：单次提交中的普通采集与自然再生均有独立流量证据，未知果龄保持未知；封存开发档另有与原生再生同事务的精确果源凭证。凭证无到期规则、不授权放置，普通果源批次的持久余量、到期和转移仍未接通。

正式居民运行已有默认关闭的共享配额模拟接线：仅允许绑定新鲜离线运行、确切存档、同账户与策略，居民实际排队优先；世界提交不替代请求结算，故障保持结果未知。此处不调用供应商、不发送正式年鉴。正式约见的提议与接受也可在独立显式开启的存档分开保存原生私有凭证，不以到场反推或开放披露。

封存短测不等同于已接入普通玩家运行。三阶段仍未达到整套提测门槛。

Godot SQLite 本地持久规则运行可显式开启私有 G1 地理候选队列，缺省关闭。只在实际规则 :59→:00 世界提交成功后，以同一持锁存档重读该小时、已闭合的原生降雨、仍有效的对应公开雨点许可、本档登记果源和合法地块，最多记录一个有界地理提议。该观测单独存放在独立文件和严格版本格式中，旧影子候选队列不读取且不受它限额或去重影响。队列重开保持原记录，不补写漏掉整点，撤权、证据缺失、达到上限或附属账异常均不产生新提议。此类 `proposed` 记录与完整影子预检隔离，不进入排期，不晋级，不修改世界、库存或居民知识，不为见证者产生通知，不开放队列读路由或真实模型。这不是正式 G2 授权或生产调度。

封存 Formal 私有 owner 可显式为一笔仍在等待的已持久排期布置一次到期预检。这一布置只在当前句柄内生效；只认原生规则恰好推进一分钟、跨过排期起点且严格早于截止的世界提交。预检在另一个事务中重读同档同头，并复核原有签审、闭雨、时限、权属、果源、容量与食物来路。失败或撤回不写检查点，不回滚世界，不补做启动前落下的时点；既有手动核对仍可用。没有新的执行批准、落果、普通正式启动或公开接线。

同一封存 Formal owner 也可显式安排一次候选生成时点。只绑定已存在的当前独立许可及其具体窗口，规则真实推进一分钟并提交后，在另一事务内重新检查该许可和同一世界版本，复用原来的编号选择和去重。未布置、重启、撤回或换许可、错过窗口及影子账异常均不生成；失败不回滚已提交世界。生成的封存候选可由拥有者另行进入既有显式排期，不自动排期、签批、落果，不读取普通地理观测，也不开放正式启动或模型。

### 交接时的版本与恢复口径

- **恢复代码**：以 GitHub 上交接记录指明的完整提交号检出源码和文档。GitHub 不保存本机存档、模型账户账本、临时测试或本机审计凭证。交接记录应标注同一提交对应的本地短测及未验证范围，不把其他版本的通过结果沿用过来。
- **恢复存档**：如需恢复世界数据，按[存档恢复步骤](../deployment.md#回滚程序与恢复数据)处理匹配版本的独立备份。恢复后核对世界身份、游戏时间、居民和库存。世界恢复成功不代表[天气历史审计](valley-spirit-formal-rain.md)通过：后者绑定原本机的世界、账户登记库和配额账文件身份。复制或迁移后，不以正常载入推断审计通过，也不为补证重新派发模型请求。
- **后续试玩**：要观察世界随时间推进，按 [README 的持久规则小山谷步骤](../../README.md#持久规则小山谷无模型)启动：导出 Godot Web 后，用新演示存档运行 `npm run dev:web:rules:persistent`，在同一台电脑打开 <http://127.0.0.1:3416>。不要复用正式档，也不要误用无模型时会停钟的 3415 入口。现有客观档案可作为起点；私有离线阅览和封存档不属于普通试玩流程。待整套达到提测门槛，再附该提交下可复现的首个玩家可见现象及对应操作。

原生一次性开发档的 G2 接线与上面各封存实验分开验收。只在新建、无 HTTP 的开发存档中，复用普通原生规则和 WorldStore 做独立双签落地、本人首次发现、一格可达时自主步行、到场且原生移动结束后再自主拾取，以及不混入普通库存的原龄持有。居民饥饿且没有优先食物、没有优先共屋餐位时，可在户外原位走完五个实际工作分钟；已有可使用的优先共屋餐位时，须先实际走到入口、进屋并抵座，五个实际工作分钟各自占到本人餐位；同一事务结算真实营养、扣一份私有持有量并写不带果实出处的普通动作事件。到期优先，重开不重扣。撤回天气出处不会改变已发生的物理结果，但会关闭私有证据查阅。其它封存路线和正式发布仍须各自验收；普通玩家入口也没有读取或启用落果。

开发档的一格前往不预占果实。在此前已亲自发现、又已实际在场的另一居民若先真实完成拾取，规则按该分钟实际发生顺序保留或阻止原路线的脚步，并同一事务结案、转为胜出者的原龄持有。尝试失败不会取消路线，不将同分钟未排序的观察算作额外发现。

普通规则 G1 私有签名审查现可对同一已提交头、当前天气公开权限、原龄果批及受控空地做一份果实的脱离式守恒对照。候选仍为地理建议：两侧保留同一果批、权属及原始生效与到期时刻，不更改存档、预算或世界。正式落地、发现、拾取与独立 G2 授权仍未齐，结果明确为阻塞，不是已通过的运行预检。

普通规则的私有已签同头审查还可在内存副本演练两个原生游戏分钟：搬入一份原龄果只发生在副本，之后由现有观察和闲置选择器分别确认有人实际发现、自主选择拾取。未能验证观察、未能验证拾取选择、或无法在果批原始到期前走完两分钟，均单列；通过仅说明这次隔离选择，未产生居民库存、运行收据、普通落地权限或 G2 授权。签名审查和候选必须在现实起点和返回前重读的已提交头仍有效；假想分钟仅受果批原始物理到期约束，不续发权限，也不证明未来实际世界头的权限。撤权或依据变化不返回演练结果。

普通持久规则可由本机拥有者显式启用 `privateOrdinaryAgedG1Decision: true`（需同时配置原 G1 审核、既有果源／落点及关闭自动步进）。先核验原签审并重放两分钟隔离演练，再由同一已固定审核人对用途独立的决定签章。只记录原生发现和自主拾取都获证的 `validated_detached`；未观察到、不确定或已失效均不记为拒绝。签章绑定原签审、原地理提议、原龄果批、同一物理存档的原生压缩头与游戏时刻、当时公开天气许可、审核纪元，以及不包含居民身份或证据标识的演练结果摘要。私有附属表、审阅纪元镜像与完整性锚同一 SQLite 事务保存，单档至多 32 项，不覆盖；同头相同签章重读不重复写入。重开原档仍须按当前权限重核原证与结果，推进、撤权、换审核纪元或证据／锚异常均不可作为当前结论。原档以更高审核纪元成功打开时，即使没有新决定也持久推进审阅下限，旧纪元不能因重开恢复。未开启选项时不读取或写入该表；不复制到普通 API、Godot、公开年鉴、地理提议或 G2 队列，不授排期、落地、拾取、通知或任何实际居民作用。依赖本机协作锁；不声称防止绕过锁的并发原始文件写入、整档一致回退或连同锚一起删除。
