# 共享室内出口失败边界

## 提交审查发现的问题

赠粮原点返回在提交前独立复核中暴露了共享出口问题：收方在另一间房屋，真实入口被暂存遗体挡住，`roomPath(current, entry)` 为 `null`。旧 `prepareRoomExit` 把它和成功的空路径一起处理，直接清空 `inside/roomAt`，于是首个0.25分钟就开始室外路线。后续赠粮旅行检查已经失去原室内位置，无法补救。

这不是居民拒绝等待或没有选择正确动作。它是可重复的物理路线错误，也影响复用出口的普通移动。修前6385项全量通过没有覆盖此边界，不能作为修后验收。

## 实现

- 共享纯出口规划区分不可达的 `null` 和已经身处真实入口的 `[]`。当前房屋、门外坐标、室内整数坐标及入口必须真实存在，起点和入口均不能被阻挡；缺失坐标不再默认为门口。
- `prepareRoomExit` 保留既有不需要出门的分支，返回明确错误，不自行生成替代行动。引擎在预留遗体/墓位之前只读预检，在预留成功之后才应用退出，避免预留失败却已经离屋。
- 遗体、医疗两分支、家庭接送及动物搬运，在初次拾起/材料扣减/取消他人计划/写入搬运状态之前预检必要出口。明确同屋且没有室外路径的工作不被无关出口阻挡误伤。遗体使用只读候选世界，只有本次合法拾起的那具遗体不再作为障碍，其他遗体仍阻挡。
- 已有退出活动每次实际移动前检查房屋身份、门坐标、目标入口、当前点、下一格和一格邻接；到真实入口前不能清空室内位置。途中路线失效会原地失败，不自动换路。
- 旧存档若保留室内位置和已选室外路线，但没有退出活动，补建真实室内路段或失败，不能沿室外路径直接抹掉室内位置。没有新增存档字段或自动决定。
- 原地等待、进食、立即拒绝/撤回及合法同屋工作保持原语义。退出本身不新增房屋进入权，出口校验不要求居民拥有该房屋。
