# 救援后的近身观察与接续核实

本切片修复一个观察缺口：成人已经被真实护送到干地，但仍不能自行决定且饥饿，既有 `context.people` 只写“在附近”，模型提示也没有读出这些人物的身体迹象；健康面板则把未结束病例标题写成“目前需要照护的人”，无病例会被误读成无人需要照护。

本次只改观察投影与只读呈现，不增加照护行动或扩大任何权限。新天气调度保持关闭。

## 居民此刻能知道什么

`observeBody` 是只读白名单投影。只有可观察、没有原地睡眠的居民，在与对方真实可接近的两格范围内，才取得当前时刻的粗粒度迹象。

- 双方必须存活并实际在谷内；同一人物不通过这个入口读取自己。自己身体仍用原有个人上下文。
- 室内必须有同一建筑、正确门坐标、双方真实且有效的室内坐标，以及至多两步的房间路径。缺坐标不回填入口；不跨房间、隔墙或从室外看到室内。
- 户外检查真实地图坐标、物理障碍和至多两步接近路径。远方已知姓名、亲属关系、传闻和过去的护送身份都不能绕过门槛。
- 本切片不覆盖渡船上的身体观察，包括同船与岸船接触。不能把共享地图坐标当作床边接触。
- 睡眠者只显示睡眠，不借此判断失能、饥饿或虚弱；睡眠中的观察者没有新观察。

输出仅为 `atMinute` 与 `signs`。它把既有模拟身体状态映射为有限粗粒度迹象：自主应对需要核实、表达受限、明显饥饿、十分疲惫或身体虚弱。饥饿使用既有照护观察门槛70，疲惫15，虚弱35；精确数值不进入这项投影。未出现迹象不证明健康，也不证明没有需要。

选择能力写作“自主应对受限，需当面核实本人的选择能力”，不是医学诊断或法律能力判定。表达限制单独显示，并明确不能据此认定没有决定能力或已经同意。底层没有独立的居民口渴指标，因此不从水量、饥饿或运输消耗反推口渴、脱水或已经喝水。也不披露诊断、严重程度、病因、财产、库存、私密计划、拒绝标记或远处的照护安排。

`decisionContext.people` 带入该瞬时投影，最终 `prompt` 只呈现与当前上下文同一时刻的迹象，不将整个附近人物记录搬入提示。监护人的身体备注复用同一门槛，移除原先精确的幼儿饥饿/健康数值旁路；既有喂养菜单文字也不再附带精确饥饿值，行动可用条件不变。观察范围外仍记得登记关系，但不会据此刷新对方身体。

这些文字不会注册新照护观察、通知他人、创建事件或修改记忆。需要留存或亲自告知时仍使用原有可选行动及其权限。原病例、运输、事件和个人见闻保持原样。

## 观察者界面的两个问题分开回答

1. **已登记的持续伤病**：仅列未结束病例。空状态明确说明，没有病例不表示自主能力已经恢复或不需接续照护。
2. **当前能力与待核实的接续照护**：列在谷内存活、当前决定或表达能力受限者，以及有既有已结束救援记录且仍有上述身体需要的人。人物档案也使用同一说明。当前能力状态是观察者对权威世界的读取，不广播给远处居民。

第二项对照当前情况和最近一条运输记录，不建立运输与当前需要的因果关系，不推断已经交接或没有人照料。送达、附近有人、持有物资或已有照护合同都不证明已经进食饮水或获得持续照护；页面提供已有照护与真实交接记录的只读入口。照护需要与实际履约仍须分别核实。

能力恢复且没有当前身体迹象后，当前提示消失；旧运输结果继续保留。死亡或离谷者不显示为当前在谷接续项目。旧记录缺床位时显示“接收床位未登记”，不再凭 delivered 补造床位。原 reason、时间和运输字段不被重写。

## 权限与未完成事项

- 不改变 `canDecide`、`canExpress`、监护人、房屋或床位。
- 不增加选项、自动代决、自动接班、喂食饮水、药物处理或长期照护授权。
- 新元数据有无不改变最终行动列表；原动作执行条件仍独立重验。
- 这不是完整症状观察模型、成人代理照护制度、救援交接协议或居民口渴系统。仍失能且没有可合法履行的接续者时，系统只准确展示需要核实，不自动替其安排。
