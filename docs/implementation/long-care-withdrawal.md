# 长期照护：本人的即时停止

## 原问题与边界

已有长期照护受益人仍能表达、但暂时不能完整决定时，原菜单和 `submitPlan` 会共同挡住取消。完整能力本人提交取消也要另走一分钟动作；若提供者只剩 0.25 分钟服务，提供者会先扣料收费。

此次只补充停止本人原合约的表达入口。不恢复 `canDecide`，不替本人选择，不创造新照护同意，不新增监护、成人代签、送水、医疗、交通或持续分支权限。其他签署人、提供者和当前监护人的既有取消规则继续要求完整能力。

## 实现

- `world/long-care-withdrawal.ts` 以当前世界中的原合约 ID 与受益人身份核验停止。本人必须在世、未离谷且 `canExpress=true`。可停止这份已提出、待孩子同意或生效中的照护；其他条款不能夹带在停止动作里。
- `longCareReason` 仅为原受益人的 `cancel` 采用窄表达校验。接受、同意、提供、开启、履行和交接保持原门槛。
- 普通一次照护与长期照护通过 `world/care-withdrawal.ts` 共用菜单、计划提交和 runtime 入口。真实菜单提供单项停止；仅能表达或已有其他计划时，只提供本人停止和短暂不停止，不赋予第二份工作计划。
- 合法停止在 `submitPlan` 内立即完成，早于下一次世界推进。只终止指定照护并退款，保留本人无关的既有计划、实际位置以及船只、护送、同行状态。短暂不停止也不替换已有计划。
- 远方已签约项沿用原 `promise.withdraw`，不靠内部实时状态显示或消失停止项。已在远方内部结算但本人尚未知时，停止只标记本人不再参与原承诺，不重复退款或透露结束原因。`promiseTarget` 与 `completePromise` 都拒绝夹带其他对象、合约或价款的混合 alias。
- 沿用原合约记录、预付款账户和计划回执，无需增加存档字段。保存重载、同一计划重放及能力恢复不会重复退款或重新开启已停合约。
- 服务工时与实际结算继续使用 `longCareReason` / `longCareWorkError` 复验原合约状态、当前拒绝、提供者能力、时窗、实际相邻和自有物资。停止后仍在队列中的服务不能扣料、改善需求或收费。

## 验证

只使用隔离生成世界、内存 SQLite 和注入的离线决定函数。最初三个主回归全部失败，分别复现菜单缺失、最后 0.25 分钟的取消竞态、重载后无法表达停止。

主测试 `tests/long-care-withdrawal.test.ts` 覆盖：真实最终菜单与 parseChoice、两个居民处理顺序、即时退款守恒、同一身份重载与回执重放、表达/死亡/离谷变化、儿童窄停止、伪造/混合动作、材料与拒绝变化、无关计划保留、远方信息边界、离线 runtime 调度，以及护送与船上停止不改交通状态。

独立测试与审查见 [长期照护本人停止：独立反例审查](../reviews/long-care-withdrawal.md)。独立审查发现的远方 alias 缺失和完整能力混合 alias 绕行均先有失败反例，再修复转绿。
