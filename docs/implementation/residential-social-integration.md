# 有限住宅租住与现场交互

2026-11-07 的跨系统回归发现：有效住宅租客可以实际走到原屋第 1 张床休息，但 `socialSpace` 的室内权限集合没有接入既有 `residentialStay`。因此产权人与租客明明在同一房间相邻位置，基本紧急照护却返回“未实际在场”，交往/结婚确认及可信丧讯也被拦截。

## 最小修复与边界

`src/world/relationships.ts` 只补上既有住宅租住谓词。它继续由 `currentPremisesLease` 核验已经接受、仍有效且尚未结束的租约、原产权、完好住宅、真实容量，以及租客在世且没有离谷；时间窗口为 `[acceptedAt, endsAt)`。不复制一套容易漂移的状态规则，也不等待下一次结算才停止授权。

这只补足本人已有有限住宿权在现场互动中的识别。双方仍分别检查权限，门内外/不同建筑不能匹配，路径必须可达且不超过两格。厨房、经营工位、第三方访问、永久入住、邀请同住和监护没有新增权限，也没有改写 `homeId` 或建筑住户名单。

`socialSpace` 不强制患者清醒；一次基本救急仍由 `careAuthority` 独立核验失能、实际危险、拒绝和及时代理。交往、结婚以及丧讯继续用 `socialPresence` 核验清醒状态，承租本身不等于同意，也不能把传来的丧讯升级为亲见死亡证据。租约到期、中途交还或原址失效不会瞬移身体、背包或重写既有关系。

## 隔离回归

[8 项跨系统测试](../../tests/residential-social-integration.test.ts)覆盖：

- 实际租床睡眠后，通过真实最终菜单执行同房紧急照护，仅消耗施救者的一份饭和水，保留住宅与监护边界。
- 租客反过来施救；有完整能力、失能但不危急、拒绝或存在及时代理时，不凭租约获得紧急权限。
- 双方分别经真实菜单、世界时钟完成交往和结婚，仍不能使用租屋厨房或给予第三方同住权。
- 已核实死亡消息向清醒租客当面送达；睡眠中拒绝，SQLite 内存重载后保留有限租住及已收消息，仍不制造亲见证据。
- 未开始、精确到期、提前结束、未接受、已撤回、损坏、产权变化、容量消失、用途变化、死亡及离谷直接使租住依据失效，即使账本状态尚未结算；照护失败不消耗物资。
- 未签报价、拒绝、实际交还和有效经营租约不冒充住宅交互权；第三方、门内外、异室、远距、阻塞端点和需绕行的障碍仍拒绝。
- 照护执行中或关系回复完成前到期，不消耗耗材、不产生追溯同意，也不把租客移出室内。

最初复现时本组 **6 项失败、2 项通过**；修复后 **8/8 通过**。独立审查结果及扩大验证见[复核记录](../reviews/residential-social-integration.md)。这些是内存夹具与离线规则验证，不代表真实模型、视觉或多年运行验收完成。
