# 居民与谷灵的共享账户账本（开发中）

独立 SQLite 保存单个账户的冻结配额策略和请求身份。账户总 RPM、TPM、并发同时核验；年鉴另有限额、冷却，给居民留足三种容量，存在居民等待时不再接纳新年鉴。已登记的等待、尚未发出的保留和疑似实发都跨重启保留；已发生的可选负载不因居民新到而假退款。只有允许调用该内部服务的账户持有者可以更新等待队列。

- 租约沿用 descriptor-anchored runtime lock 和 SQLite 事务，使用专用数据库，不创建或改写世界数据库。开户要显式同意创建，重新打开要提供完全一致的冻结策略；只读预检不认识的表、版本或损坏状态时阻断该账户。
- 外发前事务记录可能已发的阶段。取消只适用于仍未获发送许可的保留；未知请求的槽、估计 token 和请求数不能因计费窗口滚动、重启或本地中断而跳过。只有可信的完成证据才释放槽并按可信实际用量更新，缺失用量保留保守估计；超出原估计的实际用量制约后续准入。
- 请求 ID 不循环。暂保留最多 4096 条、达到上限就阻断，不截断未知请求，也不把陈旧 ID 当新请求。时间参数由将来的可信调度方提供，倒退拒绝。现阶段没有自动清账、热换配额或事务外远端对账。

离线谷灵调度可注入专用适配器走同一账本；它不包含真实模型客户端、地址、配置或默认模型参数。实际部署仍须把同一供应商账户永久绑定到唯一账本路径／服务，由居民入口和谷灵共同接入，落实账户授权与真实配额、账本持久备份和防回滚、可核实投递／用量对账与可靠时钟。对正在出账的真实运行账户，不能以新账本替代未对账请求。当前系统没有启用该生产入口，不能据此认为谷灵已可提测。

本地快速验证覆盖保留量和居民优先、账本重开、跨窗口未知与幂等身份、实际用量修正、单持有者／未知版本不覆盖，以及离线谷灵与居民共享账本。未调用任何真实供应商，单元测试仅保留当地工作区。

## 居民侧离线接入准备

受信任的居民调度器必须先登记稳定的「世界／居民／决策轮」等待标识，再让谷灵请求可选账户额度。离线居民准入适配器和离线年鉴适配器可以共用同一账本；居民请求身份不因请求体、进程重启或重试而变化。复制相同决策轮、未确定发送后或已经确认完成后不会再次执行。明确尚未开始发送的保留可以取消，超时、异常、重启不能替代送达与用量对账。完成后若权限已变化，仅记账、不交付该回复。

此适配器拒绝非离线账户标识，只接注入的本地合成回包，不接真实供应商。现有居民运行时按每个模型初始化自己的短期额度账，重试键与受理动作并未形成可跨重启的稳定账户决策轮。生产接入还须在请求前从权威世界／请求账建立稳定决策轮及排队边界，持久化收件和动作提交的恢复归属，选定唯一已审查账户并完成往期未知投递与账单对账；不能直接包裹现有自动重试回调或创建一个换名账本来规避历史约束。正式启动与真实模型开关均未改变。
