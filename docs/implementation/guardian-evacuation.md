# 健康幼儿的有限监护灾害护送

后续[成人紧急短程撤险](adult-emergency-evacuation.md)新增独立的非危重失能成人干地入口；不扩张下文的幼儿监护或医疗权限。以下历史验证与其原范围保持。

## 范围与自主权

后续[无床附近干地撤险](safe-ground-evacuation.md)新增独立无床选择，支持户外可见干地以及室内先实际出门、再现场选点。下文保留原送床入口及其历史验证，不把干地落脚等同于送床。

后续[室内已知地址护送](indoor-guardian-evacuation.md)已补上同处灾屋监护人的有限入口：实际接出并步行，到门口才核验与保留床位，不泄露或预占远方空床。下述原入口的本地核验路径仍保留。该次后续稳定代码全仓1492/1492通过，具体范围和证据见链接。

最初交付补上健康幼儿的正常决定菜单入口，复用已有 `health.rescue`，不新增自动救援、强制疏散、药物处理、家庭迁居或监护授权。原 `rescuePatients` 伤病筛选未扩大，因此不会为健康幼儿顺带生成不必要的 `stabilize`、就诊或护送提议。

- 当前监护人须是有决定和表达能力的成年人，仍符合已有护送的体力与健康要求；孩子须在本地存活、未满6岁、没有拒绝，且双方在同一实际可接触场所。
- 监护人须能现场观察，且尚未消退的已见灾害真实覆盖孩子所在位置。已实际可见的预警迹象也可成为提前护送的理由；仅在旧半径内、实际洪区外不够，已有有效建筑遮蔽也不够。洪区、旧记录半径和风暴遮蔽复用既有物理判定。
- 新入口仅枚举眼前可以检查、本人已知且有权使用的诊所或会馆。必须有真实可用的床、实际可走路线和本人1布料、1清水，不提供无床的干地抱送。暂时没人躺着不等于无主床：其他有效登记居民仍持有的原床位、借住与租约、已保留运输床、实际占床及近期照护安排都须保留。先核验候选，再限制最终展示，避免前几个无关居民或无效建筑遮住真正可行的选项。
- 最终菜单在56项总限额内保留最多2个轮换选项，仍保留等待、进食和其他个人决定。读取菜单不改变位置、库存或计划，不会替监护人选择。
- 孩子拒绝或当前监护关系失效会阻止接出并停止后续移动。有决定和表达能力的幼儿乘员可以从实际菜单单独停止自己的护送；年龄规则只放行护送拒绝/停止，不开放其他成人行为。停止仍由运输规则核验本人身份。

## 真实接出、路线与重载

新菜单的既有救助动作带有可选 `evacuationDangerId`，实际运输记录保存同一编号，不修改旧医疗护送记录。模型只能选择菜单项，不能填写或改写该字段。

接出前及实际接出劳动期间，重新检查原危险、现场接触、孩子意愿与监护职责。原危险消退或不再覆盖孩子时，不再凭这项旧选择搬动孩子，也不扣布水。实际接出完成才扣除本人1布1水，保留一张床、取消孩子原独立活动，并沿实际路线走入指定床位。

接出后的路程持续检查监护、拒绝、接收权、床位和可观察的目的地风险。离开原洪区或原灾害随后结束，是护送的正常结果，不把孩子中途放下；监护失效、拒绝、目标失效或实际道路变化则在真实当前位置停止。只对这次绑定灾害的幼儿护送复用已有撤离逐边约束：可以走出已占据的危险，不进入或重新进入另一已见洪区、预警或风暴。普通医疗护送保持既有权限与兼容行为。

SQLite内存重载测试覆盖接出前和运送中两个阶段：编号、实际位置与进度保持，失效选择不扣物资，已扣物资不重复扣，送达不重复记账。绑定不一致不能变成第二次接出。送入床位仍不代表已经治愈、有人接班、取得长期住所或完成灾后补给。

医疗目的地与现场核验的共同修复见[医疗接收地点安全](medical-destination.md)。
