# 规则小山谷：开始采集时的同分钟库存争用

从原第 56 日存档进行的独立跨季观察，在第 75 日（分钟 108655，仍为秋季）遇到本地规则停表：同一棵树起初仅剩一份木材，林禾先实际完成一份，许砚新选择的采集随后被引擎重验拒绝。旧规则入口只识别特定的在途采集失败，因而把启动争用当成故障，连同林禾的真实完成一起回滚。该旧样本未进入冬季，不能据此判定过冬或初春供餐。

- 引擎仅在开始采集的库存重验实际拒绝分支输出此次步骤的结构化失败，绑定居民、计划、资源、有效请求数量与当时可验证的库存。未知资源、无知情权限、非法数量、损坏种类或库存不产生此信号；不可实地观察的泉水/浆果不因诊断跳过原感知门。
- 本地规则入口只接受同一个步骤内、原先实际存量充足的**新**本地采集计划的同身份失败。该分钟继续正常结算：成功者只拿其实际采得的一份；失败者没有物资或完成信用，等待下个决策。其他意外失败不套用此恢复；既有在途失败处理、模型入口、资源刷新和配方不变。
- 信号只经本次推进的内部结果传递，不新增存档状态、公共观察信息或重试队列。

`npm run build && node scripts/acceptance-mvp-gather-contention.mjs` 从生成的场景验证有限泉水的争用、分数推进、争用前后 SQLite 重启、旧 pending/未知或损坏目标保留停表。可选传入本地旧故障 checkpoint 做隔离复现；脚本不会修改它，正式跨季应重新从原第 56 日起点运行，而不是把隔离重放当作验收续跑。
