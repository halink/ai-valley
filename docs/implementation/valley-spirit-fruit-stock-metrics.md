# 谷灵：落果供给的只读测量

`auditMvpSpiritFruitStock` 是默认关闭的隔离开发读取函数；不接入公开页面、运行入口、生产权限或玩家存档。只有明确指定隔离审计范围、已知作用记录及已经对齐的世界和资源时钟才返回结果。输入为一次可信、已提交的隔离快照；缺少数据不填零。

- **实际库存**：分别读取鲜果源、未拾取地面实物、仍在谷中活着的居民随身鲜果和其他居民记录的随身鲜果。地面合法格数不代表居民看见、走到或获得；合计只覆盖这三类位置，不计建筑、货运、遗产等其他库存，不声称是全谷可用存量。
- **已记录转移**：单列已提交的落果扣源、地面入账、实际拾取扣地面和个人入账，且用收据对账未拾取地面数量。普通采集、库存差或出现在地面都不是第二次谷灵产出。
- **普通自然再生与归因**：历史存档仅保留当前资源和分数进度，没有每次再生的独立完成记录；同期居民采集也会改变数量。历史实际再生量标为未记录，不能从净库存变化反推落果让多少果实长出来。只在显式选择时，从同一已提交快照克隆一个最多 1440 游戏分钟的窗口，不运行居民，直接使用现有再生规则，返回在固定输入假设下的计算结果。该计算不是实际发生记录、不归到谷灵名下。只有无落果、有落果且其他条件受控的对照，才可说明特定样本中的间接差额（见[单次对照](valley-spirit-renewal-audit.md)）。

若后续需要生产评估，须另行明确批准额度和冷却，并在普通资源再生事务中写入实际 **自然产出** 增量或流量收据，与采集、谷灵转移分别落账；单凭这一精确自然总量仍不能构造现场的无落果反事实。当前不冻结生产数值，不启动动态配额、不发通知、不把居民普通供给记为谷灵产出。

普通 Godot 规则会话现在有一个默认关闭的开发观察接点。有显式提交回调和观察者时，它仅在原生再生真正增加已登记公共鲜果源库存、且该刻世界成功提交后，交付该源的毛增量、再生前后数量、位置、时间和修订。同一刻普通采集抵消净增长，也不会抹掉实际自然再生。未接入生产启动、没有持久历史；旧存档仍不能补算，不据此推断谷灵贡献。

另有只读的离线批次鲜度工具。调用方需明确给出生效的版本化期限；工具仅把原生规则真实记下的成熟水果入账时点解释为该试验批次的出生，不用版本升级、旧库存、上次采摘或落地时间推断年龄。从精确到期时刻起视为过期。该工具不判断批次剩余量，不发出可转移对象；要支持普通落果，仍需把每次实际扣源和入账和批次余额一起提交。

普通 MVP 规则引擎已有默认关闭的单提交见证。显式开发观察者只能在世界实际提交后收到精确的期初／期末原生果源库存，由本刻成功采集与实际自然增长逐笔复核；同刻采一份又长一份，仍保留两笔毛流量。无变化的已提交时刻可以作为连续性检查点；启动、暂停、失败提交不产生记录。见证不写档、不公开，不把旧的标量库存解释成已知果龄，也不证明跨重启连续性。它只覆盖目前审查过的普通写入路径：新增能改果源的写入必须先纳入观察或不提供完整见证；只看净量无法发现相互抵消的未观察操作。

单次提交后的离线鲜度审计默认把期初库存视为未获证。只有同一次规则会话里连续交付的同世界、同果源、同库存前后头可以继承上一份内存审计；每份已知批次独立扣减当刻可能从它拿走的全部采集量，所得只是该批可能仍在的保守下限，不假定居民按先入先出拿果。真实再生在采集之后发生，可按显式冻结的离线期限纳入新批。到期仅是审计标记，不会让普通果源减少；零下限也不证明果实已被取走。剩余未覆盖库存不补填年龄。这些信息不授予拾取、落果或其他转移权限，序列化副本不能恢复证明；提交标记只来自受信任的会话提交回调后，不替代数据库收据。

封存开发库可另行运行一次原生规则分钟，若指定已登记果源在该分钟实际获得正整数自然增量，世界提交与一条私有来源凭证在同一 SQLite 事务完成。凭证只记录原生成熟入账时间、毛增量、位置和精确存档头；不回填开仓，也不固定期限。仅同一封存所有权且当前存档头原始内容仍完全匹配时可读，推进后不能沿用；不代表独立签批、保留、转移或落果权限。若同一刻还需要独立话语或供餐托管，本入口整步不写。普通运行和存档不开启该入口，也不写任何新地面数据。

可单独创建固定了独立果龄公钥和显式保鲜期的封存开发库。只有同一存档头的真实再生凭证可生成签名输入；签名绑定封存范围、果源原凭证、真实成熟入账时点与按固定政策算出的到期。验证只读，不改变果源、库存或地面，不让普通鲜果过期，不回填开仓，也不签批效果。换库、推进、改期限或换用途密钥都无法沿用；该机制不防整库恢复旧版本。

封存开发库另有单步普通生态入口：有无指定果源的再生都正常推进一个规则分钟，不指定则不写果源凭证。已实际送达的本人对话、已启用的天气托管和选定果源的真实新增可与世界同一事务保存，开启的托管失败时整步回滚。保留原生供餐行动与事件，不为它们新增私有供餐托管。没有环境外部请求、落果、公开接口或生产接线。

另有双公钥封存变体，只读生成或核对未来落地可能使用的条款编码。它先核对同一存档头的果龄签名、真实闭合雨和旧规则下合法且有余量的相邻落点，再把确切果源、修订、固定出生和到期以及一份数量绑定到另一把目的独立的公钥。携带的 G1 评估摘要没有独立核验；即使签名正确也只返回「G1 未核验」的编码结果，不构成落果授权，不启用新地面或拾取能力，既有 V1 路径不变。

封存开发档的带龄 G1 核对独立于旧版「只验签名」的条款。它必须从真实同一存档修订取得原生果实增量及独立签过的年龄，并重放持久编号候选的雨、已许可且实际观察到的雨点、站点、原候选摘要及有界队列。只读检查保留实际库容和当前冷却约束，不把旧版影子验证译成带龄携带。返回的摘要只可供人工核对；地面鲜度仍未安装，不是扣减、落地、调度或执行批准。

三钥封存审阅档可另用独立审阅密钥签精确带龄 G1 依据。每次核验从当前同一头重新取得真实候选、雨、授权和年龄；通过仅表示已审阅，不能排期或执行。唯一持久审阅状态是封存档里签名可单调递增的撤回代数，撤回立即使同头的旧签名失效，重开不重授权。旧双钥档不能启用此能力，旧版仅验签条款仍独立。整份数据库回滚不受此本地代数保护。

同一已打开的封存存档句柄会记住已提交过的最高审阅代数；若其 SQLite 行在原地被调低，该句柄隔离审阅和撤权，恢复原值也不会自动重新开放。新句柄与整份数据库回退不提供这层防护。

三把独立公钥的封存开发库可只读复核首笔 V2 出生条款。要求旧效果与拾取历史为空，从同一存档头重新核验真实果龄、G1 评估和审核签名、当前天气许可及审核版本，最后用第三把钥匙核对固定为一份、限在真实雨/果龄/提案窗口内的条款。即使核对通过也明确不授权执行，不写入 V2 元数据、地面、库存或事件。将来原子出生需要独立的执行签名域和持久关联防护；这份只读复核签名不能作为该签名使用。

封存实验可显式开启**首笔 V2 出生**，执行必须另用独立的签名域，不能使用只读复核签名。出生前在同一写锁重新核验原生果龄、严格当前 G1 审核版本／天气许可、真实雨、地块及一份额度。扣源一份、公共地面增加一份、保留原始出生及到期、观察事件与不可兼容依赖同事务写入。仅支持空 V1 效果／拾取前史，不沿用不明库存。出生后世界冻结，不允许普通加载、写入、拾取、过期或外部发布；同一签名重试只回原收据，重开走私有只读归档，依赖原始前驱、三份签名、世界/地面与归档事件完全一致。该保护不能抵抗整库回滚或同时替换全部历史依赖，不是生产启用。

封存 V2 归档可只读问某位居民在当前冻结世界内是否能看到并到达这份仍在原期限内的公共果实。校验实际视线、户外状态、可通行路径和公共用地，只返回可见位置或无结果；这不是已经发生的发现，不写记忆、事件、地面物品或拾取资格，也不公开。

首笔 V2 另可在同一显式封存执行句柄中完成一次到期：只有下一次真实原生规则分钟确实跨过出生时固定的期限才提交。临近前的安静分钟不会被推进或冒充到期；这不是自动老化系统。有开发天气托管，或该刻涉及尚不能与此路径共同保存的送达话语、供餐证据、同一果源变化时，整步无写入。该步骤留存所有适用的原生变化，另记一份地面终止事实，不再次扣源或增加居民水果；出生事实与原期限不变。重开仅用私有归档从原出生逐步复走原生分钟，与 SQLite 世界、追加事件和终止收据逐一核对，不允许普通 V2 加载、继续运行、拾取或发布。将来规则变更如不能复走这个版本的原生分钟则拒读，不以新规则反推旧结果。

同一封存 V2 试验还可选择有界连续推进，不混用旧的单步到期格式：显式从已核验修订推进一真实原生分钟，最多八次。每步独立追加确切时钟、前后状态摘要和原生事件；重新打开只可私有重放核对，不继续推进。安静分钟也可前进，但只有实际跨过原期限才终止地面果实。居民必须在原生观察阶段亲自在场、可见可达而且果实仍有效时，才留下一条该居民的第一次私有发现；重复看见不重复记录，到期边界不记录，不写公开事件、通知、记忆或拾取权限。真实话语、私有供餐证据或启用天气托管而无法同时保存时，本入口不提交对应分钟。

封存 V2 可额外验证一笔实际拾取：同一居民须已有原生发现，且在可重放步进中确实完成走到地面的最后一格；仍须站在公共地面、无现行任务，且普通规则本会闲候。有多人符合时按原生逐人决策顺序由第一个实际选择闲候者取得机会，封存调用者只能核对预期居民、不能指定获益者。此时才选择只在该封存事务可运行的本人拾取动作，执行一真实分钟并在原到期点前结算。地面减一，独立本人随身批次加一，原果源、出生与到期不变；普通水果标量完全不增加。拾取后再次冻结，后续仅可走下述专用持有步进或独立到期入口；未实现进食、交易、罐藏或遗产，不开放普通运行。旧到期／拾取互斥，同一请求仅回读原凭证。

持有后的第一条封存终止仍限一步：只有下一原生分钟确实跨过随身果实的原到期点、原持有人仍健在且未迁出、普通随身库存与原果源未变化时，才将随身批次减少一份并追加到期凭证。未到期不推进，不改水果标量、不返还果源、不给营养、不开放遗产或新食用能力。原出生、拾取和地面账保持不变；同一到期请求只回读原终止凭证；终止后重试拾取只回历史拾取凭证，不表示仍持有。重开只在私有归档中复走实际步骤、核对有序事件和索引。


封存持有也可显式选择短链步进，与旧单步到期格式互斥。最多 48 个已验证的原生分钟（包含正常 30 分钟闲候的余量），不是强制让果实过期，也不会缩短普通计划。每次都以当前精确修订与 BLOB 做比较，追加原生时钟、前后摘要、原持有与出生编号及有序实际事件。仍在原期限内时随身批次原样保留，跨过才终止；若步数用尽而未到期，就保持最后的准确状态。普通吃其他已知库存与原有事件照原规则保存，不允许使用、转移或继承这份独立果实。已核验的封存句柄才能推进，重开只读重放；未实现的持有人死亡／迁出或独立托管整步拒写。

封存持有步进可另行明确开启独立随身果实的原生进食，首次开启后续步不得回退到旧无进食模式。它保留先前报价、普通供餐／根菜／鲜果的优先级；仅在正常需求已经需要进食、本人没有更优先食物或候选餐位时，允许停留户外原位工作五个真实分钟，不替代合法餐桌路由或缩短普通闲候。完成仍须早于原到期点；期限不足不开始，恰好到期只终止，没有这份果实的营养。只有真实完成才沿用本地原生水果营养、减少一份独立批次及追加关联凭证，不改普通水果数量。旧封存步进仍可读；有界重放逐分钟核对计划与完成、围栏与历史索引。仍不支持进食这份果实的室内路线、交易、罐藏、遗产、普通启动或发布。

### 封闭随身鲜果：共屋本人餐席（V3 原生分钟回放）
仅显式开启的封闭开发夹具选择该路径；既有禁食与原位食用回放不变。在原有食物选择链的鲜果优先位置，规则从本人已知、仍有效的共屋中取原生实名席位，保留更高优先的普通食物和行为。真实户外路线、门槛、逐格室内移动和逐分钟席位占用均使用原生规则。未到真实许可餐位及取得当分钟占用前，不扣工作量。路途不计入五个完整工作分钟；原保鲜期在最后工作分钟到达时，到期优先且没有营养。

私人终结凭证绑定首次实际工作时间、完成时间和席位；原生世界分钟、营养变化、随身件减一及日志在同一事务回放核对。不向普通标量库存增加果实；不支持跨楼、私宅餐位、生产启用或普通存档加载。采用原生实名席位数量及争位规则，不新增或推断建筑总人数政策。48 分钟封闭回放上限未变；超过上限不补记用餐或到期。

### 封存 V2 带龄落果公平账
只读投影在同一次完整归档重放中区分提议指向、实际落地、居民真正发现、实际拾取。提议层仅证明与这笔执行签批绑定的一条候选，整体候选量未知；光看见的只读诊断、到达、预计收益均不计入事实。过期或吃掉仍保留历史拾取，不再计作持有。实物在地面、地面到期、本人持有、持有到期、吃掉五种状态之间互斥，显示原出生和到期时间。搬运不产生新增供给；自然再生没有在这套效果归档内记账，诱发的间接增量仍需反事实验证。缺失、错档或坏账不给可用读数；不接普通 V1、居民或公开读路由。
