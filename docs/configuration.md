# 运行与配置

## 隔离开发预览

需要 Node.js 22.13.0 或更新版本。初次查看或修改前端时，在两个终端分别运行 `npm run dev` 和 `npm run dev:web`，打开 `http://127.0.0.1:5173/ai-town/`，无需先构建。

开发后端固定监听 `127.0.0.1:3413`，每次新建临时目录内的 `preview.sqlite`。下面的环境变量在预览中均不生效：不采用 `VALLEY_DB`、模型凭据、凭据文件或 `PORT`，不加载 `.env`，不启动时钟和模型调度。前端入口也关闭 Vite 配置/环境文件加载，仅代理 3413，端口占用时报错而不自动换端口。后端修改需手动重启。正常退出删除本次临时目录，强制终止可能留下临时文件，详见[预览实现与边界](implementation/development-preview.md)。

## 正式本机启动（非隔离）

服务默认监听 `127.0.0.1:3412`，观察入口为 `/ai-town/`。先运行 `npm ci` 和 `npm run build`，再运行 `npm start`。正式启动在端口和存档独占检查成功后打开或创建 `runtime/formal.sqlite`，可能迁移并提交已有存档。**当前默认 `no-model`，不读取模型密钥或凭据文件，不因已有凭据启用模型。** 显式实时模式仍显示 `blocked`，不是可以无人值守运行的生产模型版本。它与隔离开发预览不同。

正式存档独占实现目前只支持 Linux，其他平台失败关闭。健康接口 `/ai-town/api/health` 的 `ok:true` 仅表示观察服务存活；正式入口另报 `ready:false` 和 `modelExecution.state/reason`，明确区分 `no-model` 与 `blocked`。

`npm start` 从进程环境读取变量。若使用根目录的 `.env`，通过 Node 显式加载。

```sh
cp .env.example .env
node --env-file=.env build/server/main.js
```

如确实需要正式服务热重载，可用 `npm run dev:formal`，或 `node --env-file=.env --import tsx --watch src/server/main.ts` 显式加载环境文件。两者仍使用正式存档，并沿用同一个失败关闭的模型门禁。仓库原始 `vite.config.ts` 的代理仍为 3412，但默认 `dev:web` 不加载它，而使用只连接隔离端口 3413 的独立配置。正式构建仍按常规 Vite 行为读取环境文件，不在隔离预览入口的保证范围内。

## 环境变量

| 变量 | 作用 |
| --- | --- |
| `PORT` | 本机端口，默认 `3412`。 |
| `VALLEY_DB` | SQLite 存档路径，默认 `runtime/formal.sqlite`。相对路径以启动目录为基准。 |
| `VALLEY_DAY_MINUTES` | 每游戏日对应的现实分钟数，默认 `20`，允许 `20–1440`。 |
| `VALLEY_MODEL_MODE` | 缺省或 `disabled` 为 `no-model`；`siliconflow-free-only` 仅表达候选意图，目前仍为 `blocked`，其他值也阻止运行。 |
| `VALLEY_MODEL_PROVIDER` | 候选仅允许精确值 `siliconflow`，不构成调用授权。 |
| `VALLEY_MODEL_ID` | 候选仅允许 `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`，不证明目前免费。 |
| `DASHSCOPE_API_KEY` / `SILICONFLOW_API_KEY` | 当前正式入口不读取，也不据此派发请求。 |
| `VALLEY_DASHSCOPE_KEY_FILE` / `VALLEY_KEY_FILE` | 当前正式入口不读取这些文件。 |

没有可用环境开关能绕过当前门禁。仅免费模型的生产接线仍需独立核实真实运行授权、当前精确模型与账户免费状态、此前未知请求及账单，不允许付费回退。离线候选和真实短探针是不同协议；旧探针预算不会被新配置扩展。[安全候选与验证范围](implementation/production-model-safety.md)。

界面关闭后服务仍继续模拟。缺少模型配置或开局仍在等首份镇内决定时，时钟会暂停。每游戏日为 30 分钟或更短时，如果连续三分钟未收到可执行的镇内决定，且有居民已等候至少三分钟，也会保护性停表。若个人紧急决策保护将先达到 180 游戏分钟上限，而自本次危机开始后全镇仍没有一份有效镇内决定，则会提前在个人期限前停表；该判断跨服务重启保留。有其他居民获得有效决定时，个人期限到期仍按普通世界规则推进，不会单凭某人的到期冻结全镇。较慢的时钟会在严重需要或临近期限时等待当事人作决定。时钟恢复后从暂停处继续。

## 历史底层路由与分钟预算（正式入口未启用）

下面描述保留的底层路由 API 和回归测试，不是当前正式启动策略。新的生产候选是单提供商、单模型、单槽、零自动重试及无备用，只能用品牌内存 transport 演练。真实 transport 尚未接通；默认正式入口不能到达这里的旧路由。

主模型通常从 8 个同时请求开始，备用模型从 4 个开始。它们是并发上限，不保证每轮都填满；请求还必须分别通过该提供商的滚动一分钟预算。当前主模型预留上限为 4,500,000，备用模型为 45,000，备用模型另有每分钟 900 次请求的上限。

运行时以序列化提示的 UTF-8 字节数加 512 作为保守输入预留，并另计回答和思考的输出预留，不把这个字节估计宣称为真实 token 用量。返回有效用量后用实际报告校正。尚未结束的请求继续占用预算；重启时无法核实的未完成请求不会直接清零，而会保留相应预算记录。提示随可选行动、家庭资料或口粮提醒变长时，即使仍有空闲并发槽，也可能需要等待预算释放。未发出的请求不记为失败，也不会为了填满槽而把健康主模型的普通请求分给备用模型。

[路由回归](../tests/model-routing.test.ts)分别用小上下文核对 8/4 个并发槽，以及用正式九人世界核对真实提示预留，避免把预算等待误判为并发故障。

[请求终态与重启计量](implementation/runtime-request-recovery.md)将已完成响应的待回状态与结果、用量一同持久化，避免正常停机或提交后退出把成功请求再记为未知失败。已记录的未知用量和保守预算仍保留；本地待回列表为空不代表生产请求账本已核对或费用为零。

## 自行配置主/备用模型

独立 `self-hosted-main.js` 入口支持 `.env` 显式配置主/备用供应商（`VALLEY_PRIMARY_PROVIDER` / `VALLEY_BACKUP_PROVIDER`）、型号和密钥，默认禁用。详见[自托管模型配置、费用边界和未决重启](implementation/self-hosted-models.md)。此入口单并发，只有 429 可退避或使用明确备用；未知结果停表，不沿用下面历史路由的超时 fallback。正式 `main.js` 仍关闭，不受该配置启用。

## 自托管

以普通服务用户运行 Node，给存档目录写权限，并保留 `/ai-town/` 路径。反向代理需要支持流式传输，否则地图更新会被缓冲。例如在同一台机器上的 Caddy 配置中使用以下路由。

```caddy
your-domain.example {
    @valley path /ai-town /ai-town/*
    reverse_proxy @valley 127.0.0.1:3412 {
        flush_interval -1
    }
}
```

观察接口可以读取模拟人物的活动、意图和对话。希望仅供自己或团队观看时，在反向代理配置访问控制。新实例可指定新的存档路径。备份运行中的存档时使用 SQLite 在线备份，或停止服务后复制已完成检查点的数据库文件。升级时保留同一份存档，历史回执用于阻止交易重复结算。

紧急决策保护只暂缓技术等候中的新增饥饿和耗竭健康损失，不会自动进食、休息或转移库存。濒危者须在当前或仍待回复的正常菜单中有实际可完成的自救途径。食物变质、道路阻断、照护者离开、行动前置条件改变及伤病仍按世界规则核对。有效决定到达后，停表可解除；个人保护的原期限不会因无效回复或重启延长。[实现边界与隔离测试](design/recovery.md#当前实现边界)
