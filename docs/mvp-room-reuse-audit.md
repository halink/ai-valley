# MVP 房间/床位复用审查与第一步实施

## 当前实施状态

第一步现已启用：新建小山谷保持 validation 模式，但显式创建版本 1 的真实 rooms；两位居民各有实际床位，走完室内路径才能恢复精力。`mvpSleepProblem` 仅在 MVP 房间版本启用时执行，在出口预处理、室内移动与睡眠结算前检查床位存在/权限、固定床号、可达性与实际占用。床位失效、阻塞或被其他人实际占据时原位失败，不自动出屋、重试或移走他人；醒后保持床位坐标，等待本人的下一动作。

三个历史缺陷刻画已反转为拒绝错误行为的回归断言。`mvp-room-migration.test.ts` 新增入口/床点阻塞、formal隔离、旧档安全迁移及异常拒绝回归。旧档仅当所有人都在户外，且无旧 sleep/室内 journey/rooms 时才通过一次 CAS 初始化能力；歧义旧档、未知版本、缺室内坐标拒绝启动，源档不被迁移改写。不要删除旧档或悄悄把角色移到门外；需保留旧档，另用新文件启动新 MVP。

Godot 仍隐藏室内居民，没有室内 3D 可视化，也没有假造室内动画；第二步独立观察视图尚未实施。没有真实模型/桌面GPU/长期验收。以下为初始审查记录，保留缺陷发现与决策依据，不代表当前缺陷仍存在。

## 初始审查结论与边界（历史）

现有房间模块可复用，但不能通过给小世界补一个 `rooms` 对象就把“休息”升级为真实进屋睡眠。本批只提交合成探针与方案，没有修改生产逻辑、存档或 Godot 场景，**MVP 仍是屋门休息模型**。不切换 `formal`，不顺带引入正式世界的产业、医疗等系统，也不替居民决定睡眠或出屋。

`tests/mvp-room-reuse.test.ts` 在全新、一次性 `createMvpWorld()` 中显式添加 rooms，随后仅经 `submitPlan` / `stepWorld` 推进。7 项测试中，4 项证明现有能力可复用；3 项名为 `BLOCKER characterization`，明确记录尚存缺陷。**这些缺陷刻画通过表示缺陷仍可复现，不表示功能验收通过。** 修复时必须将对应断言替换成拒绝非法恢复、保留真实位置的回归。

## 已验证可复用的部分

- 两位居民分配不同床位；先走真实室内路径，再消耗睡眠时间与恢复精力。醒后仍在床位，不自动安排出屋；下一项明确的出屋行动才走到室内入口，再迈户外步。
- SQLite 关闭再打开后，实际室内坐标、床位分配、路径和小数行走进度保持，短时继续的结果一致。仅使用临时合成数据库并清理。
- 行动开始前没有床位会明确失败，不补造床位。
- 已缓存路线被真实房间障碍阻断后停在原位置，不穿越、不自动重新寻路、不计睡眠恢复。探针中的尸体仅是现有阻塞接口测试，不表示 MVP 增加死亡系统。

## 必须先解决的缺口

1. **中途撤销床位**：睡眠开始后把容量降为 0，现有逻辑会先自动出屋，之后在屋门 `inside=home, roomAt=null` 仍计入一次恢复及睡眠时间。起点床位检查不够，必须每 tick 在移动/结算前校验仍拥有且存在的目标床位；失效应原位失败，不自动出屋。
2. **实际占床与活动 claim 不同**：已醒、无 activity 的人仍实际站在床位；若其入住资格被撤销，床位分配可给另一个人，后者会走到同点并睡眠。现有 tick claims 只覆盖活动，不等于实体占用。需要床点在进步前及结算前检查实际活人占用，包括无 activity 者；不能借清除 claim 把他人移走。普通通道是否允许交错行走应与床点独占分开，本 MVP 不扩为完整人群碰撞系统。
3. **旧档没有真实室内坐标**：旧 MVP 的 `inside=home, roomAt=null` 只是屋门语义。直接启用 rooms 后 sleep 会以入口兜底并迈步，属于补造新定位，不是恢复旧位置。没有资格把所有此类数据直接填成入口或床位。
4. **观察端尚无房间场景**：`Snapshot.visible` 会隐藏室内居民，不是仍画在屋门。正式 roomLayout 是独立的 16×15 室内格，共屋户外占地为 8×6；不能把 `roomAt` 直接当户外 `at`。快照目前也没有版本化的权威室内布局协议。

## 最小两步迭代

### A. 真实床位与安全存档（先限定两人、共屋、两床）

- 新 MVP 显式版本化启用房间能力，仍保持 validation 模式。采用原房间布局/寻路，但增加 MVP 范围内的持续床位有效性及真实占床保护；不要改变正式世界行为。
- 不改 AI 的选择：只有明确 sleep 才进屋睡觉；醒后保持事实位置，只有明确室外动作才离开。
- 默认对旧存档的歧义位置**拒绝自动升级且不改源档**，提供明确原因。旧档若全部位于户外、没有旧 sleep/室内 journey，可经一次 CAS 版本迁移初始化 rooms，不追记过去睡眠。对屋门 inside/null 或途中旧 sleep，建议继续保留旧档并新建独立 MVP 测试档，不做偷偷移位、取消行动或修复历史。
- 验收必须含双人双床、无床、床位中途撤销、已醒者占床、入口/床点/途中阻塞、睡眠及退出途中 SQLite 重启、失败无自动重试、正式世界回归。未补齐前不合并开启入口。

### B. Godot 可观察的真实室内（不扩大地图）

- 优先采用共屋的**独立室内观察视图**，沿用真 3D Mesh/Camera，而非把大室内硬缩进户外占地。点共屋进入观察视图，有明确返回山谷按钮；不是操纵居民的入口。
- 服务端按已有 roomLayout 输出小范围、版本化、只读的布局、入口、床位坐标和阻塞点；客户端严格验证，未知/不合法时显示未支持而不是自行生成布局。
- 室内渲染仅接纳 `inside` 匹配且 `roomAt` 有效的人；直接由真实室内坐标投影。户外视图继续隐藏他们，详情显示屋名/床号/实际室内格位置。室内/室外转换必须来自快照事实；不推测床位、进门动画或路径。
- 当前 completedMovement 协议只覆盖户外实际步。室内先精确快照定位，不把目标路径当已走路径；以后单独增加已完成室内步协议再做平滑。
- 验收包含双床可辨、醒而未离床、室内外切换、选中居民/断线重连、未知布局与缺坐标、遮挡/拾取。headless 与真实桌面窗口验收分别报告，不把前者称 GPU/美术完成。

## 本批验证记录

独立只读审查确认床位撤销与旧档坐标缺陷，并纠正了初始“门外渲染”的错误判断：实际是隐藏室内居民。测试和审查均没有读取 `.env`、密钥或真实存档，没有调用真实模型，没有长期运行验证，也没有 push。

验证结果：新增 7 项探针独立复跑通过；连同既有 rooms、room-work-boundaries、room-exit-boundaries 共 35 项通过；`npm run check` 通过。四个可复用探针不是完整室内安全验收：本批尚未覆盖床点本身静态/动态阻塞、同床 active claim 冲突、旧档迁移失败/回滚或 Godot 室内展示。这些必须在实施阶段补齐；当前没有迁移代码可供验收。

## 第一步实施验证补充

实施后共 80 项 MVP/饮水/持久服务/房间与原正式房间边界回归通过，随后补充持久服务中途室内路径重开、active 占床保护，两项连同迁移/生活回归 20 项复跑通过。独立审查 45 项原有相关回归及 5 项新增边界测试通过；`npm run check` 与 7 套 Godot 离线 headless 通过。历史三项缺陷测试已反转，现不再接受缺陷行为。已覆盖床点/入口阻塞、床号变动、住房失权、idle/active实际占床及歧义旧档不改写；尚无真正 Godot 室内视图、GPU窗口、真实模型或长期运行验收。普通室内通道仍沿用旧模块可交错行走规则，新增的是床位目标独占，不是全面人群碰撞系统。
