# Godot Web：从最小山谷逐步长大

## 当前源码进度与历史证据

唯一交付目标是使用手绘风格材质的 Godot 3D 浏览器版。每批生活功能一同交付美术表现、UI 和交互，实际浏览器检查关注居民动作、镜头、布局与信息可读性。

历史预览验证版本为 `6e56014`（2026-11-18 的原记录），不是当前源码或当前线上部署版本的证明。小山谷为 **48×36、四位居民、三处住家及一座灶堂**。浏览器可观察室内外、跟随步行、查看人物往来与生活手记。发布核验记录了原存档接续、模型成功决定及两条同时在途的请求。浏览器步行、并行调度及规则运行另有分项记录。[Web MVP 验证记录](godot-web-mvp.md#室内步行与跨门) · [模型验证记录](implementation/self-hosted-models.md#验证) · [部署手册](deployment.md)

当前默认本机入口仍是随进程重建的规则世界；历史模型持久入口与新增的显式持久规则入口彼此分开，不能互作回退。源码已加入有限种源/留种、初始资源/空田预算、存档安全与持久气候观测，均不代表这些增量已部署到线上原档。新增气候目前仅观测点值，尚未影响农业；详见[世界升级实施路线](world-upgrade/IMPLEMENTATION.md)与[持久气候范围](implementation/mvp-climate-persistence.md)。浏览器/GPU、异常断电恢复、长期平衡与正式访问控制仍按各版本证据分别核实。

## 当前验收约定（2026-11-16）

现行验收约定（2026-11-19）：助手承担开发工程师职责，交付范围止于功能实现、本地单元测试与可提测交接；允许快速功能冒烟。详细测试、长时测试及系统性浏览器验收交由测试组，不代做、不等待 QA 完成，也不自动联系测试组。助手仅执行本地单元测试与快速功能验证，不再启动、续跑或代跑长时间测试；长跑由用户自行负责，取消助手每批实际运行 30 分钟的强制门槛。任何测试文件均不得提交或推送，必要的本地临时验证文件也不入库；已在历史提交中的测试文件仅清点，不擅自删除或改写历史。真实模型测试仍禁止。按实际范围记录通过、失败与未验证项；构建、原生预览与短时检查不能替代未完成的浏览器或长期稳定性证据。

此前旧版本的长期运行、跨季或真实模型验收计划属于历史，不能直接当作新版本已验证。新四季升级按其明确的[分阶段退出门](world-upgrade/IMPLEMENTATION.md)另验，包括启用农业/供给影响前所需的跨季证据；真实模型测试仍不安排。下方保留历史实现的原证据边界。

### MVP-2 持续种植与供餐

代码与本地验证已经交付，原“下一批”状态已过时。有限种源/留种实现见 `360a353`；`a138382` 是其后的资源预算与额外空田，不应混成同一批。16,000 游戏分钟定向回放完成两轮耕收/留种/做饭/进食；1800.267 秒实跑仅覆盖领种、播种与浇灌。另资源批1800.468秒以每500 ms推进3游戏分钟，覆盖8次收获、8次留种、6次烹饪。不同初态、速率和覆盖不可互相代证。[分项记录](godot-web-mvp.md) · [资源批证据](implementation/mvp-initial-resources.md)

以上两批没有线上部署；当时Chrome缺WebGL2，原生预览不是浏览器验收。线上原档与当前浏览器流程仍须单独核验，不能把当前HEAD当作已部署/已视觉通过。下文保留当时的问题与退出条件。

线上第 10、11 游戏日的 119 条日志中，采浆果、吃浆果、取水和喝水共占 82 条。林禾、乔笙当时种子为零，田地为空。这个样本反映日志分布，行走、睡眠和等待由实时行动状态体现。该批验收另记完整游戏日内采集、饮食、耕作和烹饪的完成次数，观察种源恢复后生活行为怎样变化。

首版在山居灶堂提供有限种源。居民在正常菜单中选择到场领取，实际扣减种源，库存和领取记录随存档保存。旧存档可以由这条路径取得第一批种子。收获后可把部分芜菁用于留种，其余用于进食或按已有配方做饭。种源耗尽或工位不可达时，在手记中显示结果。[留种设计](design/economy.md#生产与生活资料)

退出条件用零种子的旧档副本核对。居民从正常行动入口取得种子，经历播种、有效灌溉、收获、留种并再播，完成第二次收获、做饭并吃下至少一份餐食。检查库存守恒、竞争同一份种源、迁移与重启后的结算一致性。按本机默认速度，30 分钟约覆盖 2.5 个游戏日，芜菁每轮需要四个有灌溉的生长日，两轮结算另做跨游戏日的定向规则回放。浏览器核对取种、菜畦状态、留种和做饭可见。

### MVP-3 居民自己的工作

许砚已经在原存档记下「修整木器」目标。首项工作选灶堂的一件可修整木器，提供实际工位和可获得的有限耗材。居民依据自己所知与当前目标选择工作，到场后按工时执行，完成时扣减材料并改变木器状态。目标进展引用对应的完成事件，工作可由居民推迟或放弃。工位、材料和修复结果同步呈现在场景及手记。

退出条件用带有「修整木器」目标的旧档副本核对。确认居民可从正常菜单自行选择工作，走到现场，经过工时后完成一次真实修整，存档重开可见成果。材料欠缺、工位占用或路径受阻时，检查实际状态、失败反馈和扣账。更丰富的分工逐版扩展。[木作与生产设计](design/economy.md#生产与生活资料)

## 历史增量与实现证据

### 居民自己的持续目标

居民可以写下、改写或回顾结束自己的生活、交流与探索目标。动作引擎执行这些记录操作，并保存到事件与居民状态。下一次决策会读取本人已有目标。回顾记录本人看法，生活成果以实际完成的后续行动为证据。旧存档缺少 `agency` 字段时仍可载入。

轻量核验：完整 TypeScript/build；临时内联检查菜单→模型 JSON 解析→真实动作执行→后续 prompt、目标修改/结束、重复目标拒绝、MVP 自动日程/不支持领域/其他 validation 世界拒绝，及存档读回。完成独立 review；未新增测试文件。这是代码及合成输入的执行链验证，未调用真实模型，也未做此次浏览器或长期验收；是否会自然选择并兑现目标仍未验证；现行流程不再安排模型驱动测试。

### 居民自己理解相处经历

模型驱动的小山谷现在可对本人实际收到、且涉及已认识人物的具体经历形成自己的理解，自行写下看法及有限的好感、信任、矛盾变化（各 -5 至 5）。这不是友善发言自动加分：只有本人另选理解动作后，实际引擎才改变本人的单向关系；不改对方感受，也不把听闻变成事实。菜单保留来源与完整保存的发言依据，同一经历对同一对象不能重复结算，关系及回执随现有存档保存。旧 MVP 存档在首次有效理解时才初始化必要状态；不开放正式世界的聚会，规则 demo 不会自动理解。

轻量核验：合成发言→本人菜单→构造模型 JSON→真实动作引擎→单方关系→后续 prompt，及重复/未获知记录/聚会拒绝、SQLite 读回后重复拒绝；完整 TypeScript/build 和独立 review。审查发现并修正一处分支链回归后重新验证。未新增测试文件，未调用真实模型，本次未做浏览器或长期验收；自然关系发展仍未验证；现行流程不再安排模型驱动测试。

### 把食水行动表现出来

小院继续使用既有资源、库存和行动结算，不扩大地图、不新增观察面板。居民采果/取水时朝向实际资源并做不同的手部动作；随身浆果用小篮与至多三颗浆果示意，清水用陶壶示意，吃喝时将对应道具送到手边。室内交谈使用房间坐标，循环动作在室内快照刷新后保留阶段。资源标签移出人物手脸位置。

篮子、陶壶只是表现道具，不是新装备系统；浆果标记不替代精确库存。动画不决定采集成功、消费、关系或居民意图。默认演示仍为规则驱动，真实模型模式另行配置。

该批记录中的同格重叠和床旁姿态属于当时的表现边界。后续实测见 [Web MVP 记录](godot-web-mvp.md#真实床位的躺卧表现2026-11-16)。

本增量核验：TypeScript 检查、Godot 4.6.3 Web 导出、独立代码 review 通过；review 修正了室内交谈坐标和动作阶段刷新问题。云 Firefox 在真实规则场景看到了采果、进食、取水的道具与动作；标签修正后对新导出复查，泉水标签不再覆盖采水人物头胸手。饮水曾受人物同格重叠遮挡，不能据此称所有动画已完整视觉验收。

另以未修改的规则引擎独立运行 30 分钟实时时钟（2026-11-16，1800.240 秒、3592 次推进），实际覆盖 gather / eat / mvpDrink / sleep / talk / wait；未观察到意外暂停、非有限需求数值或负库存，两位居民结束时存活。按此次执行范围通过。它没有调用模型，没有覆盖持久化重启，也不是浏览器连续 30 分钟、修改后渲染版本或长期稳定性验收；标签修正使用的是另一次短时浏览器复查。

### 共屋餐桌进食

在两位居民的现有食水闭环上增加真实回屋就餐，不扩地图、不引入旧产业系统。普通饥饿时携本人食物走到独立餐位，危急或餐位不可达时原地吃；显示桌、凳和在座吃饭姿态。暂不添加共享食物、烹饪或自动饭桌社交。这一批通过后再挑选一个完整的小生活增量，避免以更多面板代替生活内容。

### 有限小菜园

新建规则世界曾用每人一块田和两份初始种子验证播种、浇灌、四个生长日、收获及进食。后续已交付的种源和留种分项证据见 [MVP-2](#mvp-2-持续种植与供餐)。

### 收菜后的厨房

菜园之外再接一条小链：用自己的根菜和清水回共屋厨房做一份饭，再自行选择吃饭。饥渴和休息优先，保留个人饮水，不抢已有厨房工位。使用现有配方和扣账，新增锅灶、搅拌与餐碗表现；暂不扩展燃料、公共食堂或种源经济。
