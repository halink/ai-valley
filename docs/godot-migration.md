# Godot：从最小山谷逐步长大

## 方向纠正

用户决定使用 Godot 重做，并进一步明确：**先做最小可行性版本，再在它的基础上不断加功能、扩大地图，直到达到最终目标；不考虑移动端。此前工期作废。**

上一版计划把工作拆成“先迁移旧客户端，再补齐所有面板与视觉”，仍然以旧系统功能清单为主线，理解不对。现在以一个小而完整的观察体验为主线。已有快照客户端只是技术基线，不是游戏 MVP，更不等于完成了绘本重构。

最终仍然是[架空东方山居绘本 2.5D](design/storybook-valley.md)的自主居民山谷：居民根据自身处境行动、生活与形成关系，行为受世界实际规则约束，观察者能看懂发生了什么。新实现只面向桌面，不安排移动端、触控、竖屏适配作为目标。

## 第一版 MVP 范围

**一小块地图、两位居民、一处共屋、可采食物与水源，一条能反复发生的生活循环。** 地图先约 32×24 格，不先载入旧世界的 640×480 全图。

核心循环：

1. 居民有真实饥饿、体力和库存。
2. 决策选择一个当前允许的行动。
3. 沿实际可通行路线走到现场，而不是原地播动画。
4. 现场花费时间，资源/库存/需求按规则实际结算。
5. 采到食物后进食、体力低时休息，然后进入下一次决策。
6. 观察者可平移缩放、选择居民，看到当前行动、资源数量和最近记录，分清走路、现场工作、休息与失败。

先用明确标识的**无模型本地规则驱动**验证工程闭环。这不是 LLM 自主行为，不得把规则决策或合成测试算作真实模型验收。模型决策作为可替换的边界接入；只有既有模型配置接通并验证了“选择→执行→反馈”，才能声称 AI 版本 MVP。不得为了看起来活跃而伪造行动成果或把预设剧本说成自主智能。

初步复用已有 TypeScript `submitPlan`、寻路与 `stepWorld`，避免另造一套不一致的动作结算。**复用是工具，不是必须先接完全部旧系统的前置条件。** 新增场景独立、隔离，正式存档和旧服务入口不改。

## 小版本路线与验收

| 版本 | 一次解决的问题 | 退出条件 |
| --- | --- | --- |
| 技术基线（已存在） | Godot 读取完整快照、相机、选择、错误状态 | headless/契约测试与独立 review；不视为游戏可行性结论 |
| **MVP-0：生活闭环工程版** | 小地图、2居民、资源与共屋；规则驱动真实采集/进食/休息，桌面观察 | 有界测试证明到场、耗时、资源与需求结算、再次决策；Godot显示同一事实；非法状态/断线不伪演；实机窗口检查；明确无模型与几何占位 |
| **MVP-1：自主生活可行版** | 接入已有 PRIMARY/BACKUP 决策边界；先让同一小山谷生活可信，而非增加大量系统 | 决策合法性、失败反馈、等待/限流/断线清楚；真实模型短程验证另列证据；最小保存/恢复不丢关键世界状态；旧版本可回退 |
| **MVP-2：绘本样板版** | 在同一小地图完成两位居民、一处共屋及地面的绘本样板，动作和遮挡可读 | 原生桌面窗口实测、位置/脚底/门口吻合、采集/走路/休息不混淆；不是概念图代替游戏画面 |
| **后续逐次增长** | 每版只加一类玩法或一块区域：如工具与伐木、钓鱼与生态、耕种、邻里交流、住房建设 | 先定义这一小步给核心循环增加什么；有新的规则/画面/回归证据；地图扩展不破坏旧区、路径、存档和已有生活 |
| **候选发布** | 在已迭代成功的世界上整合发布包与操作文档 | 干净检出可复现；目标桌面平台测试；独立 review 无阻断；用户长期运行反馈回归后再判定正式版本 |

上述名称是计划标签，不代表已经创建 tag 或完成对应版本。地图扩张和玩法增长交错推进，不设置“先迁完旧版所有面板才能有游戏”的门槛。旧版可作为经验与行为参照，不是待搬运清单。每版都保留后续可扩展的接口，但不提前建设当前循环不需要的大框架。

## 经验与每版交付纪律

- 把“可运行代码”“完整生活循环”“AI自主表现”“绘本画面”“长期稳定”分开证明，不能互相替代。
- 从一个可看懂的闭环获得反馈，再增加复杂度；静态大地图与空面板不能代替可行性。
- 单一仓库开发；小提交、独立 review、文档与测试同步。修复后重测，不隐藏审查发现。
- 保留旧客户端、正式服务和存档，不以删旧目录或重置数据来完成重建。
- `bob` 同步及阶段 tags 要实际核对，不能把本地提交说成已推送。先检查密钥、数据库、缓存和导出产物均不入库。
- 每次报告只说本版已验证的行为、未验证项、下一最小增量；没有新证据就不升级完成度。

## 验证边界

研发使用独立合成小世界，不读 `.env`、密钥或正式存档，不自动发模型请求。无模型规则驱动版必须在启动说明与画面上显式标记，并使用与正式服务不同的入口。模型接入阶段再复用既有安全配置，不将凭据打包进 Godot。

Godot 4.6.3 已安装；暂未确认可用导出模板，未擅自安装。原生源项目运行与可分发二进制是不同交付项，Web 不是当前 MVP 的前置要求。具体运行命令、当前功能与限制见 [客户端说明](../godot-client/README.md)。

长期运行由用户负责。开发侧仍需完成有界行为回归、故障恢复和独立审查；不能因为长期验证交给用户而跳过基础检查。正式发布以实际验证为准，不恢复原来的三天期限。
