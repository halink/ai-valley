# Godot Web：从最小山谷逐步长大

## 最新方向

新版**只做浏览器版**，不交付原生桌面游戏，不考虑移动端。使用 Godot 真 3D 和手绘风格材质；Godot 编辑器和 headless 是开发工具。此前把原生窗口作为交付目标的选择已纠正，不能继续作为验收条件。此前三天工期已作废。

先交付一个小而完整的可行版本，再基于它增加功能和地图，直到自主生活山谷的最终目标。不要以搬迁旧客户端全部面板或补齐整个旧功能清单作为第一版门槛。用户概念图和设计资料保留为参考，新视觉不必严格沿用旧 2D/2.5D 提案。

## MVP-0 最小闭环

约 32×24 的小地图、两位居民、一处共屋、食物与水源。需求影响决策；行动要经过真实路径、现场耗时和资源/库存/需求结算；观察者能看懂采集、进食、饮水、休息及失败，而不是看预设动画假装完成行为。

当前 Web 工程入口先用显式标示的规则驱动，临时内存世界，不读 `.env`、不调用模型、不保存世界。Web release 已实际导出，并在云端 Firefox 实际确认 3D 场景、中文、居民选择、室内观察、缩放及首次同源连接。资源竞争停表修复也已在 Firefox 越过原故障点。以上是有限浏览器检查，不等于完整 MVP-0 或真实模型验收；不得再把已解决的会话连接问题当作当前阻碍。

| MVP-2：视觉深化 | 在 MVP-0 的手绘风格上精修材质、居民、建筑和动作可读性 | 实际浏览器/GPU 性能与美术检查通过，不以概念图或 headless 结果替代。 |

## 已有工程与未完成项

已有小世界行动结算、需求和库存、移动轨迹、共屋双床与室内观察、基础姿态、中文 UI、手绘风格材质。独立持久服务和主/备用模型配置属于可复用工程，不等同于已经通过浏览器/真实模型验收。

当前规则 Web 服务仅监听本机 `127.0.0.1:3414`。持久 Web 已在模型禁用模式完成有限 Firefox 检查和两次正常重启恢复；另一次独立短程检查确认模型禁用下正常载入保留进行中动作、位置及库存；动作续跑、异常断电恢复、公开 HTTPS 部署、访问控制和真实模型验收仍需完成。持久服务的锁目前依赖 Linux；浏览器本身可运行于其他平台，但当前 loopback 入口不能直接从另一台电脑访问；远程访问方案仍未交付，不能把 Linux 的 localhost 链接作为 Mac 可直接访问的地址。

## 清理与交付纪律

- 删除与新展示方向无关的旧客户端、实验资源和入口；先查依赖并保留可恢复版本，不清扫实际存档或秘密。
- 保留当前仍复用的模拟、存档、模型和接口契约，以及用户设计资料；旧功能存在不代表当前 MVP 已实现它。
- 所有开发与测试在同一仓库。小提交、独立 review、文档与验证记录同步（按所有者要求，不再保留既有测试文件）；核实远程 SHA 后才能说 push 成功。
- 密钥、数据库、运行日志、缓存与导出结果不入库。阶段 tag 对应实际验证范围。
- 分别报告代码完成、Web 导出、HTTP/规则短测、浏览器/GPU、真实模型和长期运行，不混用证据。
- 长期运行验证由项目所有者负责；开发侧仍需短程回归、故障恢复和独立审查。

运行方式见 [Web MVP](godot-web-mvp.md)；贡献流程见[贡献指南](../CONTRIBUTING.md)。

## MVP-1 增量：居民自己的持续目标

模型驱动的小山谷现在可自行写下生活、交流或探索目标，并在后续决定中持续看到自己的目标；可改写或回顾结束。目标经真实动作引擎执行并记入事件/居民状态，随现有存档保存；旧存档没有 agency 字段也可继续使用。没有预设目标、规则自动补写、自动完成判定或自动日程。回顾只是居民自己的看法，不证明目标已经实现；当前菜单优先保留结束已有目标的入口。

轻量核验：完整 TypeScript/build；临时内联检查菜单→模型 JSON 解析→真实动作执行→后续 prompt、目标修改/结束、重复目标拒绝、MVP 自动日程/不支持领域/其他 validation 世界拒绝，及存档读回。完成独立 review；未新增测试文件。这是代码及合成输入的执行链验证，未调用真实模型，也未做此次浏览器或长期验收；是否会自然选择并兑现目标仍待真实模型观察。

## MVP-1 增量：居民自己理解相处经历

模型驱动的小山谷现在可对本人实际收到、且涉及已认识人物的具体经历形成自己的理解，自行写下看法及有限的好感、信任、矛盾变化（各 -5 至 5）。这不是友善发言自动加分：只有本人另选理解动作后，实际引擎才改变本人的单向关系；不改对方感受，也不把听闻变成事实。菜单保留来源与完整保存的发言依据，同一经历对同一对象不能重复结算，关系及回执随现有存档保存。旧 MVP 存档在首次有效理解时才初始化必要状态；不开放正式世界的聚会，规则 demo 不会自动理解。

轻量核验：合成发言→本人菜单→构造模型 JSON→真实动作引擎→单方关系→后续 prompt，及重复/未获知记录/聚会拒绝、SQLite 读回后重复拒绝；完整 TypeScript/build 和独立 review。审查发现并修正一处分支链回归后重新验证。未新增测试文件，未调用真实模型，本次未做浏览器或长期验收；自然关系发展仍待真实模型观察。

## MVP-1 增量：把食水行动表现出来

小院继续使用既有资源、库存和行动结算，不扩大地图、不新增观察面板。居民采果/取水时朝向实际资源并做不同的手部动作；随身浆果用小篮与至多三颗浆果示意，清水用陶壶示意，吃喝时将对应道具送到手边。室内交谈使用房间坐标，循环动作在室内快照刷新后保留阶段。资源标签移出人物手脸位置。

篮子、陶壶只是表现道具，不是新装备系统；浆果标记不替代精确库存。动画不决定采集成功、消费、关系或居民意图。默认演示仍为规则驱动，真实模型模式另行配置。

当前已知表现边界：同一实际格的居民可能重叠；睡觉仍是床旁低头姿态，尚非正确躺床动画；此次不是完整手绘资产包或完整游戏交付。后续先改善这些可见生活细节，再逐步添加实际生活内容。

本增量核验：TypeScript 检查、Godot 4.6.3 Web 导出、独立代码 review 通过；review 修正了室内交谈坐标和动作阶段刷新问题。云 Firefox 在真实规则场景看到了采果、进食、取水的道具与动作；标签修正后对新导出复查，泉水标签不再覆盖采水人物头胸手。饮水曾受人物同格重叠遮挡，不能据此称所有动画已完整视觉验收。

另以未修改的规则引擎独立运行 30 分钟实时时钟（2026-11-16，1800.240 秒、3592 次推进），实际覆盖 gather / eat / mvpDrink / sleep / talk / wait；未观察到意外暂停、非有限需求数值或负库存，两位居民结束时存活。按此次执行范围通过。它没有调用模型，没有覆盖持久化重启，也不是浏览器连续 30 分钟、修改后渲染版本或长期稳定性验收；标签修正使用的是另一次短时浏览器复查。

## 可见生活增量：共屋餐桌进食

在两位居民的现有食水闭环上增加真实回屋就餐，不扩地图、不引入旧产业系统。普通饥饿时携本人食物走到独立餐位，危急或餐位不可达时原地吃；显示桌、凳和在座吃饭姿态。暂不添加共享食物、烹饪或自动饭桌社交。这一批通过后再挑选一个完整的小生活增量，避免以更多面板代替生活内容。
