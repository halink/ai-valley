## 边界与审查清单

本次审查仅使用合成世界、内存 SQLite 和仓库内 Node/tsx/tsc；不读取真实运行存档、环境秘密，不调用外部模型或浏览器。审查者不修改生产代码。

- 送达来源必须为真实完成的护送及绑定的结构化事件，不能凭文本、旧迁移记录或仅 `phase=delivered` 的对象建立在场权限。
- 已亲见原送达且当前合法近身的成年人才能选择两分钟核实；宽泛已知人物、听闻记忆、远处事件和同门口但不同房间均不足。
- 近身须检查真实坐标、障碍、船岸隔离；室内还须检查双方当下停留权。现有 `canObserveBody` 不含停留权，不能单独当授权。
- 最终菜单、解析后的原 action、submitPlan、执行开始和最后一步应一致。绑定来源不得被附加字段、跨人、跨事件或伪造 ID 替换。
- 核实期间分离、离境、死亡、睡眠、表达/决定能力变化、风险重现、房间权限失效必须停止；核实不能改变粮水、生命值、医疗或住宅权限。
- 同一原救援最多一份记录。重新提交、换人、刷新菜单、重载及重复完成均不能刷新核实时长或十五分钟在场期限。
- 本人恢复表达即可选择立即拒绝，不能要求决定能力恢复；这不授予普通工作/医疗/移动权限。混合计划及附加字段必须原子拒绝。
- 施助者可立即退出。拒绝及终止必须持久化，不能失能后自动恢复或由另一人接班；最后一步拒绝必须优先。
- 在场不是强制等待或控制受助者。自主行动、恢复能力、危险、权利失效及施助者离开应收束记录，不自动创建护理、床位、监护或接续者。
- 居民决策上下文不泄露远方当前状态、私有数值、未亲见事件；观察者 UI 可展示明确限界的记录，但不产生执行控件或营养改善叙述。
- 天气扩展默认关闭；健康/饥饿变化须区分自然时间推进与支持本身效果。
