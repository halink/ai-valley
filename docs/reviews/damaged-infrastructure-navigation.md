# 损坏桥梁与码头寻路：独立审查

## 结论与范围

对 `src/world/navigation.ts` 的有限修改及 `tests/damaged-infrastructure-navigation.test.ts` 独立审查，未发现阻塞问题。候选让寻路和居民原有逐边通行规则一致：已经在损坏桥梁或码头上的人仍可走出，但离开后不能重新进入。

这不增加通行权、食物、健康、修复能力或自动行动；不修改维护、灾害、菜单选择、存档格式或实际行走失败规则。结论仅限本次离线机制验证，不代表长期居民存活、食物供给或真实模型验收通过。

## 缺陷与修复核对

- 原实现为了允许本人离开，会从静态障碍索引中豁免其起点所在的损坏设施。无步数上限的寻路偏好道路，可能先离开桥面走较快的岸边路，再从别处进入原桥。实际执行的 `walkable` 正确拒绝重新进入，因而接受的路径最终失败。
- 原始失败记录包含从 `(19,5)` 到 `(19,4)` 的非法边，执行停在岸边并报“原路线出现阻挡，需要重新决定”。正式回归使用真实支持的十八格直桥占地，不依赖不能建造的 U 形桥。
- 新的 `entryRestrictedAreas` 对活动且有实际 footprint 的洪水，以及未退役且 condition≤0 的桥梁/码头分别建立集合。`findPath` 和 `reachableTilesFrom` 都检查当前边是否从集合外进入集合内。
- 每个区域单独检查，不能通过两个重叠区域的并集获得额外进入权。只需当前坐标，不需要增加“是否曾离开”的路径状态：任何从外到内的边都已被拒绝。
- 既有洪水条件保持不变。健康设施、退役设施、损坏道路、非活动洪水、风暴以及没有 footprint 的旧径向洪水不被新增限制。
- 搜索索引仅存在于一次查询中；修复、退役、新损坏或洪水阶段变化会影响下一次查询，不留下跨查询缓存。

## 独立运行的验证

本审查只新增审查文档及 `output/resident-survival-water-review/` 下的测试和工具目录，没有编辑被审查的源码或正式测试。

一次最终组合运行通过 **37/37**，退出码 0，零失败、取消或跳过：

- 新增正式回归：5 项。
- 既有 food-source-navigation：3 项。
- 既有 flood-retreat：14 项。
- 既有 infrastructure：9 项。
- 独立审查测试：6 项。

独立测试以直接调用 `walkable` 的 Dijkstra/BFS 作为对照，而不是用两个候选搜索函数互相证明。共核对 **45,888 次路径查询**，包括：

- 无界路径的实际道路加权最优成本，以及 0、3、10 步上限的最短步数和不可达结果。
- 精确到达与相邻到达；占用起点、树木、建筑、水面、悬崖、牧场门和调用方额外边过滤。
- 桥梁、码头和洪水的分别重叠边界；健康、退役、非桥梁设施和非生效灾害对照。
- 24 个确定性生成的小地图与多个起点。重叠区域是低层图算法夹具，不宣称这些重叠设施能够通过实际建设审批。
- 每条返回路径都是相邻实际可走边；查询前后世界深度相同。
- 实际修复、退役、新损坏及洪水阶段切换后的新查询；非法起点拒绝。
- 建设入口版 `reachableTiles` 仍将位于损坏设施内的入口视为不可用，只有本人起点版允许逃出。

另行构造了真实 `infrastructureFootprint` 和 `infrastructureSiteError` 均接受的**六格直码头**。损坏后本人可走六步到岸，五步上限拒绝，五步相邻到达允许，岸上外来者不能进入。码头中间发生洪水后，岸边道路不能成为离开后重新进入码头的绕行方案。没有把十八格桥改名为码头作为合法码头覆盖的依据。

正式回归的生存动作链也在本次组合中独立重跑：本人从最终编号菜单选择已知浆果地址，实际离开桥面；途中写入并重载内存 SQLite；到达后另选采集，有限浆果 3→0、背包 0→3；另选进食后背包 3→2。到达或采集本身不记为吃过。新损坏发生在外来者途中时，原执行边界仍及时停止，不补位置或食物。
