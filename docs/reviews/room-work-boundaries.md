# 室内入站路径的动态阻挡

## 缺陷与重现

`moveInRoom` 为已经决定的行为缓存入站路径，但旧 `guardianRoomStepProblem`
只校验共屋、公共服务及部分救援。普通睡觉、做饭等行为跳过了检查。
例如旅舍左侧床位的正常路线经过 `bodyBay:0`；另一居民随后把遗体安置到
该真实暂存位时，原睡觉路线仍会踏上遗体。这和出门路径已有的阻挡规则不一致。

`tests/room-work-boundaries.test.ts` 使用正常 `submitPlan` 睡觉选择并经
`stepWorld` 开始实际入室，再按遗体安置完成后的状态把尸体置于指定 bay。
这不是“死亡立即阻路”：新死亡的 `storedAt=null` 不形成这里的阻挡。
测试在修复前，两例均实际踏入 `{x:2,y:10}` 的 bay 而失败。

## 修复边界

所有室内移动现在逐步验证当前位置、真实入口对应关系、单格距离和当前
可通行路径。发现新阻挡则留在实际位置，结束失效安排，交给居民重新决定。
不自动绕路、瞬移、重新安排睡眠或更改 AI 决策。已有共屋、公共服务和
救援的针对性错误描述保留。正常可达睡眠/做饭/室内社交不改变。

此次仅修复实际移动边界，不改变活人是否互相阻挡、死亡或遗体暂存规则、
家具布局、睡眠收益、视觉及引擎选择。

## 验证

- 新回归包含真实世界步进和 SQLite 文件关闭重开，与不中断对照一致；
  未到床前不获得睡眠恢复，失败后不会自动重试。
- 路径上的遗体是精确指定暂存位的合成 fixture，不声称本测试完整执行了
  另一居民的搬运流程；原有葬仪回归另行运行。
- 临时 SQLite 仅写 `output/` 并在测试后清理。没有读取真实存档、`.env`
  或密钥，没有真实模型调用，也不属于长期运行验收。

本轮结果：室内/出门回归 35/35，共屋/公共服务/葬仪回归 155/155，
独立新增边界 review 4/4；`tsc --noEmit` 与 `git diff --check` 通过。
独立审查批准。未运行全量测试或长期运行验证。本修复不声称覆盖工位已经
开始工作后才新增阻挡的所有情形。
