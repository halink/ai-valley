## 初审风险

- 目录必须独占新建，拒绝既有目录、文件、符号链接和受保护的真实存档路径；读回不能跟随替换后的链接。
- 短写须重试剩余字节；零写、部分写后抛错、flush/fsync/close 失败必须失效，不把截断日志称为完整。
- 结构化白名单必须先于 trusted audit，拒绝额外字段、错误类型和序列化钩子，错误消息不能包含输入或原始 I/O 错误。
- 完整性依赖两个通道的状态、行数、连续序号、会话、世界和起止区间，而不是 JSON 可以解析或 hash 存在。
- 中途 checkpoint 不等于正常终止。缺少最终状态、崩溃或观测失败不可把缺测解释为零。
- 持久化与读回完整不代表十五日、九人存活、所有食物消费或真实模型执行；哈希不是签名或防篡改认证。

## 结论与保留边界

当前审查范围内未发现剩余阻断问题。Linux目录描述符逐级锚定与 O_NOFOLLOW 将路径保护落实于打开操作，不靠字符串前缀；文件独占创建，持久事件走共享连续序号与哈希链，封存读回同时核对原始字节、起始清单、最终状态和通道端点。失败日志只可读回前缀，不修复、不续写、不构造缺测总量。

I/O 注入只验证进程可观察失败，不证明硬件、文件系统或断电下的绝对持久性。目录选择仍依赖调用方在明确授权的独立位置使用；保护组件列表不能辨认任意名称的真实存档。writer 本身不创建/打开数据库，不替代未来 runner 的数据库独占创建、费用/请求/墙钟上限、信号控制或精确十五日端点处理。schema 拒绝常见钩子，但 JavaScript Proxy 的反射陷阱不在可信内部 sink 的边界内。哈希链不是签名，能够重写所有文件的人可重算哈希；本审查不作防伪声明。

`complete` 只表示本次已记录时段两类证据完整，范围可以是零或小数分钟。初始九人、真实模型、全部生产/消费、毛健康损伤以及十五日可持续性仍须独立证据；相关未知字段不能由 writer 推导为成功。
