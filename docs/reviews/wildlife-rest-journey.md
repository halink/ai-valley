# 野生动物返巢不能计作睡眠

## 正常流程缺陷

野生动物因疲劳或昼夜节律返回藏身处时，`moveToward` 实际前进一步后，
原代码把活动标记为 `rest`。下一次生理步进仅凭该标记给予每分钟 `+.12`
体力及 `.66` 饥饿增长倍率。因此返巢路上每隔数分钟继续走动，却一直取得
睡眠收益；疲劳动物可能尚未抵达就因体力恢复而不再满足返巢条件。

本轮不是以调参解决资源问题。行走中的标记改用已有 `roam`，理由为前往
藏身处休息；真正停下才记作 `rest`。运动 `-.03`、睡眠 `+.12`、饥饿
倍率、原有距巢两格以内停下的容差以及原地休息策略都不变。

旧存档可能仍带有 `rest` 和远处目标。因此生理计算还要求已在目标两格内
（或旧记录没有目标）才能获得休息收益，不批量改写存档、重置体力或补发食物。

## 验证方法与边界

`wildlife-rest-journey.test.ts` 以受控地图和一只疲劳成年鹿作为合成起点，
从正常行为选择逻辑驱动实际 `stepWorld`，逐分钟检查移动不超过一格、返巢
期间运动消耗与饥饿、抵达后原地恢复。另从途中关闭并重开 SQLite 文件，
对照不中断运行的同一只动物完整状态。修复前两例失败，修复后通过。

只使用 `output/` 下测试专用存档并清理，没有读取用户真实存档/密钥，
没有调用模型、强制居民选择、改视觉或进行长期运行验证。

结果：新场景 2/2、独立边界 review 7/7；最终相关生态/历史/饮水回归
135/135，TypeScript 与 diff 检查通过。最初扩展回归发现原饮水审查对
普通返巢活动标签仍期待 `rest`；已改为 `roam`，保留其原位置、路径和
水量断言（不把本修复扩大为普通返巢灾害避让）。独立审查批准。
此次纠正原来额外给予的休息收益，不能据此声称提高野生动物存活率；没有
以改动需求、补食物或改变野兽数量来抵消真实移动成本。未运行全量验收。
