# 家庭迁居年龄与本人签署独立审查

审查日期：2026-11-07。

## 结论

独立审查发现一类历史本人补签可能被降格为幼儿代理的问题，生产修复后两条独立反例及相关回归全部通过。当前审查范围内没有剩余阻塞问题。

## 已解决问题

原五岁协议的 `requiresAssent` 保持 `false`。孩子满六岁后通过正常最终编号菜单实际接受原约，产生本人签署与事件；随后出生资料变为可解析的三岁且本人失去决定、表达能力时，原实现只检查原 `requiresAssent` 和当前年龄，没有把已经存在的本人补签计入独立参与要求。

独立测试确认两种错误结果：

- 父亲的最终菜单重新出现幼儿 `escort`，也可能重新按幼儿豁免出发。
- 已出发家庭在下一步仍为 `travelling`，没有在实际位置暂停，失能的本人被重新当作代理乘客。

复现位于 `tests/family-relocation-age-authority-review.test.ts` 最后两项。生产修复者已统一 `personalMember` 判定：原本要求本人答复、当前已满六岁，或本协议已有本人实际签署，均保留独立参与要求；代理接送、途中能力校验、步速和入住等共用该判定。原签署、原成员条款和期限不改写。两项原失败反例已独立重跑通过，另复核实现方覆盖的 accepted / travelling / arrived / cancelled 四阶段及其两次 SQLite 往返。

## 独立覆盖

新增测试使用单独合成世界夹具，通过 `decisionContext → decisionChoices → parseChoice → submitPlan → stepWorld` 完成真实行动；没有注入允许菜单或直接伪造签署。

- 到达后跨六岁仍需本人补签，然后本人分别登记。监护人不能代签、代登记；补签不等于入住。
- 暂停途中本人补签不自动复行，不重复扣粮水。原约 ID、责任、成员、床位、原签署名单、出发窗口与总期限均保持原值。
- 两次内存 SQLite runtime 重载、短记忆清空与 220 条后续事件挤出后，真实签署及对应历史事件继续保留，不补签、不续期。
- 复行最后 0.25 分钟发生年龄未知、决定/表达能力失效或满十八岁时失败，不移动、不扣物；满十八岁清空监护关系是既有生命周期行为，不归因于迁居。
- 补签最后 0.25 分钟发生年龄未知、表达失效或原约到期，不追加签署。接回原住所途中出生资料异常，重载后在原位置停止。
- 原幼儿尚未签署、已经签署的孩子、监护人和房主，在年龄未知但仍有决定/表达能力时，可通过真实编号菜单拒绝原约。非当事人不能借未知年龄拒绝或签署他人的安排。
- 入住最后 0.25 分钟及其 SQLite 重载重验本人年龄与房权；先前已经入住的父亲不倒退，孩子原床位保持真实床号及原住处登记，未完成入住不改产权、钱物或亲缘。
- 旅途最后一个格子、下一餐前跨六岁，先暂停再移动/供餐；不提前抵达或释放原床。
- 远方房主年龄未知、房权转移、住宅损坏不改变途中孩子的原约补签菜单，也不自动传送消息。远方房主实际撤回只记其本人撤回，家庭到达后才被入住校验阻止。
- 原本已要求独立答复的历史成员，出生时间回退至幼儿年龄且失能时，不得重新变成监护代理。后来通过本人真实行动补签的成员同样受到保护。
