## 核心检查

1. **语义**：等待从观察边界上的候选资格开始，不从 decisionDue 推断真实开始时间。请求返回与计划接受分开；失败、重试与回退留在同一等待段。主动 wait 计划接受后结束技术等待。失去资格与 stop 为删失结束，不冒充成功。
2. **时间**：墙上时间只定位，持续时间使用单调端点差；单调时钟失效后保留 null。停表允许 gameMinutes 为零而 elapsedMs 增长，不以日速换算，不把并行居民时长当世界停表时长。
3. **失败与遗漏**：明确 TimeoutError 才归类 timeout。配额拒绝、准备失败没有伪造请求。回退待尝试与实际 backup request 区分。sink 抛错或返回 Promise 后标 failed，序号只表示尝试发出，不是可靠落盘确认。
4. **隐私与状态隔离**：runtime hooks 只传模拟 ID、模型枚举、固定原因/安全错误码与时间；事件冻结，不携带世界、prompt、回复、反馈或密钥。记录器不写入 World、snapshot 或模型上下文。固定时钟下的九人测试比较完整世界、内存存档、模型上下文和请求顺序一致。
5. **重启**：stop 关闭当前开放请求与等待；新 runtime、新 session 不补算停机时间。旧请求不能结束新会话或新等待段。关联校验修复后的回归已独立实际通过。

## 剩余边界与后续验收要求

- 目前默认服务没有持久证据 writer；未来验收需另行接入可靠 sink，并同时保存状态、检查首尾事件和序号。没有观测、崩溃、输出缺失或 failed 状态必须保持未知，不能报零。
- 同步 sink 必须快速、非重入，不通过闭包操纵 runtime。固定时钟等价不等于任意慢 sink 对真实墙钟与 CPU 开销无影响。
- 原 runtime 在同实例仍有未完成 promise 时 stop/start 的生命周期风险没有在本批修复。正式重启应创建新 runtime；证据 session 隔离不保证旧实例的世界/调度隔离。
- 新定向集充分验证居民流程，但未专门构造 regional/foreign 的完整真实候选生命周期及每一种拒绝路径；相应 hooks 本次为代码检查，不能把 19 项测试扩称为这些分支全部动态覆盖。
- 资格只在 start/tick/schedule 边界采样；边界间发生又消失的资格、会话前等待和停机区间无法恢复。人物 ID 在会话内应唯一。
- 对真实供应商超时名称、流中断方式、网络延迟、进程强杀、磁盘丢失以及跨进程持久汇总，本次没有实测。不输出真实长期等待统计，也不改隔离日报的 technicalOrModelWaitMinutes 未测状态。
