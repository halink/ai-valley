# 绘本贴图技术原型独立审查

## 范围与证据

本轮只审查显式调用的贴图准备、合成图集、只读绘制计划、观察入口和 Phaser 3.90 适配器。已阅读 `CONTRIBUTING.md` 与 `docs/design/storybook-valley.md`，并核对原有几何、素材契约和居民位置判定。没有改动五份用户设计文本、食物赠送候选或默认入口。

两张用户参考 PNG 未在此次输入中提供。`assets/storybook/synthetic-prototype.png` 是仓库自制、明确标注 SYNTHETIC 的诊断图集，不是人物或建筑正式素材。实际查看了该 PNG；四个路线箭头、问号位置标记、地块与三层共屋线框符合这一狭窄用途。文件校验测试另外核对了 SHA256、PNG 块 CRC、解压后的每行像素与生成源一致。此项不是浏览器解码或画面验收。

## 发现与处理

1. **后期场景事件注册失败会泄漏观察订阅。** 初审版本在 `createStorybookObserver` 成功后注册 `shutdown`/`destroy`。若事件注册抛错，外层 catch 仅执行表面清理 `clean()`，不会调用观察控制器的 `dispose()`。精确故障条件是模拟 `scene.events.on` 在其中一次注册时抛错；此前成功取得的快照、房间订阅仍被保留。**已修复并独立复验**：外层 catch 先释放已取得的控制器，再清理表面。直接适配器测试分别注入 shutdown、destroy 注册失败，验证订阅、纹理、输入和已建显示对象释放。
2. **相机变换是适配器边界。** `setScrollFactor(0)` 不等于免除缩放、旋转或相机 viewport 变换。未经逆变换的 `pointer.x/y` 不能直接匹配经变换后的容器；多相机也可能重复绘制。**已在限定契约内修复并独立复验**：安装时只允许单一、零偏移/滚动、单位缩放、零旋转相机；绘制、输入与 preupdate 再检查，后续变更清空绘制并停用观察，不保留可点击目标。模拟测试覆盖安装时非单位缩放拒绝和安装后旋转清空。真实相机和浏览器输入仍需以后验收。

复审重新阅读了最终适配器、观察入口及直接契约测试，并在本审查线程独立执行四文件测试。两项初审发现均在上述受限契约内解决；没有遗留阻塞项。

## 独立测试

新增 `tests/storybook-prototype-review.test.ts`，六项测试均使用新建内存合成世界或模拟表面：

- 遗体声称被不存在的人携运时，不在旧坐标绘制身体或位置标记，而是报告位置未知。
- 携运关系账本损坏时，居民位置全部保持未知；建筑仍可独立显示。
- 200 位合成人物只准入 192 个对象，居民先于建筑；其余数量明确提示；513 人记录拒绝；源快照不被修改。
- 西向真实相邻路线使用 northwest 独立帧，脚点仅按记录的 0.75 进度移动；1.01 非法进度退回已知位置标记，不继续步行。
- 两个重叠对象使用不同图集矩形时，前对象透明像素穿透到后对象；alpha=1 的像素属于前对象。
- 切换世界 ID 重置手工窗口；释放后即使旧回调再次触发，也不恢复计划、选择或订阅。

执行：

```sh
HOME="$PWD/output/storybook-prototype/home" \
TMPDIR="$PWD/output/storybook-prototype/tmp" \
TMP="$PWD/output/storybook-prototype/tmp" \
TEMP="$PWD/output/storybook-prototype/tmp" \
node --import tsx --test tests/storybook-prototype-review.test.ts \
  tests/storybook-prototype.test.ts tests/storybook-texture.test.ts \
  tests/storybook-phaser.test.ts
```

初审三文件结果为 20/20；最终四文件独立复审结果为 **26/26 通过**。新增四项适配器测试是模拟 Phaser API 契约，不是实际 Phaser 场景或浏览器测试。最初独立关系账本测试的夹具直接修改了 seed 未初始化的 `health`，因此在调用被测函数前失败；已改成明确的损坏合成账本后重跑通过。这是测试夹具修正，不是忽略产品失败。

最终补充复审核对了点击页脚（原对象标签、反算地图格和缺图/姿态理由）、320×240 最小视口、预留页脚的缩放计算，以及通过 `Reflect.get` 读取 Phaser 3.90 相机 rotation。新增九人测试确实调用 `createFrontierWorld`，冻结原世界后检查原 ID、有限窗口与不变快照，不是 54 人的 `createFormalWorld`。这些改动未发现新的契约阻塞项；页脚长文本在真实字体和小视口下的换行高度仍属于尚未执行的浏览器布局验收。

最后核对了绘制异常隔离：表面抛错后清空计划并停用，仅再尝试一次空计划清屏；第二次失败也被有界捕获，不中断原观察源。新增模拟表面故障测试验证清屏、后续源事件不重新启用、手动重启后可恢复。四文件已在此补丁后独立重跑，结果为上述 26/26。

## 边界与结论

- 绘制计划复用已有居民判定，路线方向直接取世界格相邻偏移，不使用旧投影朝向的归并结果。
- 实际占地与脚点不被图集大小改写；共屋仅在 8×6、完整状态且层锚点相符时使用诊断三层。不支持的状态不画成完好建筑。
- 暂停/断线只保留快照事实，不增加显示时钟或动作成果；室内明确回退，不把居民搬到门口。
- 原型不持有 GET、SSE、模型、存储、模拟推进或定时器；默认入口未接线。调用者必须自行显式创建专用场景。
- 所有结果只证明所列离线契约。没有浏览器、IPC、网络、密钥、真实存档、运行时读取、依赖安装或提交操作；没有重试被拒绝的浏览器访问。未运行完整测试套件，也未证明桌面/手机画面、字体、真实 Phaser/GPU 绘制、实际浏览器点击或性能预算达标。
