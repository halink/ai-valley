# 普通 care 供餐证据独立审查

## 范围与结论

检查世界内普通 `care` 成功完成点、逐步捕获、运行时提交、严格字段边界、验收汇总、writer 回读和隔离日统计。新增独立回归位于 `tests/care-meal-evidence-review.test.ts`，只使用合成世界、内存 SQLite 和临时证据目录。

发现并修复一项事实一致性缺口：原 `auditCareMeals` 只检查 `before - after = relief`，因此自洽但不符合规则的 `70 → 70 / relief=0`（以及超额缓解）可获完整数值汇总。实现者已增加 `after = max(0, before - 22)` 校验；独立回归覆盖 0、21、23、70 的错误缓解及饥饿不足22时的合法截断。修复后本次独立测试全部通过，未发现剩余阻断项。

## 已验证的反例

- 旧事件没有 `careMeals` 与显式空数组不同：前者覆盖未知、汇总为 null，后者可报告本段已观测零次；丢失会话边界也不能报零。
- 缺失原食物定义不修改世界、不补造营养，不从22反算。meal 营养未知时数量和缓解仍可保留，nutrition 为 null；water 是单独的零营养支出。
- 严格 writer 入口拒绝额外私有字段、嵌套未知字段、getter、symbol、数组空洞和 NaN，不调用 getter。旧事件仍能解析，但不能伪装 care 覆盖。
- 同人施受、错误容器、同意编号缺失、重复事件、过期/未来批次、无批次却声称营养、未知批次营养却声称总营养均不能得到完整 care 汇总。
- 实际引擎最后工作 tick 前撤回，既不扣餐也不发 receipt；成功后原同意过期，重复执行无第二次扣款/证据。
- 相同合成世界的带证据与普通 step 完成后完全相同。证据不写进 World；运行时 receipt 是脱离原对象的深冻结副本。
- 实际 care 完成遇到合成 durable commit 失败时，持久同意仍 accepted、公开运行时世界回滚且没有发布草稿 receipt；恢复提交后只发布一次真实完成。
- writer 完整封存与回读保留41营养和22缓解的不同数值；删除 close seal 后顶层及嵌套 care totals 均为 null。
- 隔离日内只要一分钟缺失 care 覆盖，后续已观测空分钟不能将日累计恢复为零；其他直接进食已观测零仍独立有效。
