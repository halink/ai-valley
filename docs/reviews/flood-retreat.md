# 洪区近处撤离独立复核

## 结论与范围

独立只读复核检查了近处洪区候选搜索、共享撤离边约束、引擎起步与逐步移动，以及新增隔离回归。最终静态复核未发现阻塞项。未修改天气调度开关；这项修复不能作为启用新天气风险的许可。

## 复核发现与修正

1. **安全终点不等于安全路线。** 最初补丁只核验候选终点，在狭窄河岸走廊仍可穿越居民原本位于范围外的风暴。独立复现：16×13地图，仅 y=6、x=0..10 为草地，(11,6)为水，其余为悬崖；居民(10,6)，洪区由水格实际生成，另有中心(8,6)、半径1的风暴。初版菜单给出(4,6)，路径9→8→7→6→5→4穿越风暴。新增回归先红，再由菜单与引擎共用逐边风险约束转绿。
2. **菜单和引擎必须使用相同的边。** 起点位于U形坏桥上的居民，可以沿原桥面走出去，但不能离桥后重新踏上坏桥。独立构造实际水岸洪区，确认普通通用寻路的三步捷径不适用于撤离；撤离引擎按真实边走五步成功。新增完整引擎回归保留这一行为，没有扩大修改所有动作的通用导航。
3. **选路后的新风险不能绕过规则。** 独立验证起步后下一格新增洪水预警时，居民在踏入前停止，无完成撤离事件。实现将共享约束用于每批移动的逐边检查，而不只用于菜单或起步。
4. **有限成本与既有行为。** 近处搜索最多24步、1,201格且只给一个选项。旧远点候选分支也只构建一次共享风险过滤器。引擎保留原道路时间权重，不承诺机械复用菜单BFS轨迹或固定24步的最终行程。

- 建筑知识、决定保护、公共设施、机会覆盖及牧场围栏五组周边回归合计70/70通过。
- TypeScript全项目检查通过。
- 另用独立内存世界验证风暴穿越复现、U形坏桥真实五步执行，以及新增预警的第一步前中断。

实现方另外运行完整离线回归、服务端编译和生产构建，最终结果见[实现与验证说明](../implementation/flood-retreat.md)。独立复核只使用新建内存世界和本地依赖，没有读取密钥或真实存档，没有模型、浏览器、npm、提交或推送。浏览器视觉、真实模型、完整四季及照护对象整体撤离仍不在本次通过范围。
