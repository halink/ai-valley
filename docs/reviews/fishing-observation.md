# 鱼群有限生态观察独立审查

## 范围与修复前证据

审查先独立阅读 `src/world/fishing.ts`、分种定义和既有鱼类测试，再核对产业观察。没有读取正式存档、环境密钥或调用真实模型。

原产业面板将水域全部鱼种的繁殖进度之和当作“下一个自然恢复单位”百分比。分种繁殖各自结算，两个品种各有 0.6 进度并不等于任何一个品种完成繁殖。原代码还将筛选和容量文案都固定为 12，导致绑定容量 24、现量 12 的水域被完全隐藏。

`tests/fishing-ecology-review.test.ts` 的独立观察反例使用另一套 64×32 合成水域夹具，绑定容量 24、现量 12，并深冻结完整世界。修复前前三项核心基线通过，而该观察断言失败：HTML 缺少实际种群 `12/24`，显示“尚未出现未恢复的捕捞压力”。这是真实执行的修复前失败，不是只靠阅读源码推断。

另加缺失绑定定义且删除默认定义的冻结世界反例：观察必须保留容量未知，不能借读取补写默认定义或改动世界。

## 核心生态现状核验

三项直接调用 `advanceFishing` 的独立基线核验：

- 两端无洪水而中间水路有活动洪流时不能迁移，洪流移除后的下一日允许有限迁移。
- 连续 224 日检查所有品种的“现量＝登记＋出生＋迁入－捕捞－捕食－迁出”，共同容量不超过 12，同刻重复推进不变化。
- 片区之间的干地屏障阻断迁移。

上述三项在修改观察代码前已通过。它们不是修复前失败反例，不是完整 `stepWorld` 长期推进，不证明默认村落长期生存或食物供给，也不证明真实模型四季验收。

## 保留边界

本轮不改鱼群出生率、容量、开局资源、捕捞和迁移规则，不将观察文字当作新生态行为。水格全部消失后留下 `shoal:null`、再恢复水格的重新定位仍属于既有文档标明未交付的河道变化范围，本轮不扩展处理。近整数繁殖进度的浮点微小负值同样未在此观察修复中改动核心结算。

## 候选复核

新增 `fishingEcologyPanel` 是纯字符串渲染，只从已存在的绑定定义读取容量，不调用会登记定义的世界 helper。行业面板仅替换水域观察段，没有改核心生态结算。逐种进度分别展示，零存量明确不能自行繁殖，迁入明确受条件限制且不保证恢复。满容量但含灭绝品种的水域仍显示。

独立审查又核验保存的水域键 HTML 转义，以及显式 `null` 容量不能伪装为默认 12。审查指出候选初版使用 `??` 会把 `null` 当缺省；主工人同时改为按自有字段存在性取值。本独立用例首次执行时该修正已经生效，因此不声称取得这个小点的修复前红测。

独立文件共 7 项已通过，其中 3 项是原核心基线、4 项是观察边界；深冻结与前后完整 JSON 对比确认本轮所测渲染未改世界。主观察 6 项与最初独立 5 项的联合 11 项也已通过。

观察字符串断言不是浏览器视觉或性能验收。真实 CSS 静态切片由主交付文档记录，不代称正式世界浏览器接线验收。独立复跑 `fish-species`、`fish-shoals` 和两个新测试文件联合 34/34 通过，包含主工人新增的三种子各一日完整 `stepWorld` 观察/不观察终态相同对照；该对照无居民计划，不代表长期居民行为或食物供给验收。
