# 未知年龄永久收养：独立审查

## 结论

本次范围内没有未解决的阻断问题。独立审查发现两类历史本人同意证据缺口，已反馈实现者修复，并在最终代码上复验通过。新增 `tests/unknown-age-adoption-review.test.ts` 共 **47 项**，与实现测试 44 项、原收养测试 8 项联合运行 **99/99 通过**，无失败或跳过。独立执行类型检查退出码为 0。

本结论仅针对未知年龄收养权限及下列回归，不替代整个共享工作区的全量测试、构建或真实模型长期验收。

## 审查发现与关闭证据

### 1. 当前满六岁不证明历史签署时已经满六岁

原 `childAssented` 只验证本人同意时点位于提议期间，并存在相同孩子 ID 和时点的签署条目。复现中，出生资料先变为未知，恢复后显示孩子签署时仍差 0.25 分钟满六岁、当前已经六岁，登记菜单却仍认可原签署。

实现者现使用 `knownAgeYears(child.bornAt, childAssentedAt)` 核实签署时年龄在 `[6,18)`。独立 `beforeSix` 用例确认：不改写旧签署或原期限；必须由当前有能力的孩子通过实际编号菜单另行签署，才可登记。

### 2. 无来源核对的匹配时间可以随时钟变成同意

把 `childAssentedAt` 和对应签署的 `at` 一起改成未来 0.25 分钟，原代码在当前时点暂时阻止登记，却在时钟追上后自动认可该记录，甚至使孩子重新签署失败为“本人已经签署”。缺失事件、指向监护人事件的引用也未得到核实。

实现者现只读核对签署 `eventId` 对应的关系事件、同一事件时点、以孩子为实际行动者及收养人参与。独立 `future`、`missingEvent`、`wrongEvent`、`guardianEventAsChild` 均已通过。最后一例同时复制监护人的真实事件 ID 和时点，确认“孩子出现在事件参与者中”不等于孩子本人同意。

合法旧证据兼容性另有实测：完成真实本人签署后推进 60 分钟、产生 205 条无关合成事件、清空个人记忆、运行 `workingEvents` 裁剪、内存 SQLite 保存和 `loadForRuntime` 重载。签署事件仍保留；出生资料恢复后无需重签，即可实际登记一次。

## 独立覆盖

- 孩子、收养人、监护人分别为 null、NaN、未来出生时间时，新提议在最终菜单和直接执行均被拒绝，不产生亲缘或登记事件。
- 2、6、17、18 岁的真实分支：幼儿豁免不伪造本人签名，六岁及以上需本人实际签署，成年者不可当孩子收养。
- 历史本人签署缺失、错人、时间不匹配、早于提议、未来、到期边界、NaN、未满六岁及错误事件引用，都不能作为本人同意；查询与失败不修改旧证据。
- 年龄同时未知时，孩子、监护人和收养人仍可通过真实编号菜单撤回；孩子和监护人仍可拒绝。无表达能力、非原当事人、未实际在场者不能借负向入口取得代理权。
- 登记行走途中出生资料损坏并重载：下一步立即中断，位置不继续移动，不生成登记；恢复资料不自动重启，须重新选择原提议登记。
- 登记最后 0.25 分钟，孩子或收养人的出生时间变为 null、NaN、未来时均不创建永久亲缘。
- 登记最后 0.25 分钟跨六岁生日，幼儿豁免失效；之后孩子通过真实选择同意才能登记。
- 原七日期限恰好到达时不能登记；未知年龄暂停不会续期，也不会阻止实际死亡、离开或恢复为成年年龄后的原失效规则。
- 合法旧监护签署不会因监护人之后年龄未知而被补造或抹除；未结束提议 ID、理由、签署和期限保持连续。
- 成功登记不重复增加养亲、监护或登记事件；拒绝、撤回或失效后旧编号动作不能复活安排。
