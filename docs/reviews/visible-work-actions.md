# 现场工作动作：独立审查

## 范围与结论

本次审查覆盖 `action-position.ts`、`person-pose.ts`、`work-art.ts`、`work-feedback.ts`、`scene.ts`、`resident-status.ts`、`main.ts`、`shared/work-completion.ts` 与 `world/engine.ts` 的相关改动，并阅读 `docs/art.md` 和 `docs/design/observation.md`。审查者只新增本报告与 `tests/work-visual-review.test.ts`，未修改实现、提交或推送。

在已验证的正常状态路径中，未发现新增模拟规则变化、观察渲染写回世界、失败动作误报完成或人物纹理遗留。位置判断区分实际相邻采集、尚未走完的路径、室内工位与门口；工作动画与完成反馈分别依据当前活动和明确的成功事件，不把工具动作当成产出。暂停测试验证工作相位冻结与恢复，不推断所有 Phaser 动画系统都已全面验收。

## 发现及修正核验

- **Low：儿童深蹲躯干。** 初版 `work-art.ts` 的身体高度可能在儿童 sow/harvest/fetch 第三帧变成零。实现者限制弯腰幅度后，已核实四年龄阶段、八动作、四方向、四相位的整数像素边界与每方向四帧可辨测试通过。该组合为 512 张帧图，不将测试迭代次数等同于浏览器截图数。
- **Low：非有限位置。** 初版 `atActionPosition` 接受双方相等的 Infinity 坐标；独立复现 water 的 focus.x 为 NaN，像素标记含三个非有限值。实现者补充 `Number.isInteger` 防护后，独立重放 Infinity、-Infinity、NaN 和分数坐标四个反例，均返回非工作位置、idle 姿势和 null focus；原问题已修正。此检查不宣称完整地图/房间越界验证。
- 初版像素基线仍为 `TO_FILL`，联合测试因此失败；这不是绘图运行错误，但必须在最终图样核验后固定哈希，不能将该次运行报告为全通过。

## 独立测试（4 项）

`tests/work-visual-review.test.ts` 使用合成世界和真实 scene 方法的离线 harness：

1. 已故与镇外居民即使保留旧工作 activity，也不获得工作姿势。
2. 人物从快照移除及世界身份切换时，四个纹理帧键全部清理。
3. `scene.accept` 与连续 `scene.update` 前后完整世界深比较一致，验证观察者渲染不写回模拟状态。
4. 完成事实缺少参与人、位置 NaN、房间缺少位置、开始时点晚于完成、事件类别错误或带镇外区域位置时，不产生完成闪光收据。

纹理测试验证删除调用及帧键，未使用真实 WebGL 纹理管理器。只读测试覆盖所构造的工作场景，不替代所有活动类型的状态变化审计。

## 静态图与验收边界

独立打开并查看初版离线生成的动作联系图：工具剪影、伸手、俯身、浇水与垂钓相位可辨；钓鱼没有绘制假鱼获，采收没有凭动画填满篮子。随后再次打开重新生成的八列静态图，查看四相位及东/南/西/北方向：播种与收获的道具、姿态区分更清楚，方向变化可见。图片仍是合成静态样本，最终打包图若再次更新，应由实现者核实与当前源一致。

静态图来自与客户端共用的程序绘图源，验证的是帧内容。scene harness 验证的是方法控制流和坐标，不是真实浏览器、GPU、事件流或实际场景遮挡验收。本次没有运行浏览器，未读取 `.env`、密钥、真实存档或正式运行输出，未调用模型，也未通过 IPC 驱动程序。长期运行、实际桌面/手机布局、真实 Phaser 动画与缓存释放仍不能据这些离线结果宣称通过。
