# 靠泊医疗救助复核

## 复现与修复

原始问题通过真实造船、发布船程、乘客独立预订和上船后再发生重伤复现。岸上救助者具备药剂、布料、清水和可达诊所，正常菜单确实给出 rescue/stabilize，但两者目标都是不可步行的船体水格 `{x:7,y:6}`，而可接触码头应为 `{x:6,y:6}`。修复前新增两个流程测试均在这项断言失败；修复后保持患者在船上直至实际完成有限稳定或15分钟接出，并经正常医疗步行流程送达床位。

## 独立审查发现

独立审查者另加 `tests/ferry-rescue-review.test.ts`，只修改测试，不修改实现。

1. **已修复：船上纯答复可夹带移动目标。** 一份有效 acceptRescue 加 targetId 能让患者通过步行路径走上岸，同时仍留在船舶乘员表。现在答复目标恒为本人实际位置，拒绝夹带目标、靠泊快照、递送阶段以及冲突的安排ID。
2. **已修复：临近接出吞掉明确撤回。** 原5分钟取消尚未完成时，接出可先清除患者计划并继续搬运。现在单独的拒绝/取消在提交时即时校验并生效，不等待劳动计时；不推进时钟、不挪动患者、不消耗物资，也不取消无关的等待计划。含其他后续动作的取消整份拒绝。
3. **已核验：一份取消不能混合有效提议和无权操作的另一项护送。** 仅允许单一 offerId 或 transportId。
4. **已核验：最后一位乘员接出不等于卸下货物。** 仍有在船货物时保留船程及船只占用。
