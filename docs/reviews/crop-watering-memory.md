# 作物浇水记忆独立审查

结论：本次普通 `water` 完成分支的文本修复未发现阻断问题。名称读取实际田地当前绑定的定义版本，不读取行动自带的芜菁依赖、活动版本、产出名或猜测定义 ID。缺少定义、无名称、空白及非字符串名称统一使用“作物”；有效名称去除两端空白。

独立测试：`tests/crop-watering-memory-review.test.ts`，5/5 通过。

- 旧版田地与新版活动定义并存时，事件仍使用田地绑定版本的名称。
- 只有本人和真实近处见证者收到同一事件的记忆，远处居民没有获知；原有错误历史记忆不被改写。
- 开始后更换田地绑定作物时，完成记录使用完成时的实际绑定名称。
- 缺失定义、缺失名称、null、数字、布尔值、对象、数组及纯空白名称均安全回退，不误写芜菁或序列化元数据。
- 缺水、作物消失、使用权改变，无论发生在开始前还是工作途中，都不会生成浇水事件或记忆，也不额外耗水。
- 正常完成仍只耗一份水、写入当前绝对日，不改变生长量或作物绑定；同日主动选择两次浇水仍产生两次完成和两份消耗，没有偷偷增加幂等规则。

验证通过真实 `submitPlan` → `stepWorld` 执行链，使用全新内存合成世界。独立测试命令以仓库 `scripts/repository-temporary.mjs` 创建专属临时目录，约束 HOME/TMPDIR/TMP/TEMP，执行单个测试文件并清理本次目录；未运行真实模型、浏览器或正式存档。此项结果不代表完整套件、持久化主链或长期模型验收，后两者由主实现测试与后续验收分别说明。

范围说明：仅改变未来普通浇水完成文本，不修补既有记忆，不改变播种、收获、浇水资格、耗水、时长或生长规则。旧版无显示名称的芜菁定义也会显示“作物”，这是避免无证据品种断言的预期兼容行为。
