# 食物交接窗口：只观察的记录计划重放

## 结论

本轮完成了[前次因果审计](resident-survival-causal-audit.md)提出的交接窗口核查。候选归档的完整十五日动作轨迹可精确重放；加入观察没有改变被核对的世界状态。失败具体落在**危险撤离优先、已选行动占用决策时间、双方离开/交付错时，以及很短的合法提议接触**，没有复现新的菜单保留或稳定候选轮换缺陷。

因此不修改生产代码、控制器、资源、等待参数、期限或自主接受/交付规则。观察到失败并不授权替居民选择接受、停止撤退、延长停留或自动交付。本轮也不声称存活能力改善。

## 三次未完成交接的实际原因

### 母亲第一次提议：接受项出现，但原选择是撤退

徐澜的第 3 份赠食在 15881 生效，固定到期 16001。苏葵早期能读到本人提议记忆，但脚本记住的供者位置过旧；随后在 15963、15970 分别选择会合移动。

在实际决策序号 5739、分钟 15977，苏葵空闲，徐澜在近身范围。对应赠食的 `accept` 同时存在于个人正式机会和最终菜单第 10 行；第 20 行是本人已知的合法野猪撤退，归档实际选择后者。该控制器本来就把危险撤离放在赠食接受之前。

15977 选择的撤退在 15978 开始，15990 完成。苏葵再选第三次会合，15997 完成后触及既有三次尝试上限，提议最后过期。这不是一直没有接受项，也不是提议记忆丢失。接受本身仍不等于已收货，不能推定改选接受就必然完成供餐。

### 第四份赠食：先交付与离开同时开始，后来返回又撞上等待

高禾的第 4 份赠食在 16021 生效，固定到期 16141：

| 分钟 | 原记录中的实际情况 |
| --- | --- |
| 16050–16051 | 苏葵选择并完成接受，约定位置为 `(431,242)`。 |
| 16051–16065 | 苏葵依次选 5、5、4 分钟等待；按原 helper 的“选择接受时刻 +15”得到停留界限 16065。这个界限是源码与归档推得，不是新采集的隐藏记忆字段。 |
| 16065 | 两人空闲，交付当下合法。苏葵先提交向 `(431,248)` 的探索；高禾后提交原赠食交付。 |
| 16066 | 两个活动开始。苏葵走到 `(431,243)`，离开约定点；高禾从 `(429,242)` 走到 `(430,242)`，仍有一分钟交付工作。 |
| 16067 | 交付因为收方已经不在约定点而失败。高禾随后选择 30 分钟等待，到 16097 才结束。 |
| 16080–16081 | 苏葵回到约定点，交付机会与执行条件均恢复，但高禾原等待尚余 17、16 分钟，没有新的记录决策。 |
| 16082 以后 | 苏葵执行自行选择的共屋核实而离开；原固定期限最终到达。 |

因此有过一次真实、当时合法的交付选择，只是在完成前丧失了物理条件。不能把全部失败说成菜单隐藏，也不能把两分钟返回窗口算作供者主动放弃了一次新决策。没有改短等待、强制留人或自动中断原动作。

### 母亲第二次提议：近身时都仍在执行移动

徐澜的第 7 份赠食在 20536 生效，固定到期 20656。执行校验允许接受的整数时刻只有 20536、20631–20633；苏葵在 20536 正沿共屋核实活动的路径行走，20631–20633 则在执行已选的移动活动，在到期前没有与合法接受同时出现的实际空闲决策。

这里的“忙碌时没有新决策”指归档 helper 及 runtime 的就绪准入，不是断言底层 `submitPlan` API 一律拒绝忙碌居民的新计划。赠食事件可以提前 `decisionDue`，但不取消已有活动。还须区分：**忙碌阻止此流程中的新接受选择，却不当然阻止收取已经接受的赠食**。实际赠食合法性以专用校验为准，不能拿泛用社交接触函数代替。

## 轮换遗漏有了物理窗口解释和正向对照

全部 363 个非空赠食操作组均显示源码规定的轮换候选，没有轮换索引或最终菜单不匹配。

- 高砚在 19410 的决策没有展示苏葵；相同合法提议候选集合连续存在于 19408–19410，仅覆盖这一次实际供者决策，索引为 1，显示陶笛。苏葵随后离开合法范围，未覆盖索引 0。
- 葛岚在 20095 的决策没有展示苏葵；该候选组合只存在于 20095，一个时刻、一次决策，索引为 1，显示葛慈。
- 18564–18579 的正向窗口确实覆盖两种轮换索引，两名候选都得到展示。18570 的另一目标展示发生在葛岚刚完成给苏葵的第 5 份赠食后；苏葵实际于 18578 吃下那份根菜，不是持续被排除的例子。

稳定候选的核查按有序的语义目标/物品/数量分组，排除随决策更新的回执与时间字段；所有实际菜单仍按完整原始动作精确核对。不能因为过了 30 或 60 分钟，就假定居民在所有轮换索引都作过决策。三个窗口中的苏葵共 163 次实际决策，也没有正式直接食物机会在最终菜单中丢失。

## 与饥饿损失的联系及边界

苏葵在 15932 吃过一个浆果，下一次实际进食为 16898，完成时刻相隔 966 分钟。中间没有进食收据；16398–16897 共 500 分钟高饥饿，对应健康从 100 降到 77.5。该间隔内父母的整数时刻随身根菜最低仍分别为 4、3 个，但私人物资不能算作苏葵可直接领取的供应。

这些事实解释了这条轨迹如何错失交接以及如何产生该段饥饿伤害，仍不是“某一次失败独自导致整个十五日健康差异”的反事实证明，也不证明延长等待、增加会合次数或取消撤退会更好。

## 可测试的改进方向

本轮原先定义的菜单保留/稳定轮换缺陷标准均未触发，因此不提交生产修复。下一阶段如要研究行为改善，应先明确独立实验的行为约定，再与同一源码/种子的未改控制器对照：

1. **承诺与忙闲协调**：分别衡量接受前、接受后等待、供者尚在执行旧动作、收方离开及到期；不把单纯“看到合法项”当完成交接。新的协调约定必须仍由双方各自选择，不代为接受或强制留人。
2. **危险与会合优先级**：同时记录危险暴露、撤退结果、被错过的接受机会和进食；不能为提高一次赠食成功率而静默降低安全优先级或调高尝试次数。
3. **短接触下的展示策略**：把时刻、候选顺序和实际决策频率共同纳入指标，保留所有目标的原有权限；如果另行研究新展示约定，应显式标为设计实验，而不是把目前正确轮换改名为缺陷。

以上方向本轮都没有改变动作来试验，没有承诺收益。后续若实验，应保留所有居民的进食、危险饥饿分钟、健康、赠食闭环、失败及资源守恒数据，并保留恶化结果，不能只看存活人数或终点饥饿。
