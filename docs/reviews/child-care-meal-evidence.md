# tendChild 供餐证据独立审查

## 结论与边界

本次独立检查 `family.ts` 真实完成点、弱引用捕获、运行时持久提交次序、schema 白名单、独立切片汇总、writer 回读与隔离日统计代码。新增独立测试位于 `tests/child-care-meal-review.test.ts`，只使用合成世界、合成证据和临时证据目录。九项独立回归全部通过，未发现本次新增证据的阻断项。

`tendChild` 不是普通 `care` 或 `emergencyCare`。原动作仍要求成年现任监护人、未满六岁的孩子、没有拒绝、实际接触和完成时饥饿至少12；消耗个人优先 meal、否则 turnip 各一单位，并配个人 water 一单位。饥饿降低48并截断至零，绝不以48冒充食物营养。记录没有创造提议或同意编号；紧急状态不使此动作变成新权限。水容器、长照、普通照护和其他消费不在该切片中，完整食物消费仍未知。

## 独立反例与实际动作

- 校验饥饿门槛12及上限100；合法12、47.999、48、48.001、100均按截断规则通过，自洽但错误的0、22、47、49、70缓解均不能获得完整总量。
- meal 和 turnip 各可形成一份食物加一份个人水的支出。berry、两种食物替代水、第三项输入、六份水、缺水批次语义、非零水营养、桶容器或施受同人均不能获得完整总量。
- 旧 schema-1 缺 `childCareMeals` 的行仍可读取，但该切片总量未知；显式空数组才可报告本段观察到零。缺会话首尾也不得报告零。普通 `careMeals` 的独立已知零没有被新切片的缺测污染。
- 同一 eventId 在幼儿照护内重复，或与普通照护、自主进食、加工切片重复，幼儿照护汇总均失败。与普通照护冲突时两种照护切片均失效。
- 事件、receipt、物品与批次各层未知字段、symbol 和 getter 均被拒绝，getter 调用次数为零；稀疏数组、无穷量、伪造 proposalId 与 emergency 权限也拒绝。
- 原定义缺失、批次不足、整个 food 元数据缺失的只读捕获不会改变世界，也不会使用当前默认营养或48缓解倒算。数量、零营养的个人水和真实缓解可以保留，食物营养仍为 null。批次数量不符、未来生产、动作时点已过期及未知批次却宣称已知营养均拒绝。
- 独立合成世界经真实最终编号菜单提交，在最后四分之一分钟分别执行成功和拒绝。成功实际扣一份 turnip 与一份 water，记录命名孩子和48缓解，事件资源一致；拒绝不扣物资、不发成功记录。开启与关闭观察的世界最终完全相同，World 没有新增证据字段，普通 care 切片为空。
- 完整 writer 封存与回读保留13原批次营养和48缓解的不同值。删除 close seal 后，顶层及 `directEating.childCareMeals` 两份总量均为 null。
- 食物行写入后的合成 fsync 失败使观察器失败、writer 标记 `sync_failed`，回读不能报告完整总量，也没有将原始异常私有文本写进报告。

## 提交与隔离检查

静态确认：`ValleyRuntime.commit` 先执行 `WorldStore.commit`，再安装 draft，最后调用证据 `committed`，没有提前发布分支。捕获仅绑定当前 World 的一次同步调用，并在 finally 解除；模拟副本不继承观察器。新 receipt 没有加入 World、居民决策输入或存档类型。

真实动作外层原有 `foodTransaction` 会先初始化旧批次。此次只读证据并不修补来源，不能把原事务的既有初始化说成新证据重建。批次不足的未知来源反例在直接只读捕获层检验，不谎称正常事务会跳过初始化。

完整 runtime durable-commit 故障注入、SQLite 重载、末刻变化、竞争、预测副本、隔离逐日和一年对账另由本批次的动作/运行时测试与实施记录报告。本独立文件不以合成 receipt 替代这些真实路径，也不据此宣称真实模型验收、完整消费账本或对任意外部证据的真实性认证。
