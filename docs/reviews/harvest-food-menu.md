# 成熟收获菜单独立审查

2026-11-10，对本批未提交补丁进行了独立只读审查与内存合成反例验证，不使用真实模型、真实存档或密钥。

## 首轮发现及修复

1. **同期照护冒充自救。** 把新收获芜菁营养设为0.1，原先单独链失败；加入即将完成的合法基础照护后，初版却把照护减饥算入成功。已改为遇到其他指向本人的供餐/照护回执时不认证该独立链。
2. **下一菜单没有预测中的进食。** 第510分钟已有浆果、餐食、蛋、奶，收获完成于520时，四种随身进食轮转没有芜菁。已改为提交预测进食前使用同一 `directFoodChoices` 核对当时实际候选，不扩食物选择预算。
3. **批次因果加强。** 仅看到成功收获和成功吃同类物品，不证明吃掉新收获批次。实际 `recordDirectEating` 扣货时点以临时 WeakMap 保存FIFO原批次，核对本次收获产出身份、总数量与营养；读取返回独立副本，不修改公开回执或存档格式。

## 复查范围

- 上述照护、旧同类高营养食品、进食期间旧批次过期及下一菜单食物轮转反例已纳入回归。
- 独立验证生成菜单后删除真实作物，旧选择仍由实际引擎拒绝，不新增粮食。
- 修改原批次证据的读取返回值不影响原证据；克隆和序列化回执不带新增证据字段。
- 既有60行全拒绝菜单原样保留；把末行改成普通新图纸入口时只替换这一行，前59项拒绝不变、总长不变。
- 模型文字不暴露内部预测字段，原世界不因预测发生变化。

复查未发现新增阻断项。完全由受保护选项占满的菜单仍不会追加收获；真实模型长期供给、跨四季存活与大人口最坏预测耗时不在本次通过范围内。

## 性能门槛独立静态复查

第二次独立审查专门检查廉价前置检查与“最终菜单确实缺失才预测”的修改，未运行测试、未修改文件。结论未发现新增阻断项：

- 原作物定义的可食判断与原逐候选条件一致，原快照的四舍五入饥饿值及低口粮触发保持。
- 以 `plotId` 比较最终菜单，不使用已重编号的选项ID。缺失任一相关项仍预测全部候选，保持“已有有效自救不新增”和“已有无效收获不遮蔽缺失有效收获”的语义。
- 精确执行、原批次FIFO、同期照护排除、多候选排序和替换范围未改。同一最终菜单管线的提取不改变原世界或候选数组。
- 生产调用在构造快照后立即同步准备菜单，无中间异步修改；人工饱和测试须先完成候选输入，再分别计算两种证明，不能把先后不同的快照当作差分。

审查同时指出验证限度：差分参考共用新的廉价门槛，因此还须用独立断言验证门槛；已补非饥饿/已有行动的短路、低口粮和79.6饥饿按原口径触发，以及公开入口的混合候选。90人合成耗时不代表长期大人口的最坏耗时。正常最多两候选各60次全世界步进的上限未改变，不能把这次优化描述成消除所有事件循环阻塞。
