# 雇佣加工食物守恒独立审查

## 范围与问题

仅审查合成世界中的私人雇佣加工、批次腐败、旧聘约快照及内存 SQLite 恢复。不读取真实存档、运行目录或密钥，不调用模型、联网、安装依赖、提交或推送。

原实现把 `recipe.input` 直接交给 `batch.inventory`。食品腐败会修改实物库存，从而同时把配方所需食材减到零；后续缺料校验拿已被污染的配方比对，可能把仅有水的批次当作完整原料。`recipe.output` 也与批次输出共用引用。

## 必须保持的边界

- 只有实际到达工作地点并提交工作安排的合约员工能加工；修复不应自动安排工作、移动居民或发放物资。
- 配方是接受聘约时的承诺，不能随当前激活配方更新。历史版本须保留其原始投入、产出和耗时。
- 恢复配方仅恢复承诺数据，不能恢复已经腐败的批次实物。批次缺料时不能继续计工或产出，剩余实物只可退还一次。
- 工资、已工作时间和产出在重复调用及 SQLite 重载后不能重复入账。
- 可用绑定历史定义或明确对应的招聘快照恢复旧承诺。缺少这些证据时，零量输入等异常不能自动获得一个新的可信定义后继续生产；居民仍应能够退出，保留已赚工资并退还实际余料。
- 没有历史证据，无法从受污染快照精确推导原意。修复不能宣称恢复了全部旧档，也不能追溯补造丢失材料或撤回已消费的错误产物。

## 独立反例

`tests/employment-conservation-review.test.ts` 使用故意不同于默认值的签约配方（3 萝卜、2 水，7 分钟产出 2 餐），签约后切换当前激活版本，避免测试只在默认配方下偶然通过。

1. 污染已签约配方与未完成批次，恢复历史承诺但不补实物；缺料清理重复调用不重复退款。
2. 同一污染状态经内存 SQLite commit/load 后修复，再退出，库存与总货币守恒。
3. 完整批次按原合同产出；同一分钟重放工作和完成入口不重复扣料、产出或计薪。
4. 真实食品批次到期不修改配方/定义；退出仅退款幸存实物。
5. 缺少合同定义时从精确招聘快照恢复，而非采用当前配方。
6. 缺少所有历史证据且食材归零时不能产餐或计薪，但仍能退出。
7. 未先调用食品清理时，工作入口也阻止一个已接近完成、却缺少食材的批次。
8. 旧初始化把已经污染的输入绑定成 legacy 定义，也不能将归零食材误认为可信生产承诺。
9. 旧进程内仍共享引用的批次，在直接推进食品腐败前隔离输入及输出。
10. 未完成批次的输出被夸大时拒绝加工，只退回实际输入，不追加产量或工资。

## 验证

修复前独立前四项测试结果：1 通过、3 失败，失败分别覆盖历史恢复、SQLite 恢复及腐败污染，证明这些测试可检测原缺陷。

最终独立复核：10/10 审查测试通过；与实现者当时新增测试、原有 employment/food 测试一起运行，共 45/45 通过。实现者随后补充两条批次进度/幸存食品时效回归，最终同组 47/47 通过。

复现命令：

```sh
node --import tsx --test tests/employment-conservation-review.test.ts tests/employment-conservation.test.ts tests/employment.test.ts tests/food.test.ts
```

审读 `employment-recipes.ts`、`employment.ts`、`food.ts` 后，在本次缺陷范围内未发现剩余阻断问题。新增输入/输出深拷贝、旧 live alias 隔离、历史承诺恢复、批次投入/输出/时间/进度校验，均有独立反例覆盖。实现者另报告 TypeScript 检查通过，本审查未重复执行该检查。

仍有明确限制：

- 对没有历史证据而正数被减少或字段完全消失的损坏，不能可靠推断原始承诺。
- 保守拒绝含零量输入的快照，也会暂停原本合法但带冗余零量字段的自定义配方；不会擅自删字段改约，仍允许退出退款。
- 这不是恶意存档全面校验、全仓测试、长期真实模型验收或真实旧档迁移保证。已腐败实物和已经消费的错误产物不会由该修复追溯重建。
