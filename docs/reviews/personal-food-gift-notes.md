# 个人赠粮交接摘要：独立边界审查

## 结论与范围

本次是对交接信息展示的最小改进审查，不是新的交接规则或生存策略。已独立阅读前次 `food-handoff-window-replay.md`、赠粮执行代码、决策上下文及最终 prompt 改动，并运行 `tests/personal-food-gift-notes-review.test.ts`：**11/11 通过**。未发现本次改动增加远方事实、自动接受/交付、强制等待或改变最终动作菜单的证据。

新摘要从本人已有、凭据完整、尚未到固定期限的赠粮记录重建，不依赖易被截短的近期经历。它把原期限、本人已知的接受状态、约定室内或室外位置、实际另行交付、收方离开原点的影响，以及仍可自行选择停留、其他行动或撤回写入独立 prompt 段落。它不改变 120 分钟期限、库存归属、一步近身办理、走路、动作忙闲或危险撤离优先级。

这里的“持久”是每次由已持久化的个人合同记录重建，不是新增全局状态订阅。`knownStatus` 是知识边界，不能以合同全局 `status` 或另一方当前身份、库存、活动替代。远方已撤回但本人尚未知情时，显示的是“本人最后获知已接受”，并明确远方变化未知，不宣称交付仍一定可行。

## 独立测试证据

1. 清空双方经历记忆后仍保留本人接受地点、期限、未收货与选择权。摘要及上下文读取前后整世界深相等；删除上下文中的新字段，最终动作编号、顺序和内容完全相同。
2. 通过真实 `decline` 动作在远方撤回后，收方摘要消失，未获现场通知的送方摘要不变。
3. 分别修改远方另一方的坐标、室内位置、名字、库存、健康、死亡、居住及表达能力，并修改合同全局结束状态/原因，摘要不变，不输出这些私有事实。
4. 本人仅知 `offered` 时，即使记录后来已有接受凭据，也不展示未获知的接受地点。无关人即使被加入 `knownStatus` 仍看不到合同摘要。
5. 本人已知结束、固定期限已到或合同数量、地点、事件凭据被篡改时不展示记录。摘要读取不执行过期处理。
6. 收方通过正常移动离开原点后，自己的位置描述改变，但送方只会看到自然流逝的剩余时间，不获得远方位置更新。离开被正常执行，合同不会强制留人或自动交付。
7. 缺少旧档可选状态时返回空字符串，不初始化或补写状态；已接受记录在内存 SQLite 存取后得到相同摘要。
8. GLM、Qwen、DeepSeek 三种最终 prompt 在很长家庭记录下完整保留摘要，最终菜单不变；测试只准备 prompt，不调用任何模型。
9. 三名合成供方通过真实动作给同一收方建立九条记录，摘要上限为六条，较新的已接受记录仍优先进入，省略数量明确，输出稳定且在测试范围内小于 6000 字符。
10. 室内约定同时保留房屋门口和原室内坐标。收方站在同一室外门口并不被说成仍在原室内交接点。
11. 有效成人 v1 旧约仍可复述已接受交接，不补写或升级年龄权限条款。

初次饱和测试误以为默认种子有更多居民，未实际造出超过六条记录；修正每位供方数量后仍不足。两次失败是测试夹具容量不足，不是生产修复。最终加入一名额外合成供方才建立九条真实记录，原失败日志均保留，未删除失败后冒称从未失败。

## 上限、兼容与剩余限制

展示最多六条，接受记录优先，再按原期限和 ID 排序；超量记录有数量提示。合同和房屋标识另限制展示长度，不缩短动作使用的实际标识。可选上下文字段保持旧上下文兼容；没有赠粮记录时不产生新增段落。家庭综合记录必要时先让出 prompt 字节预算，新摘要和既有行动不会因此被裁剪。

排序和六条上限意味着并非每条收方记录每次都全文展开。这是有限展示，不是完整远程追踪，也不授予新动作权限。摘要未保证等待更久、选不同动作或靠近更早就会收到食物。已有事件凭据被损坏的合同保守不展示，不尝试修复或发明旧知识。

这些测试证明的是展示内容和边界，不证明真实模型会改变决定，也不证明存活率、健康、饥饿、交付成功率改善。十五日同策略非干预对照如另行完成，应单独引用其产物与结果，不能拿这里的 11 条测试代替。
