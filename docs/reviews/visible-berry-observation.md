# 现场浆果观察投影独立审查

## 结论

本次变更补齐了一个已复现的**个人已观察信息到最终模型输入的投影缺口**。未发现阻断问题。这个结论不等同于模型会更合理地采集、协作、进食，也不证明死亡减少或长期存活改善。

基线 HEAD 为 b2552ac。先红证据位于 `output/food-access-followup/prompt-red.log`：相同菜单下，context 中已经不同的当前浆果量 0/0.5 与 3/12 仍生成相同最终消息。前一组证明整份采集门槛以下的信息被折叠，后一组证明单次采集上限 3 不能代替地点当前存量。没有必要通过增加食物、改变行动或提高角色能力来解释或修复这个缺口。

## 边界复核

- 信息源仍是 `decisionContext` 既有的 `resources` 快照。上游 `canInspectBerry` 维持个人已知地点、12 格距离、户外清醒在场、有效坐标及视线约束。格式化器没有读取 world、从记忆补远方库存或扩大可见范围。
- 新模块仅投影 formal context 中的 bush，最多 4 处。已有 gather 菜单目标优先，随后按曼哈顿距离和 ID 排序；同距输入反序仍稳定。其余现场观察明确说明未展开。此上限是有意的信息预算取舍，不意味着完整展示所有地点。
- 显示当前位置和余量；空量与不足一份有相应含义。缺失、null、非有限数或负量均不变成零。max、lastHarvest、regrowthDays 的改变不影响观察段。
- 可见不等于可接触、有权限、已选行动或已持有食物。水障隔开的可见浆果仍可进入观察，但不因此被添加到库存；正文明确这些限制。
- 观察记录带 context 的游戏分钟。旧快照不会因世界变更重新查询库存；离开后的地点不会通过新观察被刷新。记录可以陈旧，这不是实时全知信息。
- 最终 prompt 独立加入该段，而非挤入 familyNotes。必要时缩短家庭综合记录，保留完整观察和编号菜单。硬预算仍由 `checkedInputBytes` 拒绝超限输入，不能保证所有任意大小的 context 都能发送。
- 实现 diff 只涉及独立观察格式化器及 prompt 组装/现有预算触发条件；没有修改采集数量、菜单构造、库存、年龄门槛、能动性、世界资源或策略。

## 独立验证

独立文件：`tests/visible-berry-observation-review.test.ts`，6 项全部通过。日志：`output/visible-berry-review/tests.log`。

1. 室内、不认识地点、远距离及视线遮挡时，隐藏浆果量改变不影响最终消息或菜单；context 与世界对象解耦。
2. 格式化不改 context，不显示非浆果，不凭菜单目标虚构不存在的资源，也不泄露再生内部字段。
3. 非法/未知当前量不变成空量或 NaN/Infinity 文本。
4. 四处上限、gather 目标优先、距离/ID 排序及省略说明。
5. 三种支持模型在家庭记录压力下仍保留整段观察和全部编号选项；无法容纳的输入继续抛出 `model_context_limit`。
6. 水障使地点可见但路径不可达时不许诺可采；旧快照在世界量变和角色远离后保持原输入，新快照不再显示远方地点。

运行使用清空环境、项目内 HOME/TMP、明确 Node 绝对路径以及 `acceptance-offline-guard.mjs`、本地 tsx loader；未读取 .env/key/真实 runtime，未调用模型、网络或 push。审查仅写独立测试、本文及项目内测试产物。

## 证据限度

这些是合成离线检查及代码边界审查，不是新的 15 日世界模拟，也不是模型行为实验。计划中的个人输入归档重放可以进一步检验菜单、既存回复解析及去除新增段落后的 prompt 等价性，但该重放结果不属于本审查已独立完成的证据。任何协作、生存或死亡原因结论都需要相应的独立行为与因果证据。
