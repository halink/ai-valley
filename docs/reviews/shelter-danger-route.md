# 临时避难的已知危险路线独立复核

## 范围

针对 `frontierHazard.shelter`，检查菜单选点、开始寻路及进行中逐边通行是否复用已有 `frontierRetreatStepAllowed`。不改变已有建筑权限、容量、屋况、洪灾保护规则或实际到场工时；不替居民选择新目的地，不自动重规划、传送或增加床权。

审查了 `frontier-hazards.ts`、`frontier-hazard-opportunities.ts`、`engine.ts`、`navigation.ts`、`frontier-wildlife.ts`、`building-safety.ts`、`building-knowledge.ts`，以及既有医疗目的地与天气灾害实施边界。当前工作树及向上检查未发现 AGENTS.md 或仓库 `.agents` 技能。

## 独立反例

独立测试文件为 `tests/shelter-danger-route-review.test.ts`，使用种子73的独立合成地图，与主实现测试的正式九人夹具分开。

11项覆盖：

- 已知野猪挡住8步直线时，0.25与1.2分钟步进都实际走16步安全路线进入同一屋门。
- 内存SQLite重载的旧不安全路线，即便已有0.9步进度，也必须在第一条危险边前中止。
- 屋门到场后变更屋况、权限或容量，均不得进入。
- 路线开始后野猪位置改变、新增风暴预警，均在危险边前停止。
- 最初未见的野猪不影响初始路线；真实接近并看见后，在其危险圈前停下。
- 已提交的旧菜单回复遇到无安全路线时，沿原失败机制拒绝开始。
- 已在危险圈内的人仍能真实走出并到达原选定避难屋。

原代码实跑为 **4通过、7失败**。3项到场权利/屋况复验及已在圈内走出原本通过；其余7项直接暴露缺少 shelter 危险路径约束。野猪在本独立夹具中固定位置且处于冷却期，断言的是路线边界，不把偶然未攻击误当成安全证据。主测试固定已警戒攻击时点，并验证100和25初始健康在安全路线下均保持；修复前实际袭击/死亡另有主审计合成探针，非本独立测试。

## 验证方式与限制

只使用代码生成世界和内存SQLite，没有读取正式存档、环境密钥或联网。运行前清空进程环境，并预载现有 `scripts/acceptance-offline-guard.mjs`；HOME及TMPDIR限制在 `output/test-tmp`。没有运行或重试 bwrap，没有安装依赖、提交或推送，没有修改并行设计/赠食候选文件。

本复核不声称通过真实模型、长期四季、正式存档迁移或所有行动的通用路径审计。未知物理障碍的原导航规则保持原样；此处“不泄露”仅指没有新增对未见野兽的规划过滤。
