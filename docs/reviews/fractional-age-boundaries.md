# 分数出生时间的年龄边界审查

## 结论与范围

独立审查了 `world/time.ts` 的双向校准，以及 `server/runtime.ts`、`world/formal-seed.ts`、`world/engine.ts` 三处原先直接减出生时间的居民年龄判断。未发现生产修复的阻塞问题。生日定义为已存出生时间加整数个 `YEAR` 所得到的可表示时间；不是把所有时刻向整分钟或整数年龄取整。

`ageYears` 保留通常的连续年龄。在时间戳及非负时间差均不超过 `Number.MAX_SAFE_INTEGER` 的有效域内，计算误差远小于半岁，检查最近整数对应生日足以修正跨整数阈值的误差。直接时间比较决定边界，不对当前时间添加容差。到达生日时可以向上校准；减法已舍入到整数而当前时间仍早于生日时，向下返回严格小于整数的值。检查原始年龄附近的固定小 epsilon 不足以覆盖大时间戳，因此实际实现没有采用该限制。

动物日龄判断不在本次范围。安全进食预测仍检查原来的未来时点 `minute + mealMinutes`，仅统一年龄计算。

## 独立证据

- 原实现的独立 48 项测试为 21 通过、27 失败。负出生 seed 的最小反例为 `bornAt=1-n*YEAR`、`minute=nextDown(1)`：减法年龄已经等于 n，但当前时间仍在生日之前。
- 覆盖 6、13、18、65 岁生日的前一个可表示时间、生日、后一个可表示时间；0.25 和默认 1.2 分钟累计时点；1e9、1e12 及 2**30、2**40、2**52 的指数跨界时点。
- NaN、正负 Infinity、null、字符串、未来出生时间、时间戳越界和时间差溢出返回零，不误授成年，并使既有 `<18` 拒绝条件成立。
- 实际引擎测试通过怀孕到期生成分数出生时间，保留该时间到后续生日；验证阶段转换、能力开放、编号菜单、提交动作、工具实物完成、成年清除监护，以及 SQLite 内存数据库存取后不重复成年事件。
- 同意测试验证监护交接、长期照护供餐/收费、医疗接走恰逢六岁生日时不沿用幼儿年龄豁免，包含 0.25、1.2 步进和监护交接的 SQLite 存取。
- 补充的独立死亡测试将抽样风险设为一以排除随机巧合：每日抽样点之前未满老年阈值则不触发，分数生日不新增抽样，下一每日边界才触发，相同输入可重放，已死亡居民不再触发。生产的每日循环、哈希和风险公式未更改。

## 发现与限制

已解决：额外合跑 `later-life.test.ts` 初次为 74 项中 73 通过、1 失败：原测试严格断言连续恢复值为 `0.1925`，实际为 `0.19250000000000006`。其时点为 `480.001`，反推 75 岁出生时间后重构的生日为 `480.0010000001639`，当前时点实际上仍早于生日。双向校准正确返回 `74.99999999999999`。现断言改为连续恢复值误差小于 `1e-12`，独立只读复核认为合理；该容差不用于年龄权限或当前时间。

已解决：全量检查另发现 `emergency-care.test.ts` 的六岁生日 fixture 也依赖反向减法。现于设置出生时间后，明确令 `w.minute=child.bornAt+6*YEAR`，再检查原权限结束。独立只读复核确认该修改使测试真正位于所存出生时间对应的生日，未放宽生产权限，也未改变其余恢复、拒绝或失能分支。

修复执行者报告后续两文件合跑 30/30 通过；三个分数时间文件、`generations.test.ts` 与 `later-life.test.ts` 合跑 85/85 通过。这两组为执行者的复测结果，区别于上文独立执行的 75/75；最终全量结果另行记录。

无效日期返回零不代表全面权限 fail-closed：它仍可能被幼儿监护代理规则视作零岁。本次只承诺不误授成年，不修复存储日期，也不全面重构代理权限。时间超过安全域的处理不证明引擎可以正常模拟任意大时钟；即使域内，也未承诺0.25步进在接近精度极限时仍可分辨。

引擎测试明确跳到生日附近并隔离其他居民/风险，不是多年自然生存验收。SQLite 证据为合成内存数据库存取，不是正式存档迁移或进程崩溃恢复。测试未调用真实模型，未读取正式 runtime 存档或密钥，未执行浏览器、npm、提交或推送。死亡年龄输入边界被修正可能改变恰逢边界的资格或风险末位，不应宣称所有历史随机结果逐位不变。
