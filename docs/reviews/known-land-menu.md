# 已知田址菜单独立审查

## 审查对象

`known-land-choices.ts`、`affordances.ts`、`agency-opportunities.ts` 与 `decisions.ts` 的本次回田修复。独立审查未发现阻断项；不是对全部模拟规则、所有原有菜单类别或长期模型行为的认证。

## 独立反例

独立审查者在单独源码副本编写并运行七项反例，随后纳入 `tests/known-land-choices-review.test.ts`：

1. 同一 ID 的不同地址均可轮到；重复完整身份不增加权重。
2. 非法分钟和本人坐标不能产生田址。
3. 当前地址和非法地址在轮转前排除，不浪费周期。
4. 只可替换多余反思；唯一反思及其他动作保持，重复恢复不加行。
5. 死亡、镇外、无决定/表达能力均不提供导航；空的前置过滤结果不重建候选。
6. 真正的 context → prepare 不改写世界，远处作物变化不改变最终输入。
7. 途中、乘船、被护送和仅可撤回的旧过滤均保留；已经移除的源候选不能复活。

纳入时仅把审查夹具的取消护送字段 `rescueId` 更正为既有 schema 的 `offerId`，未修改其断言。独立执行七项通过，纳入后的重跑也通过。

## 补充验证与边界

实现测试另证明叠加水源、烹饪、播种、回田、社交、理解、线索与约见后的合成普通菜单精确为 84 项，并保留另行恢复的停止/护送拒绝入口。途中障碍与丧失表达保留真实位置，不远程浇水；田地改权后旧导航不授予种田权。新建磁盘 SQLite 关闭后由清空环境的新进程重读，完整田址轮转和编号与原结果一致，无新增持久字段。

定向田址主测试 10 项加独立审查 7 项，合计 17/17 通过。此前相关二十文件 260/260 通过，不等同全仓最终集成验收。

公平性只针对固定合格集合、逐个 30 游戏分钟窗口的候选曝光。任意跳跃的决策采样节拍可能跳过窗口，动态集合也会改变序位；不能据此承诺模型会实际走遍田地、及时浇水或保证生存。
