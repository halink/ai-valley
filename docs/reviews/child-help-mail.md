# 儿童求助镇外捎信独立审查

本次审查针对有限的“报告人另行交托 → 既有货运实际捎信 → 同源居地既有人物收到历史原信 → 本人独立答复 → 原有分段来访”连接。不是完整儿童接应、住宿或永久监护验收。

## 审查发现与修正

1. **同一货运回调重放。** 原信实际退回后，原实现仍允许同一 `shipmentId` 的重复出发回调再次拿信，随后重复到达可产生未发生的新送达。现拒绝任何已记录过的货运身份，仅另一趟既有货运可再捎原信。
2. **未核实的来源路线。** 只比较联系人与商行的来源字符串，会让未知来源进入来访路径的默认时长。现要求来源属于 `knownStationDuration` 已知路线，未核实来源不产生儿童求助来访选项。
3. **退回前的历史取信。** 第二趟货运延迟处理的出发回调，可能早于原信实际退回。已按独立失败反例补上校验：再次取信时点不得早于每次真实退回时点，不能把仍在路上的原信追补交给另一趟货运。

## 独立验证范围

`tests/child-help-mail-review.test.ts` 使用隔离合成世界，不读真实存档、配置、密钥，不调用真实模型或浏览器。货运回调反例使用明确的合成既有合同；普通最终菜单和完整货运主链由 `tests/child-help-mail.test.ts` 单独覆盖。

独立检查包括：

- 未交托时点之前的历史回调不能取信；没有同源联系人或迁居登记时不初始化新人口。
- 正在行路、死亡、失能、未知年龄、已知不在原居地、未知来源路线都不产生来访资格。
- 重复取信、重复送达、原货运退回后的重放，以及不同货运早于退回的历史取信。
- 信离开谷口后的撤回、孩子迁址、死亡和监护变化，不改变收信人的个人上下文与模型提示，也不交付孩子的死亡证明或实时位置。
- 个人拒绝不远程通知报告人，不消耗或生成物资；短记忆清空后仍以实际个人回执答复，重复拒绝无效。
- 到期后收到的信只保留历史，不能启程、延长原期限或获得照护权限。
- SQLite 重载、工作事件裁剪、个人回执、固定期限与送达幂等性。
- 入谷旅人受真实谷口路阻时停在镇外，无入谷人口、住房、监护或照护权限变化。
- 观察档案纯只读、外部文字转义，旧档没有出信字段时不补造过去运输。
