# fosterChild 跨六岁独立同意审查

## 范围和约束

独立审查 `family.ts` 的永久监护交接，核对 `long-care-consent.ts`、`adoption.ts`、`engine.ts`、`life.ts` 的相关边界。使用合成世界测试；未打开 `.env`、密钥、真实存档或 runtime 内容；未调用模型、浏览器或包管理器，未提交或推送。未发现仓库 `AGENTS.md` 或 `.agents/skills` 指引。

## 修复前证据

新增 `tests/foster-age-consent-review.test.ts`，初次运行 11 例中 5 例通过，6 例失败：

- 跨六岁后 `childApproved=true` 使本人同意入口仍被隐藏。
- 缺决定能力、表达能力或两者均缺时，监护人单独同意仍可增加永久监护。
- 原期限测试因错误提前完成、提议被删除而失败。
- 无新字段旧提议经 JSON 重载后，原年龄豁免仍被当作本人签名。

## 审查要求

完成入口必须按执行时年龄重新校验，不能依赖生命周期是否已执行。菜单只读，不得修改证据或期限。六岁及以上须本人独立同意且当前可决定、可表达。拒绝后的迟到同意不能恢复提议，原期限不得延长。成年后不能继续使用旧监护代理。合法旧本人同意和六岁前已完成的监护事实应保留。

## 最终审查结论

在本任务范围内未发现阻断问题。

- `guardian-consent.ts` 将新记录的真实本人签名与旧年龄豁免分开。读取函数不迁移、重写旧记录或编造签名时间。只有 `id`、`createdAt`、`childApprovedAt` 都不存在，才按旧一日期限模型解释原始 `childApproved=true`；提议当时已经满六岁才认可旧本人同意。
- `familyConsent` 完成时重新检查当前年龄、当前表达/决定能力、原监护人和志愿者的成年资格及在场关系，覆盖活动排队期间跨生日而生命周期还没有处理的时序。当前无能力时，监护人的新同意也不会落盘；恢复后继续原提议，不延长期限。
- 孩子先签、监护人先签均可；孩子签后暂失能力不会丢掉历史本人证据，但不能在失能期间完成永久交接。监护人的拒绝仍可执行。
- 时间在六岁前、提议前、未来、到期时，或时间为 null、NaN、缺失、布尔值为 false，均不能充当有效本人同意。部分新字段缺失不能回落为旧格式默认同意。
- `offerId` 绑定具体提议。拒绝后即使同一分钟、相同参与人重新提议，旧动作也不能签新提议。无绑定旧队列动作保守失败，需重新从菜单选择；新旧存档的当前最终菜单都会生成绑定。这是有意的队列兼容变化，不撤销旧签名、旧监护或收养事实。
- 成年后入口直接拒绝旧代理，无需等待生命周期清理旧 guardianIds。已在六岁前完成的永久监护在六岁生日后保留。收养的注册、身份和旧签名回归继续通过。
