# 本人未解释记忆轮转：独立反例审查

## 范围和执行约束

本次只编辑 `tests/interpretation-rotation-review.test.ts` 与本文。使用合成正式 seed5401 和内存 SQLite；不读 `.env`、密钥、runtime 或真实存档，不调用网络、模型、浏览器或 npm，不提交或推送。遵循 CONTRIBUTING.md 的本人可行动、实际知识和旧档未知边界。

## 已确认的旧实现反例

- 本人保留六条事件时，最新五条之外的事件不再进入候选，即使只是不断查看菜单并推进候选采样时点。
- 多人事件固定截取前两人，其余已认识对象永远不可达。已解释第一人后，不会补上第三、第四人。
- 重复 actor 与重复 memory 可生成同一个 `(event,target)` 的多行，浪费有限容量。
- 给正式 context 加入160条合成工作机会后，最终编号菜单可以裁掉全部五条解释候选。

独立测试不能替代主测试的六句真实发言与 wait30 引擎链；这里重点挑战保留上限、集合轮转、菜单第二次截断及读取边界。

## 独立覆盖

1. 6、10、79、80条本人事件分别配3、4、8个对象；不执行任何解释，只推进30分钟采样窗口，要求每个 `(event,target)` 可达，且每轮至多5事件、每事件2对象、无重复。
2. 重复 actors 和重复 memories 不能占用重复名额，所有其他对象仍有机会。
3. 饱和160条额外工作机会、停止入口，最终菜单必须保留本轮全部解释候选和独有编号；旧于18条短记忆的候选必须携带完整240字以内原话、实际hostile语气。注入式文本只能作为转义资料。构造 context、菜单及 prompt 不改变世界或 context。
4. SQLite 提交重载后，已有解释收据继续阻止同一对象重刷，但不阻止同事件其他对象。
5. 自然80条记忆遗忘、未知人物、已丢失对应事件、隔室未听到的发言均不得从全局事实补造解释入口或原话。
6. 本人旧档缺失 speechText/speechTone 时，不借用全局 event 的完整原话或语气；内存 SQLite 前后确定性菜单与输入一致。
7. 照护撤回、表达撤离、家庭旅途、乘员、船上受限模式不能因最终恢复逻辑获得额外解释权限。

8. 68条饱和现有菜单下，直接恢复函数保留所有非反思行动，包括紧急配给、拒绝与停止，保留至少一条自主目标反思；10条解释完整恢复且幂等。
9. 未来receivedAt、未来event.at和超过最后80条的旧档残留均不能通过执行验证或生成候选。

## 公平性边界

事件轮转和对象轮转若直接复用同一时钟模数，可能发生同余饥饿。事件集合长度为N时，一个完整N轮内固定对象偏移，完整事件轮转后才推进对象偏移，可避免固定候选集合下的这一问题。测试刻意不消费候选，防止依赖“前两人先被执行并移除”掩盖饥饿。

保证仅针对仍被本人保留、对应事件存在、本人认识对象且尚未处理的固定候选集合。不断加入新事件、自然遗忘、候选资格改变或者居民从未在相应时段请求决策，不能据此承诺每条最终一定执行。提供选择不等于自动解释、改变关系或核实原话。

## 验证状态

主实现修改前执行独立测试确认上述旧实现反例。主实现落盘后，执行 `node --import tsx --test tests/interpretation-rotation-review.test.ts`：9项通过、0失败，约8.2秒。此结论是离线独立反例覆盖，不代表真实模型验收、持续新事件下的无条件公平保证或性能基准。

代码审查未发现上述边界内新的正确性阻断。效率建议：候选生成构造一次完整事件Map，但每条候选仍经socialReason/source再次查找事件；长期事件账本下存在重复线性扫描，应在不放松执行时校验的前提下单独优化。
