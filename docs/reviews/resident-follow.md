# 居民室内外跟随独立审查

最终核验日期：2026-11-07。

审查范围：`src/client/resident-follow.ts`、`src/client/scene.ts`、`src/client/main.ts`、`src/client/styles.css`。本报告只记录本轮跟随功能及其直接依赖，不把工作区已有其他改动视为本轮引入。

## 初审发现（最终复审均已修复，以下行号为初审版本）

### P2：无精确位置时没有可靠恢复房间全景

位置：`scene.ts:90–91, 224–225, 247–249`；文案：`resident-follow.ts:54`。

复现路径：进入某房间并手动拖动镜头，再点击跟随同房间内一个没有 `roomAt` 的居民。`changeRoom` 因房间未变提前返回，`centerFollow` 因 `precise=false` 跳过，镜头保留拖动后的局部位置甚至房间外，但状态提示“保留房间全景”。跟随中同房间的 `roomAt` 从有变无也存在同样问题。

建议：抽取独立的房间全景定位方法；显式开始无精确位置的跟随，以及跟随从精确降级为不精确时调用。不要每帧重置镜头，也不要补造居民位置。增加同房间重新跟随和精度降级的场景级回归测试。

### P2（既有渲染依赖）：无 `roomAt` 的居民仍有看似精确的位置和选框

位置：`scene.ts:106–109, 254–255`。

无 `roomAt` 时渲染器继续用 `teachingPosition` 或 `105+(n%4)*22`、`145+floor(n/4)*24` 放置人物，并对该位置绘制正常选择圈。这是既有逻辑，并非本轮新增；新跟随状态本身没有写回或生成世界坐标。但若验收标准包含“不能把示意位置呈现为实际坐标”，仅在跟随文案提示未知仍不足以消除图像歧义。

建议：跟随未知位置人物时不绘制其精确选框，并隐藏无坐标人物精灵或明确将其置于带有“位置未记录”标识的非空间名单。应区分无 rooms 的家具样章与有 rooms 但缺少个人 roomAt 的情况。

### P3：室内精度判定缺少范围校验

位置：`resident-follow.ts:26`；消费位置：`scene.ts:109, 249`。

当前只检查 `roomAt` 为有限数，负数或超出布局的坐标仍标为 `precise=true`，随后无边界室内相机可能居中到房间外。这依赖异常快照，不是已证明的正常世界路径。建议按实际房间布局验证坐标范围，异常时降级全景，并校验用于插值的 room path/progress。

## 最终复审

- 已修复全景恢复：`scene.ts:128, 255–261` 在接收快照和显式开始跟随时恢复未知位置人物所在房间全景；逐帧 update 不重复执行全景定位。
- 已修复示意位置歧义：`scene.ts:109–117, 150, 269` 将无效或缺失位置按示意布局绘制，hover 明示“位置示意”，不绘制精确选框；`main.ts:125` 房间横幅说明缺失位置仅作示意。世界对象仍未补写 roomAt。
- 已修复 roomAt 范围检查：`resident-follow.ts:17–21` 验证房间、有限数及真实布局范围；`scene.ts:111–115` 仅匹配当前房间的活动路径参与插值，并验证路径点有限且在布局内、progress 有限且约束到 0–1。异常路径或进度回退到已记录的 roomAt。
- 最后一项可选 P3 插值健壮性建议已修复；新增真实场景回归覆盖正常半格、错误房间、NaN 进度和越界下一点。最终未发现待修复的审查问题。

## 正向结论

- 跟随身份固定为 personId，并通过实际 `inside` 字段切换坐标空间，没有以目的地、计划或住宅推断跨门槛。
- 状态机对死亡、镇外和记录缺失置为 stopped；后续 observe 不会自动恢复，显式 start 才可恢复。
- 拖动、退出房间、清除选择、查看另一居民和有效的其他地图定位路径会清除跟随。
- 坐标空间切换时杀掉旧 tween、清空目标并 snap，避免室内坐标与室外坐标间插值。
- 本轮跟随状态保存在视图实例，未发现世界写入、新的服务端修改请求或新增注入面。姓名和状态提示经 esc 转义。
