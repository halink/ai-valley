# 家畜有限饮水寻路独立审查

## 结论与范围

本轮未发现阻止合入的饮水正确性问题。实现改动仅在 `advancePastures` 的水槽寻路分支，未修改水量、口渴、草量、产品或繁育参数，也没有新增存档字段或路径缓存。独立审查只新增本报告和 `tests/livestock-water-routing-review.test.ts`，没有代主实现修改生产代码。

修复前日志的首批9项中4项失败、5项通过，失败分别涉及占位绕行、场内弯路、动态占位和重载续行。该红测是主实现工人执行的，独立审查读取了原输出，不将其称为本人再次执行的红测。独立复跑当前主15项、独立9项及既有相关测试，共62项全部通过。

## 路线与取水核验

新寻路在扩展每条边时限制本场格子，并调用既有 `pastureTileFree` 排除其他活家畜和护送目的地预留。地形、树石、建筑、围栏门与导航中的灾害/损坏设施约束仍由原寻路处理。实际移动前还会再次检查下一格；本次没有引入跨刻缓存。

`adjacent=true` 是到实际接触位，不是提前供水。水槽必须仍在本场，且通过 `walkable(w,trough,current)`；只有当前曼哈顿距离不大于1才扣槽内有限水量。独立反例确认对角线不算接触，第15分钟移动到接触位时不提前扣水，下一分钟才发生实际饮水，同分钟重入没有第二次扣减。

独立9项覆盖：

1. 绕过居民正护送另一动物的预留格，且不更改居民动作或产生模型请求。
2. 水槽本格与全部可用接触格都被动物占住时不供水；一只占位动物真正转为室内后，剩余渴畜能走到释放位置饮水，不必进入水槽本格。
3. 第一次搜索之后、下次移动之前出现新的接触位预留，重新选择另一接触位；不重置动物、水或时钟。
4. 对角距离、15分钟移动节奏、到达后扣水和同刻幂等分别成立。
5. 故意构造旧档重叠围栏时，距水槽1格但实际隔栏不能饮水。该防御夹具不是正常地权登记可创建的重叠牧场，也不证明任意损坏旧档均能恢复。
6. 邻场有水但本场槽空时不偷用邻场水；没有登记本场 `pastureId` 的动物也不会因站在槽旁自动获水。
7. 单通道的真实岩石阻断取水，岩石耗尽后立即重新寻找可用路线。
8. 居民正在与该动物交互时，不自动饮水或离开接触位；交互结束后恢复。
9. 夜间和过期但保留的牧场仍能饮已有水，退休牧场不再推进动物饮水。

这些独立测试直接推进 `advancePastures`，用于隔离边界。主测试另包含完整 `stepWorld`、编号菜单的本人实际送水、五物种末份有限水和内存SQLite重载。二者不得混称为全部使用完整世界长时间步进。

## 性能边界

新谓词增加逐边的本场格子和动物列表扫描；原 `findPath` 每次建立全图障碍索引、分配搜索数组的成本也仍存在。这不是性能优化。没有新增缓存意味着动态占位无需持久失效协议，但目前每次推进仍可能重新寻路。

额外做了一次局部微测：80×64全草合成地图、每场24格，无居民、资源、围栏；每场一只固定在非接触位的渴羊，阻挡组另放一只低体力羊。固定分钟601，重置各场的上次推进时间，20次热身后采样200次。对照函数仅在内存中还原修改前的两行寻路逻辑，未更改仓库实现。

- 20场、40只动物的占道组：原逻辑中位约0.275毫秒，新逻辑约0.415毫秒。
- 100场、200只动物的占道组：原逻辑中位约1.727毫秒，新逻辑约4.461毫秒。
- 100场、100只动物的无占道组：原逻辑中位约1.537毫秒，新逻辑约3.016毫秒。

这些数值只说明本机该局部夹具有新增成本，不是端到端吞吐、性能门槛、实际世界最大规模或稳定帧率保证。没有用更快但错误的旧路径当成功行为基线，也没有宣称长期拥挤可自行疏散。更大动物群、更多实体及复杂围栏的性能没有在本轮验收。
