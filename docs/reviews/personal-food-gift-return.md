# 自主返回本人赠粮原交接点：独立边界审查

## 结论与范围

新增 `personalFoodGift.return` 补充一个明确目的地：收方亲自接受后记住的固定原交接点。已有四向六格探索、住处或共屋门外、其他事务可能偶然回到那里，但不能稳定表达任意已约室内或室外原点。本功能不把历史交接失败重新解释为菜单缺陷，也不承诺提高存活或食物获得率。

独立检查曾复现远方目的房屋变化通过菜单消失泄露的问题，父任务修正展示条件后，最终十二项测试全部通过，当前未发现未解决的阻断问题。审查仅修改新增测试与本说明，不修改生产逻辑。父任务负责实现、原有主测试、构建和更广泛回归。

## 独立验证

`tests/personal-food-gift-return-review.test.ts` 十二项测试使用明确搭建的合成世界、实际 offer/accept 动作和真实引擎步进，不是历史重放，也不是真实模型自主选择：

- 同屋从另一格返回精确室内原点；从另一间合法房屋实际退出、走路、再进入原屋。门外坐标相同不冒充到达室内原点。
- 提交后道路变为水域会中断；完成前最后0.25分钟失去表达能力或触及原期限不会完成返回。
- 室内途中失去使用权、门坐标改变或下一格被合成遗体占据会失败；最后0.25分钟失去房屋使用权同样失败。
- 供者远方撤回或死亡，不改变收方返回菜单及本人最后获知的接受状态；返回不改赠粮记录、供者记忆或决策时间。
- 六岁且能自主决定/表达的已接受收方可以返回。错误当事人、未知年龄和额外注入的目的地字段不能取得权限。
- 添加180个合成机会的饱和菜单与等时删去返回项的对照比较，所有原有语义选项保留，只增加一个返回选项。
- 到达近身供者旁边仍只给收方产生返回事件记忆，不通知供者，不中断或重新开始其已选择的60分钟等待。
- 远方原屋损坏、产权/居住权限撤销或门位置变化，不改变基于本人已知地址的返回项；执行仍在移动前拒绝失效目的地，不修改赠粮记录。
- 三份稳定的已接受赠粮按原完整身份轮换，每次仅一项，三个30分钟位置均覆盖，没有增加自动选择。
- 收方正在返回途中仍能自行选择撤回接受，立即停止原活动与计划，后续不恢复或继续移动。

初轮六项全部通过。增加第七项及最终室内权限边界时，父任务将生产事件类型从无效 `move` 改为现有 `action`，独立测试仍匹配旧类型，联合运行出现7通过/3失败；修正测试的事件类型匹配后，七项独立测试全部通过。这一中间失败不是物理返回失败。详细输出在项目本地 `output/personal-food-gift-return-review/`，不随本文保证分发；失败阶段说明保存于 `concurrent-event-type-mismatch.txt`，完整失败输出保留于任务记录。

执行方式：清空环境，指定项目内 HOME/TMPDIR，使用 `scripts/acceptance-offline-guard.mjs` 与现有 tsx loader 运行 Node 测试。未读取 .env、密钥或真实运行档，未调用真实模型、网络或推送。第一阶段七项输出为 `final.tap`。随后新增目的地信息边界反例，十项测试出现8通过/2失败：原屋损坏与撤销权限使远方返回项消失；门位置变化已能正确隔离。红证据完整保存为 `destination-knowledge-red.tap`。父任务移除菜单生成对目的地执行校验器的预调用，改为仅核查本人已知接受、实际当前位置/运输状态等。补上三份轮换与途中主动撤回后，最终十二项全部通过，输出为 `destination-knowledge-green.tap`。父任务的其他测试结果应单独引用，不能把本报告十二项通过称作全仓验证。

## 信息及权限审查

菜单展示使用本人证据链、原固定期限、本人已知接受状态及本人当前身体/空间状态。它展示的是“尝试返回”，不预告远方目的地通路或房屋使用权仍然有效。执行资格则继续使用当前真实房屋使用权、道路和精确房间通路硬校验；展示一个记得的目的地不授予进入它的权限。它不把供者当前状态、位置、库存或尚未被本人得知的撤回当作菜单开关。返回到达不完成交付，不预留食物，不延长期限，不自动等待或进食，也不改变供者计划。

完成分支使用只有收方为 actor/witness 的 `emitEvent`，而非会同步真实赠粮状态并唤醒双方的 `localEvent`。事件确实增加全局事件/版本以及收方个人记忆，正常动作完成也会更新收方活动记录；这是可见行为记录，不能称作世界完全不变。检查 `rememberPhysicalFact` 后，该 action 事件没有死亡知识更新；测试确认近身和远方供者均不收到该记忆或决策唤醒。

返回经过现有房间工位声明路径，可能记录临时 room claim。它不授予房屋使用权，也没有资源转移。仍须送方另行选择交付，收方另行选择进食。

## 接线与局限

检查覆盖动作类型、形状校验、实际目标、精确到位判断、旅行和工作重验、单独完成分支、房间入口/出口以及儿童年龄白名单。最终菜单在普通预算之后有界保留一个返回项，不挤出旧进食、安全或拒绝选项。父任务另补齐了客户端动作显示名及合法事件类型。

这些反例不是所有可构造世界的证明。现有房间/道路引擎及证据记录有效性规则仍是依赖；未新增供者忙闲信息、自动协调、搜寻供者或任何策略优先级。历史十五日归档不在本次验证输入中，不能声称复现其数字，也不能声称已证明长期存活改善。

## 后续提交审查补充

上述十二项属于返回功能及信息边界的独审阶段。后续提交审查另行发现共享 `prepareRoomExit` 在起步出口已阻断时把 `null` 路径视作成功退出，构成阻断，原阶段测试未覆盖。该缺陷及对其他调用者的副作用修复、红绿测试和独立复核另见[共享出口审查](room-exit-boundaries.md)。本报告的阶段结论不能替代该后续审查或修后全量验收。
