# 实际自主进食证据独立复核

2026-11-07，在现有工作树上只读复核本批次的 `food-consumption-evidence.ts`、引擎接入、逐日累加器、隔离长期脚本和针对性测试。未访问密钥、真实存档或网络，未调用真实模型，未提交或推送。结论：未发现阻断问题或已证实的模拟行为回归；此结论不等于完整食物收支或真实模型生存验收。

## 检查结论

- 在真实 `eat` 扣除物品前调用原 `foodValue`，记录引擎实际使用的营养值；数量为真实扣除的一份，饥饿缓解单独记录。未通过库存差、动作文本或饥饿净变化推算营养。
- 记录器按 World 对象绑定到一次同步调用，预测副本不会串入。`finally` 在异常时解绑；调用失败不返回成功证据。
- 新入口只包装原 `stepWorld`。没有添加自动决定、改变食物保质期、增加持久化字段或将审计明细放入居民知识。
- 日累加器检查世界 ID 和连续分钟区间。漏接一分钟即令 `totals` 为 `null`，继续保留实际已观测的明细；后续恢复观测不掩盖同日缺口。日界重置新日覆盖。
- 隔离脚本每次推进绑定当前世界，年度 `store.load()` 替换对象后继续使用同一路径。不开启 `--daily-json` 时保持原 `stepWorld` 路径。
- 完整食物产量、完整消费和模型技术等待仍未知，没有将部分证据升级为总体结论。

## 独立运行的补充检查

通过 `node --import tsx` 独立执行以下内存夹具，全部通过：

1. 两人同一分钟分别吃餐食和浆果，逐人明细与逐食品数量正确。
2. 已经观测并得出总量后漏接一分钟，总量清空；恢复观测不错误恢复完整总量，已观测明细保留。
3. 捕获期间真实进食后抛错，不返回成功观测；下一次捕获不残留或重放旧记录。

三项随后均加入持久回归 `tests/food-consumption-evidence.test.ts`。实现方另验证真实引擎批次营养、正式九人世界和模型上下文不变、SQLite 内存重载、预测隔离、失败进食、日界、小数步长和异常解绑。全套测试、构建及年度隔离复验结果由本批次最终交付另行报告，不能由本次针对性检查代替。

## 保留边界

记录覆盖仅为引擎 `eat`；幼儿喂养、照护、境外旅途、加工投入与生产尚未接入。日累加器接受受信任内部观测对象，不是防篡改审计协议，不校验调用者伪造的明细或同 ID 分支；现有脚本直接传递包装器结果。

异常引擎调用可能已经改变世界，此记录器不提供事务回滚。若异常后继续验收，缺失分钟必须保持未知，不能把下一次观测当作补齐。新启动观察只能提供新起点后的证据，不能恢复未保存的历史进食数量。正式运行时尚未接入，真实模型长期验收仍需另行批准与执行。
