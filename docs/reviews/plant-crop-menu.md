# 播种菜单可发现性独立审查

## 结论

通过本次针对性实现审查与独立离线测试，未发现阻断问题。此结论不是全量测试或构建通过声明。

生产补丁保持原 focusedChoices 筛选和轮转不变，在末尾恢复一个按完整地块/作物身份选定的合法播种候选。它不替居民选择或执行动作，也不扩大年龄、旅途、土地、种子或季节权限。

## 已核对的实现性质

- 候选来自 buildChoices 过滤后的 all；不重新从世界或原始 formal.opportunities 补造候选。
- 使用 [plotId, cropId] 身份去重并稳定排序，避免同地块多作物共用旧 id 导致误去重。重复身份不获得额外轮换权重。
- 每30分钟选定一个完整候选。如果菜单已有另一种作物，仍恢复本窗口选定且缺失的候选，避免只保证类别存在而饿死某品种。
- 旧候选不提前移出普通轮转，避免改变 farming 长度、offset、跨域预算及旧非目标入口。
- 有空位则添加；满菜单只替换最后一个多余 reflect，保留最后一个反思；无可替换反思则最多添加一行。无候选或选定身份已存在时返回原数组。
- 原普通预算仍为56，极限为56普通+2水源+1烹饪+1播种。独立live stop及其他既有恢复机制另计，不把60误称整个最终菜单的绝对上限。
- 正常决策最终重新编号，解析复制完整 action，旧机会 id 冲突不改变所选 cropId 或 plotId。
- 上游现状只提供选定可见空地的作物集合；本修复没有声称轮换世界中所有空地。

## 独立测试

新增 `tests/plant-crop-choices-review.test.ts`，最终5/5通过：

1. 四个完整身份、共用旧id、重复项、反向输入、三个完整周期和同一30分钟窗口。
2. 菜单已有同id另一作物时仍恢复指定品种；相同完整身份以不同旧id存在时不重复恢复。
3. 0/55/56/59行与0/1/2/4个反思的组合，逐项验证原数组不变、仅最后多余反思可替换、增量至多1。
4. 用既有前置design入口构造真正饱和菜单；原59项逐项原位保留，播种加入后精确60。检查应急食物、拒绝、自我照护、水源、烹饪、最终独立停止和编号解析。
5. 未成年、未知年龄、船上、乘员、家庭同行及仅撤回表达边界，不恢复原始机会中的播种；合法停止继续可见；无候选及早退路径不变。

测试迭代期间校正了合成fixture：普通候选没有真正挤满前置预算，100个同域停止候选也会触发既有控制轮转；最终改为10个控制加60个前置design候选。此外最终菜单已有基础等待和厨房候选，最终断言检查相应动作类别而非强求额外合成重复候选。这些是测试假设修正，没有修改生产代码。
