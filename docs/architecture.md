# 架构概览

| 目录 | 责任 |
| --- | --- |
| `src/world/` | 世界状态、寻路、动物生态、生产、关系、交易、建造与逐步执行。 |
| `src/shared/` | 存档、行动、物品和观察更新的数据结构。 |
| `src/server/` | 模型调度、行动解析、SQLite 持久化与只读观察接口。 |
| `src/client/` | Phaser 地图、人物与动物档案、关系、图纸和历史面板。 |
| `tests/` | 隔离规则测试、存档和只读接口回归。 |

## 一次居民决定如何发生

1. 服务端从居民亲身观察、实际记忆和当前世界生成可以采取的行动。
2. 模型在这些行动中作选择，并可填写交谈内容、图纸参数或交易条款。
3. 世界推进时执行路程和劳动。抵达后再次验证库存、产权、可达性和同意，条件变化会反馈给居民重新决定。
4. 世界状态、事件和结算回执在同一个 SQLite 事务里写入。网页获取初始快照，再通过服务器事件流接收变化。

动物根据物种、饥饿、口渴、体力和危险选择行动，居民和野生动物可以消耗同一真实资源。工具耐久、货物、动物身份和季节变化随世界存档恢复。

## 观察接口

- `GET /ai-town/api/health` 提供服务、模型配置与停表状态。
- `GET /ai-town/api/world` 提供地图与世界快照。
- `GET /ai-town/api/events` 提供只读的增量观察流。
- `GET /ai-town/api/history/page` 提供分页历史。
- `GET /ai-town/api/people/:id/biography` 提供人物生平。

世界行动只能从模拟运行时产生。网页和公开接口只接受读取请求。模型密钥和限流使用窗口由服务端管理。

## 修改和测试

先确认[领域术语](../CONTEXT.md)，再沿“可选行动、实际执行、观察结果”检查改动。需要修改存档结构时，保留已有身份、物资和结算回执，并覆盖旧存档加载。新增行为至少在隔离世界经过一次正常入口和真实状态变化。
